## Findings, most severe first

L1. **Low (contract: breach of a declared deliverable) — `Match`'s docstring does not carry decision 3's sentence** (`src/vfs/models/entry.py:359`). Decision 3 and the Design say the docstring "gains decision 3's sentence", that a grep entry's regions never overlap and each holds one hit line, "because the docstring is where a caller reads what a region is"; the diff changes only the first line, from "a grep window" to "a grep region". A caller reading `Match` alone still cannot learn that a region's `before` lines may sit in the previous region. Fix text, appended to the first paragraph after "the aggregate (max) across regions.": "A grep entry's regions never overlap and each holds one hit line: a region's context starts after the previous region and stops before the next hit line, so a line shared by two windows appears once."

L2. **Low (tests: survived mutant, downgraded) — the oracle's budget-expiry exit is not pinned to return clipped regions** (`tests/support/oracles/matcher.py:182` and `:188`). I downgrade it from the table's High: the mutant lives in test support, not on any path the public surface reaches, and the engine expires only between bodies, so no product behaviour or engine-to-oracle comparison depends on this exit (READ, `verify.rs` `hits_batch`; `tests/support/oracles/matcher.py:101-112`).

Blocks read in `ATTACK-CLASSES.md`: Access control, Resource and file handling, Business logic, Feature abuse and data leakage, Chained vulnerabilities and trust boundaries, Obvious things; the MCP blocks of `AI-AND-LLM.md` were not read, as no MCP tool input changed.

Boundaries the diff touches: (1) a caller whose rights change during a line, supplying a second open of a file, against the host's held body, sink the bytes printed to the caller (access control, timing and ordering); (2) a script author whose sed script a caller runs under `--sandbox`, supplying `e`, `r`, `w` and their `s` forms, against the compile-time refusal, sinks host reads and writes under the caller's rights (feature abuse); (3) a caller's operand naming the working directory or its parent by an empty, `.` or `..` spelling, against operand validation, sink a cascading `Remove` (resource and file handling); (4) another caller creating a file at a path while a refused writer still holds bytes for it, against the writer's failed state, sink an `Append` into the other caller's file (business logic); (5) a caller reading large files through two descriptors, against `READING_BYTES`, sink the shared database's read load (resource exhaustion).

Records: (1) rejected: each open is a fresh `read` judged as the caller, and a body that gave way is read again under the caller's authority (`src/vfs/shell/host.py:361` to `:375`), so a revoke between opens is honoured (`test_an_open_after_a_revoke_is_refused`); a body held within one open across a revoke is the one-open-one-version rule the spec chooses, as a Unix open descriptor does; the open key is minted by vfs's own interpreter, never by the line. (2) rejected as a vulnerability: no sandboxed script reads a file it names or writes one, at any position of `--sandbox` (EXECUTED); the operand reads before refusal under `-f` (M1) read only files the caller named, under the caller's rights, and no byte reaches the script's output. (3) rejected: every spelling tried is refused before any lookup, and the root refusal predates this set. (4) rejected: after a refusal the writer sends nothing at any depth (P1 to P6 requests show one refused write and no later one), so the other caller's file is never appended to; the silent status in a child shell (H1) is a correctness defect, not a crossing. (5) needs_validation: the missing fact is what the lockstep re-read of M3 costs on Postgres within the default line deadline; a safe plan is the Postgres leg with a 100 MiB file read through `3<f 4<f`, counting bytes the router reads, and comparing with a single `cat f`. The `rm -ri` walk can tell a caller that an apparently empty directory holds a hidden child ("Directory not empty"), as `rm -d` already could at `5a823ea`; this set adds a route, not the oracle, and the spec accepts it, so it is not recorded against this set.

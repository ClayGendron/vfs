## The author's questions, answered first

1. **Decision 2 refuses a SQL Server database with `READ_COMMITTED_SNAPSHOT` off. Is a refusal right, or something weaker?** A refusal is right. READ, [AGENTS.md](../../AGENTS.md), the fourth rule under "Per lock": a setting that makes readers wait is "refused at first touch or flagged, never designed around", and the first rule rejects any design where a read queues behind a write "however rare the write is". A flag leaves a mount serving in the state the first rule rejects; the design is unreleased, so nothing deployed breaks; and the refusal has the shape the vector probe's already has (READ, `src/vfs/storage/backends/database/engine.py:633-661`). INFERRED: not retryable is right too, since a retry cannot change a database setting. The refusal as designed is wrong in one executed respect, finding H1: it refuses a database that has the setting on.
2. **Decision 5 sizes the executor from the pool. Does the size stay right when a host configures a different pool, and is "at most fifteen idle threads an engine" true?** The size cannot drift from the pool on an engine vfs builds: the host passes only a URL, vfs passes only `_engine_kwargs` (READ, `engine.py:220`), a `pool_size` in the URL's query does not reach the pool (EXECUTED, probe D: size 5), and the spec sets both sizes from the two constants it sums. What does not hold is the premise under the size, "a connection has one driver call in flight at most": a cancelled call's connection takes a second driver call for its close while the first still waits (EXECUTED, probe B; READ, the tree's own words at `engine.py:865-869`), finding M1. "At most fifteen idle threads an engine" is true as written for one executor, because a `ThreadPoolExecutor` never makes more threads than its width and makes them on demand (EXECUTED, probe A: two threads after one call); it is a count per engine, and the contention node's eighteen handles can hold 270, finding L6.
3. **Decision 6 detects nothing under a borrowed session factory. Is a docstring enough?** The stall stays reachable there with no word at run time (INFERRED from decision 6 and the label spec's decision 19: four of eleven runs hung on the default threads with the setting on). It is not enough where the spec puts it: `_engine_kwargs` is a private helper a borrowing host never reads, and the Intent's last sentence promises independence from the host's loop with no limit, finding L5. One read is available without an experiment (READ, `aioodbc/connection.py:50`: the connection keeps its executor as `_executor`, `None` meaning the loop's own), but it is a private attribute of the driver, so leaving it to the memo's experiment is sound.

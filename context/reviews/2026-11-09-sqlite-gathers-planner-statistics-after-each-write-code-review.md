## Findings, most severe first

- **M1** (Tests, medium; Adversarial, major with one executed failure) **Three `TestBulkInsert` spies count the statistics pass's statements**, `tests/storage/database/test_dialects.py:668-682` (`_spy_driver`), `:685-699` (`_spy_statements`), used by `test_driver_mode_pages_by_the_parameter_budget` (`:741-758`), `test_driver_mode_under_a_squeezed_budget_still_progresses` (`:760-770`) and `test_copy_mode_streams_records_on_the_raw_connection` (`:777-811`). Each test warms the store with `await storage.mkdir(path=Path("/warm"))` on a fresh file, which is a crossing commit (the first rows in a store with no statistics), so the host's pass task is pending when the spy is installed and no `settle_statistics()` runs before the counted session; the pass's fingerprint read, listing and `ANALYZE` go through `AsyncConnection.exec_driver_sql`, which both spies patch, so whichever of them lands in the window is counted as the test's own (`_spy_driver` appends `len(parameters or ())`, 0 for each). The concrete failure, EXECUTED in my parallel run of `test_statistics.py` with `test_dialects.py`: `assert ['SELECT 1', ...sqlite_stat1'] == ['SELECT 1']` with `Left contains one more item: 'SELECT group_concat(tbl || ' ' || coalesce(idx, '') || ' ' || stat, ';') FROM "main".sqlite_stat1'` at `test_dialects.py:806`. It is rare: 0 of 8 reruns of the three nodes under load and 0 of 25 isolated windows per test shape (`probe_spy_race2.py`) reproduced it, and the three pass alone and serially; it is a race on the aiosqlite worker thread's scheduling, not on the code's correctness. It is a breach of decision 20's own rule, "Any other test the full suite shows counting the step is filtered the same way", and a false red the inner loop and CI can show with the code unchanged. Closes with either `if is_statistics_statement(statement): return ...` at the top of both spy bodies (the predicate is already imported into sibling files) or `await storage._host.settle_statistics()` after the warming `mkdir` in the three tests, and the evidence is a green `uv run pytest tests/storage/database/test_dialects.py -p no:cacheprovider -q` in parallel.
- **L1** (Contract, decay) **The spec's Design says `close()` clears the analysis slot; the code keeps the finished task on purpose**: the Design's `settle_statistics()` bullet reads "`close()` calls `stop_analysis()` inside a `try` whose `finally` runs today's offload shutdown and dispose, and clears the slot", while `engine.py:566-576` never assigns `self._analysis`, and the slot's comment at `engine.py:246-247` says "kept after it ends so a test can see one ran"; `request_analysis` reads a finished task as done (`:484`), so nothing depends on the clearing. The code's reason is the better one. Fix text, in the Design bullet: replace "and clears the slot" with "and leaves the finished task in its slot, which `request_analysis` reads as done".
- **L2** (Contract, gap; Security, confirmed informational) **A pass that fails at its fingerprint read names the wrong statement, which on a borrowed engine can be a host application's table**, `engine.py:933-937`: the loop `for statement in listed:` leaves `statement` as the last listed `ANALYZE`, own or not, and the next awaited call, `pooled.info[STATISTICS_NAME] = await self._fingerprint(conn)`, does not reset it, so an `OperationalError` there (the only error the read lets through; a missing table is swallowed at `:807-812`) builds the advisory `"... failed at 'ANALYZE "main"."host_rows"': ..."`, a statement vfs never issued and a borrowed database's table name on an agent-visible Result. The write is unaffected and the leak is one identifier; no principal, path or body. Fix text: before the fingerprint read, `statement = "the fingerprint read"` or the formatted `STATISTICS_FINGERPRINT`, so the detail names what ran.
- **L3** (Ownership, minor smell) **`_own_statements()` is rebuilt for every listed statement**, `engine.py:456` and `:934` (`self._own_statements().get(...)` inside the loops): a 23-entry dict, each key re-quoted through the dialect's preparer, built once per listed statement per commit and per pass; bounded (at most the schema's tables, three on an unchanged commit) and about 0.013 ms a commit as measured, so it is cost in the noise.

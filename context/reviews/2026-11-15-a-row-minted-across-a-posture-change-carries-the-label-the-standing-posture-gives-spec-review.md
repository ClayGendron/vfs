## Scale and the production posture

- The watch: one single-row read by primary key per attempt that reads labels; it does not grow with the batch (READ, the memo's section 4: 39 to 41 statements for 10,000 files on Postgres, 496 to 498 on SQL Server).
- The hold: one single-row read per such attempt, two statements on Oracle; one integer kept on the session. Nothing grows with input and no chunk size is invented.
- The lock: one row, or on Oracle one table, held from the hold to the commit. Its wait profile differs by engine and the spec states one profile for all four: mints share it everywhere (EXECUTED on four engines), later sharers queue behind a waiting posture write on MariaDB, SQL Server and Oracle and pass it on Postgres (EXECUTED). M1 and M2.
- The redrive: one whole run of the call per posture write committed inside it, on any path of the mount. For a 10,000-file batch that is the batch's body again; the spec does not multiply it (L3).
- No designed cap, no SQLite assumption, no `IN` list, no numpy. The floor engines are the ones the criteria run on.

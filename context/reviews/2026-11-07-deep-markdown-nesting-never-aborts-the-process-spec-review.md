## The author's questions, answered first

1. **Decision 4 departs from the 0.5.3 binding by excluding every named child of an inline node from the inline parse's ranges. Is that departure sound, and is the spec's evidence that references do not change enough?** The departure is sound; the cited evidence does not test it, and stronger evidence now exists. READ: the binding's loop in `tree-sitter-md-0.5.3/bindings/rust/parser.rs` (`parse_with_options`) calls `goto_first_child` and then only examines `goto_next_sibling`, so the first visible child is never excluded; the 0.5.4 binding has the same loop, so upstream did not fix it. The skip matters only when the first visible child is named, which happens when the first line of the inline holds no punctuation token. EXECUTED (probe 2): that was true of 1,198 of 1,502,622 inline nodes; 11 inline trees differ between the two splices, and every difference is one anonymous `>` node that the binding leaves in the inline tree and decision 4 leaves out (for example `cpython/InternalDocs/parser.md` at bytes 30139-30140); 0 of the 1,502,622 inline nodes yield a different set of `link_destination` or `code_span` nodes. EXECUTED (probe 4): across both the grammar change and the splice change, 0 of 12,582 files yield a different reference list. The spec's sentence "the two-binary probe of the problem found no inline tree that differs" cannot be the evidence for decision 4: a probe that found no inline tree differing on this repository and `cpython` did not run decision 4's splice, because that splice changes the inline trees of `cpython/InternalDocs/parser.md` and two files under `context/` (INFERRED from probe 2). That is a write-in, L1. One further fact for the decision's wording: EXECUTED (probe 2), the named children of inline nodes are 119,949 `block_continuation` nodes and one `ERROR` node (`gitlabhq/doc-locale/ja-jp/user/project/issues/design_management.md`); the binding excludes an `ERROR` child too unless it is first, so this changes nothing, but the decision's first sentence should say so.

EXECUTED (probe 4): 42 of 12,582 real files have a different block tree under 0.5.4 (mostly `gitlabhq` issue and merge-request templates), so stored chunk spans can change, and `src/vfs/models/chunking.py:174-176` says a grammar crate change that alters chunk shapes bumps `CHUNK_GENERATION`. ## Findings, most severe first

Consequence if built: the code carries a choice whose stated reason is false, and a reader comparing the two modules finds them inconsistent with no named reason. Closes with: the decision's last sentence replaced by "A language that fails to load is a build defect, so `default()` panics with the grammar's name, as the 0.5.3 binding's `parse_with_options` did with `expect`; `chunk.rs` instead answers `None` per body, because its host has a fallback splitter and the reference walk has none.

F4 (High on `62ce1abb`, answered in `c0fbda4b`; the session lead's regression). What I read: the node's relabel, started after the eligible flip, takes the meta row and then updates `/x.txt` by `entry_id` (`test_races.py:1106` to `1113`). That matches the four legs exactly. Nothing else in the slice changed what it locks: the stamp is written only by the publishes, the seek terms change only the size read, a read takes no lock, and the new index's keys are written by the flip, which the relabel's column (`everyone_level`) never touches. ## Security

- Method: the installed `security-audit` skill in guidance mode; no run folder written; target code ran only as scratch scripts against SQLite files under my scratch directory, no network and no live service.
- Who may start a refresh: `refresh()`, like `rebuild()`, is a storage-level method that takes no authority and is not on the `VirtualFileSystem` surface (READ, `backend.py:1116` to `1122`; no rung in `ops.py` or `rights.py` names either).

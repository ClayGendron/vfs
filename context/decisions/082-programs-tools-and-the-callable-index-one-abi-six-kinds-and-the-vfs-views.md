# 082. Programs, tools and the callable index: one program ABI, six kinds behind it, and the system's own tree served as views under `/.vfs`

- **Status:** proposed 2026-10-15 (Clay's decisions the same day: tools and programs are two things; both have paths, anywhere; an index like `PATH` finds them; the index and the catalogues are views under `/.vfs` like the trash view, not `/.agents` families; `run` is retired; the default install directory is `/opt/bin`; a session may prepend directories it can already list). Feeds specs 167, 169 and 170. Retires the `tools` and `skills` families of `/.agents` and the `run` verb; amends ADR 080 pin 9 ("`run` on its own axis") by removing the verb.
- **Date:** 2026-10-15
- **Amended 2026-10-15** after the pre-build reviews of specs 169 and 170 and Clay's answers: `cat` never runs a tool (pin 13); `SupportsRun` deleted (pin 12); `/opt/bin` is created at posture `read` and installing needs `add` (pin 9).
- **Deciders:** Clay Gendron
- **Decided by:** human (Clay drew the tool/program line, asked for paths anywhere with an index, and chose `/.vfs` views over repo-shaped conventions; the assistant led the research and drafted the pins)

## Context

The memo `research/2026-10-15-the-agent-shell-prior-art-and-experiments.md` (§4, §5, §6; studies `02-program-catalog.md`, `03-program-abi-and-bin-namespace.md`, `10-wasm-program-spike.md`) found:

- Every peer that runs commands over a virtual filesystem gives a program the same six things and takes three back: argv, env, cwd, a stdin stream, a filesystem capability in; stdout, stderr, an exit code out. busybox, toybox and uutils dispatch by name through one table whose row's flags choose the execution strategy; the caller never sees the strategy.
- just-bash marks host-provided commands `trusted` and says they "can bypass all sandboxing by design"; bashkit has `insert_trusted` for host builtins and a resolver hook for names the host serves lazily. The July memo called it two verbs of install, two trust levels, never blurred.
- Plan 9's `/bin` is a union directory assembled by the namespace file with `bind -a`; `/dev`, `/env`, `/proc`, `/net` and `/srv` are served by devices, not stored. rc's `$path` is the order to search.
- The spike stored a real wasm program as an entry, resolved it with one `ls`, read its bytes with `read(columns={"data"})`, and ran it. `/.agents/bin` was not refused by the path rules; a top-level `/bin` collides with ingested repositories (thousands carry `bin/`).
- Classified by how vfs answers them, 30% of agent command segments are vfs verbs, 35% pure text programs, 24% shell builtins, 1% guest interpreters and 9% host programs that never run. A median text program is 233 lines in just-bash and 525 in bashkit; `sed`, `awk`, `find`, `jq` and `sqlite3` are 2,500 to 15,000.
- The `run` verb exists at rung `read`, routes to `SupportsRun`, and no shipped storage implements it. Unix and Plan 9 have no `run` command: the program's name is the command and `exec` is a system call.

## Options considered

- **One ABI, six kinds, a union index served as `/.vfs` views (chosen).** Pros: one calling convention for everything an agent can invoke; the index is a directory agents can `ls`; the system's own things live in one reserved tree the system serves; no repo convention baked into vfs. Cons: the router gains a view family it does not have today; a union across mounts is new machinery.
- **Reserved `/.agents/{tools,skills,bin}` families.** Pros: exists in part today. Cons: a dotted convention borrowed from repositories; the location makes a thing a tool, so nothing can live anywhere else; the host has no index to compose.
- **A top-level `/bin`.** Rejected: collides with ingested repositories.
- **Keep `run` as the execution verb.** Rejected: no Unix or Plan 9 user types `run`; local programs are executed by the shell's own host, which needs only `read`; the one case where storage executes (a remote tool) is a program kind, not a verb.
- **Programs spawn programs (`find -exec` inside the program).** Rejected: `xargs` and `find -exec` are shell builtins that re-enter the union; a program holds no execution capability.

## Decision

Fifteen pins.

**The ABI:**

1. **Every program implements one shape.** In: `args` (argv without the name, already split, quoted and globbed by the shell), `env` (a frozen snapshot of the exported variables; never an authority, token, URL or key), `cwd` (a canonical `Path`), `stdin` (a stream of chunks of the declared shape), `fs` (the filesystem capability), `budget` (deadline, cancellation, output cap). Out: `stdout` (a stream of chunks of the declared shape), `stderr` (text lines, never structured), an `int` exit code. A program declares `name`, `consumes`, `produces` and `forms`.
2. **The filesystem capability is the vfs verb set curried with the caller's `Authority`.** It has no authority parameter, no execution verb and no grant verbs, and it takes absolute paths only. For sandboxed kinds it is a type boundary; for Python builtins it is a discipline the review enforces. Every call re-enters the public router method, so every gate fires. A program cannot express a widened call: ADR 069's no-side-door rule is a type.
3. **Six kinds behind the one ABI.** Verb builtins (the shell's code over vfs verbs); text programs (a Python layer holding the call's `fs` for operands and writes, around a Rust core in `crates/vfs-core` with no file access, bytes to bytes); programs (bytes stored in vfs, run in a sandbox as the caller); tools (Python functions the host registered, run in the host process with the host's authority); MCP tools (executed by a remote server); skills (read, never executed). The kind is invisible on the pipe.
4. **One name, many kinds over time.** The name is the contract; the kind is a table row. Each row declares its `forms` in a declarative option grammar plus the subset this kind implements. A known but unimplemented form refuses `vfs.unsupported.form` (a child of `unsupported`) naming the program, the form and the kind, exit 2. An unknown flag is `vfs.invalid`, exit 2. When a name changes kind, the old implementation becomes the oracle in `tests/support/` and a parity test pins the new one over the measured forms. A program with no earlier kind has no Python oracle; it is pinned by recorded fixtures and the chunk-split law (output invariant to how the input is chunked).
5. **Native names, native semantics** (Clay, 2026-10-15). Common commands keep their Unix names and flag meanings. The corpus orders which forms land first; it never renames. `rg` and `grep` are one verb with two names, two flag tables and two renderers. `ls -la` prints the row's real columns in the long format's positions, never fake mode bits. Cosmetic flags (`--color`, `--line-buffered`) are accepted and ignored, never refused. GNU's flag semantics are the reference; BSD spellings agents type that mean nothing under GNU (`sed -i ''`) are accepted; where POSIX and GNU differ, POSIX's rule holds (`cut -c` counts characters); every deliberate difference is listed in the spec's known-deltas table.

**The views:**

6. **The system's own tree is `/.vfs`, served as views.** Beside the trash view: `/.vfs/bin` (the union of everything callable), `/.vfs/tools` (host-registered functions, each an entry whose content is its manifest and schema), `/.vfs/mcp/<server>/{tools, resources,prompts}` (each connected server projected by declared shape: tools callable, resources listed and readable with `cat` through `resources/read`, prompts listed), `/.vfs/skills` (the union of every skill directory on the skill index), and the `/.vfs/sessions`, `/.vfs/jobs` and `/.vfs/run` views the session and pipe decisions name. The `tools` and `skills` families of `/.agents` are retired; `AGENTS_ROOT` goes.
7. **Two owners of `/.vfs`.** The trash view stays per mount, served by each backend at `<mount>/.vfs/trash`, and every backend lists its `trash` head under `/.vfs` even when no row is stored. The catalogue views are per namespace, served by a router-owned view table checked before the mount table, never by a storage bound into the mount table. The grant verbs at a `/.vfs` path resolve to the root binding. The spec states which heads belong to which owner and what `ls /.vfs` shows at a mount point versus the root.
8. **Views are read-only.** Every data-plane mutation anywhere beneath `/.vfs/` is refused `invalid`, in global and mount coordinates, with a hint naming the writable directories on the index; `sweep` at the trash head and the grant verbs stay lawful. Installing a program is a `write` into one of those directories. The `/.vfs` tree stays hidden from unscoped `glob` and `grep`, so the catalogue never pollutes a search.
9. **Programs live anywhere; the index says where to look.** The host registers the directories that feed `/.vfs/bin`, in order. The default when a host configures nothing is one writable directory, `/opt/bin` ("optional" add-on software in the Filesystem Hierarchy Standard; collides with nothing agents ingest), created by the host as the system actor at posture `read`, so everyone lists and runs and installing needs an `add` grant (Clay, 2026-10-15). A mounted repository's `bin/` joins only when the host lists it. Skills get the same treatment with their own list; a skill is a directory holding `SKILL.md`, anywhere; a skill-index entry is a container of skill directories, and an ingested repo's `.agents/skills` or `.claude/skills` becomes one, not vfs law.
10. **Resolution order.** Shell builtins that must be builtins (`cd`, `export`, `unset`, `exit`, `set`; `source`, `.` and `alias` are `unrecognized` per ADR 081) are handled before resolution; then the kernel's program table (verb builtins and text kernels); then `/.vfs/bin` in index order, first match wins, the kinds not outranking each other. A word with a slash names an entry directly. Suffixes resolve in the order `.wasm`, then the guest suffixes, then none (a suffix-less bytes row runs when its mime is `application/wasm`); the session prefix reaches `/.vfs/bin` through the call's context. A kernel name is never shadowed by a write; the host promotes a stored program over a kernel name by configuration. A session may prepend directories it can already list to its own search order (order, not rights; Plan 9's per-process union).
11. **Resolution is gated.** Resolving a name is one batched `stat` over the candidate paths under the caller's authority; executing a stored program or calling a tool needs `read` on its entry, and the `read` is issued on every run, a cache hit included. A name the caller cannot list is 127; a name the caller can list but not read is 126. Tool and MCP entries follow the regular posture rules at their paths (Clay, 2026-10-15), no special default.
12. **`run` is retired.** It leaves `Op`, `EXEC_OPS`, `VERB_RUNGS`, the router, the `Session` facade, the README's verb table and the tests that pin a mount declaring it. Local programs are executed by the shell's own host, which reads the program's bytes through `read`. `SupportsRun` is deleted. The one kind that storage executes, the MCP tool, is reached through one router-internal gated door that the program table calls; no storage protocol carries execution. The one programmatic execution door is the `cli` meta-verb, which takes a command string or an argv list; the argv form is our `execve`.

**Ergonomics across kinds:**

13. **Same calling convention for every kind.** `name args`, stdin in, stdout out, the exit-code table, `--help` from the forms or manifest, `type name` says what it is and where it lives. A program takes argv; a tool takes a JSON schema, so the shell maps flags onto schema properties, takes stdin as the body for a single text or object parameter, and offers `--json` as the escape hatch. `cat` of a tool entry returns its manifest and never invokes it: a tool runs only when typed as a command (a `read` that executes host code would be a side door through every verb that reads).
14. **Trust is shown, not hidden.** `type` and the manifest say "runs on the host, may reach the network" for a tool and "runs as you" for a program. The calling convention does not change.
15. **Output across kinds.** A program's stdout is bytes lifted into one row. A tool's return type decides its row: `str` is a text row, `bytes` a bytes row, `None` no row, a `Result` passes through, anything else is one JSON row. An MCP result's content blocks come in through the reverse of the content-channel adapter, one row per block at `/.vfs/run/<call-id>/<i>`, links and unknown blocks as placeholder rows. A tool's `isError` is the tool's own non-zero exit: status 1, its text to stderr, no invented kind.

## Consequences

- Capability grows by adding a row to a table or an entry to an indexed directory. The parser, the pipe and the seams never change for a new program.
- The router gains a view family and a union resolution it does not have today; the trash view's precedent (rows at their own paths through a derived view) is the shape to copy.
- `AGENT_FAMILIES`, `tool_path`, `skill_path` and the directory-unit rules in `paths.py` are replaced; `Skill.to_entries()` takes a location.
- Removing `run` touches the ops vocabulary, the drift test, the router, the protocol, the session facade and the README. Small, and it leaves no verb an agent would never type.
- Tools gain permissions no peer has: a tool entry is a row with a posture and grants, so who may call a tool is who may read a file.
- The one storage-executed kind, the MCP tool, keeps a storage capability. Its spec (170) reconciles the MCP-mounts work with the stateless 2026-07-28 revision.

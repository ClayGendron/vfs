# The two faces named: `VirtualFileSystem` is the synchronous face, `AsyncVirtualFileSystem` is the kernel, both imported from `vfs`, and the synchronous face warns once when it blocks a loop that is not its own

A refactor of names and one small behaviour, decided by Clay on 2026-11-06 from [the API-shapes memo](../../research/2026-11-06-sync-and-async-api-shapes.md) and recorded here before any code is written. It changes the public API: the kernel class `vfs.base.VirtualFileSystem` becomes `AsyncVirtualFileSystem` and its session `AsyncSession`; the synchronous front `vfs.sync.SyncVirtualFileSystem` becomes `VirtualFileSystem` and its session `Session`; all four are exported from `vfs`, and the names `SyncVirtualFileSystem` and `SyncSession` disappear. It adds one runtime warning and one packaging file (`py.typed`). It changes no verb's contract, no schema format, no rights and no engine code; it needs no engine leg, because the sync face's mechanism is unchanged and its Postgres leg already ran. Every module keeps its path. It touches the same files as [the sync facade spec](../archive/2026-11-06-the-sync-facade.md) plus the kernel's own module, every test that names the kernel class, the docs and the standards; it is parallel-safe with nothing that names `VirtualFileSystem`, which is why it lands as one chunk on its own.

## The problem

Measured on the branch `claude/two-faces-named` at `d089d52`, 2026-11-06, with `grep -rnw --include=*.py` for the code counts, unless labelled otherwise.

- **The names run against what every population expects.** READ, [the memo](../../research/2026-11-06-sync-and-async-api-shapes.md) sections 1 and 4 and [the FastAPI study](../../research/studies/2026-11-06-sync-and-async-api-shapes/01-fastapi-and-software-engineers.md): httpx, psycopg 3, pymongo, SQLAlchemy and the vendor SDKs put the plain name on the synchronous face and `Async` on the other; vfs today does the reverse (`vfs.VirtualFileSystem` is async, `vfs.sync.SyncVirtualFileSystem` is the front), and the `Sync` class prefix has almost no precedent (the Supabase family and nobody else). READ, [the pandas study](../../research/studies/2026-11-06-sync-and-async-api-shapes/03-pandas-and-data-engineers.md): a data engineer who types `from vfs import VirtualFileSystem` and then `fs.read(...)` without `await` gets a coroutine today.
- **Clay's rubric and answers.** READ, this session on 2026-11-06: scored on first contact, convention match, the language's own default (plain Python is synchronous, `await` is the marked form), failure legibility, type-checker catch, churn and kernel identity, the inverted naming won on every row that measures what developers expect to see; Clay chose: sync is plain; both faces imported from `vfs`; no `a`-prefixed twins on the sync face; the sync face warns once when it blocks a foreign running loop. Clay's earlier ruling stands: the kernel is async because it must be cloud native and agent native; the `Async` marker on the kernel class satisfies it without moving the kernel.
- **The dream of one name for both spellings is closed on evidence.** EXECUTED in [the mechanism study](../../research/studies/2026-11-06-sync-and-async-api-shapes/04-the-dual-mode-mechanism.md): every mechanism that chooses by a running loop returns a coroutine for the sync spelling in a real ipykernel cell, `ty` and `mypy` reject the `Result | Coroutine` type in both spellings, and the lazy result erases types to `Any`. The two spellings must differ by name, and they will differ by class.
- **The sync face can freeze a loop it does not own, silently.** EXECUTED, the FastAPI study's placement table: the facade called from an `async def` endpoint served 100 requests one at a time in 5.68 s with the server loop frozen for 5,683 ms, every answer correct, no warning, no traceback. EXECUTED, [the LangChain study](../../research/studies/2026-11-06-sync-and-async-api-shapes/02-langchain-and-ai-engineers.md): 200 facade reads on the agent's loop thread let a heartbeat tick zero times. No type checker can see it, because the sync call is a legitimate call.
- **The package ships no typing marker.** EXECUTED, the FastAPI study: `mypy` against the installed package reports `module is installed, but missing library stubs or py.typed marker`, so every argument about a checker catching a forgotten `await` holds only for `ty` and for `mypy` reading from source. EXECUTED: `ls src/vfs/py.typed` finds nothing.
- **The word kernel is spoken for.** READ: spec 179 is "the storage seam as the kernel" and spec 181 regroups the public surface "by kernel group", both from the retired ADR 087; a module named `vfs.kernel` holding the mount router would contradict them. The router's own docstring calls it "async router over one mount table".
- **What the rename touches.** EXECUTED: the word `VirtualFileSystem` appears 24 times in 9 files under `src/`, 361 times in 17 files under `tests/`, 22 times in 9 files under `docs/` and the README, 14 times in 3 standards pages (`python-style.md`, `roadmap.md`, `constitution.md`) and 44 times in 13 active numbered specs; `vfs.base` is imported by 7 source files and 16 test files, and two test files import the kernel through the package (`conftest.py`, `tests/results/test_facts.py`).

## Decisions

Every choice this change needs, numbered, each with its reason. The sync facade spec's decisions 1 to 14 stand except where a decision below renames what they built.

### 1. The synchronous face is `VirtualFileSystem` and `Session`; the kernel is `AsyncVirtualFileSystem` and `AsyncSession`

The kernel class in `vfs/base.py` and the session class in `vfs/session.py` are renamed in place; the two classes in `vfs/sync.py` take the plain names; `SyncVirtualFileSystem` and `SyncSession` cease to exist, with no alias left behind. Reason: Clay's decision from the rubric, resting on the memo's evidence that the plain-sync, `Async`-marked convention is what the FastAPI population's libraries and every vendor SDK use, that plain Python is synchronous and `await` is the marked form, and that a `Sync` class prefix has no precedent worth following; the kernel stays the async kernel Clay ruled it must be, and the `Async` in its name says so to the readers who need it, the MCP, LangGraph and FastAPI `async def` audiences. No alias, because the tree is pre-release with no users to migrate (CLAUDE.md, Project stage), and a second public name for one class is a second thing to document and to drift.

### 2. Both faces are imported from `vfs`; no module is renamed; `vfs.sync` and `vfs.base` keep their paths

`vfs/__init__.py` exports `VirtualFileSystem`, `AsyncVirtualFileSystem`, `Session` and `AsyncSession`; the documented imports are `from vfs import VirtualFileSystem` and `from vfs import AsyncVirtualFileSystem`. Reason: Clay's answer ("both from `vfs`"), and the memo's finding that the populations pick by import, which one place to look serves best. The module paths stay because they become internal once the top-level names exist, because `kernel` is spoken for by specs 179 and 181, because `facade` is already what `Session` calls itself, and because spec 181 regroups the public surface and should own any module naming when it is picked up.

### 3. The mechanism is unchanged: the sync face wraps the kernel through one loop on one daemon thread per instance, with the guards and the drain the sync facade spec landed

Reason: the memo settles the mechanism (fsspec, Dask, Starlette's `TestClient` and LangChain's own callback bridge use it; SQLAlchemy's inverse is closed by the async kernel), and the landed code's parity tests, deadlock refusal, closed fact, drain and run-on-Postgres evidence all carry over under the new names. A rename that also changed behaviour would make the code review read two changes at once.

### 4. The sync face gains no `a`-prefixed twins; a caller who needs both spellings holds both classes

Reason: Clay's answer ("two classes only"). The LangChain population's one-object need is met by holding an `AsyncVirtualFileSystem` for the coroutine half and a `VirtualFileSystem` for the function half; the docs state the one rule that makes that safe: the two must not share one storage whose engine binds to a loop (asyncpg), because the kernel touches it on the caller's loop and the sync face on its own. The Postgres-leg experiment that pins the rule is in the memo's unsettled list, not in this spec.

### 5. A sync verb or one of the seven management methods that hop through `_await`, called on a thread whose running event loop is not the sync face's own, serves the call and emits one `RuntimeWarning` per facade, pointed at the caller's line; `close()` is exempt

The check sits in the two hops after the closed check and the own-thread refusal: `asyncio.get_running_loop()` inside a `try`, a `RuntimeError` meaning no loop and therefore no warning; any running loop the check sees is a foreign one, because the facade's own loop runs only on its own thread and that thread was refused one line earlier, so the check has no own-loop branch; a foreign loop sets a once-flag on the facade and warns with `FOREIGN_LOOP_WARNING.format(op=...)` under `RuntimeWarning`, the message reading "VirtualFileSystem.{op} called on a thread whose event loop is running; the call blocks that loop until it returns. In a notebook cell that is expected and this is the one notice; inside async code use AsyncVirtualFileSystem." The `stacklevel` is computed, not constant, so the warning's filename and line are the caller's: a facade verb is four frames from the caller and a session verb five. `close()` is exempt: it is the call that puts the facade away, its wait is bounded by the drain, and the landed pin `test_close_works_from_inside_a_running_loop` makes exactly that call; "management method" here means the seven that hop through `_await` (`add_mount`, `remove_mount`, `bind`, `unbind`, `remount`, `locate`, `locate_edge`). `_await` gains a leading `name: str`, each twin passing its own, so the message reads `VirtualFileSystem.add_mount` as it reads `VirtualFileSystem.read`. A `Session` verb reaches the check through its facade's `_result`, so the flag is the facade's, one warning per facade however many sessions it opens, and the message names `VirtualFileSystem.{op}` whichever twin was called. The call then proceeds unchanged. Reason: Clay's answer ("warn once"); the FastAPI freeze and the LangChain stall are the one mistake no type checker can see, a warning names the async face at the site of the mistake, and once per facade keeps a notebook, where every cell has a running loop, to one line per facade rather than one per call. The message speaks to both audiences because the notebook is the sync face's first audience (the facade spec's first line) and a notice that told it to leave would send a data engineer into the asyncpg loop hazard the sync face exists to avoid, or make them silence `RuntimeWarning` for the whole kernel. The location is computed because Python's default filter deduplicates a warning by its location, and a constant depth would name a line of `vfs/sync.py` and collapse every facade in the process onto that one line. A refusal was rejected because it would break the notebook; silence was rejected because the freeze is silent already.

### 6. `src/vfs/py.typed` ships in the package

An empty marker file beside `__init__.py`; maturin includes it with the Python package. Reason: the forgotten-`await` argument that favours typed twins rests on type checkers seeing vfs's annotations, and `mypy` refuses to read an installed package without the marker; `ty` reads the source and is not affected. The wheel's listing is checked at the landing.

### 7. The root `conftest.py` closes both faces at a docs page's teardown

Its teardown finds every `AsyncVirtualFileSystem` in the page namespace and closes it on the page's loop as today, and every `VirtualFileSystem` and closes it with its own `close()`. Reason: the README and the reference pages will show the sync face under the name the teardown used to match for the async one; a sync face left open by a fence would otherwise leak its loop thread into the next page.

### 8. The docs lead with the sync face for scripts and notebooks and point async-native readers to the kernel; the reference splits by face

`docs/reference/api.md` documents `AsyncVirtualFileSystem` under the heading "# `AsyncVirtualFileSystem`: the kernel's API" and the nav entry "Kernel API (async)", and says in its first paragraph that `VirtualFileSystem` is the synchronous face with the same verbs; `docs/reference/sync.md` documents `VirtualFileSystem` and `Session` under the heading "# `VirtualFileSystem` and `Session`: the synchronous face" and the nav entry "Synchronous face", loses every `Sync` spelling, and its lifecycle section says in one sentence that the foreign-loop notice appears once per instance in a notebook and what it means; `docs/reference/session.md` documents `AsyncSession` under the heading "# `AsyncSession`" and the nav entry "AsyncSession" and names `Session` as its sync twin; the README's quick start shows the sync snippet first and the async snippet beside it, both as fences Sybil runs, and its Known limits line reads "Neither face is a storage and neither can be mounted". Reason: a page titled "Session" that documented `AsyncSession` while `Session` lived on another page would send a reader following the nav to the wrong class; the memo's populations split by where they run, and the import line is the only thing that differs; showing both side by side is what the FastAPI docs do for `def` and `async def`.

### 9. The standards follow the names; the active numbered specs are not rewritten

`python-style.md`'s Async rule names `AsyncVirtualFileSystem` as the kernel and `VirtualFileSystem` as the synchronous face; every line of `roadmap.md` that spells either old name follows, each keeping its sense: X1's criteria, X2's criterion 1, K10's story and its acceptance 7, and the D28 row; `constitution.md` Article 1.4 says `AsyncVirtualFileSystem` where it says `VirtualFileSystem`, a name and nothing else; `how-we-code.md` names neither class and is not touched. `tests/lint/test_code_shape.py::test_the_standards_agree_with_the_tree` gains the forbidden entries `"python-style.md": (..., "SyncVirtualFileSystem")` and `"roadmap.md": ("SyncVirtualFileSystem", "SyncSession")` and the required entry `"python-style.md": ("vfs.sync", "AsyncVirtualFileSystem")`. The 14 active numbered specs that say `VirtualFileSystem` meaning the kernel are left as written. Reason: standards state the tree and must be true; a numbered spec is converted on pickup, as the process page says, and links point backward, so an earlier document is not edited to match a later one.

### 10. The tests keep their files and mirror the renames; the parity test's family map inverts

`tests/test_sync.py` stays the sync face's test file (it mirrors `src/vfs/sync.py`, whose path is unchanged); its `FAMILY` map becomes `{"AsyncSession": "Session", "AsyncVirtualFileSystem": "VirtualFileSystem"}`; every other test file replaces the kernel's name mechanically. The warning gains its own pins and the marker its own. Reason: the mirror rule, and a rename whose tests moved files would hide the mechanical part of the diff.

### 11. This spec lands as one chunk after Clay's review of the sync facade's pull request, on the branch Clay names

Reason: Clay asked for the decision to be committed as a spec now and the coding deferred; the rename touches more than forty files, so it must not ride inside the open pull request's review.

## Intent

A developer who types what the language suggests, `from vfs import VirtualFileSystem` and `fs.read(...)`, gets a `Result` in a script, a notebook cell, a thread pool and a FastAPI `def` endpoint. A developer writing async code types `from vfs import AsyncVirtualFileSystem` and `await fs.read(...)`, the name telling them which they hold, and their type checker catches a dropped `await` because the kernel's verbs return coroutines and the package now says it is typed. A developer who puts the synchronous face inside `async def` sees one warning that names the class they wanted, instead of a frozen server and no message. Nothing a verb does changes, and nothing in the mechanism that keeps an asyncpg engine on one loop changes.

## Design

**The renames.** `src/vfs/base.py`: `class VirtualFileSystem` becomes `class AsyncVirtualFileSystem`; its docstring's first line says "the asynchronous kernel; `VirtualFileSystem` is its synchronous face". `src/vfs/session.py`: `class Session` becomes `class AsyncSession`. `src/vfs/sync.py`: `class SyncVirtualFileSystem` becomes `class VirtualFileSystem` and `class SyncSession` becomes `class Session`; the module docstring's example reads `from vfs import VirtualFileSystem`. `src/vfs/__init__.py` imports and exports the four; `__all__` sorted as it is today. Every other `src/` reference follows (`vfs/base.py` builds sessions; the doubles in `tests/support/` subclass the kernel). The mechanical pass goes by import path, not by name: every `from vfs.base import VirtualFileSystem` becomes `AsyncVirtualFileSystem`, and the two package-level imports of the kernel, `conftest.py` and `tests/results/test_facts.py`, change to `from vfs import AsyncVirtualFileSystem`, because after the rename `from vfs import VirtualFileSystem` keeps resolving and binds the sync face.

**The warning.** In `src/vfs/sync.py`, a private method `_warn_if_blocking_a_foreign_loop(self, op: str) -> None` called by `_result` and `_await` after their closed check and own-thread check, and by nothing else (`close()` never calls it); it reads `asyncio.get_running_loop()` in a `try`, returns on `RuntimeError`, returns when `self._warned` is already set, else sets it and warns with `FOREIGN_LOOP_WARNING.format(op=op)` under `RuntimeWarning` at the depth `_caller_stacklevel()` returns. There is no own-loop branch: the own loop never reaches the check, because the own-thread refusal before it is the same fact, and a branch for it would be a line the 100% gate cannot reach. `_caller_stacklevel()` is a private module function that walks `sys._getframe(1)` outward until a frame whose `f_globals["__name__"]` is not `vfs.sync` and returns that count plus one, so a facade verb and a session verb each point at the caller's line (Python 3.12's `skip_file_prefixes` does the same and is not used because 3.11 is in the matrix). `_await(self, name: str, call, *args, **kwargs)` takes the management method's name first, and each of the seven twins passes its own. `_warned` joins `__slots__` and `_attach` sets it to `False` beside `_closed`, so `wrap()` gets the flag as `__init__` does. The constant `FOREIGN_LOOP_WARNING` holds the message template of decision 5 beside the other detail strings, and `LOOP_THREAD_DETAIL` ends "uses `AsyncVirtualFileSystem`" now that the name says it.

**The marker.** `src/vfs/py.typed`, empty.

**The root conftest.** `_teardown` closes `AsyncVirtualFileSystem` instances on the page loop and `VirtualFileSystem` instances by calling `close()`; both found by `isinstance` over the namespace values, deduplicated by identity as today; it ends with `assert not [t for t in threading.enumerate() if t.name == LOOP_THREAD_NAME]`, so the docs step of `scripts/ci.sh` holds criterion 10 on every run.

**The docs.** As decision 8, with the three headings and nav entries it names changed in the pages and in `mkdocs.yml`; the README's quick start becomes two fences under one heading, "Synchronous, for scripts and notebooks" and "Asynchronous, for servers and agents", each writing and reading one file and asserting on the `Result`. The fences build their own instances under names other than `fs` and `storage`, which the conftest provides as the kernel over a scratch SQLite file.

**The standards and the lint.** As decision 9.

**The tests.** `tests/test_sync.py` gains `test_the_four_names_are_exported_and_the_old_ones_are_gone`, `test_the_plain_name_is_the_synchronous_face`, `test_a_sync_verb_on_a_foreign_running_loop_warns_once_and_serves` (an `async def` test, so the test's own loop is the foreign one; a facade verb, a session verb on a second facade, then more verbs and `locate`; `warnings.catch_warnings(record=True)` with `simplefilter("always")` around each, the first record's `filename` compared with the test module's `__file__`, the later records empty), `test_no_warning_without_a_running_loop`, `test_the_own_loop_refusal_comes_before_the_warning` and `test_close_inside_a_running_loop_emits_no_warning`; the landed ipykernel pin asserts the notice's text appears exactly once across its cells' streams; `tests/test_version.py` gains `test_the_package_ships_its_typing_marker`; `test_the_docs_name_the_two_faces` reads the three pages' first `#` headings and `test_the_reference_page_is_in_the_nav` the three nav strings. Every existing test keeps its node id.

**Scale.** Nothing grows with input; the warning check is one `get_running_loop()` call per hop, a dictionary lookup in the running interpreter, and the once-flag makes the `warnings.warn` call happen at most once per instance.

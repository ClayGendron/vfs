## The question we are answering
Clay (2026-10-15): build a full CLI for agents, Unix and Plan 9 class. "Agents shouldn't feel limited from what they can do with a bash terminal." The CLI is the agent-facing surface vfs promises in its README ("your agent already knows `ls`, `grep`, `cat`"). It must be built so its capability grows over time: today the vfs verbs as builtins; then pipes and the pure text programs; then wasm programs installed as entries; then guest interpreters (Python via Monty or CPython-on-WASI, JavaScript via QuickJS) behind one capability contract; eventually a hermetic runtime.

The layering we start from (from the July memo, below): shell plus verbs are the kernel, our code, trusted; programs are user space, untrusted, capability-only. Every program is the same shape: arguments, a stdin stream, an environment and a filesystem capability in; stdout, stderr and an exit code out. The filesystem capability IS the vfs verbs with the caller's authority; no other door exists (ADR 069's no-shell rule is an enforcement property: `grep` in this shell can only resolve to `storage.grep()`). The program table is a directory in the namespace, Plan 9 `/bin` style; installing a program is a `write`.

Multimodal: the shell's unit of data is the row, not the byte. An `Observation` already carries `data` + `mime_type` (spec 152 slice A landed it). Text output gets a canonical placeholder for media, never base64. The ONLY wire target for typed content is the MCP standard's content blocks (Clay, 2026-10-15: "follow the MCP standard and only that"; no LangChain/OpenAI/Anthropic-specific adapters). A pure-text CLI and an MCP tool are two projections of the same `Result`.

The goal is measurable: a corpus of real commands agents issue in a bash terminal, and the fraction of it that parses and runs on the vfs shell. Toybox's roadmap (commands ranked by what distros actually invoke) is the model for the catalog.

The memo this feeds will produce five ADRs: (1) the shell surface at v1 — grammar, quoting, operators; (2) the program ABI and the bin namespace; (3) the pipe payload; (4) execution policy — the rung `run` needs and how a host denies a program; (5) the content channel — the Observation media field's final shape, the placeholder grammar, the MCP adapter.

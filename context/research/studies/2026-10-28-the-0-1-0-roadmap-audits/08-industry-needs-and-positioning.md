# Audit: industry positioning for vfs 0.1.0 (late 2026)

- **Date:** 2026-10-28
- **Scope:** what the industry needs from an "agentic filesystem" now, how vfs positions against it, and which of Clay's eight themes are table stakes, differentiators, or deferrable.
- **Evidence labels:** READ (a repo document, path given), WEB (a web source, URL given), INFERRED (my synthesis).
- **Method limits:** `~/Git/Repos` does not exist in this container, so prior-art facts come from the repo's research memos (READ) and the web. `modelcontextprotocol.io`, `docs.langchain.com` and `amplifypartners.com` are not resolvable from this session; for those I cite WebSearch result summaries and the repo's own MCP/eve memos. ## 1. What the industry needs in 2026 (one page)

**1. The interface thesis is won; it no longer differentiates.** Every peer gives the model `ls`/`read`/`write`/`edit`/`glob`/`grep` over a tree (READ `context/research/2026-09-15-filesystem-over-database-landscape-and-vfs-differentiation.md` §4: deep agents, Cloudflare Computer, MongoDB VFS, Letta, Mastra, Anthropic memory). Anthropic's context-engineering essay recommends "just in time" retrieval by file path and `head`/`tail` over large data (WEB https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents); LangChain says the same (WEB https://blog.langchain.com/how-agents-can-use-filesystems-for-context-engineering/); an arXiv paper titled "From Everything-is-a-File to Files-Are-All-You-Need" reports agents interleave search with reading sections rather than relying on vector search (WEB https://arxiv.org/pdf/2601.11672). vfs's own corpus of 12,627 real agent Bash calls: nine commands are 86% of segments, pipes in 74%, `&&` in 44%, control flow under 10% (READ `context/research/2026-10-15-the-agent-shell-prior-art-and-experiments.md` §2). **Need:** the Unix surface plus pipes; the pitch starts one sentence later (READ ADR 069 "Learnings").

**2. Tools are becoming files, and code execution is replacing tool-call fan-out.** Anthropic's "code execution with MCP" presents MCP servers as a filesystem of code APIs the agent explores with `ls` and calls from code, with a worked example dropping ~150,000 tokens to ~2,000, and a `./skills/` directory where working code is saved (WEB https://www.anthropic.com/engineering/code-execution-with-mcp, Nov 2025; Cloudflare's "Code Mode" is the same finding). Agent Skills are folders loaded on demand (WEB https://www.deeplearning.ai/courses/agent-skills-with-anthropic). eve (Vercel) makes the agent itself a directory: `tools/`, `skills/`, `connections/` are files the framework compiles (READ `context/research/2026-09-15-eve-vercel-agent-framework.md` §1). **Need:** tools and skills discoverable as paths, with a verb door for parameterised actions (mcpfs showed write-shaped tools cannot be files; READ `context/research/2026-09-04-mcpfs-projecting-mcp-servers-into-a-namespace.md` §1).

**3. Governance, not capability, is the blocker, and every peer deferred it.** Vendor surveys cited in ADR 058: 86.9% of organisations delayed an AI deployment because they could not govern it; 88% report an agent-related security incident (READ `context/decisions/058-*.md`, directional). Three of four category peers wrote the deferral down: MongoDB "access control, tenant isolation ... should be enforced through the application"; LangChain "Direct backend usage does not currently incorporate permissions"; Cloudflare "agent-local scratch, not shared mutable state" (READ landscape memo §1). Tenancy everywhere is "one store per principal", which cannot express one document shared by two callers with different rights (READ ADR 069 Learnings). **Need:** a principal on every call, rights judged in the data path, one tree with per-path and per-principal rights. This is the slot nobody fills (READ ADR 069 pin 5: "peers use the database as a disk; vfs uses it as a gate").

**4. What enterprises ask of an agent data layer** (all vendor writing; consistent across sources): no token passthrough from client to upstream, exchange it under RFC 8693 for a short-lived scoped token; on-behalf-of execution so every action is attributable; row-level security enforced by the query layer, not the MCP endpoint, "because the endpoint authorizes the connection but does not see the final SQL"; per-tenant audience validation; a per-request audit record of identity, endpoint and data returned (WEB https://www.dreamfactory.com/hub/mcp-security-enterprise-companies/, https://www.cockroachlabs.com/blog/multi-tenant-ai-agents-why-data-isolation-starts-at-the-database/, https://www.snowflake.com/en/blog/engineering/enterprise-mcp-gateway-ai-agent-governance/, https://truto.one/blog/how-to-architect-a-multi-tenant-mcp-server-for-enterprise-b2b-saas/). The MCP **Enterprise-Managed Authorization** extension went stable 2026-06-18, built on the IETF Identity Assertion JWT Authorization Grant (Okta's "Cross App Access"); Okta is the only IdP shipping it; Claude, Claude Code and VS Code are early clients (WEB https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/, https://thenewstack.io/mcp-gets-its-missing-enterprise-authorization-layer/, https://mcp.directory/blog/mcp-enterprise-managed-authorization-2026). vfs's compiled-predicate design is the library-tier form of the same instinct the industry now states as RLS-in-the-data-layer (INFERRED; READ landscape §3 names `mcp-virtual-fs` as the one peer using Postgres RLS).

**5. Human-in-the-loop has a settled wire shape and a settled host shape.**
- *MCP 2026-07-28 is the current revision* (no newer one found). Multi Round-Trip Requests (MRTR) replace server-initiated `elicitation/create`, `sampling/createMessage` and `roots/list`: every result carries `resultType: "complete" | "input_required"`; a server needing input returns `input_required` with `inputRequests`, and the client **retries the original request** with `inputResponses`. Tasks moved to the `io.modelcontextprotocol/tasks` extension with poll-based `tasks/get` and `tasks/update`; `tasks/list` and blocking `tasks/result` are gone; notifications move to one `subscriptions/listen` stream; Dynamic Client Registration is deprecated for CIMD; credentials are issuer-bound (WEB https://blog.modelcontextprotocol.io/posts/2026-07-28/, https://modelcontextprotocol.io/specification/2026-07-28/changelog via search summary). Consequence: a server never holds a request open for a human; the retry is the resume, so the server must make the retried call idempotent (READ `context/open-questions.md` "MCP 2026-07-28: long-batch execution model": the revision ships no idempotency mechanism).
- *LangGraph*: `interrupt(value)` pauses a node and surfaces under `__interrupt__`; `Command(resume=...)` re-enters and its value becomes `interrupt()`'s return; a checkpointer and thread id are required; **the node re-runs from the top on resume**, so code before `interrupt()` must be idempotent (WEB https://docs.langchain.com/oss/python/langgraph/interrupts, https://reference.langchain.com/python/langgraph/types/interrupt). deepagents' `FilesystemPermission(operations, paths, mode="allow"|"deny"|"interrupt")` turns a matching call into an interrupt a reviewer can approve, edit or reject; `interrupt_on={"execute": True}` gates the shell separately; permissions are refused alongside execute-capable backends, and issue #6513 (closed, not planned) shows a `/secrets` deny rule not covering `secretsary/` under `execute` (WEB https://docs.langchain.com/oss/python/deepagents/permissions, https://github.com/langchain-ai/deepagents/issues/6513).
- *OpenAI Agents SDK*: `needs_approval=True | async fn` on `function_tool`; the run pauses with `ToolApprovalItem` interruptions; `RunState.approve()/reject()`, `RunState.to_json()/from_json()`, then `Runner.run(agent, state)` (WEB https://openai.github.io/openai-agents-python/human_in_the_loop, https://openai.github.io/openai-agents-js/guides/human-in-the-loop). *Claude Agent SDK*: `canUseTool(tool_name, input)` fires for anything rules do not auto-approve; `ask` rules route there even in `bypassPermissions` (WEB https://platform.claude.com/docs/en/agent-sdk/permissions).
- *The warning every practitioner repeats*: an approval prompt is not authorization; resume is another request boundary and rights must be re-evaluated then (WEB https://arcjet.com/learn/openai-agents-sdk-security, https://blakecrosley.com/fr/blog/ai-agent-approval-prompts-not-authorization, https://www.zenml.io/blog/openai-agents-sdk-durable-runtime).

**How a library like vfs should expose an interruptible operation (INFERRED from the above):** the decision point must be a *value*, not a blocking callback. The call returns a classified `pending` record carrying a digest of exactly what was refused and a request key; the host does the pausing with its own engine (LangGraph checkpoint, OpenAI `RunState`, MCP MRTR retry); the resumed call is the *same call again* with an allowance attached, re-enters the gate, and is idempotent under the request key. An optional in-process `ask=` coroutine on the kernel is a convenience for hosts with no durable runtime (Jupyter, scripts); the value form is the contract. This is exactly spec 148's `pending` kind mapped to MRTR `input_required` and spec 177's request key (READ `context/specs/active/148-*/spec.md` status line; `context/decisions/087-*.md` context). Nothing needs inventing; it needs landing.

**6. Peers' current state (for the "closest competitor" column).** Mirage (Strukto): 0.0.7 on PyPI 2026-10-20, 0.0.8a1 2026-10-21, ~3.7k stars, Apache-2.0, ~56 mounts, a rewritten bash, FUSE/FSKit/NFS/SFTP/HTTP/RPC/CLI fronts, adapters for OpenAI/Vercel/LangChain, `hide/show` and `allow/ask/deny` profiles, no versioning, no data-path principal (WEB https://pypi.org/project/mirage-ai/0.0.8a1/, https://www.strukto.ai/; READ `context/research/2026-09-04-mirage-design-patterns.md` §1–2, kernel memo §3). Cloudflare Computer: `@cloudflare/dofs` (SQLite-in-Durable-Object inode tree), `computerd` FUSE + RPC daemon, push/pull sync around each command, monotonic `rev`, "preview", three execution backends (container, just-bash worker, isolate) (WEB https://flaviocopes.com/cloudflare-computer/, https://www.everydev.ai/tools/cloudflare-computer; READ landscape §2). Agent shells: just-bash ~90 commands, 1.5M weekly downloads; bashkit 167 commands, 97.3% of the Oils suite that real bash passes (READ shell memo §11). Arize's counter-argument: a SQL skill scored 99 vs 93 for a Postgres-backed VFS; "every time you fake a filesystem, you sign up to maintain one" (WEB https://arize.com/blog/postgresfs-vs-sql-skills-ai-agent-filesystem/; READ landscape §7).

**7. Write safety and envelope conventions that converged** (READ landscape §4): whole-file writes with a content-hash or version precondition (Anthropic `content_sha256`, memgres `base_hash`, MongoDB `IfMatch`, eve read stamp); truncation with a reason; errors as stable codes. Hosted peers mint a version per write; open-source database peers do not.

## 4. Three sentences a 0.1.0 announcement should be able to say truthfully

Each sentence names what must be true for it to be said (INFERRED from the honesty lines in ADRs 058 pin 7, 069, 075).

1. **"vfs 0.1.0 is a governed file system for AI agents over the SQL database you already run — SQLite, Postgres, SQL Server and Oracle — where every read, search, write and tool call passes one gate that judges the caller's rights on every row."** True today for files on the four engines (gate, ladder and grants are built); true for tools only once `/.vfs/bin` and the program table land (specs 167/169).
2. **"Agents reach it as the interface they already know — `ls`, `cat`, `grep`, pipes — from Python, sync or async, from an agent shell, or over MCP, with `glob`, `grep`, ranked `glean` and `graph` built in and scoped to what the caller may see."** Needs theme 5 (sync facade), theme 6 (`serve()`), and spec 167's shell; the search half is built.
3. **"Every change is versioned and reversible, a refused action can become a question a human answers and then resumes safely, and one permission structure governs a file and a tool alike."** Needs spec 161 (version rows), spec 148 (`pending`) with spec 177 (request key), and theme 7's views. Until 161 lands, public copy may say "delete is reversible", not "every change is versioned" (READ ADR 069 Consequences).

## 5. Risks in positioning

1. **"True file system" without FUSE/NFS.** The two most visible peers mount into a kernel (mirage: FUSE/FSKit/NFS/SFTP; Cloudflare: `computerd` FUSE). vfs's own kernel memo rules POSIX out of the public API and makes handles a facet (READ ADR 087 options; kernel memo §0). Say "a filesystem-shaped kernel: path-keyed, cursors, ranges, preconditions, with search inside the gate" and "mount fronts are facets we add later"; never "POSIX" or "mount it on your laptop" at 0.1.0. Arize's line ("the closer you push it to behave like the real thing, the more you've just rebuilt the real thing, slower") lands squarely on an over-claimed "true filesystem"; the answer is ADR 069 pin 6 and a published "when not to use vfs".
2. **"Bash-like" without bash.** bashkit publishes 97.3% of the Oils suite; just-bash has 1.5M weekly downloads; vfs v1 refuses `for`, `if`, functions and arithmetic by design (READ shell memo §1). Say "a pipeline shell for agents that runs 87% of what agents actually type and refuses the rest with a named reason", publish the number, and never say "bash" without the qualifier. Also "full unix-like CLI" invites `git`, `docker`, `uv run` — the 9% of segments that will never run inside vfs (READ shell memo §2).
3. **"Governed" ahead of the tree.** Immuta, hoop.dev and Kiteworks ship enforcement today (READ ADR 075 Consequences); the alpha banner is load-bearing until version rows, `pending` and the history read exist. A 0.1.0 *final* that carries the governance headline without spec 161 over-claims against companies that can show the feature.
4. **"MCP servers authenticating as the user."** The MCP spec forbids forwarding the client's token upstream; the standards answer (EMA/XAA, RFC 8693 exchange) has one shipping IdP (WEB). Promising user-identity pass-through at 0.1.0 risks a security design done under release pressure. Scope the promise to "credentials per principal, supplied by the host, never a forwarded token"; defer exchange.
5. **"Interruptible" sold as security.** Practitioners across SDKs say an approval prompt is not authorization and resume is a fresh request boundary (WEB Arcjet, Crosley, ZenML). vfs's own position is stronger — the gate re-judges on resume — so market interrupts as *workflow* (a refusal becomes a question) and keep "the gate enforces" as the security claim.
6. **"Everything is a file, including tools."** mcpfs proved a write-shaped tool cannot be a file you `cat`, and `stat` must never execute (READ mcpfs memo §1). Say "every tool is a *path* you can see, grant and call", keep the verb door (`cli`/program invocation), and never imply `cat /.vfs/bin/deploy` runs anything.
7. **Scope versus capacity.** Eight themes plus WASI Python plus the history read is more than one solo 0.1.0; the product plan's sharpest finding is that every plan exceeded solo capacity 3–4× (READ product plan §6). The alpha lane absorbs this if beta entry is defined narrowly: gate + `pending` + replay (1), sync (5), `serve` (6), views and the rung rule (7), thin tools (4), shell core (8); the rest ships as 0.2 minors, which is what the `0.x` lane is for (READ open-questions "What makes 0.1.0 final", leaning (a); this audit recommends (b): the held beta **plus the MCP surface**, since every consumer and the README's headline depend on it).
8. **Four headlines in one repo.** README ("Governed data access"), `docs/index.md` ("Agentic Search on your Database"), `mission.md` ("the agentic filesystem"), and Clay's "true file system". Immuta's shelf and mirage's shelf are different aisles; a buyer who reads two pages sees two products. Pick before beta.
9. **The engine list.** Clay names four engines; the tree is green on five (MariaDB included) and refuses MySQL community by design (CLAUDE.md). Say "SQLite, Postgres, SQL Server, Oracle, MariaDB" or explicitly drop MariaDB; silence reads as an omission.
10. **The verb set is not a pitch.** Every peer has `read/write/edit/ls/glob/grep`; leading with the verbs puts vfs beside deep agents, where it loses on adoption (29k stars). Lead with the gate, the one shared tree, and versions (ADR 069 pins 1–3), and let the verbs be the on-ramp.

## 1. The kernel API of each repo

**computer / dofs.** The kernel is a bag of free functions over one `Database` wrapper: `mkdir`, `writeFile`, `readFile`, `rm`, `rename`, `readdir`, `stat`, `lstat`, `chmod`, `find`, `ls`, `grep`, `symlink`, `readlink`, `gc`, `watch` (READ `packages/dofs/README.md`, "Filesystem primitives under `src/fs/*`"; one file per verb under `packages/dofs/src/fs/`). Every function takes `(db, path, ...)` — **path-keyed at the API, inode-keyed in the rows**: `vfs_nodes.inode` is the primary key and `vfs_dirents(parent_inode, name) -> child_inode` is the namespace (READ `src/schema/core.ts:31-55`). The lower surface is whole-value (`writeFile(db, path, bytes)`), but it also carries explicit **ranged** entry points `readRangeSync(db, path, offset, length)` and `writeRangeSync(db, path, bytes, offset, ...)` (READ `src/fs/readFile.ts:199-245`, `src/fs/writeFile.ts:1010-1096`). Handles exist one layer up: `SQLiteWorkspaceProvider` keeps an fd table (`#fds: Map<number, FdState>`, `#nextFd = 3`) and turns `readSync(fd, ...)`/`writeSync(fd, ...)` into the path+offset kernel calls (READ `src/provider.ts:110-170, 575-637`).

**agentfs.** The kernel is a Rust trait, explicitly **inode-keyed and handle-based**: `FileSystem { lookup(parent_ino, name), getattr(ino), readlink(ino), readdir(ino), readdir_plus(ino), chmod, chown, utimens, open(ino, flags) -> BoxedFile, mkdir, create_file, mknod, symlink, unlink(parent_ino, name), rmdir, link, rename, statfs, forget }` and `File { pread(offset, size), pwrite(offset, data), truncate, fsync, fstat }` (READ `sdk/rust/src/filesystem/mod.rs:161-318`; the doc comment says "inode-based operations rather than path-based operations, matching POSIX and FUSE semantics", `:181-185`). The open handle stores the resolved `ino` plus the pool and chunk size (READ `sdk/rust/src/filesystem/agentfs.rs:79-83`). A path-keyed convenience layer (`stat`, `read_file`, `pread(path, ...)`, `pwrite(path, ...)`, `rename(from, to)`) sits on the same struct (READ `agentfs.rs:895-2243`), and the TypeScript SDK mirrors node:fs by path (READ `sdk/typescript/src/filesystem/agentfs.ts:465-1198`).

**libsqlfs.** The kernel is the `sqlfs_proc_*` family mirroring FUSE's high-level ops one-for-one: getattr, access, create, readlink, readdir, mknod, mkdir, unlink, rmdir, symlink, rename, link, chmod, chown, truncate, utime, open, read, write, statfs, release, fsync, xattrs (READ `sqlfs_internal.h:105-135`). **Path-keyed all the way down**: the primary key of `meta_data` is the full path string (`key text ... primary key (key)`) and `value_data(key, block_no, data_block)` is keyed by the same string (READ `sqlfs.c:3236-3241`). `read`/`write` take `(path, buf, size, offset)` — ranged, but no handle state beyond FUSE's `fuse_file_info`.

**jackrabbit-oak.** Two kernels, layered. The store kernel is `NodeStore`: `getRoot()`, `merge(builder, commitHook, info)`, `rebase`, `reset`, `createBlob`, `getBlob`, `checkpoint(lifetime, props)`, `checkpoints()`, `retrieve(checkpoint)`, `release` (READ `oak-store-spi/.../spi/state/NodeStore.java:46-189`). Its values are immutable `NodeState` (`exists`, `getProperty`, `getChildNode(name)`, `getChildNodeEntries`, `getChildNodeCount(max)`, `builder()`, `compareAgainstBaseState(base, diff)`, READ `NodeState.java:134-381`) and mutable `NodeBuilder` (`child/getChildNode/setChildNode`, `moveTo(newParent, newName)`, `setProperty`, `remove`, `createBlob`, READ `NodeBuilder.java:196-429`). A node state is **unnamed and location-free** ("does not contain information about its location within a larger content tree", READ `oak-doc/.../architecture/nodestate.md`). The API kernel above it is **path-keyed**: `Root { getTree(path), move(src, dst), commit(), rebase(), refresh(), getQueryEngine(), getBlob }` and `Tree { getPath(), getChild(name), addChild(name), getChildren(), setProperty, remove, orderBefore }` (READ `oak-api/.../Root.java:69-177`, `Tree.java:112-342`). There are no handles; a `Root` *is* the session's snapshot plus its pending changes.

**Lesson for vfs:** every project that had to serve FUSE ended up with an id-keyed row model under a path-keyed API, and the one that chose inode-keyed *as the kernel* (agentfs) did so explicitly to match FUSE/POSIX and then re-grew a path-keyed convenience layer on top — the kernel key and the public key are separate decisions.

## 2. Bodies: storage, ranged reads, appends, and the 1-byte-into-100-MB write

**dofs.** Fixed 512 KiB chunks (`CHUNK_SIZE = 512 * 1024`, READ `src/fs/writeFile.ts:29`), **content-addressed**: `vfs_chunks(inode, idx, hash, size)` maps a file's chunk grid onto `vfs_blob_bytes(hash, bytes)` keyed by sha256 (READ `src/schema/core.ts:65-87`). A ranged read computes `firstIdx = floor(start / CHUNK_SIZE)`, `lastIdx = floor((end-1) / CHUNK_SIZE)`, selects just those chunk rows `ORDER BY idx`, and slices the first and last (READ `src/fs/readFile.ts:78-101`); a per-`Database` LRU keyed by blob hash skips SQLite for repeated chunks (READ `README.md`, "Content-addressed blob cache"). Append = `writeRangeSync` at `offset = size` (the provider stats for EOF when the fd was opened `append`, READ `src/provider.ts:616-623`). **1-byte write into 100 MB (direct path):** `applyChunkedInodeUpdate` walks the chunk grid but issues SQL only for chunks the write touched (`if (old?.size === intendedSize && !touched) continue`), re-hashes that one chunk, upserts one blob row, `INSERT OR REPLACE` one chunk row, and stamps the node row with `manifest_hash = NULL` (READ `src/fs/writeFile.ts:643-696`). So: one 512 KiB read-modify-write plus two small rows. Under FUSE a write buffer is opened per file at `open`/`create` and committed once at `release`, with the driver tracking dirty byte ranges so release reuses unchanged chunks (READ `src/fs/writeFile.ts:733-807`; commit `a48e55a` body reports "provider-only one-byte edit in a 64 MiB file: ~63.8ms -> ~6.3ms"). The cost they could not remove: every chunk hashed on release (READ `docs/19_performance.md:167-173`).

**agentfs.** Fixed chunks, default 4096 bytes, set once in `fs_config` and immutable afterwards; `fs_data(ino, chunk_index, data)` with `PRIMARY KEY (ino, chunk_index)`; not content-addressed (READ `SPEC.md`, tables `fs_config` and `fs_data`). Ranged read selects `chunk_index BETWEEN start_chunk AND end_chunk ORDER BY chunk_index` and skips `offset % chunk_size` in the first chunk (READ `agentfs.rs:113-125`). **1-byte write:** `pwrite` iterates only the overlapping chunks, does a read-modify-write when the chunk is partially covered (`needs_read = data_start > 0 || data_end < chunk_size`), `DELETE` + `INSERT` that chunk, then `UPDATE fs_inode SET size, mtime` (READ `agentfs.rs:1478-1565`). Cost: one 4 KiB chunk and one inode row.

**libsqlfs.** Fixed 8 KiB blocks (`BLOCK_SIZE = 8192`, READ `sqlfs.c:96`), one row per `(key, block_no)` (READ `sqlfs.c:3240`). Read: `select data_block from value_data where key=:key and block_no=:block_no` per block (READ `sqlfs.c:1207-1212`); write loops from `begin / BLOCK_SIZE` and does `update ... set data_block` with an `insert or ignore` to create the row (READ `sqlfs.c:1248-1255, 1434-1500`). **1-byte write:** one 8 KiB block row plus the `meta_data` row. Cheapest design here, and also the one with no dedup and no sync story.

**Oak.** Binaries are `Blob`s: `getNewStream()`, `length()`, `getReference()`, `getContentIdentity()` — **immutable, no write-at-offset** (READ `oak-api/.../Blob.java:51-89`). The store splits a binary into blocks "so that each block fits in memory" with a hash-tree indirection ("each data store id is a list of entries: data, hash of content, or hash of a data store id"), default `blockSize = 2 MiB`, `blockSizeMin = 4096` (READ `oak-blob/.../AbstractBlobStore.java:40-60, 115-121`; Mongo sets 2 MiB − 1 KiB, READ `MongoBlobStore.java:111`). Ranged reads are first-class at the store: `BlobStore.readBlob(blobId, pos, buff, off, length)` (READ `oak-blob/.../BlobStore.java:60`). **1-byte write:** INFERRED from the API — the caller must stream a new 100 MB binary through `createBlob`; every 2 MiB block is re-read and re-hashed, unchanged blocks dedup by content hash so storage grows by about one block plus a new id list, but CPU and I/O are the full file.

**Lesson for vfs:** every design that serves a FUSE or POSIX front end stores bodies as fixed-size chunk rows and makes the ranged read a chunk-range query, and the two that also sync or dedup (dofs, Oak) pay for it by hashing every chunk on commit.

## 3. Directories: children, listing at scale, and the cost of renaming a directory

**dofs.** Children are rows `vfs_dirents(parent_inode, name, child_inode)`, `WITHOUT ROWID` so the `(parent, name)` lookup is a covering PK-leaf read (READ `src/schema/core.ts:43-56`). `readdir` takes `limit`/`offset` and runs `ORDER BY d.name LIMIT ? OFFSET ?` (READ `src/fs/readdir.ts:46-50, 137-158`); `find` walks with a keyset cursor instead — `WHERE d.parent_inode = ? AND d.name > ? ORDER BY d.name LIMIT CHILD_PAGE_SIZE` (READ `src/fs/find.ts:162-173`). A later changeset added `readdirEntriesSync(path)` returning type, mode and inode "from one query" because FUSE readdir wanted them (READ `.changeset/dofs-readdir-entries.md`). **Rename of a directory:** the namespace change is one `DELETE` + one `INSERT` on `vfs_dirents` (READ `src/fs/rename.ts:131-137`) — but because sync is path-based, a directory move then runs a recursive CTE to stamp every descendant's `rev` and insert an old-path tombstone per descendant in two set statements (READ `src/fs/rename.ts:147-154, 217-227`). So O(1) for the tree, O(descendants) for the sync log.

**agentfs.** `fs_dentry(id, name, parent_ino, ino)` with `UNIQUE(parent_ino, name)` and an index on `(parent_ino, name)` (READ `SPEC.md`, table `fs_dentry`). Listing is `SELECT name FROM fs_dentry WHERE parent_ino = ? ORDER BY name ASC` into a `Vec` — **no limit, no cursor** (READ `SPEC.md` "Listing a Directory"; `agentfs.rs:1741-1774`). **Rename of a directory:** one `UPDATE fs_dentry SET parent_ino = ?, name = ? WHERE parent_ino = ? AND name = ?` plus nlink/ctime bookkeeping (READ inside `rename`, `agentfs.rs:2243ff`). O(1).

**libsqlfs.** No children table: a listing is `select key, mode from meta_data where key glob :pattern` with the parent path turned into a glob (READ `sqlfs.c:1989-1995`), fed straight to the FUSE filler; no pagination. **Rename of a directory:** `rename_key` is `update meta_data set key = :new where key = :old` (READ `sqlfs.c:788-794`), and `rename_dir_children` globs every descendant key and renames each (READ `sqlfs.c:2251-2303`). O(descendants) rows rewritten in both tables.

**Oak.** In the document store each node is one document whose `_id` is `depth:path` "to align sibling keys in the index" (READ `oak-doc/.../documentmk.md:140-142`); children of a path are a **sorted key range** `[getKeyLowerLimit(path), getKeyUpperLimit(path))`, continued from the last returned name, through `DocumentStore.query(NODES, from, to, limit)` (READ `DocumentNodeStore.java:1534-1560`; `DocumentStore.java:108`). `readChildren` asks for `limit + 1`, drops children deleted at the read revision, and sets `hasMore` (READ `DocumentNodeStore.java:1476-1500`); `DocumentNodeState` pages with a fetch size starting at 100 and doubling to 1600 (READ `DocumentNodeState.java:72-77, 317-328`). The API exposes only `getChildren()` iterables and `getChildrenCount(max)` — pagination is internal. **Rename (move) of a directory:** `Root.move` resolves source and destination trees and calls `source.moveTo(newParent, newName)` (READ `MutableRoot.java:195-221`); `MemoryNodeBuilder.moveTo` annotates the source path, `setChildNode(newName, getNodeState())` and `remove()`s the old (READ `MemoryNodeBuilder.java:385-388`). In memory and segment stores that is a pointer re-parent (INFERRED from immutable shared subtrees, `nodestate.md`); in the document store every descendant must get a new path-keyed document and the old ones a `_deleted` entry (INFERRED from the path-keyed `_id`).

**Lesson for vfs:** `(parent_id, name) -> child_id` makes directory rename one row and listing a bounded key range, and the only O(descendants) cost that survives in dofs is the path-based sync log — a cost vfs would inherit wherever it keys anything but the tree by path.

## 4. Versioning and deletion

**dofs.** **No content history**: "the store keeps no content history" (READ `docs/02_sync_protocol.md:171`). What exists is a monotone `rev` stamped on `vfs_nodes` by every write (`incrementRev`, READ `src/fs/writeFile.ts:688-696`) and a `vfs_changes(id, rev, path, op CHECK(op IN ('delete')), prior)` tombstone log written on `rm` and on rename (READ `src/schema/sync.ts:16-22`); `prior` is a fingerprint of the version the delete removed so a replayed tombstone cannot destroy a recreated path (READ `docs/02_sync_protocol.md:375-379`). Delete itself is hard: `unlinkDirent` removes the dirent, and when the last link goes, the chunk rows and the node row (READ `src/fs/unlink.ts:15-32`); orphan blobs are swept by `gc` only after a one-hour safety window (READ `src/fs/gc.ts:17-35`). The FUSE adapter sees none of this; the sync protocol sees rev + tombstones as "live entries plus tombstones" (READ `02_sync_protocol.md:96`).

**agentfs.** No versions in the schema; the README's answer is "Snapshot an agent's state ... with `cp agent.db snapshot.db`" (READ `README.md`). Delete decrements `nlink` and hard-deletes inode and chunks at zero (READ `SPEC.md` "Deleting a File"). The `tool_calls` table is an insert-only audit log of tool invocations, not of file content (READ `SPEC.md` "Tool Calls").

**libsqlfs.** No versions; `remove_key` / `remove_key_subtree` delete rows (READ `sqlfs.c:544, 607`).

**Oak.** Versions at two levels. (a) The **store** keeps every revision: the document store "does not overwrite existing data but adds it to an existing document when a property is updated" (READ `documentmk.md:992-996`); `_deleted` is a map `revision -> true/false` so a delete is a new entry, and resurrection is a later `false` (READ `NodeDocument.java:166-177`, `documentmk.md:143-146`); old data is split into "previous documents" at 100 commits or 1 MB (READ `documentmk.md:468-473`); **Revision Garbage Collection** is periodic and app-triggered (READ `documentmk.md:997-1003`). Named snapshots are `NodeStore.checkpoint(lifetime)` / `retrieve(checkpoint)` — "like a tag in a git repository" (READ `NodeStore.java:130-189`, `indexing.md:184-188`). (b) **JCR versioning** is content: `checkin` copies a frozen node under `/jcr:system/jcr:versionStorage` (READ `oak-core-spi/.../VersionConstants.java:95`; `ReadWriteVersionManager.java:271-317`). Adapters: the JCR adapter sees (b) through `VersionManagerDelegate` and never sees (a); the HTTP servlet sees only the session's current `Root` (READ `OakServlet.java:75-96`); only `AsyncIndexUpdate` consumes (a), via checkpoints (READ `AsyncIndexUpdate.java:576`).

**Lesson for vfs:** the stores that keep history keep it in the kernel's row model and expose it only as snapshots/checkpoints, never as POSIX-visible state — every POSIX-shaped adapter sees exactly one version.

## 5. Search beside the tree

**Oak (the main case).** The query engine hangs off the path-keyed API, not the store: `Root.getQueryEngine()` (READ `Root.java:140`) → `QueryEngine.executeQuery(statement, language, limit, offset, bindings, mappings)` → `Result { getColumnNames, getSelectorNames, getRows(), getSize(precision, max) }` whose rows are `ResultRow { getPath(), getPath(selector), getTree(selector), getValue(column), getValues() }` (READ `QueryEngine.java:63-126`, `Result.java:29-76`, `ResultRow.java:31-67`). So a result is **a separate shape (rows with columns) whose each row resolves back to a `Tree` of the same tree API** — `ResultRowImpl.getTree` returns the session's `Tree` (READ `ResultRowImpl.java:84`). Indexes implement `QueryIndex { getMinimumCost, getCost(filter, rootState), query(filter, rootState) -> Cursor, getPlan, getIndexName }` with `FulltextQueryIndex` and `AdvancedQueryIndex`/`IndexPlan` extensions (READ `oak-query-spi/.../QueryIndex.java:58-222`); the cursor yields paths that the selector then re-reads through the tree (READ `SelectorImpl.java:614-621`). Index **maintenance** is an `IndexEditor` ("listens for changes to the content and updates the index data", READ `IndexEditor.java:18-27`) invoked either in the commit hook — "the index content gets updated as part of the commit itself ... atomically in a single commit. This mode is currently supported by `property` and `reference` indexes" — or by `AsyncIndexUpdate`, a scheduled `Runnable` that diffs the last checkpoint against a new one and is "eventually consistent ... and lag[s] behind" (READ `indexing.md:139-151`, `AsyncIndexUpdate.java:103, 576`; the switch is the index definition's `async` property, `IndexConstants.java:52`). Lucene/fulltext is async only; the **hybrid index** answers the lag by storing recent entries as a synchronous property index, moving them to Lucene asynchronously, and making "any query ... a union of query results from both" (READ `hybrid-index.md:60-69`). Adapters exposing a query: the JCR adapter does (JCR `QueryManager`), the HTTP servlet does not — it resolves only the longest existing tree prefix and renders it (READ `OakServlet.java:75-125`); there is no virtual-directory-of-results anywhere I read. The JCR adapter's own **id→path translation rides on the query engine**: `IdentifierManager.getTree(uuid)` runs `SELECT * FROM [nt:base] WHERE [jcr:uuid] = $id` (READ `IdentifierManager.java:121-147, 339-343`).

**dofs.** `find` compiles a glob to a regex and walks the dirent tree with keyset pages (READ `src/fs/find.ts:46-185`); `grep` imports `iterateFoundEntries` and `readFile`, streams every candidate file through a JS `RegExp` with bounded `limit`/`offset` and context lines (READ `src/fs/grep.ts:1-6, 142-145, 210-231`). **No index**; search is a scan expressed through the same two primitives (walk, read) that FUSE uses. Results are their own shapes (`WorkspaceGrepMatch { path, line, text, context }`, READ `grep.ts:14-19`).

**agentfs.** No search of any kind in the SDK, CLI or MCP server (READ: a grep for `search|glob|grep|fts` over `sdk/rust/src` and `cli/src/cmd` returned nothing; the MCP tool list is read_file, write_file, readdir, mkdir, rmdir, rm, unlink, copy_file, rename, stat, access and kv_*, READ `cli/src/opts.rs:397-399`).

**libsqlfs.** None.

**Lesson for vfs:** the one store with real indexes keeps them *beside* the tree, maintained by commit hooks (sync, cheap kinds) or a checkpoint-driven background diff (async, expensive kinds), and returns results as rows that point back into the same tree API — never as a second tree.

**Which adapter forced kernel changes.** dofs's history is explicit: FUSE drove `writeRangeSync`/`truncateFileSync`/`createFileSync` ("so local callers can use the direct incremental write path without going through file descriptors", READ commit `d71ec4b`), then the per-open **write buffer** inside the kernel ("buffer writes per open file and drop inline storage ... Bytes have one owner (DOFS), the commit boundary is per file", READ `541c142`), then dirty-range flushes (`a48e55a`), the cached `size` column and `WITHOUT ROWID` dirents (READ `src/schema/core.ts:4-22`), and `readdirEntriesSync` (READ `.changeset/dofs-readdir-entries.md`). agentfs: no history in the clone; INFERRED from the trait doc that FUSE/NFS set the inode-keyed shape from the start. Oak: history too shallow; INFERRED from `differences.md` and `RefreshStrategy` that JCR's session model pushed complexity into the adapter rather than the kernel.

**Lesson for vfs:** the adapter that needs offsets and handles (FUSE) is the one that reaches into the kernel — dofs had to grow ranged writes, a per-open write buffer and a one-query readdir inside the store, while path-only adapters (HTTP, MCP, CLI) added nothing below the API.

## 7. Permissions: where rights are checked

**dofs.** The kernel enforces one thing: read-only mount roots, checked "at the data layer so container-side writes that arrive via pullOnce -> applyChanges are caught too" (READ `src/fs/mount-guard.ts:1-16`). Mode bits are stored and returned (`chmod`), but `EACCES` is never raised in `src/fs` (READ: `errors.ts:8-9` declares it; the only `EPERM` sites are root removal and link, `rm.ts:105`, `link.ts:55`). INFERRED: POSIX permission enforcement is left to the FUSE kernel side or absent.

**agentfs.** `fs_inode` carries `uid`, `gid`, `mode` (READ `SPEC.md`), but the SDK never checks them (READ: no `EACCES`/`PermissionDenied` sites in `sdk/rust/src`). The NFS adapter checks RFC 1813 access against AUTH_UNIX credentials on its own (READ `cli/src/nfsserve/permissions.rs:1-4`). Rights live in the adapter.

**libsqlfs.** Checked in the kernel: `sqlfs_proc_access` compares the caller's uid/gid (from `geteuid` or the stored sqlfs uid) with the row's mode bits, root bypasses, and `check_parent_access` walks parents for `X_OK` (READ `sqlfs.c:1683-1703, 1863-1901`).

**Oak.** Checked in the **tree view**, once, for every reader. `MutableRoot` wraps the store's builder in `SecureNodeBuilder(builder, permissionProvider)` and builds the root `Tree` over that (READ `MutableRoot.java:172-173`). `SecureNodeState` wraps a `NodeState` with a `TreePermission`: `exists()` is `treePermission.canRead()`; `getProperty` returns null unless `canRead(property)`; `getChildNode(name)` wraps the child with its own permission; `getChildNodeEntries()` is passed through when `canReadAll()` and otherwise filtered entry by entry; counts follow the same rule (READ `SecureNodeState.java:60-61, 67, 113-117, 124-130, 141-147`); `SecureNodeBuilder.remove()` requires `exists()` (READ `SecureNodeBuilder.java:167`). Because `Tree.exists()` is the same test, **listing hides unreadable children and path lookup of an unreadable node returns a non-existent tree** — which is why `OakServlet` walks up to the longest *readable* prefix (READ `OakServlet.java:78-85`). **Query results pass through the same gate**: `QueryImpl.getTree(path)` is `context.getRoot().getTree(path)` on the session's secure root (READ `QueryImpl.java:1404-1412`), `SelectorImpl` caches that tree per row and drops the row when `!ct.exists()` (READ `SelectorImpl.java:614-618, 940-962`); the `PermissionProvider` is carried in the `ExecutionContext` (READ `ExecutionContext.java:49-116`). The index may return a path the caller cannot read; the row never reaches the caller.

**Lesson for vfs:** Oak puts the permission check in one wrapper around the node view and gets listing, lookup, mutation *and* query filtering from that single seam — the index is allowed to be permission-blind because every result is re-read through the secure tree.

## Design facts for the synthesis

1. READ — All four stores key rows by id (inode or `depth:path` document id) and keep the namespace as `(parent, name) -> child`; libsqlfs, which keys by path string, pays O(descendants) row rewrites on directory rename (`sqlfs.c:2251-2303`).
2. READ — The only kernel that is inode-keyed *at the API* (agentfs `FileSystem`/`File`, `mod.rs:161-318`) says it did so to match FUSE/POSIX, and still ships a path-keyed layer on the same struct for SDK, CLI and MCP callers.
3. READ — Bodies are fixed-size chunk rows everywhere: 512 KiB content-addressed (dofs), 4 KiB (agentfs), 8 KiB (libsqlfs), 2 MiB hash-tree blocks (Oak); a ranged read is a chunk-range query, and a 1-byte write touches one chunk in the three POSIX stores.
4. READ — Oak's `Blob` is immutable with no write-at-offset (`Blob.java:51-89`); INFERRED — a small edit to a large binary re-streams and re-hashes the whole file, with dedup saving storage but not I/O.
5. READ — FUSE forced dofs to add ranged writes, a per-open in-kernel write buffer committed at release, dirty-range flushes, a cached `size` column and a one-query `readdir` with types (commits `d71ec4b`, `541c142`, `a48e55a`; `schema/core.ts:4-22`); path-only adapters added nothing below the API.
6. READ — Directory listing is paginated by `LIMIT/OFFSET` (dofs readdir), keyset `name > ?` (dofs find, Oak child docs with `limit + 1` and `hasMore`), or not at all (agentfs, libsqlfs); Oak hides the paging behind an iterable.
7. READ — dofs keeps no content history; it keeps a monotone `rev` per node and a tombstone log with a `prior` fingerprint, consumed only by sync (`sync.ts:16-22`, `02_sync_protocol.md:171, 375-379`); deletes are hard and orphan blobs are GC'd after a safety window.
8. READ — Oak keeps every revision in the store (`_deleted`/`_revisions` maps, previous-document splits, periodic Revision GC) and exposes history only as named checkpoints; POSIX-shaped and HTTP adapters see one version.
9. READ — Oak's indexes are maintained by `IndexEditor`s either inside the commit (property/reference) or by a checkpoint-diffing `AsyncIndexUpdate` (Lucene), with a hybrid index unioning both to cover the lag (`indexing.md:139-151`, `hybrid-index.md:60-69`).
10. READ — Oak query results are rows (`ResultRow.getPath/getTree/getValue`) that resolve back into the same `Tree` API; no adapter I read exposes a query as a virtual directory.
11. READ — Oak checks permissions in one wrapper (`SecureNodeState`/`SecureNodeBuilder`) around the node view, so listing, lookup, mutation and query rows are all filtered by the same `canRead`; agentfs and libsqlfs check (or do not) in the adapter.
12. READ — No project in this set has both an index-backed search and a POSIX front end over the same kernel: dofs's `grep`/`find` scan through walk+read, agentfs and libsqlfs have no search, and Oak has no POSIX adapter.

# A stdlib `ast` test in the shape `tests/lint` already uses holds vfs's layer map, finds today's five adapter imports and three upward edges in under a second, and matches what import-linter's `protected` and `layers` contracts find; no lint tool ships a module-size ratchet, so size is a committed one-way baseline the same test reads

On 2026-11-07 Clay asked, after a structural review of the day's eleven landings: "Please research prior art before writing these specs, ensure we are following good patterns and then write up the specs." The review had found that the router, `src/vfs/base.py`, had begun importing its thread pool, wall budget and byte chunker from inside the database backend package, that no lint refuses such an import, and that the router grew from 3,257 to 3,710 lines in a week with no check reading the trend. This memo answers one question: how do Python projects hold import direction and module size mechanically, and which shape fits a project whose lint runs as pytest tests. One researcher, a fresh agent with no knowledge of the author's reasoning, worked a 45-minute box and finished inside it; the author ran one further experiment. The study, the brief, the experiments and the clone logs are under [the studies folder](studies/2026-11-07-import-direction-and-module-size-fitness-functions/). There is no intention: the work adds a check to the gate and the review rubric.

## The answer

EXECUTED: a 206-line pytest test using only the `ast` module walks the 94 modules under `src/vfs`, builds 558 module-level internal import edges (160 of them under `TYPE_CHECKING`) in 0.38 s, and reports five imports of the database backend package by modules outside it and three imports from a lower declared layer to a higher one. EXECUTED: import-linter, run once through `uvx` with nothing added to vfs, reports exactly the same five lines under a `protected` contract and the same three direct edges under a `layers` contract, plus indirect chains that all run through the extension module's import of its parent package, a quirk grimp documents and ignores in its own configuration. READ: six public projects run one of these tools in CI, and every one declares a layer ladder first and a protected or forbidden rule second, with an ignore list that is held exact and may only shrink. READ: pylint caps a module at 1,000 physical lines as a hard limit, ruff has declined that rule as incompatible with its formatter, and the only ratchet-shaped tools are two small single-author packages. INFERRED: the stdlib test fits this project today, because the lint already runs as pytest tests over the tree, the contract is two rules, and the dependency would bring a Rust wheel and a configuration file for a check that one file holds; import-linter replaces it when the contracts outgrow a handful. Module size has no tool answer, so the fitting shape is dify's: a committed baseline of the modules over a ceiling, read by the same test, that a landing may lower and never raise.

## 1. What the tools do

1.1 READ ([study](studies/2026-11-07-import-direction-and-module-size-fitness-functions/01-import-linter-tach-and-a-stdlib-test.md), section 1). import-linter checks contracts over grimp's import graph: `layers` (a ladder, same-layer groups written with `:` when they may import each other), `forbidden`, `independence`, `protected` (nothing outside package P imports from P except the named importers, which is the rule the review wanted) and `acyclic_siblings`. `TYPE_CHECKING` imports are parsed by grimp's Rust parser and counted unless `exclude_type_checking_imports = True`. It runs as `lint-imports` in CI or pre-commit and depends on click, grimp (a maturin wheel) and rich.

1.2 READ (section 2). tach is a Rust binary driven by `tach.toml` with a per-module `depends_on` list and an optional layer ladder; it ignores `TYPE_CHECKING` imports by default and offers `exact` and closed layers. Its last commit was 2026-10-30.

1.3 READ (section 3). pytest-archon is the one tool that is a pytest test by construction, a fluent rule over modules resolved through `find_spec`, transitive by default; it is pure Python and has had no commit since 2025-09-19.

## 2. What projects declare

2.1 READ (section 4). kedro declares `layers`, `independence` and two `forbidden` contracts in `pyproject.toml` and runs `lint-imports` from a pre-commit system hook. dify declares a `forbidden` domain boundary and a four-layer ladder in `api/.importlinter`, with a large `ignore_imports` list held exact as a migration baseline that may only shrink, run by `uv run --directory api --dev lint-imports` in its style workflow. kopf declares five `layers` contracts, an `independence` contract and one custom contract type. scipy, PostHog and docling run tach with per-module `depends_on` or a layer ladder. EXECUTED: GitHub code search floors at 40 repositories with `[tool.importlinter]`, 40 with `.importlinter`, 30 in `setup.cfg` and 40 `tach.toml` files with `depends_on`.

2.2 READ (section 5). pylint's C0302 counts physical lines like `wc -l`, defaults to 1,000, is a hard cap with a per-file pragma, and projects that touch it keep 1,000 or raise it to 800 or 2,000; none ratchets. ruff ships only function-scoped size rules, and issue 25001, open since 2026-05-05, declines C0302 as formatter-incompatible. `ratchet-size` 0.2.3 and `riskratchet` are the only ratchet-shaped tools, both young and single-author. dify's exact ignore list is the mature precedent for a one-way baseline.

## 4. What this means for the spec

4.1 INFERRED. The protected-package rule is the one the review needs first and it has a two-line owner today: after the runtime concern moves to package level, the allowlist is `vfs` (the public export) and `vfs.storage.backends` (the re-export), and the test fails on anything else. The layer ladder is the second rule, and the three upward edges are its starting baseline in dify's shape: an exact list the test holds, that a landing may shorten and never lengthen. A stdlib test keeps the gate's dependencies as they are, runs in the same `tests/lint` job, and names file and line in its failure as the other shape tests do; the study's draft is the shape, not the code, and every line of the gate is written here.

4.2 INFERRED. Module size has no mechanical precedent worth copying as a hard cap: a cap of 1,000 would fail nine modules today and invite pragmas. The one-way baseline is the fitting shape: the modules over a declared ceiling are listed with their line counts, the test refuses any growth of a listed module and any new module over the ceiling, and a landing that lowers a count edits the list. The review rubric then reads the same number: a code review's ownership lens states the touched module's line count before and after, and a growth of a listed module is a finding the author answers.

## What this memo does not settle

The ceiling and the first baseline: the spec sets them from the trend table and the review's judgement, not from a measurement. The running time of the stdlib walk on a tree ten times this size, or once a transitive closure is added: an experiment when either happens. Whether the three upward edges move or stay: the spec decides, because `base` importing `session` is a cycle the public surface may want kept, and `results` importing the grep matcher is a question of where the line-splitting helper belongs. What kopf's custom contract type and PostHog's wrapper add beyond the stock contracts: unread, and not needed for a two-rule gate.

## One line

Hold the layer map with a stdlib `ast` test in `tests/lint`, two rules and a baseline that may only shrink, because that is what the five-line finding needs today and what six projects do with a tool vfs does not yet need; hold module size the same way, since no lint tool offers a ratchet and a hard cap would only breed pragmas.

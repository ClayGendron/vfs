## The question

The router, `vfs.base`, imports the session facade, `vfs.session`, at runtime, so that its `session()` method can build one. The facade names the router's class in its type annotations. The layer-map spec declares the session above the router, which makes the router's import point up the ladder. Which of the two should sit beneath the other, and what has to change in the code so that neither names the other against the ladder?

## What is known today

1. EXECUTED on 2026-11-12, vfs at `4a6d3e0`. `src/vfs/base.py` holds one import of the facade, `from vfs.session import AsyncSession`, at module level and at runtime. READ: the name is used in one method, `AsyncVirtualFileSystem.session(authority)`, as its return annotation and in its one line of body, `return AsyncSession(self, authority)`.
2. EXECUTED, the same run. `vfs.session` imports two `vfs` modules at runtime, `vfs.ops` and `vfs.results`, and seven under `if TYPE_CHECKING:`, one of which is `vfs.base`, for `AsyncVirtualFileSystem`, the type of the `fs` its constructor takes. READ: `AsyncSession` calls 25 verbs on that `fs`, each the same call with `authority=` filled in. So there is no runtime cycle between the two modules: the router imports the facade at runtime, and the facade names the router for types only.
3. EXECUTED, the same run. Three modules import `vfs.session`: the package root, which exports `AsyncSession`; `vfs.base`; and `vfs.sync`. READ: the synchronous face does not use the router's factory. Its `Session` builds `AsyncSession(fs._fs, authority)` itself (`src/vfs/sync.py`, `Session.__init__`), and `VirtualFileSystem.session` returns that `Session`.
4. EXECUTED, the same run. With the session above the router, as the spec declares it, the pair gives one upward import: the router's, at runtime. With the session placed beneath the router, on the rung of the router's own modules or on a rung of its own, the router's import points down and the facade's typing-only import of `vfs.base` points up instead. The pair gives one upward import in every placement, and the ladder's other three exceptions do not move. A redraw of the ladder alone does not remove the entry.
5. READ. [The public-surface spec](../specifications/active/181-the-public-surface-regrouped-by-kernel-group/spec.md), section 1.6, lists `session` among the eleven control-plane members of the public class and names no move of this import. EXECUTED: `.session(` is called on 18 lines of the tests and the docs, the fixture corpus aside, across both faces (`tests/test_sync.py` 6, `tests/base/test_authority.py` 4, `docs/reference/sync.md` 3, `docs/reference/session.md` 3, `docs/reference/api.md` 1, `docs/how-to/run-calls-as-a-principal.md` 1), and once in the docstring example of `session.py`.
6. INFERRED. Three shapes would each end with no import against the ladder, and this memo chooses none. First, the facade is typed against a protocol of the verbs it calls, declared beneath the router; the session then sits beneath the router and both imports point down. Second, the factory leaves the router and a caller builds `AsyncSession(fs, authority)`; that changes the public API. Third, the two modules stay as they are and the entry stays, as a declared two-way tie of the public surface.

## The experiment that answers it

The research is done when each item below has a labelled result.

1. Each of the three shapes in a scratch copy of the tree. For each: the number of faults the ladder test reports; the number of errors `uv run ty check src/ tests/` reports; whether `import vfs` succeeds; and the number of lines of `src/`, `tests/` and `docs/` that change.
2. The size of the protocol the first shape needs: the count of router verbs `AsyncSession` calls, the count of distinct parameter types they name, and whether a protocol already in the tree names any of them.
3. The prior art, each from a clone refreshed and licence-checked as [AGENTS.md](../../AGENTS.md) requires, described and never copied: where the factory for a scoped facade lives relative to the engine it wraps, and which module imports which, in `sqlalchemy` (the engine and its connection, the session and its maker), `httpx` (the client and its transports), `psycopg` (the connection and its cursor), `redis-py` (the client and its pipeline) and `mongo-python-driver` (the client and `start_session`).
4. What the following spec needs from this memo: the three shapes side by side on the counts of item 1, the protocol's size, and the prior art's choices. The choice among them is that spec's.

## One line

The router builds sessions and the session is typed against the router, so one of the two imports points up the ladder wherever the session is placed; the research is to count what each of three ways out would cost.

# A prior version of a file reads back whole and passes its recorded hash

A draft, written on 2026-11-25 against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. This is unit 180-2 of [roadmap story K8](../../context/standards/roadmap.md), criterion 2, gate f, converted from [spec 180](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/spec.md) §§7.2–7.3 and 8 and [task 8](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/tasks.md). It rests on the rewind storage reader, K3's integrity contract and K8's attributed version labels.

## The outcome wanted

After writing `"first"` at revision 1, moving the file at 2 and writing `"third"` at 3, `read(new_path, version=1)` returns `"first"` and its writer. Revision 2 has no body label and the public read reports `vfs.not_found`. Revision 3 returns `"third"`. A read of stored binary content returns its original bytes. Once packing starts, the same requests return the same observations. A confirmed damaged body yields one nonretryable `vfs.unavailable.integrity` error and zero observations.

## What the code does today

The four read faces and the storage signature have no `version` keyword (`src/vfs/base.py:802`, `src/vfs/session.py:97`, `src/vfs/sync.py:267`, `src/vfs/sync_session.py:80`, `src/vfs/storage/protocol.py:143`). A source search found neither `VersionTarget` nor `read_versions` on dev, the three kernel-records branches or the four vid branches. The composite primary key is `(entry_id, version_number)`, with separate snapshot text, diff text and binary columns (`src/vfs/models/rows.py:488`). The mint saves the replaced body as a snapshot under the replaced revision (`src/vfs/storage/backends/database/versions.py:145`). Executed through the kernel on file-backed SQLite, a text write, move and binary write produced revisions 1, 2 and 3. The only stored version was the whole text labelled 2, and the projected current bytes were exactly `00 ff`. Decision 5 of 180-1 changes that old label to 1.

The reserved spelling already reaches ordinary files. On in-memory SQLite, an overwrite of `/example.txt` from `old` to `new` left `read("/.vfs/example.txt/__meta__/versions/1")` at `vfs.not_found`. A public `write(parents=True)` to that literal address then succeeded and a plain `read` returned `physical`. The ordinary file still read `new`. The mutation guard reserves the metadata root and the trash view (`src/vfs/paths.py:875`).

## The problem

K8 calls for a single-path historical read, while Article 1.5 promises a namespace address that dev already accepts as a stored path. Dispatching that address as a view can hide existing bytes. Rewind can recover the body held through a revision gap, but that fact cannot prove that the public version label exists. Its proposed error for a mismatch also disagrees with D8. Searching all earlier snapshots for every read would let one deeply edited file dominate a call across a deployment of 10 million files.

## Decisions

1. **Add the keyword to the existing read and retain the literal path's meaning.** Take `read(path, *, version=N)` as the standard kernel form. Article 3's preference for a namespace view yields here because even the exact reserved spelling can name stored bytes. Amend Article 1.5 in the landing to name the keyword as the supported address and reserve a future view subject to a collision rule. Record in Article 4 that this standardized selector applies across history-capable backends. Its rule for backend-specific extensions still applies. The deviation expires when a namespace design can expose the view without taking a stored path away. Neither the new form nor a call at a nested mount constructs or parses a synthetic path. A path near the UTF-8 length limit therefore needs no extra suffix. Precedents are K8 criterion 2, the probe above and the constitution's longest-prefix rule.

2. **Accept one positive revision number for one path.** Add keyword-only `version: int | None = None` to the async and sync filesystem and session reads, the read protocol and database adapter. Omission and explicit `None` use today's call with no extra keyword sent to storage. Add the nullable integer to `PARAMS["read"]` with bounds 1 through `INT_CEILING`, excluding booleans, as for the existing version precondition (`src/vfs/params.py:63`, `:190`). Keep the one-target rule and add a mutually exclusive presence rule for `version` and `observations`, including an empty batch, following the listing shape at `params.py:435`. A nonnull version with `verify=False`, or with a nonnull `range` when [the ranged read](../2026-11-25-read-takes-a-byte-range-and-the-row-says-which-slice-it-carries/spec.md) lands, gives `vfs.invalid` before dispatch or direct-storage first touch. Historical success always has a whole-body proof. The public selector takes a number alone. The vid identifies the selected row on output and remains mandatory for the existing private target.

3. **Route to one mount and resolve one live entry inside the storage read attempt.** Apply the ordinary read gate and require `versions` in the resolved mount's effective capabilities (`src/vfs/mounts.py:93`), including its denial mask. Also require the provider's declared `read_version: verified` trait for the new read argument, following the ranged-read spec's decision 6, “a backend declares an engine cut”. Add the key and value to `TraitKey` and `TRAIT_VALUES` and expose the corresponding `read.version` argument when argument discovery lands. Both listing-only providers and private-only rewind providers can retain their existing declarations. A missing declaration or an effective mask on either operation gives `vfs.unsupported` with zero data calls, even at the current revision. An ordinary read never checks this trait. Pass the local path, number, columns and caller's authority to the normal read dispatch. Database storage delegates to `read_versions` with a singleton of a second private target type, `PublicVersionTarget(path, version, columns)`. The public type has neither a vid to fabricate nor a holding hash. Keep `VersionTarget` and its identity check intact. Widen the seam's target sequence to accept either target type. The same storage attempt admits the live file under 180-1 decision 6, selects its body row, mints its vid and reconstructs it. There is no first `stat`, history-page walk or call as system. A concurrent move, replacement or revocation cannot bind a previously admitted entry to another entry's bytes. Rebasing applies to the observation and to errors once, under the outer `read`.

4. **Separate a public label from the private body-at-revision lookup.** For an admitted file reject a requested number above its current revision as `vfs.not_found` with detail `no version N`, substituting the decimal number. At the current revision use the live-body head, including when metadata advanced since that head began. At an earlier revision require an exact body-start label, including a still-live head at its own label. An absent earlier label gets the same miss, even if the private floor seek can find bytes for that revision. An admitted file whose current revision lacks its required live-body head has an integrity fault. Select by the admitted entry id throughout. No history row is sought until ordinary path, kind and rights checks pass, and no tombstone or historic grant admits a public read. This retains archive criterion 27 and 180-1's new body-start labelling, while rewind and replay can still read across gaps and reach an authorized tombstone.

5. **Return the historical metadata and original source body from one snapshot.** With `columns=None`, return 180-1 decision 4's fields and exactly one additional populated field, `content` for text or `data` for bytes. Empty strings and empty bytes are present bodies. Use the requested revision and its minted vid, the addressed path and the writer, time and subjects of the body-start row. Live-body reads obtain bytes from the owning entry and verify the historical head's recorded hash, never a newly computed replacement for it. A disagreement between the live entry's and head's recorded hash is a damaged history association and follows decision 7. A column projection keeps path, kind, version and vid, and otherwise intersects requested fields with this historical row's available fields. Always verify first, including a metadata-only projection. Fetch subjects only when projected or when returning the full row. Never borrow current renderings, current metadata, or the actor who replaced the body. The extra binary fetch on explicit historical reads fulfils K8's promise to return the original. Use 180-1 decision 8's history identity for a versioned result so that combining two labels at one path preserves both. Keep it an operation named `read` and carry the same history-class marker as the listing through projection and wire serialization. The existing unversioned projection still only fetches bytes when asked (`src/vfs/storage/backends/database/reads.py:131`).

6. **Decode a bounded forward chain in the shared reader when pack first emits diffs.** For a selected whole snapshot or live-body head, read only its own source body. For a diff, seek metadata by the same entry key at or below the selected body-start label in descending order with `LIMIT SNAPSHOT_INTERVAL`. Include the selected row. Stop at the nearest whole text snapshot and fetch payloads only from that anchor through the target. Apply each forward diff in ascending stored-label order. Never count a gap as a row. The ceiling is on stored rows, including the anchor (`src/vfs/models/versioning.py:23`). Pack must preserve that limit through competing or interrupted commits. An overlong chain is damaged and never triggers a wider scan. Bytes are whole snapshots only. Reject a missing anchor, a bytes/live head used as a text predecessor, a missing or contradictory payload, or a malformed patch. The native apply kernel in `crates/vfs-core` is shared with pack and follows the dev Python law at `src/vfs/models/versioning.py:48`, `:70` for valid patches, including a missing final newline. Validate patch structure and hunk bounds before accepting a result. A nonempty string parsed as no patch is invalid even if the base hashes correctly. Keep the Python law as a parity oracle, per `AGENTS.md:113`. Hash the anchor and each materialized source body with 175-1's digest before using it as the next base. A target matching by chance cannot turn a damaged predecessor into success.

7. **Use one confirmed integrity refusal across historical consumers.** Replace rewind decision 5's `vfs.internal` on mismatched bytes with D8's nonretryable child, including before packing. Until pack lands, its specified non-snapshot refusal stands for private callers and a public request encountering that impossible stored form is an integrity finding. At the pack landing all consumers use decision 6. Use 175-1's reasons `missing`, `unhashed` and `mismatch` for absent required payload, absent digest and unequal computed digest. Add one structural reason, `chain`, with detail `the stored version chain is invalid`, when representation, association, decoding or patch validation prevents a verified body. Keep the expected digest if available and use a null actual digest for a structural fault. Error data names the failing revision, its vid and source body field. Add `requested_version` when the failed dependency is an earlier revision. The error path is the addressed file. Use a history-specific hint that this version could not be verified and an independent copy is required. No patch, content, bytes or private id leaves on failure. Use 175-1's fresh-attempt confirmation, rechecking rights and identity, with the failed link's label, vid, reason and evidence in the finding. A malformed representation includes a digest of the faulty stored representation in the private comparison so two different faults cannot confirm each other. A stable fault costs two attempts. A healed or newly denied read takes the fresh result. Continued change exhausts the existing retry budget as `vfs.conflict`. No write, repair or lock follows. The private `holding` shortcut still returns no body and makes no claim about verified bytes.

## Cost

Let `H` be the number of historical single-path calls out of the reference deployment's 150,000 daily verb calls, `S = SNAPSHOT_INTERVAL` and `B = BLOB_PAGE_BYTES`. On both served engines one clean whole-body attempt needs one live-entry lookup, one version-metadata seek, one chosen-body fetch and at most one subjects query, apart from existing rights and miss-classification work. A diff adds one bounded metadata seek over at most `S` labels and reads at most `S` payload rows. Use the primary key for every range. Fetch the selected payloads in byte pages of `B` using their physical sizes, allowing one oversize payload by itself. The number of payload statements is the number of those pages, at most `S` for a public request. Default historical attribution adds one subjects read per served file, independent of its age. Thus at most `H × S` chain rows are materialized on healthy calls, and zero on ordinary reads, nightly writes or index visits. Confirmation repeats one attempt for a stable fault.

For private batches preserve rewind's output-byte page and membership slices. Group overlapping requested chains by entry and label within the page. Use a bounded key range per target in the metadata statement, as in 180-1 decision 7's per-file page. Use `membership_budget` for paths and the declared tuple/OR-arm bind budget for entry-label pairs (`src/vfs/storage/backends/database/dialects.py:541`, `:558`). Budget windows by actual input bytes as well as target output sizes, including a large anchor of a small diff. Retain one running body and its successor per active reconstruction, releasing the prior body before the next step. Limit concurrent working bytes by processing chains serially within a page. Peak storage-side payload memory is the returned page plus an input page and the largest intermediate and successor, with individually oversized bodies allowed. For a whole snapshot reuse 175-1's per-call threshold. With a packed chain, choose offload once per reconstruction using the sum of stored payload lengths and logical body sizes for the anchor through the target, compared to `MEASURE_OFFLOAD_BYTES`. At or above it, perform apply and digest off the event loop, one sequential worker task per payload page carrying the running body forward. Below it, run inline. A normal one-page public chain makes zero or one hop. A corrupt size smaller than the materialized byte count must never be trusted as an allocation limit: check actual source lengths before apply and validate computed lengths before accepting each row. The bound is on rows and on working pages, never a refusal of a valid single large snapshot. Use a read transaction on SQLite and Postgres with no writer serialization point. An unknown dialect retains ordinary core reads and advertises public history only if it can supply coherent attempts and bounded seeks on the generic floor.

## Earlier decisions this reverses

Rewind decision 5 used `vfs.internal` for a mismatch and `not_found` for a diff row. Decisions 6–7 replace those answers as their respective landings ship. Source §7.2 envisioned an unbounded search for an earlier snapshot if the cadence was broken. The declared row limit applies even to a damaged chain. A consistent SQLite or Postgres snapshot need not retry merely because pack committed elsewhere.

## Not checked

A SQLite in-memory oracle did run on 2,500 gapped labels with a whole Unicode/CRLF snapshot every `SNAPSHOT_INTERVAL` rows. Five selected labels reconstructed in 0, 9, 9, 0 and 9 applications, with each intermediate SHA-256 checked. Changing the last chain's anchor produced a mismatch. Removing its snapshot flag produced a missing-anchor refusal within ten rows. SQLite's plan used the composite primary key. A PostgreSQL 16.2 single-user prototype on two entries of 2,500 labels each used a backward primary-key scan with exactly ten rows and one loop for label 7498. These are independent lookup and decoding probes. Public dispatch, conformance, races, full SQL statement counts, the native kernel, private batch paging and writer compatibility await implementation. The checkout lacks the private reader and pack writer. No test suite ran. The Postgres driver/concurrency leg was not run because the available server could not create its Unix socket.

## Choices to confirm

1. **Keyword or reserved address.** Take the additive keyword and the narrow Article 1.5/4 alignment in decision 1. Making the namespace the sole address or enabling both now would intercept a working literal read. A collision-safe view can be added later. No relocation, erasure or shadowing of existing stored paths is authorized by this choice.
2. **Which bytes a historical projection carries.** Take the source field by default, including raw binary, and verify the whole source before applying even a metadata-only projection. Mirroring the ordinary read's rendering-only default or skipping the hash on an empty projection would let an explicit historical read succeed without proving the requested body. Changing ordinary read defaults would affect more callers.
3. **How to report an unbuildable chain.** Add the `chain` reason to the existing integrity kind, leaving the three existing reason values intact. Calling invalid patches a digest mismatch would invent an actual digest. A future split into more detailed structural reasons can preserve the same parent and error path.

## One line

`read(path, version=N)` serves the original body at a public version label through the rewind reader, with the same whole-body proof before and after packing.

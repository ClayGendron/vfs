# The full index pass packs cold history into snapshots and verified forward diffs

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. This is unit 180-3, the [roadmap’s gate 0.2 pack phase](../../context/standards/roadmap.md), with no named story. It converts [spec 180](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/spec.md) §§1–4, 8–9 and [tasks 1–3](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/tasks.md). It rests on the gate-f historical reader and the full pass’s existing index lease.

## The outcome wanted

After a series of small edits, a storage’s `rebuild()` returns the number of old bodies it examined and the payload bytes saved. The newest replaced body still reads in one fetch. An older text body needs at most one whole snapshot and nine forward patches. Every label still gives the original bytes and writer, including after an interrupted rebuild. A damaged predecessor can prevent a saving, but never authorizes replacing the only whole copy with an unproved patch.

## What the code does today

The mint inserts whole replaced bodies and their subjects (`src/vfs/storage/backends/database/versions.py:127`). Format 28’s composite key is `(entry_id, version_number)`. It has `content`, `data`, `version_diff`, `is_snapshot`, logical metrics and attribution, with no judgement or physical byte count (`src/vfs/models/rows.py:135`, `:486`, `:516`). Python emits and applies unified diffs, including a missing-final-newline marker (`src/vfs/models/versioning.py:48`, `:70`). Its standalone model constructor chooses by label modulus (`:164`). The model is exported and its existing behaviour has callers in tests (`src/vfs/models/__init__.py:47`, `tests/models/test_models.py:472`). The only runtime import of `unidiff` is the Python diff law (`pyproject.toml:38`).

Executed through `DatabaseStorage.write` and `rebuild()` on in-memory SQLite 3.46.1 and disposable Postgres 16.2. Four generations of the edited 20-line file in source criterion 1 produced three snapshots labelled 1, 2 and 3, each 390 UTF-8 bytes. Rebuild issued zero statements naming `vfs_versions` and returned no pack extra. The dev diff from the first body to the second was 148 bytes and applied to the exact second body on both runs.

## The problem

At the reference deployment, nightly ETL can replace a million files. A one-line edit stores another full body. The daily rebuild already visits ten million files, while `refresh` promises work in proportion to dirty entries (`AGENTS.md:83`, `:87`, `src/vfs/storage/backends/database/maintenance.py:152`). A space saving must preserve undo, survive a rival lease holder and give a bounded read even on the most heavily edited file.

## Decisions

1. **Pack once in the full pass.** Run `pack` after the signal phase at the end of `_rebuild_phases`. The existing outer `_embedded` step still follows (`maintenance.py:141`, `:405`, `:643`). Pass the maintenance context, tables, lost event and token, as render does at `:414`. No pack work runs on `refresh`, on a foreground write, or through a new verb. Decided 2026-11-15: keep the newest old version whole ([kernel rulings](../../context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md), decision 11). Declare private `PACK_HOT_ROWS = 1`. Exclude the live-body marker from both sides of the count. A *cold* row is a completed row with at least one newer completed row of the same entry. Labels may gap. A live head and a single completed undo therefore yield zero candidates.

2. **Record physical size and completed judgements on the row.** Add nonnullable `packed` (Boolean, default false) and `stored_bytes` (Integer, default zero) to `vfs_versions` and `VERSION_ROW_ONLY_COLUMNS` (`rows.py:98`). In 180-1’s existing insert the live head starts false and zero. Its existing completion update sets false and the full source’s byte size, including zero for an empty body. This adds no write-side query or second copy. Hot rows stay false. A judged snapshot or diff is true. The physical count measures the UTF-8 patch, UTF-8 snapshot or binary snapshot payload, excluding database overhead. Advance `SCHEMA_FORMAT_VERSION` once from the then-current format. First touch of an incompatible mount gives the existing `vfs.unavailable.schema` (`src/vfs/storage/backends/database/engine.py:922`), including for older processes against packed mounts. No automatic migration or reprovisioning.

3. **Seek a bounded page of cold row keys, including retained deleted entries.** Add `ix_vfs_versions_packed` over `(entry_id, version_number)` with the predicate `NOT packed AND NOT body_is_live` on SQLite and Postgres. Seek strictly after the last tuple in this order, limit to the host’s membership budget, and require both an owning `vfs_entries.entry_id` and a higher completed label under that same id. Use indexed existence probes. Orphans belong to reclamation. Unit 180-4's `versions` phase removes an orphaned file's version rows together once none is younger than a day, so no packed chain is cut (its decisions 10, 11 and 27). Avoid a path join or a `deleted_at` filter. On the first page capture the greatest pending tuple as this run’s upper bound in the same statement. For a file split across pages, capture its greatest cold label on first sight by a reverse primary-key seek and finish only through that label before advancing to the next id. A new write beyond either bound waits for the next rebuild. New work behind an advanced cursor is eligible next run. The marks are the durable cursor after a crash. An empty pass issues one work-list statement and opens no pack writer.

4. **Prepare a prefix of each file’s pending work outside the writer.** Read candidate metadata in key order. For each run’s first row, seek at most `SNAPSHOT_INTERVAL` preceding *stored* rows under that id, newest first. Stop at the nearest snapshot, exclude the live head and never widen the seek on a damaged chain. Batch the per-file ranges with their own limits, using bounded correlated primary-key seeks as in 180-1 decision 7. Fetch only the anchor and patches needed to seed the running text, and eligible candidate text. Carry the verified predecessor and its depth between adjacent rows. Cut rows, including the middle of one long history, by the membership and byte budgets in Cost. Read source, payload presence and lengths as metadata. Do not select binary data or oversized text into the process. Use UTF-8 byte lengths (`length(CAST(text AS BLOB))` on SQLite, `octet_length` on Postgres) and an in-statement size guard on the body projection so damaged size metadata cannot force an oversized fetch. On SQLite fetch eligible text as bytes and decode strictly in the worker, so invalid UTF-8 follows the integrity path. Each input page comes out of a short read transaction. Release it before CPU work. The predecessor of a resumed slice is either carried from a committed prefix under this token or reconstructed and verified again.

5. **Make and replay a forward unified diff in the required Rust engine.** Add the pure diff/apply kernel in `crates/vfs-core/src/versioning.rs`, register it in `lib.rs` and `python.rs`, and advance the paired extension protocol from its then-current value (`crates/vfs-core/src/python.rs:29`, `src/vfs/native.py:36`). Use `src/vfs/models/versioning.py` as the Python owner of the native calls. Move dev’s independent Python compute/apply code to `tests/support/oracles/versioning.py` and move `unidiff` to the dev dependency group. For successfully generated patches require byte parity with the oracle, including its line splitting, three context lines, matching/tie order, headers and final-newline marker. On stored history use strict single-file decoding, checking complete consumption, hunk order, coordinates, source context, removals and lengths before accepting output. Empty diff is the identity. Keep existing model construction and compatibility helpers callable through the native engine. The standalone constructor’s label-based heuristic never chooses a stored form in the mint or pack. This avoids breaking the existing model tests while retiring the Python runtime implementation.

6. **Use only verified, affordable text as a base.** Declare `PACK_MAX_BODY_BYTES = 2 * 1024 * 1024` as source §2 proposes, independent of the index eligibility cap at `src/vfs/storage/backends/database/indexing.py:114`. Apply it to both base and target. If a deployment narrows the page budget below that gate, use the smaller budget for both operands. Existing valid patches remain readable under a narrower writer budget. A binary or oversized row stays whole, resets depth and supplies no text base. Hash every eligible snapshot that can become a base, including a cadence anchor or a row kept for lack of savings. Verify every reconstructed predecessor against its stored digest and logical size. Use 175-1’s `content_digest` for the proof in the offloaded batch around the native calls. A damaged body/representation is a break in the chain. Leave it as found and retain the next eligible whole row as a fresh anchor after verifying it. A previously packed row used as context is never rewritten. Pack does not certify bytes it did not fetch.

   With a verified predecessor and depth below `SNAPSHOT_INTERVAL - 1`, generate the candidate from the immediately preceding stored label. Keep it only if it is strictly shorter in UTF-8 bytes than the full target, its strict replay gives the original target bytes, and that replay passes the target hash. Equal sizes, failed candidate replay or exhausted diff work keep the verified target whole and reset depth to zero. A retained diff increments depth. A whole row is compulsory once the predecessor has nine diffs. A run, a page and a label gap never reset depth by themselves. Stop emitting a candidate at the target’s byte size. Bound worst-case matching with `PACK_MATCH_STEPS = PACK_MAX_BODY_BYTES` candidate-line visits per pair, charging each old/new match position visited by the matcher, including repeated-line candidates and match extension. Exhaustion is an ordinary keep with no error. Use linear auxiliary space and intern lines once. One offload hop per nonempty text slice, never one per row. The reader applies stored patches independently of the writer’s matching budget.

7. **Land only a verified, contiguous prefix under the current lease.** Use `execute_leased` so SQLite’s managed transaction actually begins as a writer before any CTE update (`engine.py:981`). In that short transaction lock version keys in sorted order (`dialects.py:514`). Confirm the read identities, representation, hashes and actual bounded payloads for each candidate and dependency, under the same entry, including the immediate predecessor across a slice boundary. Compare payloads bytewise. A carried prefix saves recomputation only while its bounded seed rows still compare equal under the landing locks. If any differs, discard the proof. Completed labels are immutable under the mint. The only competing ordinary changes are a higher label, deletion of the whole entry, or a different lease. A newer completed label only cools more rows. Recheck the owner and presence of the newer completed witness in sets. Use the token fence as the last statement. With `lost` already set, issue zero landing statements. If the fence misses, roll back every candidate and return the standard retryable `vfs.conflict`.

   Update by entry and label with guards for completed, snapshot, unjudged and the recorded digest. A keep flips only `packed`. A diff also sets `is_snapshot=False`, clears `content`, and sets `version_diff` and `stored_bytes`. No insert or delete. Use bounded set updates with matched-key verification on both served engines (a named `VALUES` CTE on SQLite, a typed `VALUES` relation on Postgres), costed by `statement_budget` at `dialects.py:598`. Never apply a surviving subset after a guard miss. Roll back, reread and replan the slice within the existing retry bound, drop vanished files and skip rows already judged. Persistent contention returns the existing retryable conflict. A retry of an obsolete plan must return to the read/compute step, even when the write runner can itself retry a transient driver conflict. Advance progress and totals only after commit. An interrupted slice can be retried without changing cadence or attribution. This strengthens source §3.5, which allowed rival landings to exceed nine diffs. No work in this phase writes paths, entry stamps, vids, logical metrics, times, actor, provenance, source identity, grant revision or subjects. Its statements never name `vfs_content` or `vfs_blobs`.

8. **Enable the shared chain reader in the same landing.** Replace rewind’s non-snapshot refusal in `src/vfs/storage/backends/database/version_reads.py` with 180-2 decisions 6–7, using the same strict native apply function as the writer. Both the public historical read and the private rewind/replay seam use one coherent read attempt and verify each link. A missing anchor or overlong chain gets the specified confirmed integrity error, never a deeper scan. A snapshot fetch and the private holding shortcut stay as specified. The generic floor keeps its ordinary verbs. Leave all history whole on a dialect until the storage supplies the verified reader, byte-bounded selection and guarded, fenced landing for it. No pack statements are issued there while those guarantees are undeclared. The served SQLite and Postgres profiles supply all three in this landing.

9. **Report committed work, including on interruption.** When the phase runs, give `Result` a `pack` extra with integer `files` (distinct entries judged), `judged`, `diffs`, `kept`, `bytes_before`, `bytes_after` (physical payloads of judged rows only), and `rot` (distinct damaged rows encountered in committed work, including seed rows). An empty executed pass has seven zeros. An ineligible generic mount or an earlier phase failure has no pack extra. Count in key order with at most one entry’s bounded context for deduplication. Sum `kept + diffs = judged`. Exclude abandoned plans. Preserve other phases’ errors, extras and embedding work. A confirmed damaged candidate is marked judged and left whole, so the next empty pass does not report it again. For damage give one nonretryable warning of kind `vfs.unavailable.integrity`, with the first affected `entry_id` and `version` in storage-only warning data and the total in `rot`. Admit the warning only on a successful representation recheck at landing. This bounds diagnostics even if a whole batch is damaged. A patch rejected for size or generator failure is no evidence of storage damage.

## Cost

Let `M` be the host’s `membership_budget`, `P = BLOB_PAGE_BYTES`, `A = PACK_MAX_BODY_BYTES`, and `S = SNAPSHOT_INTERVAL` (`dialects.py:81`, `:541`, `src/vfs/models/versioning.py:23`). Use the live dialect’s parameter budget and measured compiled width for each keys/values statement. For compound disjunctions also take `arm_budget` (`dialects.py:556`). For a 10,000-file batch use the smaller applicable cap on SQLite or Postgres. No statement grows a bind list to the corpus size.

| Multiplier | Work and bound |
|---|---|
| Per material write | Two bookkeeping values ride the existing head insert and completion update, plus insertion of the completed key into the partial index. At most about 1.05 million such completions per day at the reference centre. No per-file statement is added. Wider existing bulk statements still obey their measured bind cap. |
| Per daily rebuild | For `F` entries with a hot completed undo and `U` newly cold rows, the pending-index walk visits about `F + U` keys plus pending orphan keys, and probes for a newer label/owner. At ten million files with retained history this can mean ten million hot keys on an otherwise clean day. The scan returns no hot bodies. A per-refresh pass would repeat this work up to 96 times a day. |
| Per metadata page | Return at most `M` candidate keys, with at most `S` seed rows per entering file. Split seed ranges by both actual bind count and a declared `M` metadata rows per result, processing at most `max(1, M // S)` independent ranges at once. A single range uses its own limit if a test narrows `M` below `S`. A file with millions of versions spans pages. No whole-file metadata list or window over its full history. |
| Per work slice | Slice by the smaller of the metadata cap and `P` UTF-8 input bytes, including seed payloads. Page a seed chain across reads if it alone exceeds `P`. Keep one running reconstruction, input/output pages and at most one carried seed chain (`S × A`) for a split file. Bound each comparison/update’s payload by `P`, splitting statements within the same transaction. At most `A` source bytes per eligible operand and `PACK_MATCH_STEPS` match visits per candidate. Binary and oversized cases use metadata only. |
| Per statement and commit | One candidate seek per key page plus the terminating seek, grouped context/metadata seeks per bounded range page, and one fetch per nonempty payload page. Per nonempty landing, grouped validation/locking reads plus one update per bind/byte chunk of each present form and one final heartbeat. Count the actual slices and chunks when testing; tiny and empty texts still consume a row slot. SQLite’s writer slot and Postgres row locks cover this commit only. Readers take no writer or lease lock. |
| Per historical read | Only the diff branch adds a bounded seed seek and up to `S - 1` applications. Output pages and fresh-attempt confirmation are costed in 180-2. Unversioned reads and refreshes acquire no pack work, independently of the reference deployment’s 150,000 daily verb calls. |

## Choices to confirm

1. **Which retained owners qualify?** Include deleted entries, excluding orphans. Filtering to live entries would leave restorable histories indefinitely uncompressed. The selected side preserves all labels and supports a later narrower eligibility filter.
2. **How to find new work?** Take the partial pending index and the daily hot-key scan. A write-side cold-work queue can eliminate that scan but adds a concurrent update to the preceding completed row or a queue table to each material write. The simpler index can be replaced after measuring the daily scan against that write cost.
3. **How much matching work may one pair consume?** Take the deterministic candidate-visit cap in decision 6 in addition to the source’s body-size gate. The alternative allows quadratic matching through the entire eligible input. A keep on exhaustion preserves verified source bytes. A future budget change needs no decoder change.
4. **How much damage detail leaves a rebuild?** Take one warning with the first key and an exact total, following the aggregate rendering warning at `maintenance.py:347`. An unbounded warning per damaged row can itself consume corpus-sized memory. A bounded list of further examples can be added compatibly.

## One line

The daily rebuild rewrites only cold, completed history whose shorter forward diff has reproduced the original bytes, and every stored version remains attributable and readable in at most nine patch steps.

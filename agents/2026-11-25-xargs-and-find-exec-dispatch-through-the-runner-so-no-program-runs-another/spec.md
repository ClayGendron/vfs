# The shell starts each child of `xargs` and `find -exec`, and deletes only the rows `find` selects

A draft, written on 2026-11-25. It is not reviewed, and nothing in this amendment is built. Checked against `dev` at `27f3d24d` for [roadmap story F6, gate f](../../context/standards/roadmap.md). Converted from [the text programs, §§1.5–1.6](../../context/specifications/archive/168-text-program-kernels/spec.md). It extends the standing program table and the indexed verbs using the shell machine's existing start request and the interrupted line's job.

## The outcome wanted

Over 25 text files, `find . -name '*.py' | xargs -n 10 grep -l TODO` starts three children as the admitted caller. Each gets empty standard input. Three public `grep` calls search ten, ten and five files. A batch with no match gives the completed pipeline statuses `[0, 123]`. A name with a space or newline travels intact through `find -print0 | xargs -0` or directly through `find -exec`.

With `find . -name '*.tmp' -exec rm {} +`, only the selected operands reach `rm`. With `-exec C {} \;`, the child's success is the truth of a test on one path. With `-delete`, a directory can go only after its children have gone. A stopped change belongs to the one line and resumes without repeating a completed child.

## What the code does today

At the checked commit `run_program` takes library names locally and otherwise sends `Start { name, args, cwd }` (`crates/vfs-shell/src/machine/exec.rs:1094`). `_start` answers `library`, `started`, `refused` or a lookup error. A started program's writes and exit arrive through `Feed` (`src/vfs/shell/host.py:439`, `crates/vfs-shell/src/programs/mod.rs:65`). Both a refusal and a program's exit currently become a plain integer. `_grep_form` requires recursion (`src/vfs/shell/programs.py:358`). The find parser's actions stop at printing and pruning (`crates/vfs-shell/src/programs/files.rs:245`). A grouped `delete` checks all path gates before dispatch, groups by mount and applies an admitted database group atomically (`src/vfs/base.py:1883`, `src/vfs/storage/backends/database/trash.py:132`).

Executed with the dev machine on SQLite in memory and a fresh disposable Postgres database. Both returned `[[141, 127]]` for the F6 line, one `glob` and zero `grep` calls. Each find action probe (`-exec false {} \;`, `-delete`) returned 1 with an unknown-predicate diagnostic. Direct `grep -l TODO f00.py f01.py` printed both names with two stats, two reads and zero public greps. As a prototype of the host calls, a metadata-only public `read` over each group returned file kind, text source, size and version. Public `grep("TODO", paths=…, output_mode="files", allow_scan=True)` over the three groups of ten, ten and five returned ten, ten and zero hits on both engines. A second in-process prototype registered the proposed explicit-file grep on the dev host. A Python loop batched the 25 names printed by real find and ran three ordinary machine lines. Both engines produced three host starts, six metadata reads, three public greps, child statuses `[0,0,1]` and 20 printed names. A bytes-sourced file containing the same pattern fell back and printed its name. This exercised host resolution, the metadata recheck and feeds; the batching loop was a prototype.

## The problem

Flattening a child into shell text would interpret a filename as syntax. Calling the host's program function inside another host program would hide child requests from the machine and could repeat mutations on resume. Conversely, three correct starts still give zero indexed grep calls on dev. At the reference deployment's ten million files, materializing a whole traversal for an action, or accidentally cascading through a directory whose children failed the predicate, is the wrong unit of work.

## Decisions

1. **The machine consumes argument vectors and alone starts children.** Put the private child driver in `crates/vfs-shell/src/machine/children.rs`. The standing table's tokenizer and the find planner emit a vector or a visit action and accept its outcome. Neither receives a callable runner, parses a new script, invokes a process, or calls `cli`. At the ordinary expanded-program dispatch point, after normal outer function and builtin precedence, run such a plan in the machine. Resolve every child vector afresh by its literal first word, using the standing table's builtins, library entries and ordinary host lookup. A child is a utility invocation: no alias expansion, shell function lookup, parse-time shorthand, globbing, word splitting or evaluation of its operands. At both the direct-library entry and the host's `library` handback, select this driver for `xargs` or an action-bearing `find`. Ordinary utility code gets filesystem and descriptor methods only: move the host feed driver to the machine, hide the raw `Shell` and general `Request` sender behind a machine-owned program context, and expose only the file, stream and budget operations existing library implementations use. The action parser returns data. A source rule excludes child dispatch, `Start`, `Feed` and raw host calls from program implementations. Dev's current `Prog` exposes both its shell and generic request method (`crates/vfs-shell/src/programs/mod.rs:110`); an additional general execute method would make that boundary impossible to enforce.

2. **Each child has the parent's output descriptors and its own shell state.** Use `Shell::fork` (`crates/vfs-shell/src/machine/shell.rs:344`) and its deterministic task key, shared budgets and current directory. Open descriptor 0 on `Fd::Null` for an xargs child. A find child inherits the find command's input. A host child uses its ordinary `Start` and `Feed` sequence, including `library` fallback. Other children use their ordinary local entry. Forward writes in order through the inherited descriptors, including `2>&1`; do not collect a child transcript. Only the outer command contributes the pipeline status. Normalize child-local exit and return at the fork boundary, and propagate line-fatal conditions. The ordinary dispatch charges its existing requests. Debit one child start against the shared verb budget, using its `Start` debit if it has one, a local debit otherwise. Charge feeds and other requests ordinarily. Nesting, memory and fuel are never reset by a child. The Linux GNU oracle verified `find … -exec cat \;` and the plus form inherit stdin, while an xargs child reads EOF.

3. **A batch has both an argument count and a byte bound.** The shared planner declares `ARGV_BYTE_BUDGET = 128 << 10` in the machine, the command-buffer size reported by local GNU `xargs --show-limits`. Charge every encoded argument including the utility and fixed words, plus one terminator per argument. Count only added arguments for `-n`. Flush before adding an item that would exceed either bound, and execute a count-full batch as soon as it is ready. Check template substitution after expansion, including repeated placeholders. An oversized fixed vector or item that cannot fit alone fails the command with status 1 and a diagnostic, without dispatching that vector. Never split an argument. Use a bounded pending item, the input chunk and a single batch. Reserve capacities and fork state against the line's memory before growth, release on consumption, error, early close and drop. Checkpoint while scanning input, substituting and walking. A line budget is the machine's failure, including 137 for memory, distinct from a utility's size error.

4. **All child kinds use the same xargs input contract.** Support the archive's `-0 -d D -n N -I R -r -t -P N`, short-option clusters and attached arguments, and `--`; stop option parsing at the utility. Default utility is `echo`. Positive decimal `-n`, nonnegative decimal `-P` (including zero), nonempty replacement string and a single-byte literal or GNU delimiter escape are required. Serve GNU's corresponding long names (`--null`, `--delimiter`, `--max-args`, `--replace`, `--no-run-if-empty`, `--verbose`, `--max-procs`) with their GNU argument conventions. Run serially for every accepted parallelism bound. An omitted optional long `--replace` value selects `{}`. In default mode split on ASCII space, tab and newline, with GNU single/double quotes and backslash; preserve a quoted empty item and carry unfinished items and escapes across input chunks. In delimiter mode, blanks, quotes and backslashes are data; emit consecutive empty items, the unterminated final item and no phantom item after a final delimiter. Default empty input invokes once; `-r` and replacement mode invoke zero times when there are no records. Replacement mode consumes one logical line (or one delimited record), removes GNU's leading unquoted blanks in line mode, and substitutes every occurrence in arguments after the utility. Apply GNU's last-option rule and warnings for competing `-I` and `-n`, including the quiet `-I… -n1` exception. `-t` quotes the final argv as GNU xargs does and writes it on stderr before start. Bad options, unfinished quotes and invalid input exit 1; earlier completed batches stand, the incomplete batch does not run. For bytes the text-only argv cannot represent, see choice 1. The recorded cases own punctuation and quoting in the shell's configured locale.

5. **Keep start failure distinct from an executed child's exit.** Return a private tagged outcome at the shared dispatch point before ordinary simple commands convert it to their existing integer. Preserve child stderr and host warning evidence. An xargs lookup miss or deliberate 127 refusal stops with 127; an unstartable command or 126 refusal stops with 126. Prefix the utility diagnostic with `xargs: NAME:`, using the host's specific reason where present, with `No such file or directory` for a generic miss. No second bash-prefixed diagnostic. For a completed child, exit 0 continues, 1–254 records aggregate 123 and continues, and 255 prints the abort diagnostic, stops, and returns 124 even after an earlier ordinary failure. All success or no child gives 0. A real machine cancellation, timeout, budget end, pipe closure or policy stop travels on its existing control path, never inferred from a number. There is no process-signal report in `Reply::Output`; do not invent a GNU signal exit from `128+n`. GNU findutils 4.10.0 was run with two inputs: children explicitly exiting 126, 127, 137 and 254 ran twice and gave 123; exit 255 ran once and gave 124; a missing executable and an unexecutable directory gave 127 and 126. This resolves the gap above 125 in archived §1.5.

6. **Serve explicit text-file `grep -l` through the public grep.** Extend the common host parser in `src/vfs/shell/programs.py` for the nonrecursive filenames-only form, with an accepted pattern, at least one explicit file operand, no stdin operand, no include/exclude filters and no other output mode. This applies to the same argv however it was started. Probe unique absolute operands together by public `read(observations=…, columns=frozenset({"source", "kind", "version", "content_hash"}), authority=…)`. Admit only complete, readable, text-sourced ordinary files. Make one public `grep` over their distinct paths with the existing translation, `output_mode="files"` and `allow_scan=True`. Before emitting, repeat the metadata projection; any incomplete result, warning, missing identity, changed stamp, unexpected descendant or binary source hands the whole start back to the library without printing any partial answer. This keeps the library's explicit-operand errors and raw bytes behavior and never prints a directory descendant as a file operand. Emit matching original spellings in argument order, duplicates included, with exit 0 for a match and 1 otherwise. All three calls use the admitted authority. This narrow exception amends indexed-verbs decision 3; the fallback also handles operands changing during the search. There is no new kernel grep mode.

7. **Plan find actions from expanded words before walking.** Extend the existing find expression parser into a shared private plan, recognizing actions only in primary position. Consume child words as opaque operands up to a literal semicolon, or a standalone `{}` followed by `+` for batching. An ordinary plus within a semicolon template is data. Validate the complete expression and all templates before the first visit, child or change. GNU misuse gives find status 1, an explanatory stderr line and zero actions. Semicolon requires a utility, permits no placeholder and replaces every literal `{}` occurrence, including embedded or repeated ones. Plus requires a fixed utility and exactly one occurrence of `{}`, as the last standalone argument. With either action suppress implicit printing, preserve explicit printing, conjunction, alternatives, negation, parentheses and short-circuit evaluation. Keep the host's built read-only find for the ordinary F6 pipeline. For an action plan use the indexed host's ordinary `library` handback before any effect, then drive the plan in the machine. A word consumed by a predicate or child must never be rescanned as `-delete`, a depth option or another action. The same private planner/evaluator serves both hosts.

8. **The action walker streams visits, and each exec form has its own reduction.** Walk start operands in input order, names within a directory in the shell's existing byte order, with the paged list helper; hold a cursor and at most one charged page per open directory. Preserve the displayed spelling for child argv and use the normalized path for router requests. Semicolon starts once immediately per selected visit and returns its truth to the expression. An ordinary nonzero or failed lookup makes that primary false, leaves find's exit unchanged and allows subsequent visits. Plus queues paths per occurrence, returns true immediately, batches under decision 3, flushes in expression order at end and starts nothing for zero matches. A failing invocation sets find's final status to 1, including a failed start or child exit 255; later batches still run. Both keep genuine traversal failures at 1. A previously admitted pending batch flushes at normal walk completion even if a later start path was missing; a terminal line abort drops pending work. No synthetic pipeline appears in `PIPESTATUS`. GNU was run with two explicit starts: a false child gave 0 under semicolon and 1 under plus, and `-exec false {} \; -o -print` printed both starts.

9. **Delete the visited path, in depth-first postorder, without a cascade.** Presence of a delete primary anywhere implies depth-first visits for the whole find expression. Honor explicit `-depth`, `-mindepth` and `-maxdepth`. Diagnose `-prune` with implied depth before effects as GNU does; with explicit depth it is a true primary with no effect on descent. Respect the predicate on every row, including the start. Follow GNU's special case for the starting `.`: the visited current-directory entry spelled `.` is kept; a separately named directory start is eligible. Before normalizing, refuse a start ending in the literal directory entry `.` or `..` (including `./`), except for that exact `.` no-op. Never turn `a/.` into permission to remove `a`. Use the invalid-argument diagnostic for the protected spelling and status 1; this consistently protects aliases on virtual mounts (choice 3). For a postorder `-empty` test, determine emptiness after completed descendant actions. Evaluate an observable delete immediately with the ordinary `Remove {recursive:false}`. Success is true and silent. Failure is false, retains the router's classified warning and prints `find: cannot delete ‘PATH’: REASON` in the configured locale; it latches final status 1 and traversal continues. A list refusal is trouble and never evidence that a directory is empty. Mount protection, live-child occupancy and the fate of a deleted row are the public verb's. An unseen child, a child outside the predicate, or one created after listing must survive.

10. **Batch only independent deletes whose truth no later action consumes.** For a terminal delete following a conjunction of pure tests, buffer contiguous distinct selected regular-file siblings. Flush before a directory, a duplicate, a change of parent, any observable action, a new start, normal end or the first row past the page or argv byte budget. Use a new private `RemoveBatch {paths}` request, each path absolute, in visit order; the vfs host calls public `delete(observations=[Observation(path=p) …], cascade=False, authority=…)` once. Directories and general expressions use the single-path request. Reuse the file batch for the plain, non-interactive, nonrecursive multi-file `rm` case reached by `-exec rm {} +`, retaining its existing option, dot-operand, directory and diagnostic checks and flushing before any diagnostic or nonbatchable operand. A plus child always passes through ordinary resolution, so a handback or refusal follows normal rules. Use the listing dependency's page count as the row bound, never an SQL bind count. With GNU `rm` the distinction between a file and a directory matters: keep `rm`'s per-operand stat before admitting a file to the batch. See choice 2 for the failure boundary.

11. **Each batch is one public change and one replayable reply.** The batch reply carries results in argument order, with confirmed deleted paths, the router's specific refusals, and a group failure for any remaining unconfirmed path. A path with no reported success is never counted as deleted. Report a group-wide reason once, keep the original facts through the host's bounded evidence collector, mark the action or child failed, and continue with subsequent groups. Never reissue a partially committed, denied or ambiguous batch. Keep view, session stamps and mutation checks at the guarded router; listing and filtering confer no right to mutate. Mirror the request and reply on the reference host, binding and module wire. Extend spec 8 decision 6's journal forms with this ordered reply, its ordinary request digest (including ordered paths), and its own mapping for a denied step. A stopped batch has no completed reply. On resume, completed starts, feeds and batch replies replay, then the stopped step receives its answer once; no private action log and no child job. The stop gives the outer interrupted result of spec 8 decision 22, never xargs 126/123. A resumed denial inside an already started child reduces through that child's normal exit. The warning, any host execution state and the guarded router's per-path stamps for confirmed changes replay with the reply; the same batch cannot apply to a newly created file at a freed name. A successful resumed line returns all output exactly once.

## Cost

Let `B` be the declared argv byte budget, `P` the listing page count, `D` the maximum depth visited and `A` the number of plus actions in the admitted expression. Input scanning and copying are linear in input and actual expanded argv bytes. The xargs planner holds one chunk, one partial item and one vector, each independently charged to the line; the find walker holds at most `D` pages and `A` vectors of at most `B` bytes, plus one delete group bounded by both `P` and `B`. No line first collects all matched paths to run an action. Fuel, memory, output and verb budgets can terminate any such walk. The read-only served find's preexisting materialized answer remains a cost of that path (indexed-verbs decision 7).

For 10,000 nightly input files at `-n10` with short operands, 1,000 starts and 1,000 public greps replace 10,000 file-body reads in the shell; each successful grep group adds two metadata-only reads. At the reference deployment's hundred such batches this is 100,000 starts, 100,000 greps and 200,000 metadata reads, spread across independently budgeted lines. Counts describe work before an admission budget stops it. No new work runs on the other 150,000 daily calls or the ten-million-file rebuild. A served find action pays for pages of visited directories; a semicolon pays one child per selected visit. In a single directory, deleting `M` short, distinct eligible sibling files costs `ceil(M/P)` public deletes when the byte budget permits a full page; a general expression costs up to one delete per selected visit. Each group commits within the verb, with no writer lock across a page read, child, or wait for approval.

For a child fork the copied part of shell state costs its current charged size once per start; serial execution holds at most one such fork per active dispatch depth. The existing nesting budget also bounds nested `xargs` and `find` child drivers. Recheck a budget before the fork so an input cannot grow the native stack or clone uncharged state. No new SQL, table or engine-specific setting. The router splits a group by mount. The database's `membership_budget`, `arm_budget` and row/parameter budgets bound the statements independently of the shell's page (`src/vfs/storage/backends/database/dialects.py:556`, `src/vfs/storage/backends/database/trash.py:412`). SQLite's expression-depth limit and both served engines' parameter limits remain binding (`AGENTS.md:62`); an unknown dialect uses the generic floor. A generic storage returns its usual public result.

## Choices to confirm

1. **An argv item that is not valid UTF-8 or contains a data NUL.** Take an explicit xargs diagnostic and status 1 before dispatching the affected batch. A NUL serving as the selected delimiter is consumed normally. GNU on Linux passed invalid bytes to a utility and truncated a default-mode item at NUL with a warning. Dev's `Start` uses `String`. Refusing avoids directing a mutation to a different decoded name; widening the argv wire later is additive. Give the stable diagnostics `xargs: argument is not valid UTF-8` and `xargs: argument contains a NUL byte`.
2. **Atomic public delete groups or per-file retry after a mixed refusal.** Take the public result once for each bounded group and retain every confirmed change. An ordinary refusal may leave an otherwise removable sibling in the same uncommitted group. GNU performs independent unlinks; the per-file alternative costs one commit per file, and retrying a failed group could delete a replacement at a reused path or bypass a decision made on the group. Mark the difference in the reference and corpus. A later per-item execution mode can be added without changing the verb or replay format.

3. **Protect a start naming a literal dot entry before normalizing.** Take a uniform refusal for dot-entry aliases, with GNU's exact `.` exception. Local GNU returned `Invalid argument` for `a/.` and `./`, and `Directory not empty` for `a/..` in a populated parent. Looking up the normalized target to reproduce the particular OS error would inspect the parent and could remove it. Narrowing the diagnostic later is reversible.

## One line

The machine starts each argument vector under the line's caller and budgets, while find preserves expression truth and removes selected entries through the reversible public delete.

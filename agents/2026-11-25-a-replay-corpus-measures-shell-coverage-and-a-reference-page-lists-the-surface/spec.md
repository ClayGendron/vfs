## The outcome wanted

A reader can see how many in-scope commands from the weighted sample run and how many admitted Oils cases the shell answers as Bash does. The README gives both as counts and percentages. The score report explains the two populations, shows where names and option forms fall short, and gives enough information to reproduce a miss. The shell reference distinguishes a program returning 75, 123 or 134 from a facility that assigns that status.

## The problem

The reference reports 3,218 of 3,339 local cases passing, including accepted differences (`documentation/reference/shell.md:169`). The landing reports 72 of 77 in-scope weighted lines running ([progress](../2026-11-21-the-shell-speaks-bash/progress.md), line 11). That denominator was derived in prose. The test counts raw runs and checks an absolute floor. Neither figure measures Oils conformance. The README gives neither F5 headline. The prior experiment compared only selected Oils files and treated any two nonzero statuses alike (`agents/2026-11-21-the-shell-speaks-bash/studies/2026-11-21-prior-art/experiments/oils_diff.py:39`).

Run on the native Rust `MemoryHost`, using the exact dev sample setup and decoded JSON lines: all 100 parsed and 72 passed the existing run predicate. A valid `false` counted as a run, as did `ls --no-such-option` and `cd /missing && madeup`. Printing the literal text `command not found` to stderr counted as a miss. Thus raw run, name availability, supported options and agreement with Bash can yield different numerators. Counting committed files gave 3,339 scripts, 121 named failures and 36 delta entries, after stripping comments and blank lines.

## Decisions

1. **Keep the three populations identifiable.** Decided 2026-11-25: use the weighted `experiments/s1/corpus.jsonl` from the path at `measured_corpus.rs:20` once per ID, including repeated command shapes. Keep the coverage-stress sample separate. Give the weighted result the label “weighted sample, in-scope runs (reference host)”. Use the landed run predicate verbatim through one shared measurement helper. This is a measure of lines reaching an end without the diagnostics the predicate recognizes. Reserve “match” for an oracle comparison. The local recorded conformance score keeps its own label and denominator. The archive's stdout-and-status definition of run belongs to that comparison (`context/specifications/archive/167-the-shell-pipeline-core/spec.md:178`).
2. **Declare scope before scoring.** Add `tests/shell/weighted_scope.json`, keyed by sample ID, with a SHA-256 digest of its UTF-8 command text, required command names and forms, and a reason on each excluded ID. Classify using the published target surface, including the standing table even while incomplete. An intended host-only command excludes the entire row even when an earlier command fails or the offending command is behind a redirect. An admitted but unimplemented feature is a miss. D22 keeps external `awk` and `jq` outside this target until the release surface changes (`context/standards/roadmap.md:648`, `:1233`). Inspect command position, including function bodies and substitutions, rather than matching text in an operand or here-document. Fail on missing, duplicate, stale or extra IDs. Count overlapping exclusions once. Print total and in-scope counts independently. Gate the latter with positive denominator and `100 * ran >= 85 * eligible`, alongside the existing raw floor. Reconcile changes from the historical 77 with case IDs and reasons. A denominator change requires reviewing the manifest, never deleting an observed failure.
3. **Report parse, name and form coverage separately on the same weighted IDs.** Use the real parser with its ordinary limits. For each ID list the names its workload requires, including commands on a branch the sparse fixture never reaches. Resolve those names with isolated `command -v` probes in the measured host and the row's local function definitions where needed. Count an unknown or expressly refused target as a resolution miss, with the deliberately unavailable subset counted once per row and printed beside resolution. The scope annotation identifies deliberate unavailability independently from probing. Executed on the native reference host, these probes found the library name `ls`, builtin `true` and locally defined `f`; a missing name returned 1. For each distinct required option form use an existing recorded case that distinguishes the form from its omission, or add the smallest such case through the existing recorder. Compare the real reference-host result to the Bash record, never the shell's delta. Count the row for flag coverage only if it parses, resolves and all its form witnesses match. A resolved row with no required options qualifies. Resolution also requires parse success. Use the total selected IDs for each denominator, never just the previous stage's passes. Deduplicate shared name/form witnesses across rows only when their setup is identical. Keep run independent under decision 1. This measures form support without guessing from an exit of 2 or changing production dispatch.
4. **Pin and enumerate the complete Oils comparison.** Add the manual command `uv run python scripts/shell_oils.py --oils ../oils`. Require the clean sibling checkout at the full object ID resolved from the study's `d114978ca467` and commit that full ID in the measurement manifest. Reject an ambiguous abbreviation, changed checkout, untracked suite inputs or unknown assertion syntax before publishing. Use the pin's `test/sh_spec.py` case parsing and assertion semantics. Select every case in every `spec/*.test.sh` whose `compare_shells` includes Bash. Identify a case by relative file and zero-based case ordinal at that pin. A small reviewed manifest may exclude only requirements outside the declared noninteractive vfs surface, with an explicit reason per ID. An unimplemented admitted construct, missing vfs program promised by the surface, missing vfs helper or vfs budget end stays a miss. No keyword skip list or exclusion based on the vfs answer. Reconcile the selected total as scope exclusions + in-scope Bash baseline failures + eligible cases. Fail the measurement on missing files, duplicate IDs, an incomplete traversal or empty denominator.
5. **Score what the upstream Bash assertions actually say.** On the pinned recorder image, run each in-scope case as an unprivileged Bash process with the Oils stdin invocation and helper environment (`SH`, `TMP`, `REPO_ROOT`, the pinned helper path and locale), in a fresh disposable directory. Mount suite inputs read-only. Pass the identical source and logical paths to a fresh reference host with its normal programs and budgets, empty work directory, no inherited user files and no native command fallback. Give helper files the same visible paths on both sides. Score the actual shell behavior for a helper it cannot execute. Follow upstream generic assertions with Bash-specific overrides, including `OK`, `N-I` and `BUG`, default status 0 and stderr only as asserted. Compare exact status and asserted raw bytes, including final newlines, before any UTF-8 replacement. A shell syntax error may satisfy an expected syntax failure. A crash or resource termination cannot satisfy a matching numeric status. Check the reference command, suite reader and helper paths before starting any case. A case that the reference Bash fails stays visible with its ID and reason outside the eligible denominator. A failed runner setup or missing reference prerequisite aborts publication rather than removing a whole class of tests. Report eligible cases whose full source parses and eligible cases passing the assertions as two independent fractions over that same denominator. The Oils rate has no floor. This follows [the suite study](../2026-11-21-the-shell-speaks-bash/research-bash-suites.md), sections R5.1 and R5.5, and F2 criterion 1.
6. **Publish reproducible numbers from one completed run.** Keep a small dated `tests/shell/coverage.json` report with vfs revision measured, full Oils pin, image digest and Bash version, host, SHA-256 hashes of both scope manifests, counts and IDs/reasons for exclusions and misses. Keep upstream scripts and expected outputs in the external checkout only. Provide an explicit `--write-report` on the manual command to run both measurements and replace the report atomically after all checks pass. Normal runs print results. Render an adjacent two-row README table from the report with the two labels, numerator/denominator and percentage to one decimal place. Link the reference for the scopes, probe definitions, local recorded score, Oils parse fraction, pinned revisions and reproduction command. Check the generated text offline from the committed report. A new measured revision or scope change gets a new full run before the numbers change. A missing checkout, a stale scope or a partial run never publishes a placeholder, a competitor's rate or the prior study's sample.
7. **Qualify the three new exit rows by producer and availability.** Add 75 for H5's suspended host-tool stage with its ask as evidence, 123 for `xargs` aggregating an ordinary child failure, and 134 for another guest runtime trap after the guest's deadline and budget cases have been handled. Until the corresponding producer exists, mark the entry as planned and name its owner. Decision 22 of the interrupted-line draft still governs the outer result. An internal trap of the shell's own module currently maps to 1 (`crates/vfs-core/src/shell_binding.rs:552`). Preserve the generic program-status row and make the overlap explicit. Native reference-host probes `exit 75`, `exit 123` and `exit 134` completed normally with those statuses. GNU `xargs false` on one input exited 123. The host's `EX_TEMPFAIL` was 75 and `128 + SIGABRT` was 134. None of those observations establishes that a vfs stage suspended or a guest trapped.

## Cost

This is offline work per published measurement. For W weighted rows, P distinct probes with their setup, S selected Oils cases and E eligible cases, the added work is one weighted parse and run per ID, at most P witness runs, at most S reference Bash runs, E parser checks and E shell runs. Read one case at a time. Keep fixed counters, the manifest and one bounded verdict per ID. Keep only IDs and classifications across cases. Discard raw streams after comparison. Use the recorder's named `CASE_TIMEOUT_SECONDS` and `BATCH_TIMEOUT_SECONDS` for workers and batches (`scripts/shell_record.py:32`), ordinary `ParseLimits` and machine limits per script, and enforce the machine's output budget on captured external streams. Kill and reap the case worker on a case limit. A shell limit is a measured miss, while an incomplete measurement batch fails without replacing the report. The normal gate needs only the committed local data. Per 10 million production files and 150,000 daily calls (`AGENTS.md:74`, `:82`), the added rows, statements, binds, locks and requests are zero on SQLite, Postgres and the generic floor.

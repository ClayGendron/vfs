# A keyed mutation commits its answer with its change and a resend gets that answer back

A draft, written on 2026-11-25. It is not reviewed, and nothing is built. Checked against `dev` at `27f3d24d` for story K5, gate b, unit 177-3, from [the archived replay specification](../../context/specifications/archive/177-replay-the-contract-and-the-request-key/spec.md), sections 3 and 4. It rests on the grant fence, the decision on kernel records and the commit-in-doubt conversion.

## The outcome wanted

A caller that loses the reply to a move resends the same move with the same key to the same storage. Within the retention window it gets the original destination row, version and warnings, even if another call has since moved the file again. Exactly one `vfs.replayed` information record identifies a replayed mount answer. The resend reads the saved answer once and issues zero mutation statements. If the first transaction rolled back, the resend makes the move once. The key proves what happened to this call. A job waiting for approval continues through `resume`.

## What the code does today

The writer commits only a successful result, after the fenced body. SQLite starts its writer with `BEGIN IMMEDIATE`. A public writer can append advisories after the commit. A grant's `granted_at` is a Python datetime inside the open `grants` extra. A posture row commits before the bounded relabel transactions whose counts are returned. See `src/vfs/storage/backends/database/backend.py:1291`, `:1317`, `:1380` and `:1465`, `engine.py:489` and `:981`, `rights.py:1484`, and `authorized.py:218`.

Executed on the in-memory storage at this tree: after a one-file write, each of two `set_posture` calls on the root reported two rewritten rows, two statements and one relabel transaction. For both answers and for a `grant` answer, decoding `model_dump_json(exclude_none=True)` with `Result.model_validate_json` gave an unequal result. The grant timestamp became a string. The result codec and the treatment of the twelfth verb therefore cannot be copied verbatim from the archive.

## The problem

After a lost move reply the namespace alone cannot identify the call that made the move. After a lost append reply, repeating the append can duplicate data. At the reference deployment the nightly million file writes arrive in 100 batches. A process-local cache vanishes on restart, and storing one receipt for each file would turn 100 acknowledgments into a million. A claim in a second database can survive a crash with no evidence of whether the mount committed. None can return the exact answer that the caller missed.

## Decisions

1. **Decided 2026-11-25: the answer belongs to the mount that owns the mutation.** Its unique claim, successful side effects and answer pages share the mount session and commit. A persistent mount can reproduce the answer after closing and reopening. An in-memory mount keeps it for the lifetime of its database. Each distinct backing database and schema owns its slice, keyed in storage-local coordinates. Two bindings of the same physical tables share the namespace for keys: identical local slices replay and different ones refuse. A restart between mounts can therefore replay a committed slice and run a missing one. No mount claims a different mount's result. This follows the storage seam's existing transaction boundary (`src/vfs/storage/protocol.py:35`) and preserves kernel-records decision 10. A kernel claim followed by a mount commit followed by a lost completion could never distinguish a completed append from one still to run. Kernel jobs and the action log retain their own transaction discipline.

2. **A storage declares the guarantee it can supply.** Add `replay: keyed` to the trait vocabulary (`src/vfs/storage/protocol.py:78`) and declare it on the SQLite and Postgres database profiles, including the in-memory SQLite subclass. Keep the untested generic floor's keyless core verbs and withhold the trait there, following the measured-profile check in `backend.py:240`. A direct keyed call checks the capability before SQL. The protocol and concrete storage accept keyword-only `request_key: str | None = None` on `write`, `edit`, `mkdir`, `delete`, `restore`, `copy`, `move`, `mkedge`, `rmedge`, `grant` and `revoke`. Decision 11 governs `set_posture`, the twelfth name in the source after the public-name correction. Maintenance, `destroy` and the two membership writes take no key. The absence of a key bypasses key validation, hashing, answer storage and lookup.

3. **The request id identifies one caller's key and the fingerprint identifies one effective call.** Reject a non-string, empty or overlong key, or any character outside ASCII `!` through `~`, as `vfs.invalid` before SQL. Declare `MAX_REQUEST_KEY_LENGTH = 255`, the identifier width at `src/vfs/models/rows.py:142`, shared with 177-4. Refuse anonymous with the same kind before lookup, because unrelated anonymous callers share an identity. A direct storage call with no authority uses the system actor (`backend.py:1179`), while routing supplies the authority it resolved. Hash a versioned domain tag `vfs.replay.1`, actor, ordered subjects, narrowing and the opaque key with SHA-256. Frame each field with its UTF-8 byte length as an unsigned four-byte big-endian integer. Frame principal kind, sub and sorted scopes separately, prefix sequences with their count, and sort subjects by the full principal tuple. Proof provenance and source identity describe how this caller arrived and do not split its receipt. Persist only the digest of the key. A change of actor, subjects, scopes or narrowing has an independent key space. A rights change outside the authority does not re-judge the original receipt. Today's router gates still precede dispatch, and every miss passes the current row gate and commit fence.

4. **Fingerprint effective arguments after normalization and body measurement, before opening the writer.** Feed a SHA-256 object the framed domain `vfs.call.1`, verb and named storage arguments in sorted name order, defaults included, excluding authority and key. Use distinct type tags for absent, boolean, integer, binary64 float (network byte order), string and path. Count and preserve sequence order, and sort maps by normalized key. An entry contributes path, kind, source, measured content hash, MIME type and requested owner, the inputs consumed in `writes.py:209`; omit generated timestamps and derived metrics. An address observation contributes its path. Encode an edit's old text, new text and replace-all flag, a pair's two ordered endpoints, and an edge's source, target, edge type, weight and distance. Include the edge provenance argument, version mappings, creation flags, append flag, grant principal and level, and all other effective verb arguments. A newly supported condition such as a vid must enter the versioned encoder before keyed calls accept it. Reject reuse for a different verb or fingerprint with one `vfs.invalid`, no path or data and no identifying value in the detail. Two calls that differ only in generated timestamps or map insertion order are the same call.

5. **Two private mount tables hold the head and the ordered pages.** Extend `VFSTables` and `build_vfs_tables` (`src/vfs/models/rows.py:279`, `:327`). Create `vfs_replays(request_id, answer_id, op, fingerprint, actor_id, created_at, expires_at)` and `vfs_replay_pages(answer_id, page, expires_at, payload)`. The head primary key and fingerprint are 64-character digest strings. Each successful generation has a fresh `ULIDKey` answer id. Use a unique head constraint on that id, a composite page primary key `(answer_id, page)`, non-null integer page numbers from zero, `String(16)` for the verb, `String(MAX_PRINCIPAL_ID_LENGTH)` for the actor, `_timestamp()` for UTC times and `_body_bytes()` for payloads. Index heads by `(expires_at, request_id)` and pages by `(expires_at, answer_id, page)`. All fields are non-null. Pages live until their own expiry and have no cascading foreign key. Reusing one expired key therefore never deletes an unbounded previous answer under the claim lock. Take the next `SCHEMA_FORMAT_VERSION` at landing (28 on this dev), provision fresh mounts by normal first touch and retain the existing `vfs.unavailable.schema` refusal for an older format. No kernel table or kernel format changes.

6. **One read-only lookup settles a live key.** Each retry attempt opens an ordinary snapshot, selects the head by request id and left joins that generation's pages, ordered by page. Bind one UTC reading per attempt, join pages only for a live matching fingerprint and verb, and close the read session before opening any writer. A live mismatch returns decision 4's refusal. A live match verifies and decodes the pages, then returns. A missing page is damage even when it is the only page. The lookup skips the mutation body, gate, statistics, advisory drain and commit. This ordering gives a file-backed SQLite hit a reader's `BEGIN`, so a committed answer can be read beside an unrelated writer. The archive's lookup inside `BEGIN IMMEDIATE` would make the same hit queue for the sole writer.

7. **A conditional claim makes the gap between the read and the write safe.** After a miss, use the normal writer session and its existing isolation for the verb. Insert the head first. After reading an expired head, replace it with an update conditional on the observed request id, answer id and expiry, assigning a fresh generation and timestamps. The only unique violation treated as a competing key is on the request-id claim; an unrelated constraint failure keeps its classification. Use the profile's targeted insert with conflict on the request id and test its affected count, so a unique failure on the answer id never looks like a duplicate send. A lost replacement race or a request-id collision discards the whole writer and restarts at the read in a fresh snapshot, with the existing bounded `with_retry` policy (`engine.py:336`, `dialects.py:777`). On exhaustion return the existing retryable conflict. A denial or failed result rolls the claim and all changes back; a later corrected call can use the key. On success, write all pages before the existing final rights, posture and topology proofs, so packing a large answer does not lengthen those shared locks. Failed proofs roll the pages back too. Use the normal commit guard. A lost commit has the 177-2 kind and `refresh` class and is never retried inside the failed call. Set its `retryable` only for a keyed writer with time left on its receipt; replay safety requires resending the original call inside that window. A lost reply after commit hits, and one before commit misses.

8. **Store the entire successful storage result as a versioned, lossless value.** Preserve ops, ordered observations including the populated mask, errors, severity, data, extras, nulls and cursor. Keep the timestamp type in a grant extra: encode the ordinary unabridged result JSON together with a version and a side list of typed locations for native datetimes in untyped extra/data values, with typed path segments for map keys and array offsets. Restore these locations before final model validation. The shipped keyed extras use JSON values and these datetimes. A producer adding another non-JSON type must extend the codec and its round-trip test in that landing. Do not call the lenient quarantine reader or a renderer. Compress with zlib level 1. Slice the compressed byte stream into pieces of at most `BLOB_PAGE_BYTES` (`dialects.py:81`), one insert per piece. Use a backend worker through `call_offloaded` (`src/vfs/offload.py:153`) for the dump and pack and for the decode and parse. Verify contiguous page ordinals from zero, exactly one complete stream including its checksum, no trailing bytes, a supported version and a validated successful envelope for the expected verb. Missing, damaged or undecodable content yields one `vfs.internal` with a path-free detail, zero mutation statements and no fall-through to the verb. An encoding failure before commit rolls back the change.

9. **A hit copies the stored result and appends exactly one marker.** Use `classified(ErrorKind.replayed, severity=Severity.info, data=...)`, the phrase “Replayed”, retry class `never`, `retryable=False`, and no local path or source. Its two producer fields `first_at` and `expires_at` are UTC ISO 8601 strings from the stored head. The bare keys follow the vocabulary at `src/vfs/results/kinds.py:52`. The ordinary rebase provides the mount as source. The record survives merge and severity keeps the result successful (`src/vfs/results/envelope.py:148`, `:565`). Store only the unmarked answer. Include held host advisories in the original successful keyed answer before encoding: reserve them once for that attempt, restore the reservation on known rollback or cancellation before commit, and keep later arrivals for the next newly executed public call. On an ambiguous commit return the reservation to the host for delivery if necessary; a later advisory may repeat, but the durable answer is never edited. The public runner then appends what the host holds to the in-doubt answer it returns, as it does for a keyless call (unit 177-2's decision 9), so the advisory is delivered once on that answer and again inside the stored answer a later hit returns. Never append newly arrived advisories on a hit. This moves delivery for keyed successes ahead of serialization and leaves keyless delivery as it stands.

10. **Expiry is per storage, and reclaim is a bounded part of the retention pass.** Add keyword-only `replay_hours: int = 24` to `DatabaseStorage` and pass it through the explicit constructors of `SQLiteStorage`, `PostgresStorage` and `InMemoryStorage`. Reject a non-integer, a boolean, a negative value or an interval outside the representable UTC datetime range at construction with `ValueError`. A replaceable private UTC clock supplies the claim's `created_at` and expiry (claim time plus the configured hours), the lookup cutoff and the pass cutoff. Normalize SQLite's returned naive timestamps as UTC. Equality with expiry is a miss. Zero gives no replay window and no retryable in-doubt promise. After a successfully authorized `destroy` of the trash head, reclaim expired pages and expired heads for this mount using one fixed cutoff and two ordered phases, each in point-key windows of at most the host's `membership_budget` and each window in its own short writer transaction. For each phase delete keys from an indexed ordered limited subquery, repeating the expiry predicate on the outer delete so a concurrent renewal is safe. A partial pass leaves only expired garbage and its next call starts afresh. Return `replays_reclaimed`, the number of deleted heads, counting only committed chunks; propagate a later chunk failure with that partial count. A targeted destroy or refused retention pass does no replay reclaim. Where unit 180-4 is built the retention pass is a loop of slices, and this reclaim is called from its `run_retention` after the last of its four phases has committed (that unit's decision 26): a pass that a refusal, a failure or a commit in doubt ended early reclaims no replay row, the two phases here are not names of that unit's `RETENTION_PHASES`, and under unit 180-5 an unfinished page reclaims none. This follows kernel-records decisions 17 and 18 in the mount's own tables. It replaces K5 criterion 5's two unbounded deletes and the archive's potentially unbounded deletion of all pages on one expired-key replacement.

11. **A returned posture result cannot be stored by the single-transaction algorithm.** The source proposes keeping the posture-row result and calling `_settled` on each hit. On dev the returned `relabel` count is first known after other transactions run (`backend.py:1317`, `labels.py:369`). It can be nonzero on first delivery and zero on a resend, and a resend can change other pending labels. Neither outcome meets this contract. The eleven single-transaction verbs and the reclaim arm may land independently. Publicly promising the twelfth verb waits for the ruling under Choices to confirm. A partial posture receipt must never be advertised as an exact answer.

## Cost

For a warmed mount let P be the ceiling of compressed answer bytes divided by `BLOB_PAGE_BYTES`, at least one. A keyless write adds zero statements. A successful keyed miss adds one read-only select, one insert or guarded replacement and P inserts, no additional write commit. A hit adds one indexed select yielding P rows and zero writes. A mismatch reads one head. Competing claims pay these costs per attempt up to the host retry budget. SQLite's landed one-file create is eight non-control, non-statistics statements and its one-edit case is seven (`tests/storage/database/test_writes.py:139`, `:234`). A one-page keyed create is eleven. A corrupt hit costs only its lookup.

At the reference centre of 50,000 individual writes and 100 nightly batches, keying all of them makes 50,100 heads per day, 100,100 at the design ceiling. With one-page answers the added statements are 150,300 and 300,300 respectively. Each additional packed page adds one. Processing 10,000 entries adds a linear fingerprint walk and one answer-sized pack; the hit reconstructs 10,000 observations without reading the entries. Two codec hops across a miss and its replay. Fingerprinting uses one digest with space for the current framed value, plus sorted subjects and argument-map keys. Temporary codec memory is proportional to that call's answer, including the raw and compressed forms, plus the existing batch; statement payload is at most one blob page. Stored bytes are the sum of packed answers plus indexed headers and page overhead. Expiry bounds the live window; physical storage is returned only when retention runs.

For E expired pages and H expired heads, at budget B, a noncontended complete reclaim takes at most `ceil(E/B) + ceil(H/B) + 2` delete statements with a final empty probe per phase. The indexed subquery binds a cutoff and a limit; a composite page key stays in SQL. SQLite and Postgres each use the host budget derived by `dialects.py:541`. Neither answer size nor corpus size expands a bind list. A claim locks only that caller's request id before the body. Competing Postgres sends on the same id can wait for that logical call; unrelated keys need no common replay lock. The SQLite file retains its ordinary single-writer contention and readers use snapshot connections. The private in-memory single connection retains its existing serialization. Rights and topology locks remain at the commit fence where that fence is required. No read, rebuild or index visit adds a replay statement.

## Choices to confirm

- **The twelfth verb.** One option keeps exact replay on the eleven one-transaction verbs and removes `set_posture` from the public keyed set. Another keeps twelve by making posture a resumable receipt: claim with the posture change, checkpoint its counters with every relabel chunk, finish the full answer before first delivery, and explicitly allow a resend of unfinished work to run further chunks. That changes the promise for an unfinished keyed mutation and needs a failure and takeover contract. Returning the grant-row answer alone would change today's successful result. No side is taken: the build of keyed `set_posture` and the twelve-verb public promise wait for this ruling. Withholding posture meanwhile is additive. Once shipped, an exception to the zero-write resend promise or a persisted, recoverable posture protocol would both bind callers.
- **The generic floor.** Withhold the replay trait until an additional dialect can pass the concurrency and recovery contract. The alternative is to advertise it from the plain SQL shape alone. Adding a proven profile is reversible before it is advertised; withdrawing an advertised replay promise after a lost response is not.
- **The marker's field names.** Take unprefixed `first_at` and `expires_at` under the producer-key rule. The archive used `vfs.first_at` and `vfs.expires_at`; prefixed aliases could be added without changing a stored answer, since the marker is created on lookup.
- **Small-answer codec work.** Take one worker hop in either direction, including for a one-row answer. The source offloads only large JSON, but measuring JSON exactly by dumping it on the loop pays the work the threshold was meant to move. A bounded small-answer fast path can be added after measurement without changing a stored byte or a caller's answer.

## One line

A mount that commits a keyed change keeps its complete answer in the same commit, so a caller that loses the reply can recover it with a single read.

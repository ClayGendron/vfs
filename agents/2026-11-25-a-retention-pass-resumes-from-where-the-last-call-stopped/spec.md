# A retention pass resumes from where the last call stopped

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. This is unit 180-5 at gate 0.2. [The roadmap](../../context/standards/roadmap.md) assigns bounded retention to that gate without a named story (line 1181). It converts [numbered spec 180](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/spec.md), sections 5.1 and 5.4 and criteria 14, 16 and 20, and [task 6](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/tasks.md). It rests on the deletes spec, the bounded slices of unit 180-4 and the choice of who calls retention.

## The outcome wanted

With 250 expired single-file roots, a deployment calling `destroy(limit=100)` at the trash head receives 100 destroyed roots. Sending the returned key as `after=` processes the next 100. The following call destroys the last 50 and can spend its remaining allowance examining body keys. A page can have zero observations and still have a continuation. The caller stops on a successful page with no key. An unpaged call still finishes the walk in one call. If a rebuild or a job owns the walk, its driver can make the same bounded steps with a private position.

## The problem

On `dev`, `sweep` has no page arguments on the router or the storage seam (`src/vfs/base.py:1130-1152`, `src/vfs/storage/protocol.py:230`). After 180-4, short transactions will release the writer between slices, but a call can still inspect the whole mount and accumulate the whole answer. On a ten-million-file mount, restarting at the first body key every time a bounded call returns would inspect the same live bodies indefinitely. Destroyed roots leave the work list by themselves. An examined live body stays on it.

## Decisions

1. **One allowance spans all phases.** Extend 180-4's private `run_retention` to accept an optional position and optional positive work allowance. Before each slice take `min(remaining, B)`, where B is the host's `membership_budget`; an unlimited call uses B. A committed slice returns its actual unit count alongside the existing answer and mark. Debit only committed roots or distinct family keys examined, including live or young keys yielding no warning. A lookahead key, an empty phase and a redriven attempt consume zero. This preserves the accounting of 180-4 decisions 3, 7 and 8 when the allowance crosses a transaction or phase boundary.

2. **The returned position identifies the next work.** Start at `roots` with no key. While more roots exist, repeat that mark and seek the remaining roots. In an orphan phase resume strictly after the last key examined, including a key whose row has since disappeared. On exhausting a phase advance to the next phase with no key, even when the allowance has just reached zero. On exhausting `versions`, return no position. Stop at zero without probing later phases, so a returned position may lead to an empty final page. Decisions 5–7 and 10 of 180-4 supply that progress rule without an offset or an extra existence query.

3. **Carry the first pass's instant across calls.** The position pairs the 180-4 mark with its original UTC instant, mount identity and original root cutoff. Use that instant for the orphan age fence. If a resumed mount has lengthened retention, use the earlier of the saved cutoff and the cutoff its current policy permits at the original instant. A shorter policy never advances this pass's cutoff. Fresh calls without a position take a new instant. This extends 180-4 decision 9 over all pages without holding a snapshot. A newly inserted key behind the mark waits for the next walk. Restores, concurrent destroy calls and vanished cursor rows are resolved by the existing slice checks. Convergence counts assume a quiescent corpus.

4. **Keep the private step independent of its caller.** If a rebuild or job is selected, its driver keeps the last committed position in its own pass state and uses the same allowance on the next invocation. Save a checkpoint only after the slice commits. On loss of an unsaved checkpoint, resume from the last saved one, or restart if none survives. Repeated examination is safe. The owning work specifies where its run state survives a restart and when to schedule a new pass. This arm adds no public parameter, result field or secret. If the deployment remains the caller, decisions 5–7 provide the external adapter. Neither arm authorizes an unattended destroy.

5. **The public adapter takes two nullable keyword-only arguments on the retention arm.** After the deletes rename, add `limit: int | None = None` and `after: str | None = None` on the four faces, the mutation seam, the database backend and the `destroy` row of `PARAMS`. The router and storage apply the same positive, non-boolean `1..INT_CEILING` domain as existing page sizes (`src/vfs/params.py:63,144-147,659-666`), with units in the parameter description. `after` is a string, never a path. With only `after`, drain the remainder. A non-null page argument on any address other than the resolved mount's own `/.vfs/trash` returns `vfs.invalid` naming the trash head before a mutation. This includes the lawful single-set arm. The existing busy, mount and authority gates still apply. As for the listing trait at `src/vfs/cursor.py:128-131`, a backend declares support explicitly, here by the proposed `retention_cursor: bounded` trait. A bounded request to a backend without it returns `vfs.unsupported` without calling its destructive method. Send neither keyword on unpaged calls to legacy storages. Truncating the answer of an unbounded mutation cannot bound the mutation.

6. **A public position is an opaque key for one durable mount.** The database backend alone seals and opens it. A live body-key window can finish at an entry the caller may never inspect. Plain base64 of the mark would expose that entry's identifier. Use the library Fernet authenticated-encryption format from a direct `cryptography` dependency. Prefix the token with `ret1.`. The fixed-width plaintext, in order, is the mount ULID (16 bytes), a phase byte (0–3 in 180-4 order), a presence byte (0 or 1), the 16-byte last ULID (zero-filled when absent) and two signed 64-bit big-endian UTC microsecond counts since the Unix epoch (instant and cutoff). Reject a positioned root, invalid flags or padding, impossible dates, a cutoff later than the instant, an unrecognized version, a foreign mount or failed authentication as one `vfs.invalid` at the local head without echoing the token. Check the exact encoded length derived from that fixed record and format before decoding. No expiry is needed: a lost position can always be replaced by a new pass. Bind to the durable `vfs_meta.mount_identity`, established at first touch (`src/vfs/models/rows.py:604`, `src/vfs/storage/backends/database/engine.py:671,945`). Aliases of the same store and a new process can continue. Each invocation independently judges its current caller. No token grants a right.

   Generate a separate Fernet key once per mount with `Fernet.generate_key()`. Keep it in a private, non-null binary `vfs_meta.retention_secret` column. Include its initialization in the existing metadata insert. Read it once per host after the schema-format check, so an older store still receives the established schema refusal (`src/vfs/storage/backends/database/engine.py:625-633,668-676,922-929`). Advance the format from the then-current version and populate one fresh secret per mount in the predecessor-format upgrade, preserving existing rows. A fresh first-touch race adopts the winning row's secret. Keep the secret out of results, diagnostics and query-parameter logging. No per-page checkpoint row or per-page lookup is needed.

7. **Return the key as `Result.retention_after: str | None = None`.** Emit it on a successful, unfinished external call only. A zero-row success can carry it. Preserve it byte for byte on `model_copy`, enrichment, error rollup and either mount rebase, where normal row and error paths still rebase. Clear it on result set operations and all merges because these lose the identity of a single call. Keep the field on a payload round trip, omit it when null under the existing default, accept an older envelope without it, and render the existing `more: after=<key>` line when present. These rules follow `src/vfs/results/envelope.py:524-565,622-637,678-747` and `src/vfs/results/render.py:72`; a mount prefix can never be added to the token. A listing continues to use its own field.

8. **Only a successful final page finishes retention.** A refusal or failure returns the committed observations and warnings plus the classified failure under 180-4 decision 14, with no continuation. A cancellation propagates. A caller that lost a reply can retry with its last input key or start again. A retry may examine live keys again and cannot undo or report a destroyed root twice. There is no exactly-once page delivery. On the kernel-records branch require a successful, exhausted, explicitly requested root retention pass before running the store's pass. A successful intermediate page, failed page, child mount or internal rebuild step starts zero store passes. A new explicit completed pass can run the store again, as kernel-records decision 17 requires.

## Cost

At the reference deployment (`AGENTS.md:74,87,94-101`), a pass across 10,000,000 distinct body keys at a caller-chosen limit of 1,000 needs 10,000 calls for that work. Roots and distinct versioned entries add their own units. One page holds at most L destroyed observations plus reclaim warnings combined, apart from ordinary advisories and errors. SQL selects at most `min(B, remaining) + 1` *keys* per slice. The purge of one directory can still visit every descendant, and distinct version keys can span many physical versions. These are the costs of 180-4 decisions 8 and 10. With four phases a successful bounded call has at most `ceil(L/B) + 3` slice transactions including empty phase transitions, before redrives. B comes from the engine's declared membership and bind budgets (`src/vfs/storage/backends/database/dialects.py:541-548`), including on SQLite, Postgres and the lower generic floor.

The public adapter adds at most one open and one seal of a fixed-length record per external page, one constant-size secret per mount and one extra metadata read per host initialization. A private continuation needs only one position. Neither adds a statement to a slice, work to an ordinary file write or index visit, nor a lock across calls. SQLite gives up its writer between slice transactions. The Postgres serialization point and the time it is held remain 180-4 decision 4's until the topology-lock change lands. Readers acquire no new lock.

## What the docs must say

The retention docstring gives a loop that checks `result.success` before reading `result.retention_after`, saves the opaque string unchanged and stops on `None`. It states the unit, the possible empty page, the one-large-directory cost, whole-call default, and the restart from a previous input after a lost reply. The internal driver's docstring states the same work and failure rules if that caller is chosen.

## Choices to confirm

1. **Who owns the position?** Build the private bounded step first. The external adapter waits for the caller ruling on the deletes branch. If explicit calls by the deployment own retention, build the public adapter. If the rebuild or a job owns it, build only the internal driver. Selecting an unattended caller can irreversibly remove data in deployments that currently never ask for retention. That selection has no reversible default.
2. **Which public field and representation, if needed?** Take the additive `Result.retention_after` and a backend-sealed mount-bound mark. The alternative is a random handle to a persisted position per pass, which needs a write path and cleanup of abandoned positions. The sealed representation costs one secret per mount, keeps unseen row identifiers private and leaves the wire format replaceable by version.

## One line

A single allowance covers the roots destroyed and the body keys examined, and the next call continues from the last committed position.

# A registered host tool has a manual in `/.vfs/bin` and runs by name through the caller's `run` verb

A draft, written on 2026-11-25. It is not reviewed, and nothing in this unit is built. Checked against `dev` at `27f3d24d` for [roadmap story T3, gate b](../../context/standards/roadmap.md). Converted from [170, sections 1, 2, 5 and 6](../../context/specifications/archive/170-tools-and-mcp-servers-as-views/spec.md) against [the reassessment of 170-2](../2026-11-25-the-backlog-converted/reassessment/views-and-tools.md). It rests on the served program directory, the root binding's rights check, the shell host, the policy step and the interruptible job.

## The outcome wanted

A host adds an async function called `word_count` once. A caller with read access can inspect `/.vfs/bin/word_count`, run `word_count 'two words'`, or pipe the same text to it. Each command prints `2` followed by a newline. Python can call `run("/.vfs/bin/word_count", arguments={"text": "two words"})` on the same session. Each execution calls the same function once, subject to the same rights and policy. Reading its manual, asking for help or looking for it calls the function zero times.

## What the code does today

`run` belongs to `EXEC_OPS` and needs `read` (`src/vfs/ops.py:89`, `:173`). Its argument table has `path`, `arguments` and `authority` (`src/vfs/params.py:390`). The four faces delegate to the same router (`src/vfs/base.py:1679`, `src/vfs/session.py:419`, `src/vfs/sync.py:589`, `src/vfs/sync_session.py:361`). A capable storage may serve a mount-local call through `SupportsRun` (`src/vfs/storage/protocol.py:390`, `src/vfs/base.py:2949`). The shell starts registered *shipped* programs through its own table and its feed handler drains output prepared at start (`src/vfs/shell/host.py:439–469`). The published [job guide](../../documentation/how-to/interrupt-a-job-and-ask-a-person.md) at lines 341–361, 401–413 and 505 describes host tools ahead of the implementation.

Executed through the dev router on in-memory SQLite and disposable Postgres: for a named caller, `run("/.vfs/bin/paint", arguments={"x": 1})` was `vfs.unsupported`; a system `stat` there was `vfs.not_found`. With the path still absent, setting the parent posture successively to `none`, `list` and `read` gave (list held, read held) of (false, false), (true, false) and (true, true) via the storage's actual `holds`. Mounting the existing `RunnerStorage` double at `/legacy` and running `/legacy/paint` recorded exactly one call at `/paint` with the original argument object on both engines.

## The problem

A function unique to one host process needs an address whose grants are meaningful across callers. A stored manifest can outlive that function or be discovered on a different host. An independent shell runner can bypass policy, misbind pipeline input or disclose a hidden schema in a usage error. At 10,000 registered tools and 150,000 verb calls a day, discovery cannot call a function, read all its manuals for a name lookup or issue one rights query per name.

## Decisions

1. **Decided 2026-11-25: host registration publishes a validated descriptor.** Export `tool`, `Tool` and `ToolError` from `vfs`. Bare `@tool` and `@tool(name=..., description=..., schema=..., stdin=..., approval=..., mime_type=..., deadline=..., capabilities=...)` return a frozen descriptor. Defaults are the function name, the first nonblank docstring line or empty text, a schema inferred from annotations, no pinned input, no approval, `application/octet-stream` for bytes, the host deadline and no declared capabilities. Both router constructors accept `tools=()`; both routers have plain, synchronous, host-only `add_tool(tool)` and `remove_tool(name)`, returning `None`. Both are defined with the mount administration of `src/vfs/base.py` and `src/vfs/sync.py`, before the first verb (unit 181-1's decision 16); being plain methods they are in no group and join no set of `vfs.ops`. Accept a decorated value, a plain annotated coroutine function through the same decorator, or the T3 adapter shape: name, description, Pydantic `args_schema` model and async `ainvoke(arguments)`. Support a JSON Schema object on that adapter under decision 3. Inspect the callable without invoking it. Reject sync bodies, async generators, missing parameter hints, positional-only parameters, variadic signatures and ambiguous injection with `TypeError`. No import of LangChain or MCP, host callback on a session, or public method for invoking an installed descriptor outside the router. This follows the overview's async ruling and T3's dependency-free shape.

2. **Publish each name once, atomically.** Accept case-sensitive single ASCII command names matching `[A-Za-z_][A-Za-z0-9_-]*` and the ordinary path segment limit. Reject bad names, collisions with another tool, shipped program, shell builtin, reserved word, permanent refusal or static shorthand with `ValueError` at registration. Derive occupancy from the actual program, builtin and parser tables, including implementations running in the machine (`crates/vfs-shell/src/machine/builtins.rs:21`, `exec.rs:1083`). Shell functions and ordinary files on a caller's PATH still obey T1 precedence. Validate a constructor batch before publishing it. A duplicate, even of the same object, fails the whole batch. Removal of an absent name raises `ValueError`. Removal makes it available to a new registration and has no effect on a body already entered. Publish the name map and sorted names as one snapshot. Serialize writers for the compare-and-publish operation so two concurrent registrations cannot lose an entry. Recheck descriptor identity after any awaited policy or approval before entering the body. An uninstalled descriptor cannot silently turn into its replacement. An identical spelling on another router is independent. This follows the interrupt draft's decision 5 and policy decision 9.

3. **Compile the signature and one UTF-8 manual at registration.** Use the installed Pydantic model facilities for typed parameters, retaining declaration order, required properties, defaults, documented constraints, nested model instances and the declared return schema where expressible. Optionality of a type permits null; only a Python default makes omission lawful. Treat a Python `bytes` parameter as a JSON string with `contentEncoding: base64` and decode it exactly once for the function. Exclude the injected parameter from all published forms and reject any supplied value for it. An explicit decorator schema can be a Pydantic model or a JSON Schema 2020-12 object whose exposed names bind to the signature, with every required function argument represented. Refuse mismatches at decoration. For a schema-only adapter accept a JSON Schema 2020-12 object, validate the schema once and the complete JSON instance before invocation with the core `jsonschema` validator (new core dependency for this case). Resolve only document-local references, never load a URL or host file. Reject a missing reference or invalid host configuration at registration with `ValueError`. A descriptor's manual contains the exact name, host provenance, first-line description, usage, one row per property (name, type, required or default, enum and description), input schema and return schema when known. Its trust line reads “runs on the host, with the host's authority (network: yes|no)” according to declared `network` membership. Capabilities are host declarations, not enforcement of network access. End with one newline and serve identical bytes to `read` and sole `--help`; help requires read access, enters no body and asks no run approval. T1 decision 10 keeps `type name` as the path report; the manual carries the trust statement. No registration stores a row.

4. **Keep `run` as the single public execution door under D63 and adopt D64's shared address.** Add keyword-only `stdin: bytes | None = None` to the existing four `run` faces and the bytes argument to the parameter table or its `RunStep` owner. `None` means unconnected and `b""` means connected and empty. `arguments=None` means an empty object. The Python verb takes the normalized file path, including ordinary root-relative normalization; name search belongs to the shell. A tool lookup yields its served path at `/.vfs/bin/<name>`; bare and slash command words use that same path. No tool is exposed under `/.vfs/tools`. A shipped manual passed to `run` is unsupported (126); the shell dispatches its shipped implementation through T1. On addresses outside the served directory preserve existing capability checks, local coordinate rebasing and `SupportsRun` calls when stdin is absent. A connected stdin there is `vfs.unsupported` at the capability gate: the existing storage protocol has no stdin slot. Never forward an unexpected keyword to a third-party storage. This keeps the working mount path proved above.

5. **Admit a tool before interpreting its schema or judging its run.** Keep public argument types, closed-state, caller and hop checks. For the global served path use the router's catalogue capability and respect the root's explicit `deny_ops` for `run` even though the underlying storage need not advertise execution. Report the served run capability independently of whether a caller can see a particular tool. Ask the actual root binding for the requested path even on a miss. Use T1 decision 4 and batch-rights decisions 1–4 unchanged. A missing or hidden name gives the same `vfs.not_found` (127); a listed tool below read gives `vfs.permission_denied` (126). An unavailable or failed proof gives its classified refusal and no tool data, usage, callbacks or invocation. A successful read proof precedes all tool-specific diagnostics. Validate the JSON instance against the schema and freeze the inputs, ask the normal `RunStep` policies, then apply a tool's `approval=True` through the job's approval mechanism before entering its body. Only then construct typed arguments for the callable, invoking user-defined Pydantic validators once and supplying just the keys actually present. A validator's rejection returns the same status 2 without echoing the rejected input. A host-written validator, like other host code, must keep external effects after the last interrupt. Repeat admission under current rights after a suspension. No policy or log event represents a second execution door. Nested VFS calls are separately gated steps, including when the outer tool was admitted. This supplies the proof left open by policy decision 10; I3b owns serving policy and its open-posture threshold.

6. **Map expanded argument words by the following table.** Work on words already split by the shell. Never split a value again. Support `--key value`, `--key=value` and `--` to end options. The exact property name wins. For camel and snake case offer one lowercase kebab alias, splitting the lower/digit-to-upper and acronym-to-word boundaries and replacing underscores by hyphens. When another exact name, generated name or boolean negation claims a spelling, preserve exact names and omit ambiguous generated spellings. Reserve `--help` and `--json`. Resolve a local reference into `$defs` or `definitions` one level for flag presentation and strip a sole nullable alternative (`type` array or `anyOf`/`oneOf`). Complex schemas still undergo full validation. This preserves archive §2 with the [code-mode study](../2026-11-23-code-mode-prior-art/2026-11-23-code-mode-keeps-the-tool-catalog-out-of-the-context-and-vfs-can-add-search-and-authority-to-it.md), section 9 item 7.

| Property after normalization | Words and resulting JSON value |
|---|---|
| String | Verbatim, including an empty value in `--x=`. In a string flag value, `@path` reads the caller's VFS file as strict UTF-8; `@@text` supplies the literal `@text`. Positionals and JSON strings stay literal. |
| Base64 string | `@path` or bound stdin encodes the exact raw bytes as base64. A literal flag or JSON string must be valid base64. |
| Integer | Signed decimal integer, with an optional leading minus and JSON's leading-zero rule. An integral spelling remains exact, including above the binary64 exact-integer limit. |
| Number | JSON number grammar. An integral spelling stays an integer; a decimal point or exponent yields a finite float. Reject NaN, infinity and overflow. |
| Boolean | `--x`, `--no-x` or `--x=true` / `--x=false`. A following word is an operand. |
| Enum or const | Match a member by its JSON type and value, after that type's coercion. A literal string member wins an otherwise ambiguous spelling. Whole-object JSON can select the other type. |
| Scalar array | Each repeated flag contributes one item by its item rule. Preserve order; a comma stays data. |
| Other array | Each repeated flag contributes one complete JSON item. Validate against the item schema. |
| Object, nested model, multi-arm union or untyped value | Parse a complete JSON value. Only a union with a string arm can fall back to the original word if parsing fails. Validate the resulting shape. Free-map objects use JSON, never dotted flags or a second `key=value` grammar. |

7. **Bind without guessing or silently overwriting.** Flags fill properties by name. Positional operands then fill still-unset required scalars in schema `required` order. A last required array takes the remaining operands, with each coerced by the item rule, even when optional properties follow it. A flag and operands for that same array cannot be mixed. Zero remaining operands leave the array unset; empty arrays are expressible with JSON. Omit absent defaults so Python or the adapter applies them. Tokens following a value-taking flag are its value even when they start with a minus; a missing value is invalid. Refuse a repeated scalar, contradictory switches, unknown option, surplus operand, wrong type, missing required member or unknown property. A leading-dash operand uses `--` or the explicit flag assignment. Properties named `help` or `json` and names outside the usable flag grammar are JSON-only. A top-level schema with no single property map uses whole-object JSON only. Sole `--json '<object>'` and `--json -` accept one complete object; the latter consumes connected stdin. Reject mixed flags/operands/extra stdin, duplicate object keys at any depth, malformed/nonfinite JSON or values outside the schema. Check top-level keys against declared properties (or the whole root schema when no single map exists). Apply the same nested constraints to direct calls and shell calls. Input errors return `vfs.invalid`, status 2 and the readable manual's property lines, without quoting supplied secrets. The body is never entered on a validation failure.

8. **Bind connected input exactly once.** A host may pin `stdin="body"` to a declared string, array or object (required or optional); reject a bad pin at registration. Otherwise there must be exactly one unbound required property and it must have one of those types. An unpinned second required property of a different type makes input ambiguous even when only one string remains. Bind text with strict UTF-8, base64 strings from raw bytes, and arrays or objects from strict UTF-8 JSON of the indicated shape. A pipe or redirect plus an already supplied pinned input, zero or multiple candidates, wrong type, malformed input or absent stdin for `--json -` is `vfs.invalid` with status 2. Keep line endings and distinguish an empty pipe from no pipe. Route each `@path` read through the caller's public read, relative to the command's working directory, in source order after authorization for this manual. Propagate the read's kind on failure with status 1 and no tool call; no host filesystem fallback. Direct `arguments` are JSON data, so a string beginning with `@` there stays literal. Tool-specific shell usage comes from the readable descriptor. If it changes before `run` admits the parsed words, refuse under decision 11 rather than applying them to another schema.

9. **Feed one admitted execution, preserving bytes and input presence.** Extend the tool-class `Start` wire with resolved path and a bit for connected stdin (pipe, explicit redirect or explicitly supplied input to the line, including an empty one). Track input presence through bindings and shell descriptor duplication; preserve current empty input for ordinary commands. Make omission distinct from explicitly supplied empty bytes on all `cli` faces, adapting to the existing machine's byte buffer plus presence bit. Keep the tool's argv and bounded input per request key. Invoke `run` once when the input is complete, or immediately for unconnected input, via the line/session's guarded router. A feed before EOF cannot execute a partial body. Remove state on completion, early close and cancellation; a cancelled or incomplete producer must not start a discarded request. Use the existing stream/status reply and warning collector. Journal the request, EOF and replies by the interrupted-line rules: no completed tool stage is executed again during line replay. The adapter never calls the function itself. Future MCP serving of the shell command uses the same result and gates, with no MCP dependency in this unit.

10. **Inject only a handle for this invocation's caller.** Identify at most one parameter by resolved annotation exactly `AsyncSession` or `Session`, including forward annotations to either, independent of its name or the face that made the call. Preserve the original effective authority, narrowing, policies, turn and read/write guards. With no originating session use a restricted handle on that router for the admitted authority. Give the async annotation the awaited interface. For an explicitly requested synchronous `Session`, provide its real synchronous operations through a bridge to that same running loop, usable from an awaited `asyncio.to_thread` block; calling a blocking verb on the kernel thread gives the existing `vfs.invalid` own-loop refusal (`src/vfs/sync.py:65`, `:97`). Never start a second kernel to satisfy this annotation. Both handles refuse `jobs` and `resume` with `vfs.invalid`, expose no host management and cannot mint a more powerful child. Close the borrowed handle on return, error, cancel or interrupt; this does not close the caller's session. Contexts copied by spawned tasks lose the same handle on close. Use the existing hop budget on nested tool runs. The body runs as host Python; only VFS operations through the handle inherit these restrictions.

11. **A run step names what was approved, and a resumed run proves it again.** Add optional `stdin` to `RunStep` and its canonical/payload encoding using the policy spec's bytes rule (base64) with a distinct absent value. Keep `arguments` as the explicit JSON object before stdin binding so replay cannot bind the same property twice. Freeze a detached copy of inputs at admission. For calls through the injected handle set policy `via` to a frozen tool-call value carrying the canonical tool path and originating line if present. Its wire tag is distinct from a direct call and a `Line`; authority comes only from the caller. Re-enter policy on each nested verb outside the outer step's inner-call exemption. Use a registration identity allocated once per installation, private to its router; include it in saved run matching alongside canonical input and the job's caller. A different registration, including a freshly started process without that installation, refuses a pending execution with nonretryable `vfs.conflict` before claim if its name remains readable; a lost right gives the ordinary hidden or denied result first. An in-flight descriptor removed during judgment likewise cannot start. Never bind an old approval to a new function with the same manual. This takes the conservative side of the interrupted-line decision 13 on a changed build.

Use the job's asking context for the body and for the built-in approval under distinct identities. Capture the stamps of reads that informed a question, including indirect input files, and the fact of a successful mutation on the guarded handle, including nested calls. Propagate its stop signal past the host exception handler. Save the detached explicit arguments, stdin-presence bit and bytes, ordered file bindings (property, array position if present, absolute VFS path, observed stamp and codec), registration identity, stamps and answer positions in the existing job part. Never place the Python function or a session handle in the record. On resume, authorize the answering principal and original caller separately, verify registration, inputs and observed files, and run the body's first line against the answers still valid. A changed input file invalidates its answer; a shell `@path` is reread as the original caller before rebinding. Apply decisions 38 and 41 of the job spec, including the system-actor refusal. A stopped program has no final stage status until it resumes; completed predecessors replay their replies. D65 takes no shipped `ask_user`; a host can register its own async question function.

12. **Use one conversion from the return value to output.** A returned `Result` passes unchanged to the direct caller. For shell use its ordinary result rendering as UTF-8 for stdout on success or stderr on failure, status 0 or 1, keeping its classified facts; an interrupted result follows the job path. Otherwise return a `Result` with `ops=("run",)`, declared program `exit_code` and `stderr` on a small `RunResult` subclass; its observations are the output. On normal completion status is 0. A string gives one text observation and exact UTF-8 bytes, bytes give one bytes observation of declared MIME and exact raw bytes, a JSON value or Pydantic model gives one compact UTF-8 `application/json` line with a final newline, and `None` gives zero observations and empty stdout. An empty string or empty bytes still gives one row. Use the addressed tool's canonical path as the origin on ephemeral observations (`Observation.path` is required, `src/vfs/models/entry.py:451`). They are output of `run`; a subsequent `read` at that path still gives the manual. Do not invent a stored stdout address, version or callback replay. Streams, raw bytes and status feed the existing machine independent of terminal UTF-8 display. The three front paths for a line all receive the ordinary shell result. T2 alone publishes a readable spill address after its commit.

13. **Keep failures distinct from control flow.** A deliberate `ToolError(message)` gives status 1, no observations and the message plus a newline on stderr. Another ordinary exception, including a return value that cannot be serialized, gives status 1 and only `<name>: tool failed\n`; the host logger records the exception without adding arguments or stdin. These are program failures, so the direct result has a nonzero `exit_code` and no kernel error, as a completed shell command can fail while its surrounding line runs to completion. Caller-correctable validation fails with `vfs.invalid` and status 2 before entry. A policy denial retains `vfs.permission_denied.policy` and status 126. A tool times out under the smallest of the remaining line deadline, `WALL_TIME_BUDGET` (`src/vfs/deadline.py:36`) and a positive finite per-tool `deadline` in seconds when specified. It returns `vfs.timeout` and status 124. Cancel the cooperative async task and revoke its handle, release buffered input/output, never retry automatically. Preserve external task cancellation and the job's interrupt signals as control flow; the shell owns its existing 130 cancellation result. VFS cannot preempt blocking or cancellation-suppressing host code or roll back external effects.

14. **Account for the host's bytes and keep ranked search off this landing.** Declare shared `TOOL_INPUT_BYTES` and `TOOL_OUTPUT_BYTES` ceilings using the machine's `MEMORY_BYTES` and `OUTPUT_BYTES` defaults respectively (`crates/vfs-shell/src/machine/mod.rs:60–79`). Cap line calls also by their remaining memory/output allowances. Count UTF-8 byte lengths and raw stdin, decoded file bytes and base64 expansion before allocation where the size is known; include argv, accumulated feeds, materialized argument representations and pending output in the limits. Bound JSON nesting at the shell's declared parse-depth default; reject excess as `vfs.budget_exhausted`, status 137. Streaming encoders stop at the first over-budget chunk, before retaining a second complete representation. Apply the same ceilings to direct calls, including returned results measured in their selected transport encoding at the output boundary, without changing an in-budget returned `Result`. Caller/host allocations inside arbitrary Python code cannot be charged by VFS. Reuse the job spec's decision 10 `SCHEMA_BYTES` limit for one schema. Declare `TOOL_CATALOGUE_BYTES` at the machine memory default for the sum of installed name, schema and manual bytes; count UTF-8 bytes at registration, free the charge at removal and refuse an over-budget batch with `ValueError` before publication. Do not silently truncate a schema. Use rights-filtered `ls`, `glob` and `grep` of the served bin files for discovery. The memo measured a lexical ranking advantage, but the ordinary index describes stored files and a process-local tool may disappear independently. This unit adds no term postings, scores, embeddings, hidden corpus statistics or query-time scan to `search`. A later ranked catalogue can be added without changing an address or the call ABI.

## Cost

Registration is per host deployment, independent of the 10-million-file estate. For a constructor batch of `T` tools, compile each distinct descriptor once, build the name map in O(T), sort once in O(T log T), and retain one schema and manual per descriptor plus O(T) keys. At 10,000 manuals of 1 KiB each, manual text occupies about 9.8 MiB before schemas and metadata. Total charged catalogue bytes cannot exceed `TOOL_CATALOGUE_BYTES`. Single add/remove copies at most O(T) registry references and publishes by a short atomic swap; readers keep one snapshot. No SQL write or writer lock is acquired for registration or execution. No read transaction spans an awaited tool or policy. A tool's own file changes have their ordinary per-verb transactions.

Name lookup is one dictionary probe plus the T1 rights check. A fresh non-system proof for a tool point has four distinct posture keys (the path, bin, meta root and root). It costs one authority resolution plus `ceil(4/B)` posture reads for the membership owner's effective key budget `B`; a system proof issues zero. Lookup and execution can each pay it, and a suspended run pays it again when resumed. At 150,000 direct runs per day and `B >= 4`, this is 150,000 posture reads beyond authority resolution, without any corpus visit. SQLite and the unknown-dialect floor use their own membership budget, Postgres its bound-array or bind budget as supplied by 170-1. A full batched proof of 10,000 sibling tools has 10,003 distinct keys, counted with the dev ancestor helper; when T1 examines them in batches of sizes `nᵢ`, budget for the sum of `ceil((nᵢ + 3)/B)` across batches, including any lookahead. Never issue a point proof per listed tool. Bounded shell pages and early consumer close limit work where a page fills with visible names; a sparse grant may require scanning every remaining registered name to establish EOF.

Argument scanning is linear in words plus value bytes, apart from the declared schema validator's work. Each file indirection makes one public read per occurrence and inherits the file read's cost. Check its projected size before fetching an oversized body where possible, and check the actual version/size on read. JSON validation, retained feeds and rendering are bounded by decision 14; complex user-authored schema constraints and the Python function's own work are host code costs. If a public read still returns a whole file in one allocation, a separate size probe alone cannot guard against replacement. Collect the requested file observation with its size and body from the same version; to enforce an allocation ceiling, have the read implementation honor a private byte limit in the call context and refuse an oversized version before fetching its body. Apply that bounded read only to an indirect operand and exercise a growing-file race on both database legs. Input held by simultaneous stages is charged to one shared line total, with release on EOF, early close and cancellation, so a long pipeline cannot reserve the full line allowance per stage. Direct callers pay per active call. The bounded indirect read may add one metadata point read per operand on a backend needing it. A backend unable to bound the return can answer `vfs.unsupported` for the indirect form before calling it. No requests introduce a storage table, bind list, index visit or background job.

## Choices to confirm

1. **Rank manifests now or defer ranking.** Take rights-filtered manual reads and grep now. A lexical index tied to process-local registration and per-query rights can be added without changing these results. Ordinary stored postings would advertise tools a different process cannot run.
2. **Offer free-map assignment or one JSON grammar.** Take JSON for nested objects and free maps, literal `@@` for an at-sign, unambiguous kebab aliases only, and decimal integer preservation. Extra option spellings can be introduced later without changing a valid command. For mapping-only adapters retain a full offline JSON Schema validator as a core dependency; the cheaper dependency alternative is to accept only Pydantic-backed adapters. The former also validates raw nested schemas in `--json` calls.
3. **Address transient output and preserve storage dispatch.** Take the tool path as the origin of returned rows and preserve the existing storage call without stdin off the served path. A future storage capability can explicitly accept input; a future publisher can give durable output its own address.
4. **A synchronous session annotation inside an async body.** Take an actual guarded synchronous handle usable off-loop and prefer `AsyncSession` in examples. An async handle masquerading as the synchronous type would silently change every annotated method's contract. The existing own-loop refusal makes the wrong call fail promptly.
5. **Carry approval across reinstalls or require a fresh one.** Scope it to one installation. A stable host-supplied deployment identity could later permit cross-process resume. Matching by path or schema alone could authorize a different implementation.
6. **Confirm the roadmap leans on the call door and shipped tools.** Take D63's existing `run`, D64's one directory as in T1 decision 1 and D65's no preinstalled question tool. These are the sides taken by this draft; the roadmap rows at lines 1274–1276 are still leans on the checked commit. Keeping the existing op and leaving the name unoccupied permit later additions. No independent choice blocks implementation after the named dependencies and their rulings.

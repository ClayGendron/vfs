# The router serves program manuals and skill files, and the shell searches PATH as its caller

A draft, written on 2026-11-25. It is not reviewed, and nothing in this unit is built. Checked against `dev` at `27f3d24d` for [roadmap story T1, gate b](../../context/standards/roadmap.md), converted from [169a, sections a1–a7](../../context/specifications/archive/169-programs-the-index-and-the-vfs-views/spec.md). It rests on the meta root, caller-scoped listings, the executable bit and the shell's gated host requests.

## The outcome wanted

On a fresh router, `ls /.vfs` shows `bin`, `skills` and `trash`. `cat /.vfs/bin/grep` reads the shipped manual. `command -v grep` prints `/.vfs/bin/grep`, and that exact path works in command position. A line can put a stored directory first with `PATH=/work/bin:$PATH`. Installing there requires the ordinary right to create a file. A caller can list a skill, read its instructions and follow its resources through the view. No discovery operation invokes code.

## What the code does today

On dev's SQLite-backed shell, `type grep; command -v grep` printed `grep is /usr/bin/grep` and `/usr/bin/grep`. Setting `PATH=/missing` still found it. `/usr/bin/grep` and `which grep` exited 127. `hash -t grep` printed nothing and exited 0. Executed through `AsyncVirtualFileSystem.cli` as a named caller. The host sets `/usr/bin:/bin` and supplies 16 library and 11 host program names in this build (`src/vfs/shell/host.py:53`, `:174`, `:228`). The machine refuses slashes before trying the table, invents the displayed path and treats `hash` as a no-op (`crates/vfs-shell/src/machine/exec.rs:1095`, `builtins.rs:2001`, `:2069`, `:262`).

A focused probe on in-memory SQLite and disposable Postgres mounted a second storage at `/m`. Under a named authority, one batch for `/a/p` (hidden), `/b/p` (list only), `/m/p` (readable) and `/b/missing` called each storage's `stat` once and neither storage's `ls`. The observations were a bare `/b/p` and a populated `/m/p`. The misses named `/a` and `/b/missing`. A second probe populated `/large` with 10,000 sibling files on each engine. Asking for `/bad/n09999` and `/large/n09999` together made one storage `stat`, zero `ls` and zero body reads on each, returning the latter path beside one `vfs.not_found`. Thus a batch can have usable answers beside errors, and the path in a miss can be an ancestor. In each engine `glob("*/SKILL.md", paths=("/skills",), kind="file")` found `/skills/unit/SKILL.md`. At a pre-existing `/opt/bin` with posture `read`, a create-only write got `vfs.permission_denied`, then `created` after a grant of `add`, then `vfs.exists` on repetition.

## The problem

An address advertised by the shell cannot be opened or executed. A table lookup outside the namespace cannot distinguish an invisible command from a visible command that the caller may not run. Scanning a 10,000-child directory for each command at the reference rate of 150,000 calls a day could visit 1.5 billion rows just to match one basename.

## Decisions

1. **Decided 2026-11-25: D64 takes one served directory, with default `PATH=/.vfs/bin`.** Shipped external programs and registered host tools share that directory. There is no second tools head or implicit `/usr/bin` alias. A literal `/usr/bin/grep` succeeds only if an ordinary runnable file exists there. This reverses the address in the bash-refusals decision 10 while preserving its intent that the displayed absolute name runs. A synthetic alias would hide an ordinary directory that the caller could own. A changed `PATH` affects only the shell search order. Neither it nor a lookup provisions directories or changes rights. This rules the conflict before the remaining design, following domain G at `context/standards/roadmap.md:780–784`.

2. **Serve the two heads at the global root, ahead of legacy rows with the same address.** Install read handlers for exactly `/.vfs/bin` and `/.vfs/skills` in the router, outside its mount table. Use the same selection after canonicalization for single paths, mixed batches and explicitly rooted pattern verbs. Merge their bare directory rows once into a successful root meta listing, applying the ordinary depth, projection and page frontier. A walk of `/.vfs` may descend into each served head subject to its gates. On a fresh child mount `ls /data/.vfs` still shows only `trash`. Other legacy rows follow 169-1. An unserved, absent head gives `vfs.not_found` on a read. An unscoped walk, including `grep` rooted at `/`, never enters a head. Keep `mounts()`, mount administration and grant routing on the real binding table. D38 takes `mounts()` alone for the mount table. For `locate`, keep the real root mount and coordinates, and check a served address via the caller's view when `exists=True`. This preserves the meaning of the `Location` tuple (`src/vfs/base.py:598`, `src/vfs/mounts.py:538`). No backing mount or closeable view resource is created.

3. **Derive a manual and an execution identity from a single catalogue entry.** Use a private router-owned catalogue in a leaf module, keyed by canonical single-segment name. For shipped entries take the union of the running library and host tables, retaining the existing host-first fallback when a program has both implementations. Store authored usage and description as UTF-8 manual text with a final newline. Reuse the option parser's static help where available (`src/vfs/shell/programs.py:55`, `:831`). Reading a manual never calls even a help handler. Registering a name already held by a builtin, shipped entry or another tool is an error at registration, owned by 170-2. Functions, shell-only builtins, syntax, aliases and refusal hints have no file. D34 supplies the shipped inventory as its implementations land, including the canonical grant verbs and excluding `awk`, `jq` and the unserved 168c programs. No static second list of runnable words, basename masks, implicit suffix expansion or write-time shadow exceptions.

4. **Use ordinary file observations and apply visibility before producing any observable part of a response.** Both heads serve `stat`, `ls`, `tree`, explicitly scoped `glob` and `grep`, and `read` on files. The directory and wrong-kind cases follow the corresponding ordinary read verbs. A shipped manual is readable by every admitted caller. For a tool, ask the root binding at its catalogue path under 170-1. Below `list`, treat it exactly as absent. At `list`, return only `path` and `kind` on discovery, refuse a direct read with `vfs.permission_denied`, and omit its content from a grep. At `read` or above, serve its manual. Filter first, including before matching, counting, clipping or generating `next_after`. A failed or unavailable rights check is a classified refusal with no tool report. An unsupported rights interface gives `vfs.unsupported` for enumeration or a non-shipped name, independently of whether a matching tool was registered. A point query for a shipped name alone needs no rights interface. For a non-shipped point, check the requested path even on a registry miss so that an unavailable rights engine cannot reveal registration. Preserve outer admission and policy checks. A manual is a file, with `source="text"`, `mime_type="text/plain"`, the UTF-8 size and content on reads at the usual projection. Do not fabricate a stored version, timestamp, source address or execution token. `grep` uses the ordinary matcher on readable manual rows. Grant administration at these paths goes to the root binding, as in `src/vfs/base.py:1950`; file writes follow 169-1. The refusal detail may say “install in a writable directory on PATH” but never lists another caller's paths. Ranked search is outside the served verbs.

5. **Expose stored skills through ordered, explicitly configured containers.** Add `skill_paths: Sequence[str] = ()` to the async and sync router constructors only. Accept a sequence of path strings, rejecting a bare string. Canonicalize once, retain the first occurrence of each path, and reject a malformed path or a container in a reserved meta tree with `ValueError`. Recheck the terminal coordinates on use so topology changes cannot turn a source into a view. Missing or invisible containers contribute no names. A file at `<container>/<name>/SKILL.md` visible to this caller identifies a skill directory. The first visible manifest in container order wins, even when list-only. Resolve a known name with point probes of those manifests. Every suffix, including `SKILL.md`, reads only beneath that winner. A missing or denied resource never falls back to a different container. Canonicalize the full view path before routing, re-enter public verbs as the same caller under the hop budget and enforce the source row's own rights. A skill is read-only and never a command. Only view coordinates appear in rows, errors, matches and keys. Strip the container and winning unit prefixes before rebasing, including structured error data. Apply the existing unaddressable-row and overflowed-key rules to the resulting alias (`src/vfs/results/envelope.py:686`). No independent grant on the alias can elevate source rights. This preserves archive §a7's unit grammar and first-wins rule without a program index or an installed skills table.

6. **Page skills by their directory names and programs by their catalogue names.** For each skill container seek ordinary child `ls` pages by source child path, batch-`stat` the `SKILL.md` of directory candidates, and discard absent, invisible and non-file manifests. Merge the sorted name streams, consuming all equal names together in container order. Seek strictly after the last visible alias on resume. Nested `tree` and pattern results merge by full view path, using the existing frontier, depth and filter rules. In particular do not drain one unit's descendants before a lexically earlier sibling. For programs seek an ordered catalogue snapshot after the key and ask for rungs in slices, filling through hidden names until there is a further visible row or the stream is exhausted. `limit=None` returns the full permitted result. Refresh rights on every public page. A Python oracle over two containers, shared and hidden names and page sizes 1–3 reproduced the full visible union in 96 cases. Sorting manifest paths orders `a-z`, `a.`, `a`, while sorting their unit paths orders `a`, `a-z`, `a.`. This is why the archived one-glob discovery rule is replaced for paged listings.

7. **Add one non-executing machine request, Lookup, after shell-local resolution.** Its inputs are the expanded command word, the effective colon-separated `PATH`, the current working directory and whether all matches are requested. Functions and builtins retain the machine's existing precedence, including POSIX special builtins. A slash word skips name search and probes just its normalized address relative to that directory. Otherwise form one exact candidate per component in left-to-right order. Empty components and an empty or unset search path mean the current directory. Relative components are relative to that command's working directory, including in a subshell. Prefix assignments apply for that command only; `command -p` selects the default search path. Deduplicate equal normalized candidates in first-seen order. No operating-system PATH, host file lookup, system authority or implicit runtime suffix is consulted. Reply with the normalized path and its execution class (machine library, shipped host program, host tool or stored file), or a visible non-runnable candidate, miss or classified failure. The native reference host, Python binding and WebAssembly wire must share the request, reply tags and deterministic ordinal, as for `Start` (`crates/vfs-shell/src/machine/mod.rs:165`, `src/vfs/shell/host.py:439`).

8. **Resolve point candidates as a batch without leaking a hidden hit or a discarded error.** Resolve catalogue candidates against decision 4. Issue one public `stat(observations=..., columns=..., authority=...)` for stored candidates, requesting `kind` and D66's `executable` beside the path. Remap returned observations by canonical path to the original candidate order. A bare file lacks read permission, even if a real executable bit is set on its stored row. Skip absent and invisible candidates and paths that cannot descend through a non-directory component. Take the first readable executable file, remembering the first visible unusable match for an execution refusal if no runnable match follows. A directory is unusable. A caller who can list a tool but cannot run it gets 126 if no later runnable file wins. Missing or hidden alone gives 127. Discovery may report the visible file path when all candidates are unusable, never a directory as an executable. Ordinary inaccessible PATH components contribute no hidden path to evidence or stderr. Keep unexpected infrastructure and budget failures classified, fail closed and suppress internal candidate addresses; never treat an incomplete check as a definitive match. A non-terminal host failure ends the stage at 126 with its classified fact. Exhaustion of a line budget or deadline retains the line’s existing terminal outcome. Shell refusal-table diagnostics keep their existing execution-only meanings on a generic miss. They are never catalogue entries. `PATH` can select a same-named stored executable ahead of a shipped external program. Every effect still passes through its own gate.

9. **Start the resolved address and recheck any mutable permission at use.** Dispatch a machine or host implementation only when the selected address is its served file. Preserve the host-to-library fallback for the selected shipped implementation. A stored program is read as the caller with its current body, source kind and executable bit in the same read result; a replacement or revocation between lookup and execution must never run unchecked bytes. D66 decides script interpreters. A byte program without a supported runtime is a visible `vfs.unsupported`, exit 126. Generic WebAssembly loading belongs to T6. Host tools pass their resolved path to 170-2's gated `run`, which judges the caller again before invoking the body. The machine's result is a location, never authority. Classify a newly invisible or missing target as 127 and a visible target denied at execution as 126. No fallback to host execution by the basename of a stored path.

10. **Use the same lookup for path reporting and hashing.** Preserve shell-local output for keywords, functions and builtins. For external files, `type name` prints “name is <path>”, `type -P`, `which` and `command -v` print the path, and `type -a` lists the matches in search order. `which` searches external files only. `hash name` records a found runnable path silently, `hash -t name` prints it, bare `hash` lists its current entries and `hash -r` clears them. These are the path-printing forms of hash in bash. An uncached or lost name is a nonzero hash query. Keep per-shell positive path hints only, clear them when PATH changes and invalidate relative-component hints on `cd`. On every use or display of a hint, check its path as this caller first, evict a lost hint and search again on execution. `type -a` and `which` enumerate the current PATH without the hint. Hash state dies with the shell and stores no body, negative answer or rung. A Bash probe over `/bin:/usr/bin` showed both paths in `type -a ls`, silence for `hash ls`, `/bin/ls` for `hash -t ls` and status 1 for that query after `hash -r`. Rights rechecking on display departs from Bash's cache because an old name can outlive the caller's grant. The departure lasts while path visibility is revocable.

11. **Install with ordinary writes in a real directory chosen by the caller.** Provision that directory using normal authorized operations, put it on PATH in the desired position, then install a fresh name with `write(path=..., content=..., if_absent=True, authority=...)` (or a D66 batch entry carrying the bit). The ordinary gate requires `add` to create. Set the executable bit through D66 with the required write right. Until that succeeds the new file is visible at its usual rung and cannot run. A guarded replacement uses the current write precondition, version and occupied-row/ownership rules. No create-on-read, automatic posture, override for shipped basenames, special package manager or PATH-dependent restriction on other writers. A tool registration belongs to T3 and never writes a manual row. This keeps installation subject to the same gates, retries and conflicts as any other file.

## Cost

At the [reference deployment](../../AGENTS.md) there are ten million files, a million directories and 150,000 verb calls a day. A cold external lookup with `D` distinct PATH candidates in `M` real mounts issues at most one grouped storage dispatch per represented mount and zero directory listings, even in a directory of 10,000 files. For 150,000 such calls that is at most `150,000 × M` dispatches and `150,000 × D` candidates, independent of directory size. A literal slash word has one candidate. A default-path shipped lookup touches no stored candidate and needs zero SQL. Host and machine charge path candidates and hash state to the effective line memory budget before allocating, with checked arithmetic for long repeated names. Lookup consumes one request under the line's verb budget.

One dispatch is not a promise of one SQL statement. The existing point reader fetches distinct target and ancestor keys in slices of `membership_budget(profile, parameter_budget)` (`src/vfs/storage/backends/database/reads.py:203`, `dialects.py:541`); caller resolution and roads may add statements. For tool rights, 170-1 counts `ceil(K/B)` posture reads per non-system batch for `K` distinct ancestor keys and the membership owner's budget `B`. SQLite, Postgres and the unknown-dialect floor inherit their own bind/element budgets. No new table, SQL dialect, lock or background write.

A program page may inspect every remaining registered name if rights hide the rest. Inspect in batches of at most `LISTING_PAGE`, using the same declared page size for container reads. For `C` containers hold at most one source page per container and one merge head per stream, plus output. For `N_i` immediate children examined in container `i`, use at most one manifest batch per source page, with a point dispatch per represented mount. Hidden or malformed units may require exhausting the containers. No scan outside those immediate children is needed for discovery. An unpaged full result costs its visible output plus these buffers. Scoped grep costs the readable manual bytes or the selected skills' source search; ordinary lookups fetch no bodies. An install adds zero catalogue writes per file write or index visit. Reads take no writer lock.

## Choices to confirm

1. **Skill containers at construction or a mutable discovery API.** Take the ordered, empty-by-default `skill_paths` constructor argument. The archive requires explicit source containers, and reconfiguration methods can be added without retiring a public index.
2. **Expose a skill's underlying path and callable classification as query fields or keep ordinary observations.** Take ordinary view paths and file/directory kinds. The skill manifest and the manual are already addressable. Additional fields could be introduced later without exposing source locations now.
3. **Combine the catalogue and host tool registration into one landing or let T3 consume the T1 catalogue.** Take separate landings sharing one table. T1 can be built and tested with shipped programs and a private tool fixture. Later registration adds a producer without changing any printed address.

## One line

Program discovery returns an address the caller can open and run, skill aliases obey the source files' rights, and installing a stored command costs an ordinary authorized write.

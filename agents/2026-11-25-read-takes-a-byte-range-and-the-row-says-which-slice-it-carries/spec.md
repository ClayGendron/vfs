# A read takes a byte range and its row says which slice it carries

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. This is unit 178-2 of story K6, gate b, converted from [the ranged read](../../context/specifications/archive/178-the-ranged-read/spec.md) and its [tasks](../../context/specifications/archive/178-the-ranged-read/tasks.md). It rests on [the engine's byte-slice builders](../2026-11-25-the-engine-cuts-a-byte-slice-of-a-body-on-every-tuned-dialect/spec.md) and the landed router precedent for a derived listing page.

## The outcome wanted

A caller can read a file header with `read(path, range=(0, 4096))`, or ask for the same interval of each file in `observations=`. A bytes projection carries the exact raw bytes available. A text projection includes the whole UTF-8 characters touched. For `"a😀z"`, `range=(2, 1)` serves `"😀"` with `range_start=1` and `range_length=4`. The next request starts at byte 5. A caller needing the single requested byte can cut it from the returned character locally. The answer has these semantics on every mount, including a backend that only implements a whole read.

## The problem

All six read signatures lack a range, verified by inspecting the running package. The router, the async session, the sync filesystem and the sync session call the whole-read path (`src/vfs/base.py:802`, `src/vfs/session.py:97`, `src/vfs/sync.py:267`, `src/vfs/sync_session.py:80`). The seam and database implementation do likewise (`src/vfs/storage/protocol.py:143`, `src/vfs/storage/backends/database/backend.py:259`). The point fetch selects the bare body column (`src/vfs/storage/backends/database/reads.py:1117`). At the reference deployment's median 4 KB and mean 0.3–0.7 MB per file, transferring the tail dominates a prefix read. The engine expression alone gives a caller no way to select the interval or know what a text read returned.

## Decisions

1. **One optional keyword on the existing verb.** Add `range: ByteRange | tuple[int, int] | list[int] | None = None` on all four faces, `SupportsRead.read` and `DatabaseStorage.read`. Define `ByteRange(NamedTuple)` with `offset: int` and `length: int` in `src/vfs/ops.py` beside `TwoPathOperation` and export it from `vfs`, as the [naming standard](../../documentation/maintainers/how-we-name.md) requires for a public signature. K6 spells the argument `range`. Add the single `range` entry to Ruff's `flake8-builtins.builtins-ignorelist` (`pyproject.toml:116`). Omission and explicit `None` use the ordinary read. One pair applies to the single path or to every batch row, as in the archive. The position belongs to this call.
2. **Refuse a bad range before dispatch or first touch.** Add the nullable `"range"` kind and `ParamSpec("range", "range", minimum=0, maximum=INT_CEILING, ...)` to the read table. Accept precisely a tuple or list of two integers, excluding booleans, each within those inclusive bounds. Reject negative, oversized, malformed and noninteger inputs with `vfs.invalid` naming `read range`. Validate each component separately, even if their sum exceeds the ceiling. The current bound is the existing integer seam and the width of `size_bytes` (`src/vfs/params.py:63`, `src/vfs/models/rows.py:384`). Add a `OneBody` entry in `VALUE_RULES["read"]` (`src/vfs/params.py:538`): default columns select `content`, otherwise exactly one of `content` and `data` must appear, with any metadata allowed. Both or neither give `vfs.invalid` naming `range` and the two alternatives. Normalize the pair to `ByteRange` and an explicit validated projection to a frozenset. Share the pure range and one-body predicates with direct database calls under `src/vfs/storage/slicing.py`. Pass the declared ceiling into the predicate: the params gate has `INT_CEILING` and the adapter has 178-1's equal `SQL_INT_MAX`. This respects the import ladder at `tests/lint/test_code_shape.py:46`.
3. **Use the smallest whole-character interval covering the requested bytes.** Let the requested interval be `[o,o+n)`. For raw `data`, fetch those bytes, ending at the available end. For positive `n` on `content`, ask 178-1 for the window from `w=max(0,o-3)` to `min(INT_CEILING,o+n+3)`, exclusive. If the window does not reach byte `o`, serve the empty string at `o`. Otherwise start at `o-w`, retreat across continuation bytes to the leading byte, and advance the clipped exclusive end across continuation bytes to the next boundary or window end. Decode only that interval, strictly. Each edge moves at most three bytes, including when both fall in one four-byte character. For `n=0`, request zero bytes and serve the typed empty value at `o` whenever the body exists. With a positive request at or beyond EOF, also return success, the typed empty value, start `o`, length zero. An exact byte consumer cuts the encoded result at `[o-range_start:o-range_start+n]`. Outward snapping permits that cut and guarantees progress for a positive request inside the body. The same `snap_text` works on both paths. A malformed selected interval is never decoded with replacement or allowed to escape as a Python exception. Pending 178-3's source-integrity classification, omit an undecodable source row and return a nonretryable `vfs.unavailable` at its visible path. For an undecodable rendering preserve the row without its text or range fields and add the nonretryable `vfs.unavailable` warning of 175-1 decision 16, choice 4. Use the stored source internally if it is absent from the caller's projection; it never appears in the result solely for this check.
4. **Two query fields describe the selected body.** Add `range_start: int | None = None` and `range_length: int | None = None` to `Observation` and `OBSERVATION_QUERY_FIELDS` (`src/vfs/models/entry.py:420`, `:531`). Stamp both values and both names in `populated` for every delivered body value, even an empty one, regardless of the metadata projection. They are absent from the mask on whole reads and fetched-null or denied bodies. Preserve the projected entry metadata, including whole-source `size_bytes`, `content_hash` and `version`. A bytes entry's default `content` is its rendering: the range addresses that rendering's UTF-8 bytes and its total cannot be inferred from the raw source's size or hash. Honor `render_notes` exactly as the whole projection does (`reads.py:937`), including a pending or failed rendering with no slice, a truncated rendering with its note, and a supplied empty rendering with a zero-length slice. Reading `data` on a text-only row keeps its fetched-null mask. In payloads and across a mount, the ordinary row carries both integers, including zero. A pager asking positive lengths resumes at the served end and stops when that end is short of the requested end or the body is empty. Exact final pages may require one more read. Each read is its own snapshot.
5. **Cut in the existing point projection before bytes cross the database seam.** Pass the window down `read_rows → _point_rows → mappings_by_path → _entry_projection` (`reads.py:156`, `:889`, `:203`, `:1117`). Replace just the selected body expression by 178-1 decision 4's labelled binary expression. Request a body-presence bit from the same joined table's non-null key when needed to distinguish SQL empty from missing. On the installed SQLite 3.46.1, a direct probe of `substr(x'',1,1)` and of `substr(CAST('' AS BLOB),1,0)` returned null, while a positive request past nonempty data returned empty bytes. A present row with an empty value must serve an empty slice; an absent outer-join member must keep a null body. Each body table's body column is non-null (`src/vfs/models/rows.py:457`, `:470`). Keep the membership query, view, target order and classification ladder. Construct text observations only after screening the mapping and snapping its window. Preserve every good row in a partly failed batch. An unreadable but listable file gets `vfs.permission_denied`, a directory gets `vfs.wrong_kind`, and a hidden file gets the ordinary miss at the same component. The trash target is the same row and side a whole read would serve (`reads.py:232`, `:913`).
6. **A backend declares an engine cut with `read_range: "engine"`.** Add the one-valued key to `TraitKey` and `TRAIT_VALUES` (`src/vfs/storage/protocol.py:78`). `DatabaseStorage.traits()` declares it exactly when `profile.body_slice is not None` (`src/vfs/storage/backends/database/backend.py:240`). In the existing read dispatch after authority resolution (`src/vfs/base.py:2880`), use `SupportsTraits` and the actual declaration once per ranged mount call, as the cursor does. A declaring storage gets the normalized range. Any other storage gets exactly one ordinary read with the same targets, projection and authority and no `range` keyword, including no `range=None`. Apply `slice_rows` to the body values in its admitted rows, preserving result errors, masks, paths and order even on partial failure. For a direct generic-profile database read use the same transformation on the ordinary result inside the one read. A whole read skips the trait lookup. The archive's bind-time trait snapshot would duplicate the landed mechanism. K7 can move this declaration into `features()` at gate f.
7. **Keep a slice and its body together when equal-path rows merge.** The ordinary fill in `Result._merge_observation` is field by field (`src/vfs/results/envelope.py:474`): a whole left body could acquire the bounds of a sliced right body, or two slices could put one pair of offsets on two bodies. For a collision involving a sliced row, take the first sliced operand's selected body, bounds and membership of all four fields (`content`, `data`, `range_start`, `range_length`) as one group. Fill other fields by the existing rule, including the agree-or-null version. With no sliced operand keep the existing merge. This gives the same first slice for either grouping of a fold, including `|`, `&` and the grouped router merge. Separate pages are concatenated by their served offsets by the caller.
8. **Render the interval from facts on the row.** In `_render_read` (`src/vfs/results/render.py:313`) append one marker to each sliced row after its normal content or projected block, before the next row or errors. Write `[slice: bytes A–B]` for the half-open served interval. Add ` of N` inside the brackets only when a populated size is demonstrably for this selected source body (raw data, or text with `source="text"` and a known version). Append `; end` when that total proves EOF, otherwise `; next offset=B` for a positive served length. An empty interval with unknown total gets the bare interval: a zero-length request alone cannot establish EOF. The renderer has only the result and its projection (`src/vfs/results/render.py:42`). Printing the caller's original length from the widened length would invent a request. A raw shell pipe still receives the field alone.
9. **Count bytes at the body boundary and revise K6's two cost criteria.** Implement the common window accounting seam `served_window` in `src/vfs/storage/slicing.py`: pass native window bytes before snapping, and pass the whole selected body on fallback before cutting. Instrument the seam in tests, count each fetched mapping once at receipt rather than each duplicate target, and cross-check SQLite driver rows across all body selects to catch hidden full fetches. Record SQL with the existing listener pattern at `tests/support/cursor_contract.py:58`, excluding statistics via `tests/support/statements.py:17`. In K6 criteria 1 and 4 distinguish raw bytes (`n`) from UTF-8 text windows (`n+6`), and count the point-select chunks over distinct targets *and ancestors*. Count transaction statements separately. The amended bounds apply to a declaring backend. The derived path moves the whole body and is tested at that cost.

## Cost

- For each touched mount there is one ordinary backend read or one native ranged read, with the usual rights work. At 150,000 verb calls per day, about three in four read-shaped, the range adds zero database round trips per call. A warm system read on in-memory SQLite was probed on dev: one `BEGIN` and one body `SELECT`. A native prefix of 4,096 raw bytes on a 4 MiB file transfers 4,096 bytes; text at offset zero transfers at most 4,099. Engine page reads follow 178-1 decision 9: SQLite can materialize the whole stored value internally, and Postgres text can read a prefix or the whole compressed value.
- For `K` distinct stored targets plus ancestors and `M=membership_budget(profile, parameter_budget)`, body selects on one mount cost `ceil(K/M)` for a nonempty system batch. The formula is per mount and matches the ordinary read (`src/vfs/storage/backends/database/descent.py:150`, `:176`). The host budgets the smaller of its IN-list capacity and the bind budget less the fixed reserve (`dialects.py:535`, `:541`). SQLite is the tighter tuned profile. A 10,000-file batch in one directory below root has 10,002 keys. With the probed SQLite default `M=32,668` it takes one body select. With a smaller declared budget it splits. The range adds two binds for raw data, two for SQLite text or three for Postgres text per statement, all inside the reserve, and no body is bound as input.
- For `D` raw files and `T` rendered or text files across such a batch, the native transfer is at most `D×n + T×(n+6)` bytes for positive `n`, and zero body bytes for zero length. Memory holds the existing target/ancestor maps plus their windows and the returned slices. Snap work is linear in returned text bytes with at most six edge steps per row. A derived batch holds whole admitted bodies of total size `S`, costs `O(S)` transfer and up to `O(S)` memory plus its output, encoding one selected text body at a time. The native trait identifies where the smaller bound holds. Neither path scans the corpus, changes writes or index passes, takes a writer lock or adds a wait on a writer.

## Choices to confirm

1. **K6's byte budget.** Take the archive's bounded UTF-8 window and amend criteria 1 and 4 in the implementation. A literal `length` bound across all body transfers cannot both cover a single requested continuation byte and deliver its four-byte character. This changes the accounting for text only and leaves an engine free to transfer fewer bytes.
2. **One row carrying differently sourced bodies after algebra.** Prefer the first sliced operand's body group on an equal-path merge. The alternative is a separate interval per body and a new row shape. The chosen rule distinguishes slices using the two promised fields and can be extended if consumers require both ranged bodies on a merged row.
3. **What the renderer offers for continuation.** Print the served end as `next offset` when a nonempty row has no proven EOF. The archive's full next tuple needs the original length, which a stored or round-tripped result does not carry. Keeping the renderer pure avoids new wire state and leaves room to add the tuple later.
4. **Malformed text before the integrity work lands.** Use the existing parent kind `vfs.unavailable` for an undecodable source interval, without replacement characters. Its future integrity child is an additive refinement. Classifying partial corruption against a whole-source hash waits for 178-3 and imposes no additional wait on this build.

## One line

`read(range=(offset, length))` returns the available raw bytes or the whole UTF-8 characters they touch, and every served slice reports its byte start and length whether storage or the router cut it.

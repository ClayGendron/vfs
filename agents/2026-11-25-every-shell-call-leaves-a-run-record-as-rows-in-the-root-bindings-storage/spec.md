# A completed shell line leaves its output and status under its owner's run directory

A draft, written on 2026-11-25. It is not reviewed, and nothing of the run view is built. Checked against `dev` at `27f3d24d` for [roadmap story T2](../../context/standards/roadmap.md), gate b, unit 169-3. It converts [archived spec 169, §c1](../../context/specifications/archive/169-programs-the-index-and-the-vfs-views/spec.md). It rests on the shell, the root's kernel store, the served meta heads and the action log's outer call identity.

## The outcome wanted

A named caller runs `cat /a.txt | tr a-z A-Z` and gets the ordinary output and a call id. Another process opening the same root can read `/.vfs/run/<id>/stdout` and `/.vfs/run/<id>/status` as that caller. The first file holds the final stream, even if empty. The second identifies what ran and how it ended. A clipped display tells the caller exactly which file holds the omitted output. A different principal naming the same path sees the same answer as for a missing run.

## What the code does today

Executed through `AsyncVirtualFileSystem` on file SQLite and disposable Postgres. A system write of `ab\n` to `/a.txt` and a read grant to a named principal let that principal run the outcome's pipeline. Both engines returned `AB\n`, exit 0 and `[[0, 0]]`. Both returned empty stdout and `[[1]]` for `false`, `[[0]]` for `:`, and no statuses for the empty line. The malformed line `if` returned `vfs.invalid`, exit 2; once unit 167-4 is built the kind is `vfs.invalid.syntax`, and a test that pins it compares by `kind_family` or names `ErrorKind.syntax`, with exit 2 unchanged. Printing byte FF returned U+FFFD on both. On each, `stat("/.vfs/run")` returned `vfs.not_found`. The host gathers raw chunks and statuses and replacement-decodes at return (`src/vfs/shell/host.py:246–275`). Its result declares text streams, status vectors and fuel, without a call id (`:137–170`).

## The problem

The current caller can display output, but its next process cannot retrieve the original bytes or identify which executable supplied a pipeline stage. An analytics row cannot carry those bodies. At 150,000 verb calls a day, synchronously writing an audit copy from every nested read would compete with the nightly 10,000-file batches for SQLite's writer. The completed line, not each file read, is the unit asking for durable output ([reference deployment](../../AGENTS.md), lines 68–94).

## Decisions

1. **Decided 2026-11-25: a run is a private kernel record with two immutable file projections at the global root.** Amend kernel-store decision 1 at line 96 only for those projections. The records remain private SQL rows. The router synthesizes directory and file observations; no ordinary Entry, grant, version-history row, index posting, embedding or second mount is created. This preserves one physical home for a line that crosses mounts, the meta root's write grammar and D53's private log. An independent process needs a router over the same file or database and schema. Calling the storage seam directly cannot resolve a router view. A root whose record place is memory, including the fallback for an unknown dialect with no durable place, offers the same view to that router until close and no cross-process promise. No SQL is added to the generic mount profile.

2. **Publish every terminal line that started a stage under an identified caller with logging enabled.** Small text, empty stdout, nonzero program exit and a terminal machine refusal after a stage started all qualify. The clipping threshold decides display only. Validate authority, arguments and parse first. At the first actually entered stage, obtain H0's outer call id and synchronous claim before the stage can do any work, including redirection or expansion with effects. Signal admission from the evaluator before its first such action; `statuses` alone cannot prove it. A syntax refusal, definition-only or empty line with no stage, and an interrupted or cancelled coroutine returning no terminal output have no visible pair. On eventual terminal resume use the original line id and owner once, never a second id per approval or a new record on reading back a finished job. An anonymous line still runs normally but owns no readable record: unrelated anonymous transports share one authority (`src/vfs/authority.py:149`, `:189–215`). Under H0's explicit `log=False`, preserve ordinary shell output and write neither the outer log row nor the private output. A reader's local logging switch does not revoke previously published files. This takes T2's small-output example over the spills-only suggestion in the [code-mode study](../2026-11-23-code-mode-prior-art/2026-11-23-code-mode-keeps-the-tool-catalog-out-of-the-context-and-vfs-can-add-search-and-authority-to-it.md), items 5–6.

3. **Return one optional `LineResult.call_id`, set only after publication commits.** Use the canonical 26-character uppercase ULID of §c1 as the H0 outer id, unique in the root store. Existing Entry creation already uses `str(ULID())` (`src/vfs/storage/backends/database/staging.py:397`). A pre-dispatch collision obtains a fresh id before a stage starts. No new path argument or public verb is needed. If the claim fails, return its classified failure and dispatch zero stages. Never hold the claim's transaction across execution. Publish both files, retention changes and H0's completion in one store commit. First conditionally take the still-open outer claim by id and owner in that transaction. A competing finisher can publish nothing until it observes the committed outcome. A retry of that commit uses the same id and captured bytes, enters no shell stage, and recognizes an already completed claim without changing its rank or extending its lifetime. A crash before completion leaves an invisible H0 claim of uncertain outcome, never authority to repeat the line. A live publication failure returns the shell's output, codes and evidence plus the store's classified fatal fact, with detail that effects may already have landed. It exposes no id or spill link. Shield an in-flight final commit under the store's cancellation rule and propagate cancellation after its fate is known. A process crash can leave effects without a published pair. There is no cross-mount transaction.

4. **Capture stdout as emitted and status as an owner-only UTF-8 JSON document.** Capture only bytes sent to the caller's terminal, after pipes and redirections, before replacement decoding. For stdout, use `src/vfs/models/media.py:108` to detect a known binary signature first. Otherwise strict UTF-8 with no NUL is text, including empty text; anything else is bytes of the sniffed type or `application/octet-stream`. Use the normal `content` or projected `data`, `source`, MIME type, byte count and SHA-256 body measurement (`src/vfs/models/version.py:71–85`). Give both immutable files version 1. Preserve Python's `stdout` and `stderr` strings. The status file uses `source="text"` and `application/json`. The status document has `command` (submitted text), `exit_code`, `statuses`, `stderr` (the shell's returned text) and `stages` as arrays parallel to the top-level status vectors. Each stage has `program` (expanded command name or null for a compound without a command word), `callable_kind`, `resolved`, `content_hash` and `exit_code`. Encode the resolver's machine library, shipped host program, host tool and stored file as `library`, `host_program`, `tool` and `file`. The evaluator can also report `builtin`, `function` or `compound`. An unresolved command has a null class. No executable file means a null executable digest. A missing or shell-local name has no resolved path. For an executed stored file use the path and hash from the same read that supplied the executed bytes, even if it moves later. Distinguish that digest from the stdout file's digest. Carry the actual executed identities with the evaluator's status reports, including the final inner pipeline when it supplies a compound's vector (`crates/vfs-shell/src/machine/exec.rs:375–438`). Do not parse the submitted text again or append unbounded per-iteration traces. A terminal abort keeps only completed vectors, any emitted bytes and the terminal exit code. Status excludes input bodies, environment, authority proofs and H0's internal records. Its command, streams and attribution stay solely in these private files.

5. **Keep the T2 tables private to the kernel store.** Add `vfs_kernel_runs` keyed by `call_id`, holding the 64-character `owner_key`, owner publication sequence, expiry, ready/retired state, charged bytes and for each of the two files its size, digest, source, MIME and page count. Use a unique index on owner and sequence, an index on (owner, state, sequence), one on (owner, state, call id) in bytewise path order and one on expiry. Store the bodies in `vfs_kernel_run_pages(call_id, part, seq, data)`, primary key the first three columns, with `part` either `stdout` or `status` and contiguous zero-based sequence. An empty stdout has zero pages and an explicit zero-size descriptor. Encode compact UTF-8 JSON once, without an ASCII-only escape expansion where UTF-8 can represent a character, and charge its encoded length plus the raw stdout length. Use the job precedent's declared page and statement-byte bounds, private `RUN_PAGE_BYTES` (1 MiB) and `RUN_STATEMENT_PAGES` (16), further reduced by the store's row/bind budgets. Stream the pages from the captured data into each bounded insert. Metadata and both file projections become visible together. Never put stream or status bytes in H0's documented table. Bump the kernel format once at landing under store decision 8. The mount format does not change.

6. **Authorize the projection by the exact owner key before observing the body or the existence of a run.** Derive it anew from the effective actor and sorted subjects using session decision 6. Renewed credentials for the same owner work; an actor acting on behalf of a different subject set is a different owner. No system override, broad grant, parent posture or possession of the id widens this check. Retain normal router admission, masks, policies and projection validation. A hidden, expired, unfinished, retired or absent id gives the same `vfs.not_found` at a point, including a guessed suffix, before wrong-kind checks. When the caller has no visible record, echo only the submitted path in a not-found result, exactly as for a true miss. Join the authorized, ready, unexpired head to just the requested parts. A body read returns the whole selected immutable file in one statement snapshot, ordered by page; stream the result cursor in bounded fetches. At Postgres READ COMMITTED a second statement for the pages could race a sweep. Stat and directory listing fetch descriptors only. Apply the same check to batch paths, including caller-supplied observations carrying stale values or `data`. No cached observation, redirection, accessible alias or legacy mount row under the address can supply content by bypassing the view.

7. **Serve the run head and enumerate only this caller's visible files.** At the global `/.vfs` merge the constant `run` directory with served heads. A mounted storage's own `/.vfs` has no alias to the global run store. `ls /.vfs/run` shows live id directories in path order; `ls` of one shows `status` then `stdout`. `stat`, `read`, `tree`, explicitly scoped `glob` and `grep` use ordinary projection, wrong-kind, matching and page rules. Apply owner and expiry predicates before matching, clipping, counts and `next_after`. An anonymous or system reader sees an empty head. Unscoped search and traversal never enumerate the meta subtree. Ranked `search`, history and graph verbs on this served head are uniformly unsupported, without probing a guessed record. Mutations use the existing `vfs.invalid` path rule. Grant management remains on the real binding and cannot confer run ownership. These restrictions give `sed -n` and a scoped grep a file to read without exposing the entire audit table.

8. **Keep a completed record for at most 24 hours and trim an owner's oldest completions first.** Declare `RUN_LIFETIME` (24 hours), `RUN_RETENTION_CALLS` (64) and `RUN_RETENTION_BYTES` (64 MiB). These are output retention targets, distinct from D43's saved job and D52's analytics lifetime. Record `expires_at = store.now() + RUN_LIFETIME` on publication. Equality means absent. Reads never refresh age or order. Keep the newest contiguous suffix whose count and total charged bytes fit, retaining the latest completion whole even if it alone exceeds the byte target. An oversize completion stands alone until it expires or a later completion replaces it. There is no cross-principal eviction. A small completed line can evict a large old one. This preserves a truthful path on the publishing call, with an explicit one-record exception to T2's byte target.

9. **Serialize publication per owner and reclaim in bounded commits.** In the completion transaction increment and return the sequence in `vfs_kernel_run_owners(owner_key, seq)` by atomic upsert before retention is judged. The SQLite writer or Postgres owner row lock covers this commit only. Read at most `RUN_RETENTION_CALLS + 1` ready descriptors for that owner in descending sequence, including stale ones; retire stale descriptors and the suffix outside decision 8, setting their expiry no later than the transaction's clock. Mark only the selected ids, chunked by `store.key_chunks`. All previously ready heads, even unswept expired ones, are inside that count by induction. Eviction immediately hides the pair; physical rows may await the operator's next store sweep. Register the store's dependent-first `expiry_sweeper` for pages then heads, followed by a bounded pass over empty owner rows. For that pass index candidate owners by a stored `expires_at` refreshed at each publication; lock each candidate owner in the same order as a publisher, recheck its expiry and absence of any head under lock and delete only if still empty. A concurrent publisher reuses or recreates the owner row. Its sequence only needs to be increasing while a head of that owner remains. Never retire or reclaim H0's row, a job's saved part or another owner's promise as a side effect. A sweep removes at most its passed `limit` physical rows per call including owners. No read performs cleanup or acquires a writer lock.

10. **A spill marker names a file only after that file can be read.** For a committed result, replace the bounded shell renderer's generic hint with `read /.vfs/run/<id>/stdout` when stdout is clipped, `read /.vfs/run/<id>/status` when only stderr is clipped, and both paths in that order when both streams are clipped. Track the source of removed characters when joining the streams, including a line crossing the boundary. Retain the renderer's canonical single marker, removed character and row counts, whole-line prefix, facts and declared `RENDER_CHARACTER_BUDGET` on budgeted surfaces. An exactly fitting display has no marker. With no id keep the renderer's existing generic hint. A terminal binary stream with a committed descriptor displays the shared binary placeholder with its actual stdout path, MIME, size and version, even below the character threshold. Leave piping, file redirects and raw Python stream fields alone. A small uncut text result still carries its id in the typed result and wire payload, without adding a line to stdout. No marker, id or persisted output is needed merely to format a refusal that never ran. The memo's head-and-tail suggestion would change the standing whole-line prefix rule; a single readable file makes the tail available explicitly.

## Cost

Let `C` be eligible outer shell calls per day, `S` captured stdout bytes and `J` encoded status bytes. At the reference workload `C ≤ 150,000`; the actual fraction is unknown. Retaining all 150,000 outer ids for 30 days would mean 4.5 million heads before counting files. With 1,000 distinct owners, the count target bounds *visible* heads at 64,000. The byte target for that population is 62.5 GiB plus any excess of the single newest record per owner. Additional delegated owner identities count separately. Physical storage also includes expired and retired heads, pages, indexes and owners until sweep. If sweep never runs, stale bytes grow with total output. In the 4 KB median-file example, 150,000 lines each printing one such file produce about 600 MB of stdout in a day before status, separate from H0 retention.

One outer claim and one completion transaction per eligible call; a 10,000-file write inside a line is one line completion. Within completion the fixed work is H0 completion, owner upsert, one new head, one owner-window read of at most `RUN_RETENTION_CALLS + 1` metadata rows, and at most that many retirement ids passed through the membership budget. Let `P = ceil(S / RUN_PAGE_BYTES) + ceil(J / RUN_PAGE_BYTES)`. The page inserts are batched up to `min(RUN_STATEMENT_PAGES, rows_per_statement(parameter_budget, rows))` pages per statement, with at most one partial batch per part. All variable path/id lists use the store's live `membership_budget` and key-width helpers. SQLite and asyncpg both have finite bind limits (`AGENTS.md:62–64`); no per-body-byte or per-file-in-a-pipeline SQL. The store's retries rerun only its database transaction. A line whose programs only read still writes its *outer output* and may queue for the SQLite writer. After the store's first touch, a direct read, a nested read and a run file read acquire no writer for T2. An indexed run read fetches just the requested head and its pages; a keyset listing reads at most one owner's retained window. Explicit grep may inspect that owner's selected bytes, including the oversize exception, under the existing grep budget. The renderer and body classification take linear work in emitted bytes. Keep one raw output buffer plus the shell's existing decoded streams, status vectors, serialized status and at most a statement of page buffers. The machine already declares source, memory and output limits (`crates/vfs-shell/src/syntax/mod.rs:19`, `crates/vfs-shell/src/machine/mod.rs:43–79`).

Executed an independent SQL oracle on file SQLite and disposable Postgres. With two connections, an uncommitted pair yielded zero rows, then its owner saw two, a different owner saw zero, and expiry equality yielded zero. With count 2 and charge target 4, three two-unit publications for one owner followed by a five-unit publication left only the last one and the other owner's one-unit run visible. A fresh OS process on each database read the five bytes FF from the last run and found zero matches under the other owner. The oracle used a synthetic charged size, an atomic owner-sequence upsert and a joined visibility predicate. It did not implement VFS, page streaming or H0.

## Choices to confirm

1. **Kernel projection or ordinary owner-only entries; every line or spills only.** Taken: project every eligible completed line from the kernel store. It preserves T2's small-output contract and leaves ordinary namespace rows, grants and indexes untouched. Restricting later publications to spills can be done at admission without moving existing data. Expanding the projection to more private kinds would require a separate ruling.
2. **Scope and duration of output retention.** Taken: the 24-hour run lifetime and count and byte targets per owner, with the newest complete output retained on its own if oversized. A global pool lets one principal evict another's files. A hard single-record ceiling loses the only complete answer. The memo's 30-day lifetime applies only if chosen separately for output; the shorter output default follows T2's D43 background and avoids treating the analytics window as a promise to keep bodies.
3. **Anonymous output and the analytics opt-out.** Taken: no readable pair for an anonymous caller or a new line under `log=False`. A shared anonymous owner would expose command text across anonymous connections; keeping the files while logging is explicitly off would retain bodies without the H0 call from which T2 is defined. Per-connection authenticated ownership and a separately configured output-only mode can be added without exposing any previously private output.
4. **Availability of the H0 transaction seam.** The build of the integrated publisher waits for H0 to specify and supply a stable outer id and a certainty-bearing completion commit that can include T2's writes. Independent competing completion records have no reversible reconciliation after shell effects have run. No second action-log schema or substitute replay claim is chosen here.

## One line

A named caller can reopen its completed shell output by id on the same durable root, while every other owner sees a missing path.

# One bad row rolls back its mount’s batch, even at ten thousand rows

A draft, written on 2026-11-25 against `dev` at `27f3d24d`. It is not reviewed, and the new conformance family is not built. It serves [roadmap story K7](../../context/standards/roadmap.md), gate f, criterion 1 (`roadmap.md:194-198`). It converts [spec 179](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/spec.md), sections 7 and 8.2 and criterion 16, and [tasks 6 and 8](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/tasks.md). It rests on the landed write preconditions and the [conformance split](../2026-11-25-the-conformance-battery-is-split-by-kernel-operation-with-no-test-lost/spec.md).

## The outcome wanted

An ETL pipeline sends 10,000 good rows and one bad row to one mount. The answer names the bad row alone. The 10,000 good rows have no effect, even if the engine had already inserted them. The same 10,000 creates sent without the bad row land under one commit. With two mounts in one call, the pipeline can see which mount committed and which refused. The successful mount’s rows are durable and its observations stay in the answer.

## The problem

One commit per SQL page could leave half a night's batch in storage while reporting only the last page's error. A count of visible files would miss an overwritten body, a bumped parent version, an orphan edge or a changed grant revision. At 100 batches a night over one million files, the difference matters to the next reader and to any retry of the failed batch ([reference deployment](../../AGENTS.md), `:74-86`). The router already promises independent outcomes after its up-front checks (`src/vfs/base.py:983-988`). No existing cross-mount write test pins the merged answer against the two stores.

## Decisions

1. **Test one storage call through the storage method on each of the three conformance legs.** Add `AtomicityRows(ContractBase)` in `tests/support/contract/atomicity.py` and compose it into `StorageContract`. Use each leg's own `storage` fixture: memory, file SQLite and a private Postgres schema (`tests/storage/test_conformance.py:65-80`, `:102-116`, `:181-188`). The tests need a database handle for the image and the event listener. A fixture local to this mixin narrows the handle to `DatabaseStorage`, with an explicit skip for a third-party storage without that facility. All three served legs run every case, including memory with its own connection lifetime (`src/vfs/storage/backends/memory.py:40`). The generic dialect floor has no engine leg (`AGENTS.md:62-65`).

2. **Compare every stored value on the same isolated mount before and after the refused call.** Add the test helper `await full_image(storage)` in `tests/support/images.py`. On one fresh read connection select every column of every table in `storage._host.tables.metadata.sorted_tables`, ordered by all of that table's primary-key columns in declaration order. Return a mapping from table name to the ordered tuples of decoded row values, including an empty sequence for an empty table. Keep identities, timestamps, versions, content, bytes, labels and index rows. Include multiplicity. The mounted metadata supplies schema qualification. This extends the table walk at `tests/storage/database/test_refresh.py:117-123`. A metadata probe found 24 tables, each with a primary key, at this commit (`src/vfs/models/rows.py:279-306`). The oracle follows the metadata when a table or column is added. Engine catalogs, planner statistics and Postgres sequence positions lie outside this mount-table image. No second store could supply an exact reference for generated identities.

3. **Count the verb's outer commits at the engine.** Provision and seed first, require success of every setup call, then await `storage._host.settle_statistics()` before opening the image connection. Close that connection before invoking the verb. Install a SQLAlchemy `commit` listener on the mount's `storage._host.engine.sync_engine` for the duration of the awaited call and remove it in `finally`. Count every outer commit except one on a connection with the statistics pass's execution option `STATISTICS_NAME`. Keep savepoint releases out of the count. Detach the listener, settle background work, and read the after-image on a fresh checkout, including on the one-connection memory leg. The event counts outer commit attempts even when a driver emits no SQL text into the statement trace (`tests/storage/test_conformance.py:139-169`, `src/vfs/storage/backends/database/engine.py:462-467`, `:881-888`). The data check independently proves what landed. This measures the existing commit-on-success runner at `src/vfs/storage/backends/database/backend.py:1465-1497`.

4. **Reject one attributable error and compare the complete answer and state.** In each fatal case require `success is False`, empty `observations`, exactly one record in `errors` with severity `error`, the kind and path below, zero commits, and equality of the full images. When the bad input names two paths, check the second address in `data["vfs.target"]` where shown (`src/vfs/results/envelope.py:251-288`). One valid sibling must do real work if sent alone. Use distinct files and edges under existing shallow parents. Seed an unrelated text body with a prior version, a bytes body, a tombstone and an authored edge so a change outside the target directory is observable. Seed named grants before the image. The small width costs little and distinguishes the source's refusal kinds.

| Storage call | Good input | Bad input and single expected refusal |
| --- | --- | --- |
| `write(entries=…, parents=True)` | A text overwrite, a create with a missing parent and a bytes create | File under a live file. `vfs.wrong_kind` at the blocking ancestor, with the requested child in `vfs.target`. |
| `write(entries=…, if_absent=True)` | Fresh files | Existing live file. `vfs.exists` at the occupied path. |
| `write(entries=…)` | Material overwrite | File entry at an existing directory. `vfs.wrong_kind` at the directory. |
| Named `write(entries=…, parents=True)` | Material overwrite by a principal with `read_write` at the root | File under a file. Same ancestor and requested-child attribution as the system call. |
| `edit(observations=…, edits=…)` | Each file matches the same replacement exactly once | Text without the old string. `vfs.invalid` at the unmatched file. |
| `delete(observations=…)` | Live leaf files | Absent path. `vfs.not_found` at that path. |
| `move(operations=…)` | Distinct live sources to unused destinations | Missing source. `vfs.not_found` at the source. |
| `copy(operations=…)` | Files copied to distinct unused destinations | Live source to an occupied destination. `vfs.exists` at the destination, with the source in `vfs.target`. |
| `mkedge(edges=…)` | Fresh authored edge triples with live endpoints | One missing target. `vfs.not_found` at that endpoint. |
| Named `rmedge(edges=…)` | Existing triples whose source the principal may modify | A visible, read-only source. `vfs.permission_denied` at that source. |
| `restore(observations=…)` | Distinct tombstoned file roots under a live parent | A live file. `vfs.exists` at that file. |

The storage signatures and the verdicts follow `src/vfs/storage/backends/database/backend.py:693-1015`, `staging.py:226-245`, `topology.py:165-190`, `trash.py:280-327`, `edges.py:149-157` and `tests/support/storage_contract.py:821`. A missing triple in `rmedge` has a different verdict. Submit an existing and an absent triple together, with both endpoints live and distinct. Require success, exactly one `deleted` observation for the existing edge, one `vfs.not_found` warning for the absent edge with source path and target field, one commit, and removal of just that authored edge on a fresh read. This pins the mixed outcome left open by the already-landed second-removal test (`edges.py:207-248`).

5. **Exercise a refusal after actual application writes.** Seed a live file at `/bad`; obtain its current precondition and submit a material overwrite of it after all good creates. At `write:before-apply`, once, use `attempts` and `clearing` from `tests/support/commit_worlds.py:129` and the current attempt's session to advance only the bad row's version and change its hash, following `tests/storage/database/test_writes.py:1986-2007`. Use the landed precondition spelling under Builds on. The precondition was true during staging. The creates execute before the bad row's guarded update (`src/vfs/storage/backends/database/writes.py:471-479`, `:521-541`). Use `after_cursor_execute` and the compiled insert's table identity to count successful entry inserts on the actual mount, including a schema-qualified Postgres mount. The seam itself issues only an update. Require at least one such insert, one seam visit, one `vfs.conflict` at `/bad` with `retryable is False`, and all the checks of decision 4. This stages a change inside the tested transaction so the full image must also recover the bad row's original values. No independent writer changes the baseline.

6. **Use 10,000 genuinely good inputs plus a final bad input, and separately require 10,000 good creates under one commit.** Declare `BATCH_ROWS = 10_000` in the new family as the K7 acceptance width. Mark these cases `slow`. Run decision 5 at this width. Also run a natural bad-child write with 10,000 fresh creates, and a precondition already stale at entry. For the latter, seed 10,001 files, collect their preconditions, advance the last file before taking the baseline, and request a different body for every file with its original precondition. The new precondition case checks the image and commit on all legs. The existing SQLite-specific no-mutation-statement test stays under Builds on. Run the seven other plural verbs of decision 4 at this width with one bad input last. Use one pair per transfer, one observation per file and one distinct authored triple per edge. Keep the extra small write variants small. For the all-good write, start with an empty, precreated target directory and distinct bodies derived from each file's index. Require one outer commit, success, no errors, exactly the 10,000 expected `created` observations, and exact equality of stored live path/body pairs with the input on a fresh read of `entry` joined to `content` (`src/vfs/models/rows.py:308-310`, `:454-465`). K7 counts rows and commits independently.

7. **Pin the mount boundary through one public `AsyncVirtualFileSystem.write(entries=…)` call.** Use an `InMemoryStorage` at the root and a second at `/right`, where `/right/taken` is a live directory. Submit files at `/a`, `/right/b` and `/right/taken`. All pass the router's argument and mount checks. Require failure, exactly the `created` observation at `/a`, and one `vfs.wrong_kind` error at `/right/taken` with `source == "/right"`. Count one commit on the root and zero on the child, read the submitted body at `/a`, and require the child's exact before-image including the standing directory and the absence of `/right/b`. Settle both hosts before both image reads. No assertion depends on which mount finishes first. The router groups and merges the calls at `src/vfs/base.py:2470-2518` and preserves observations beside errors at `src/vfs/results/envelope.py:565-603`. A gate refusal before dispatch would test a different boundary.

## Cost

The image and the listeners live in tests. Across the reference deployment's 150,000 daily agent calls, 100 nightly batches and ten-million-file rebuild, the added production statements, locks and bytes held are zero. No read queues behind the oracle. The transaction and the lock lifetime on each engine stay those of the existing verb. In a test, two images of the isolated mount cost `2 × len(metadata.tables)` selects, 48 here, with no bound parameters. They retain two copies of the fixture's row values, proportional to its total payload. Bound the fixture by `BATCH_ROWS`, shallow paths, one short body per file, and the fixed sentinels. Never run this table scan against a shared corpus. Report the first differing table, primary key and column instead of rendering the whole image.

For the workload under measurement, a membership lookup of N keys uses `ceil(N / host.membership_budget)` chunks. An insert of N homogeneous rows uses the host's parameter budget and `rows_per_statement`. These bounds come from `engine.py:250-257` and `dialects.py:541-548`, `:573-587` under `src/vfs/storage/backends/database/`, including SQLite's narrower variable limit and asyncpg's bind limit (`AGENTS.md:60-64`). Use `chunked` for any seed or verification query that takes the fixture's keys. No test introduces a fixed SQL page width. The large transfer cases also pay the existing pair loop (`topology.py:165-244`). A memory probe of shallow distinct pairs counted 118 statements with eight good pairs plus one bad and 230 with sixteen, for both verbs. At the observed slope, about 140,000 statements per 10,000-pair test; this is an estimate for that fixture, not a production or Postgres budget. Seed the files, deletes and edges in batches. Run the expensive parameter cases independently so each releases its fixture before the next.

## Choices to confirm

1. **How should the late write lose its guard?** Use a one-shot change on the attempt's own session on all three legs (decision 5). A real competing connection on Postgres would commit an independent change between images and require a different oracle. The chosen fixture works on one-connection memory, exercises the real guarded update and can be replaced on a single leg without changing the contract.
2. **How should an exact image be represented?** Keep typed row tuples ordered by each table's complete primary key (decision 2). The archived source sorted tuples of printable representations. Every current table declares a key, decoded values preserve bytes and timestamps, and the representation remains private to test support. A disk-backed representation can replace it if a measured fixture needs one.

## One line

A refused mount batch returns only its bad row’s error and restores every stored value, 10,000 good creates commit once, and a successful sibling mount keeps its rows.

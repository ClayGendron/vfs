# Study: serve() auth, a token in, an Authority out, and nothing identity-shaped on the wire

## Verdict

live-0.1.0. Nothing of the edge is built: no `TokenVerifier`, no `authority_from_token`, no `serve` extra, and `provenance="edge"` is a value no code mints (EXECUTED: grep over `src/`, `tests/`, `pyproject.toml` at HEAD 0ed462f returns no hit for `TokenVerifier`, `authority_from_token`, `joserfc`, `attested`, `allow_open`, `def serve`). The roadmap places the spec as story I1, gate b, and MCP ships with 0.1.0 (READ, `context/standards/roadmap.md:377`, `:1071`, `:100`).

Of the spec's six numbered rules, only rules 1 and 2 and the door token belong to this spec at conversion; rule 3 and the open-mount refusal belong to story I2 (spec 171's conversion), rule 4 to story I4 (spec 170's), and rule 5 to story M3 (INFERRED from the story headings, READ `roadmap.md:387`, `:408`, `:786`).

## Against the tree

- `src/vfs/authority.py` holds `Principal`, `Authority` (frozen, slotted dataclass), four doors `of`, `on_behalf_of`, `system`, `anonymous`, and `Provenance = Literal["edge", "constructed", "system"]` (READ, `src/vfs/authority.py:40`, `:116-186`). No door returns `provenance="edge"` (READ, `:157`, `:173`, `:180`, `:186`).
- The module docstring already promises "the edge factory that turns a verified token into an authority" that does not exist (READ, `src/vfs/authority.py:18-19`); the roadmap records the same dangling sentence (READ, `roadmap.md:368`).
- The reserved names exist: `SYSTEM_NAME = "system"`, `ANONYMOUS_NAME = "anon"`, `EVERYONE_NAME = "*"`, `GROUP_NAME_PREFIX = "group:"`, `MAX_SUBJECTS = 64` (READ, `src/vfs/authority.py:44-60`). These are the four `sub` values I1's claim table refuses.
- The one-construction-site pin exists as a grep test over `src/`: a bare `Authority(` outside `authority.py` fails it (READ, `tests/base/test_authority.py:246-259`). It is a text pin, not the door token; a bare `Authority(...)` from app code or a test still constructs (READ, `tests/test_authority.py:119-121` constructs bare instances to test invariants).
- `vfs.unauthenticated` exists as an `ErrorKind` with a contract row; today it is produced only by the rights compile for an anonymous caller below a posture's rung (READ, `src/vfs/results/kinds.py:70`, `:183`; `src/vfs/storage/backends/database/rights.py:391-401`).
- The ladder is six rungs `none, list, read, add, contribute, read_write` (READ, `src/vfs/ops.py:117`). The spec's `open`, `shared`, `private` posture words do not exist in the tree (INFERRED from the `Rung` literal; READ, `roadmap.md:369`).
- Groups resolve on the spine through a `memberships` table with `add_member` and `remove_member` verbs (READ, `src/vfs/models/rows.py:361`, `src/vfs/base.py:1691`).
- `provenance` and `source_identity` of an `Authority` are persisted nowhere: the only other `provenance` in `src/` is the edge row's author class `user|agent|system` (EXECUTED: grep; READ, `src/vfs/base.py:1170`, `src/vfs/models/rows.py:104`). The audit distinction rule 2 argues for has no sink until story H0's action log, whose row carries "actor, subjects and provenance" (READ, `roadmap.md:278`).
- `Result.to_payload` / `from_payload` carry no authority field (EXECUTED: grep `authority` in `src/vfs/results/envelope.py` returns nothing). I1 criterion 6 therefore pins only that the token never serialises and that a result produced under an edge authority round-trips (INFERRED).
- No MCP package, no `serve()`, no `[serve]` extra: `pyproject.toml` optional dependencies list embedders, drivers and renderers only (READ, `pyproject.toml:49-70`).
- A door token is mechanically sound: a module-private sentinel as an `InitVar` of a frozen slotted dataclass refuses a bare construction with `TypeError`, refuses `dataclasses.replace` with `TypeError`, and lets `copy.copy`, `copy.deepcopy` and `pickle` round-trip with equality and hash unchanged (EXECUTED: scratch probe under the session scratchpad, `uv run python -I door.py`).
- Spec 070 landed `vfs/authority.py`, its doors and `vfs.unauthenticated` on 2026-09-06, and on the same day added `anonymous` as the fourth door (READ, `context/specifications/archive/070-principal-scoped-sessions/spec.md:3`, `:117`, `:127`). No dated archive spec from 2026-10-29 onward touches the edge (EXECUTED: listing of `context/specifications/archive/`).
- Spec 148 (`narrow`, `pending`) is a seed and unbuilt: `AsyncSession` has no `narrow` (READ, `context/specifications/active/148-sessions-narrowing-and-pending/spec.md:3`; `src/vfs/session.py:51-414`).

## Open choices, each verified

1. `groups` claim: read it as a hint the spine verifies, or ignore it. Lean: ignore (spec rule 1; roadmap D13 lean "Ignore", not marked Decided, READ `roadmap.md:1085`). Verification: holds. Precedent: groups resolve on the spine in the landed memberships table (READ, `src/vfs/models/rows.py:361`); the authz-engine lens resolves membership per query and rejects enumerating groups into literals (READ, `context/research/2026-09-05-permissions-lens-authz-engines-and-databases.md:120`, `:255`). The agent-native lens notes IdPs ship a flat groups result at login, which is evidence an IdP is a memberships table, not that vfs should trust it (READ, `context/research/2026-09-05-permissions-lens-agent-native-2026.md:133`).
2. A fourth provenance value `attested` for a subsystem-vouched member list, versus reusing `constructed`. Lean: add `attested` (spec rule 2; roadmap D14 lean "Add it", not Decided, READ `roadmap.md:1086`). Verification: holds. Precedent: the delegation lens takes Kerberos's two SIDs, "verified at the edge vs asserted by a subsystem", as the provenance class to record (READ, `context/research/2026-09-05-permissions-lens-capabilities-and-delegation.md:134`). Caveat, INFERRED: the value has no persisted reader until H0's action log, so its audit value is realised there.
3. Where `authority_from_token` lives: `vfs/authority.py` or a `vfs/serve/` package. No lean in the spec. Verification: holds-amended. Amended text: the claims-to-authority factory lives in `vfs/authority.py` as the fifth door, importing no JOSE library; the `TokenVerifier` protocol may sit beside it, and its `joserfc` implementation lives in the extras-gated MCP package spec 171 creates. Precedent: I1 criterion 5 requires every construction outside `vfs.authority` to raise, and criterion 2 requires the core install to import neither the verifier implementation nor the library (READ, `roadmap.md:381`, `:384`); the landed pin already treats `authority.py` as the only construction site (READ, `tests/base/test_authority.py:246-259`).
4. The door token: close the bare constructor now, or keep the grep pin until later. Lean in the spec: "judged overkill before the edge exists", i.e. close it when `edge` is first minted. Verification: holds. The roadmap adopts it in I1 criterion 5 (READ, `roadmap.md:384`); the mechanism is sound, `copy`, `deepcopy` and `pickle` round-trip and `replace` raises (EXECUTED, scratch probe). Precedent: none found in vfs or a memo; rests on the constitution's classified-error rule that a programming error is a raise, not a `Result`, as I1 states.
5. Which refusal kind a reserved `sub` gets. The spec says only "refused". Verification: holds-amended. Amended text: a `sub` of `system`, `anon`, `*` or a `group:` prefix is `vfs.invalid`; a verifier failure or a missing audience is `vfs.unauthenticated` (READ, `roadmap.md:382`). Precedent: the reserved-name constants and the group-prefix rule already in the tree (READ, `src/vfs/authority.py:44-60`).
6. Where `kind` comes from: "a declared claim or the client registration", with a `service` principal's sponsor recorded. No lean. Verification: needs-a-ruling. Needs a ruling: whether the verifier is configured with the claim name that carries the kind (default `user` when absent), whether the client registration is consulted, and whether a sponsor is recorded at all, since `Authority` and `Principal` carry no sponsor field (READ, `src/vfs/authority.py:77-126`) and I1's criteria name no kind or sponsor rule (READ, `roadmap.md:380-385`).
7. Issuer namespacing of `sub`. Rule 3 binds `(client_id, issuer, sub)` and rule 4 maps remote names as `(issuer, sub)`, but `Principal` carries `sub` alone (READ, `src/vfs/authority.py:77`). Not marked in the spec. Verification: needs-a-ruling. Needs a ruling: one issuer per `serve()` (a `sub` is unique by configuration), or an issuer-qualified principal name. Precedent on the triple: fastmcp's principal is `(client_id, issuer, subject)` (READ, `context/research/2026-09-05-permissions-lens-agent-native-2026.md:36`).
8. The carrier of a trusted subsystem's member list (unit 3): a token claim, an HTTP header, or the MCP request `_meta`. Not marked in the spec. Verification: needs-a-ruling. Needs a ruling among those three; rule 3 forbids a tool argument, and I2 criterion 5 counts no schema naming `authority` or `provenance` (READ, `roadmap.md:394`).
9. Rule 6's refusal shape: absent token. Already ruled: amended 2026-10-15 in spec 171 and carried by I2 criterion 3, an absent token is anonymous judged by the ladder and only an invalid token is 401 `vfs.unauthenticated` (READ, `context/specifications/active/171-the-mcp-adapter-and-the-cli-tool/spec.md:19`, `:46`; `roadmap.md:392`).
10. Rule 3, a session id bound to the triple. Already ruled: amended 2026-10-15 (spec 171) to per-request derivation with no sessions; D51 leans a per-principal stamp table, not a session handle (READ, spec 149 rule 3's amendment; `roadmap.md:1123`). This belongs to I2 and M1.
11. The open-mount refusal's meaning of "open". Lean (D15): refuse when any mount's root everyone-level is `add` or above. Not this spec's at conversion (story I2). Verification: needs-a-ruling is left to I2's conversion; recorded here only so the conversion does not carry the `open/shared/private` words (READ, `roadmap.md:1087`, `:369`).
12. Rule 5, `pending` as MRTR `input_required`. Lean (D9, D10): vfs carries `pending`, never asks. Not this spec's at conversion (story M3, gate f). Verification: not judged here; the spec's own fallback "served tools are `complete`-only" matches spec 171 (READ, spec 171 `spec.md:54`).

## Notes for the conversion

- The roadmap decisions this spec cannot be built without: D13 (groups claim), D14 (`attested`), D35 (JOSE library). None of the three is marked Decided; each carries a lean (READ, `roadmap.md:1085-1086`, `:1107`). D15 is needed by I2, not by this spec.
- Keep the factory pure: claims in, `Authority | ResultError` out. Verification (signature, issuer, expiry, audience) is the verifier's, so the factory is testable over a table of claim dicts with no keys (INFERRED from I1 criteria 2 to 4).
- Scale: the edge runs once per verb call, about 150,000 a day at the reference deployment (READ, `AGENTS.md`, the reference deployment's per-verb multiplier). Verification must be in-process against cached keys, never a round trip to the issuer per call; a JWKS refresh is per key rotation (INFERRED). No statement is issued by the factory.
- `MAX_SUBJECTS = 64` bounds unit 3's member list; a list above it is `vfs.budget_exhausted.authority`, the kind the tree already has (READ, `src/vfs/authority.py:60`; `src/vfs/results/kinds.py:89`).
- Unit 1 touches the four existing doors and every test that constructs a bare `Authority`; the grep pin at `tests/base/test_authority.py:246` is extended, not replaced.
- The enumeration defence (unknown principal and wrong proof indistinguishable) has precedent in the Plan 9 lens (READ, `context/research/2026-09-05-permissions-lens-plan9.md:180`) and should be a criterion: an unknown issuer, a bad signature and an expired token produce the same `vfs.unauthenticated` payload.
- The non-goals stand: no issuance, no login, no IdP, no transport; cross-app access and token vaults are I4 and T7 territory.

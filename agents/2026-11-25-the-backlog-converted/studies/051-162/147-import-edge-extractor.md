The type is a module constant, not a parameter: generalising the publisher to an edge type is still to do (READ `links.py:24`, `:122`, `:137`).
- The stamp pair is one pair on `vfs_entry`: `link_source_hash String(64)`, `link_generation String(32)` (READ `src/vfs/models/rows.py:456-459`). `link_generation()` returns `f"md:{LINK_GENERATION}"` with `LINK_GENERATION = 2` (READ `src/vfs/models/links.py:37`, `:62-64`). A composite `md:2+py:1` fits the 32-char column (INFERRED).
- The pass is `chunk_dirty`, one slice a transaction, the body read once and handed to the offload hop `_assess_and_split`, which calls `extract_link_work` (READ `src/vfs/storage/backends/database/indexing.py:237-354`, `:684-727`). Both `rebuild` and `refresh` run it through `_chunk_pass` (READ `src/vfs/storage/backends/database/maintenance.py:527`, `:574`, `:609`).
- Every row the slice reads is stamped with the link pair whatever its extension (READ `indexing.py:323-332`), and the generation-law probe `_stale_generation` compares `link_generation` against the one running value with no extension term (READ `indexing.py:644-652`). So any bump of the link generation re-reads every chunked body once (INFERRED): at the reference deployment that is 10,000,000 body reads on the next `rebuild`, the per-corpus multiplier, affordable once a day and nowhere else (READ `AGENTS.md`, reference deployment, "Per corpus").

## Units proposed

The three slices land apart only in the sense that A without B mints nothing; A alone is dead engine code to the coverage gate's eye unless pinned by its oracle, which it can be. Two units, then.

1. `python import statements are read by an engine kernel`: "The engine returns every Python import statement in a batch of bodies, with its module path, imported names, relative level and folded referring line, and nothing found inside strings or comments." Gate 0.2. Depends on spec 138 (archived, landed) and nothing unbuilt. Rewrite depth: amend (protocol 15 to 16; the batch shape follows `markdown_refs`, `src/vfs/native.py:130-139`). Source: spec 147 Scope (kernel), Slice A, Decided semantics 4.
2. `python imports become imports edges in the index pass`: "`rebuild` and `refresh` mint one `imports` edge per resolved source-to-module pair, weight the statement count, replace only a re-extracted source's extracted `imports` rows, and report unresolved imports in an info record beside the links leg." Gate 0.2. Depends on unit 1, and on the two rulings below. Rewrite depth: amend (names `reindex`, the graph verb, the golden-set criterion and the stamp facts changed). Source: Decided semantics 1-3, Slices B and C, Landing criteria.

A small build could fold both into one unit; the split keeps the Rust protocol bump and the schema-free publisher change reviewable apart (INFERRED).

## Open choices, each verified

1. Which package roots the Python resolver tries (`[NEEDS CLARIFICATION]`, spec.md Decided semantics 2). Options: (a) the parent of the file's topmost `__init__.py` package and the mount root only; (b) those plus a fixed `src/` root the resolver declares; (c) those plus a list declared per mount. No lean is stated; the text leans toward (b) in "any `src/`-style layout the resolver declares". Precedent: vfs's markdown resolver uses a fixed two-root order with no configuration (READ `src/vfs/models/links.py:103-124`); the `src` layout is the Python Packaging Authority's documented layout (packaging.python.org, "src layout vs flat layout"; not fetched here). Evidence: on this repository, (a) leaves the 798 test-to-`vfs` import lines unresolved (EXECUTED/INFERRED above), so (a) fails the spec's own corpus check. Between (b) and (c): (c) adds a mount configuration surface, a product choice. Verification: holds-amended for (b): "the resolver tries, in order, the file's own package for relative imports, the parent of its topmost package, the mount root, and `/src`; no per-mount list in this spec". Precedent: `link_candidates`' fixed root order and the PyPA layout. Whether a per-mount list follows is left to a later spec. Note also that the "walk up while `__init__.py` exists" step is a database probe of ancestor `__init__.py` paths, at most depth-many per file, batched under the membership budget per slice, and PEP 420 namespace packages (no `__init__.py`) are missed by it (INFERRED); the converted spec should state both.
2. One stamp pair for all extractors or one per extractor (`[NEEDS CLARIFICATION]`, Decided semantics 3). No lean. Facts: the generation string is already prefixed `md:` (READ `links.py:62-64`), which anticipates the composite `md:2+py:1`; the chunker and the link extractor already hold separate pairs (READ `rows.py:453-459`), a precedent for one pair per derivation. Cost: with the current extension-blind probe and stamp (READ `indexing.py:323-332`, `:644-652`), either choice makes a bump re-read every chunked body once; only a per-extractor pair whose probe and stamp are scoped to that extractor's extensions confines a `py` bump to `.py` rows, at the price of two columns and a schema format bump (currently 27, READ `rows.py:139`) (INFERRED). Verification: needs-a-ruling. Needs a ruling: one composite generation on the existing pair (no schema change, every bump re-reads the corpus once on `rebuild`), or one pair per extractor scoped by extension (a schema change, a bump re-reads only that language's files).
3. Resolution order of `from a.b import c` when both `a/b/c.py` and a name `c` in `a/b.py` could be meant (Decided semantics 2 lists both; implicit fork). The spec lists submodule candidates first. Precedent: CPython's `from` import takes the attribute of the package first and falls back to importing the submodule (Python language reference, "The import statement"); the module file `a/b/__init__.py` or `a/b.py` exists in both cases, so preferring the submodule file when it exists is a path-only approximation (INFERRED). Verification: holds; precedent the import reference plus `link_candidates`' first-live-candidate rule (READ `links.py:113-124`, `storage/.../links.py:107`).
4. Edge weight as the statement count and the first referring line as `context` (Decided semantics 1). Precedent: `publish_links` folds a document's references to one target into one row with weight the count and context the first line (READ `src/vfs/storage/backends/database/links.py:96-131`). Verification: holds.
5. Unresolved stdlib and third-party imports counted on the info record (Decided semantics 2). Precedent: the links leg's `unresolved` count on one info record (READ `indexing.py:219-226`). Verification: holds-amended: the record carries `"leg": "imports"` beside the existing `"leg": "links"` record, one record per leg, so the existing record's shape and detail text are unchanged.

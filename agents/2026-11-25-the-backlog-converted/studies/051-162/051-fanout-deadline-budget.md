# Study: A deadline for fan-out, so one hung mount cannot stall the namespace

## Verdict

live-0.1.0, gate f, conversion by rewrite. The gap the spec names is still open at HEAD 0ed462f: no fan-out chokepoint has a time budget and nothing in `src/vfs` produces `vfs.timeout` (EXECUTED, grep below). ## Open choices, each verified

1. Mutations under a deadline (spec.md Scope bullet 3, `[NEEDS CLARIFICATION]`). Options: (a) no deadline on mutations; (b) wait but stop reporting; (c) a deadline with an "outcome unknown" kind. Spec lean: (a). Not ruled: the roadmap's form is itself marked "(lean)" and no D-row carries it (READ roadmap.md:351, §16 rows D1-D54). Verification: holds-amended. Amended text: "A mutating verb given `deadline=` is refused `vfs.invalid` at ingress, before any statement; mutations are never bounded by a fan-out deadline." The roadmap states this form (READ roadmap.md:351). Precedent: the settle rule that no sibling keeps mutating behind a caller who saw a failure (READ src/vfs/base.py:3038-3042); T4's rule that a call cut by the wall is issued once and never retried, so a cut mutation has an unknown outcome (READ roadmap.md:721); ingress refusal of an argument a verb does not take, as `overwrite=` leaving `write` was ruled (READ roadmap.md:1078, D7). Option (b) fails on its own words (it lies); option (c) needs a new kind, which H1 criterion 2 limits to exactly one new core kind for `pending` (READ roadmap.md:292) (INFERRED).
2. Where the budget lives (spec.md Scope bullet 4, `[NEEDS CLARIFICATION]`). Options: per-call kwarg, per-mount attribute, node default with per-call override, or both. Lean: none stated ("Possibly both"). Verification: holds-amended, as "a per-call `deadline=` on the read verbs; the per-mount transport wall belongs to the view that owns the transport (T4)". Precedent: H6 criterion 1 names `grep(pattern, deadline=…)` (READ roadmap.md:350); `Deadline` is passed as an argument and never stored on a long-lived object (READ src/vfs/deadline.py:14-15); T4 carries the per-server wall as `vfs.timeout` (READ roadmap.md:719); the MCP specification has the sender set a timeout per request (2025-06-18 basic lifecycle, "Timeouts": implementations SHOULD establish timeouts for all sent requests; recalled, not fetched here). A node-level default is not supported by any precedent found and is left out (INFERRED).
3. The public argument's value. Not a marker in the spec; it follows from choice 2 and the conversion cannot write a signature without it. Options: seconds as a relative `float` (asyncio's `timeout(delay)`, `wait_for(timeout=)`, and vfs's own `close_timeout: float` at src/vfs/base.py:373), or an absolute `Deadline` instance (asyncio's `timeout_at(when)`, gRPC deadlines; vfs's internal convention since 2026-11-07). The kernel ruling of 2026-11-15 names no deadline argument family (EXECUTED grep over context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md). Verification: needs-a-ruling. Needs a ruling: `deadline=` takes seconds from the call (float) or an absolute `vfs.Deadline`; both have engine and library precedent, and the frozen-surface rule (D2) makes the choice public at b1.
4. What a timed-out mount reports (spec.md Scope bullet 2): cancel stragglers, merge what settled, one `timeout` per unanswered terminal at the mount prefix, `success=False`. No fork stated; listed because it is the core semantic. Verification: holds. Precedent: H6 criterion 1 (READ roadmap.md:350); `_skip_entry` stamps the bind path as `path` and `source` (READ src/vfs/base.py:3059-3072); a downed peer's `backend_unavailable` record (READ src/vfs/base.py:2989).
5. Outer cancellation precedence (spec.md acceptance 4): an outer `CancelledError` re-raises untouched and outranks a timeout. Verification: already-ruled in effect: H6 criterion 3 (READ roadmap.md:352) and the landed `_gather_settled` precedence (READ src/vfs/base.py:3044-3048). Not a D-row ruling; recorded as holds-by-precedent in the structured summary.
6. No budget configured is today's behaviour bit for bit (spec.md acceptance 5). Verification: holds-amended, in the counted form "statement counts are identical to today on every leg" (READ roadmap.md:354); AGENTS.md *Performance tests* forbids timing assertions, so "returns within the budget" (spec.md acceptance 1) becomes "the slow coroutine is cancelled, counted = 1" with a fake clock patched on `vfs.deadline.monotonic` (READ archive/2026-11-07-bounded-work-has-one-home.md:199).

## Notes for the conversion

- Build the read unit on the landed `Deadline`: one `Deadline` per verb call taken at ingress, its `remaining()` cut where the gather starts (an `asyncio.wait` over tasks with that timeout, then cancel and await the stragglers), so the same fake clock drives it (INFERRED from src/vfs/deadline.py:9-17).
- Keep the two walls distinct: `WALL_TIME_BUDGET` expiry mints `vfs.truncated` for CPU stages; a fan-out deadline mints `vfs.timeout` per unanswered mount. The spec must say which wins when both fire in one call (INFERRED; no source decides it).
- Which verbs take `deadline=`: the read class that fans out (glob, grep, search, tree, ls over the root) at least; the conversion lists them against the 25 routed verbs and names each mutating verb that refuses it (INFERRED).
- Scale: the deadline adds no statement and nothing that grows with batch size; at 150,000 verb calls a day it costs one clock read per call (INFERRED from AGENTS.md reference deployment and archive/2026-11-07-bounded-work-has-one-home.md:171).
- A read never waits on a writer: a cancelled straggler must leave no open transaction on a server engine; the test counts a cancelled task and checks the storage session is released (INFERRED from AGENTS.md *Per lock* rules).
- The cancel unit is written after H1 and H4 specs exist; it inherits their names (`ticket`, `run_id`, `resume`) and D44's API shape.
- On landing of unit 1, R7 criterion 2's "spec 051 is replaced by H6" is satisfied by deleting this folder (READ roadmap.md:966).

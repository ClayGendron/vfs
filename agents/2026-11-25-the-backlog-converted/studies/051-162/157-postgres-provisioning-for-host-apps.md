# Study: Postgres provisioning for host apps — create the schema on first touch, choose the bulk path by driver

## Verdict

live-0.1.0. None of the spec's three behaviours is in the tree at HEAD: first touch creates no schema, a privilege refusal at first touch still classifies `internal`, and the bulk path is still chosen per dialect, so a psycopg 3 session factory reaches `copy_records_to_table` on a connection that has none. The roadmap places it as story D3, gate b, and its own acceptance list is wider than the spec (a SQL Server `aioodbc` refusal and a facade `install_extensions(path)`), so the conversion takes the roadmap's story as its scope.

One slice of the spec is overtaken rather than open: rule 3 (the extension step during provisioning) no longer applies, because first touch never installs pgvector; it probes for it and refuses naming the fix, and a separate developer-plane verb installs it (READ `src/vfs/storage/backends/database/dialects.py:541-552`, `src/vfs/storage/backends/database/engine.py:326-353`, `engine.py:633-661`).

The 2026-10-28 audit records it as unbuilt, with `install_extensions` covering the privilege half for the extension only (READ `context/research/studies/2026-10-28-the-0-1-0-roadmap-audits/02-storage-engines-and-dialects.md:113`). ## Units proposed

Three units; each lands green on its own (INFERRED from the disjoint code sites: `_verify_or_provision` and `classify_failure`; `bulk_insert`; the facade allowlist and a first-touch check).

1. Slug: first touch creates the mount's schema and names a privilege refusal. Title: "A mount with `schema=` on Postgres or SQL Server creates its schema at first touch when it is absent, and a role that may not create it is refused `unavailable` naming the schema and the privilege, never `internal`." Gate b. Depends on: story D2 by roadmap ordering only; decision D3 (MariaDB second tier, which keeps MariaDB out of schema creation). Rewrite depth: amend (the existence test before DDL, the line numbers, the 42501 predicate already built, the counted no-statement criterion for SQLite, MariaDB and Oracle from roadmap D3 acceptance 1). Source: spec §§1-2, §5's `vfs_nocreate` role, acceptance bullets 1-2.
2. Slug: the bulk insert path follows the driver on the connection. Title: "A bulk insert takes asyncpg's binary `COPY` only when the connection's driver is asyncpg; a psycopg 3 session factory runs the conformance contract and lands a 10,000-file write through Core in at least two counted pages." Gate b. Depends on: nothing beyond the tree. Rewrite depth: amend (`bulk_insert` is the current helper; the `assert` moved; `vector_version` replaces `pgvector_version`; the bench path; a second Postgres URL in `tests/conftest.py`, the workflow and the db_test skill). Source: spec §§4-5, acceptance bullet 3.
3. Slug: host-app provisioning edges on SQL Server and from the facade. Title: "A borrowed `mssql+aioodbc` factory without `use_setinputsizes=False` is refused `invalid` at first touch naming the argument, and `install_extensions(path)` runs one mount's install from the facade." Gate b. Depends on: unit 1 (shares the first-touch site), decision D2's freeze rule only in that a new facade name is an addition. Rewrite depth: rewrite (not in the spec; the content comes from roadmap D3 acceptance 4-5 at `roadmap.md:478-479`). Two independent halves; the writer may split it if a reviewer prefers one behaviour per unit.

## Open choices, each verified

1. Schema DDL issued unconditionally (`CREATE SCHEMA IF NOT EXISTS` on Postgres) — spec §1, decided in the spec, not a marked lean. Verification: holds-amended. It FAILS as written against Postgres's documented order (permission before existence, `schemacmds.c` as cited above), which would refuse a least-privilege role on a host-made schema. Amended text: "When `schema=` is set and `Inspector.has_schema(schema)` is false on the first-touch connection, issue the profile's `schema_ddl`; when it is true, issue nothing." Precedent: the tree already tests before DDL (`_has_meta_table` before `create_all`, `engine.py:680`, and `create_all(checkfirst=True)`); SQLAlchemy `Inspector.has_schema` (EXECUTED present in 2.0.52). The `IF NOT EXISTS` form stays as the race guard for two first touches on a fresh database.
2. A `DialectProfile.schema_ddl` field rather than SQLAlchemy's `CreateSchema(if_not_exists=True)` — spec §1. Verification: holds. Precedent: AGENTS.md "Lean on SQLAlchemy; keep profiles lightweight" admits a profile field for a decision SQLAlchemy takes no position on; the spec's reason (one compiled text that SQL Server rejects) is an engine fact; existing profile fields carrying per-engine statements (`vector_function.install`, `file_settings`, `range_settings`, READ `dialects.py:541-556`). SQL Server's `EXEC('CREATE SCHEMA ...')` wrapper follows from `CREATE SCHEMA` having to be the only statement in its batch (SQL Server documentation for CREATE SCHEMA; INFERRED from engine behaviour, not fetched here).
3. The kind of a first-touch privilege refusal: `unavailable` (spec §2 and roadmap D3 acceptance 2, `retryable=False`) or `permission_denied` (what the tree's own `install_extensions` answers for the same SQLSTATE, `engine.py:347-351`). Verification: holds. Rationale with precedent: the kind contract defines `permission_denied` as "the caller is known and may not", with the hint "Target a path this caller may access, or request access" and a path referent (READ `src/vfs/results/kinds.py:71`, `kinds.py:189-194`); a database role lacking `CREATE` is the deployment's condition, not the vfs caller's rights, and the named-fix `unavailable` refusal of a missing vector function is the precedent (`engine.py:657-659`). The roadmap is later than the spec and keeps `unavailable`. Note for the conversion: the two refusals of one SQLSTATE then differ in kind; Needs a ruling: whether `install_extensions` should move to `unavailable` for consistency or keep `permission_denied` because it is an explicit developer act; this spec need not change it.
4. 3F000 `invalid_schema_name` "keeps `unavailable` and names the schema" — spec §2. Verification: holds-amended. Today it is `unavailable` with `retryable=True` and a generic detail (READ `engine.py:411`). Amended text: "3F000 at first touch classifies `unavailable`, `retryable=False`, with `data["schema"]`." Precedent: a missing schema is not cured by retrying, the same reasoning as the never-retry missing-function refusal (`engine.py:657-659`); INFERRED that after unit 1 a 3F000 at first touch is reachable only on a dialect with `schema_ddl` None (Oracle user absent) or a race.
5. Extension step tolerance — spec §3, marked resolved on 2026-10-08. Verification: already-ruled, overtaken. First touch never installs pgvector; it probes and refuses (`dialects.py:541-552`, comment "a precondition first touch never installs"), and `install_extensions` is the explicit install (`engine.py:326-353`). The conversion drops rule 3.
6. psycopg 3 in `"driver"` mode — spec §4, a fork taken only after `bulk_insert_bench.py` shows it winning; lean: `"core"` for every non-asyncpg Postgres driver. Verification: holds. Precedent: the 2026-07-14 posting-storage memo records psycopg 3 using its native `executemany` under Core (READ `tests/fixtures/ranking/vfs_native/corpus/context/research/2026-07-14-database-storage-posting-storage.md:144`, a corpus copy of the memo); AGENTS.md "Count operations, never wall-clock time" keeps the measurement in a bench, out of scope here. The ADR 056 §6 citation leans on a retired record; the bench lives at `context/research/studies/2026-08-26-bulk-inserts/prototype/bulk_insert_bench.py` (EXECUTED find).
7. Store the chosen mode on `EngineHost.bulk_insert_mode`, since no logging convention exists — spec §4. Verification: holds. Precedent: `EngineHost.vector_version` and `value_cap` are first-touch facts held on the host (READ `engine.py:210`, `engine.py:602`). INFERRED amendment: `bulk_insert` takes the session's dialect, not the host, so the single producer `bulk_insert_mode(profile, dialect)` is what `bulk_insert` calls; the host attribute is a read of the same function for the test pin.
8. Borrowed `mssql+aioodbc` without `use_setinputsizes=False` refused `invalid` at first touch — roadmap D3 acceptance 4, marked "lean". Verification: holds. Precedent: the `_string` docstring names the engine kwarg as the bind-side half of non-Latin1 losslessness (READ `src/vfs/models/rows.py:178-187`); `invalid` is "the caller's input is wrong and the caller can fix it" (READ `kinds.py:78`). How first touch reads the setting off a borrowed engine (`dialect.use_setinputsizes` on the live dialect) is INFERRED and must be confirmed against SQLAlchemy's mssql+aioodbc dialect when the unit is written.
9. `fs.install_extensions(path)` joins the management allowlist — roadmap D3 acceptance 5, no lean marked. Verification: holds. Precedent: the backend verb exists (`backend.py:1098-1115`); rests on the roadmap's acceptance text. Decision D2's freeze lean is the additive rule, which an added name satisfies (READ `roadmap.md:1074`).

## Notes for the conversion

- Take roadmap story D3 as the scope; spec 157 supplies items 1-3, the roadmap items 4-5.
- Unit 1 must test for the schema before issuing DDL (open choice 1); its acceptance gains a case: a pre-made schema plus a role with schema-level `CREATE` but no database `CREATE` serves its first write on Postgres. The `vfs_nocreate` init role then needs two variants or two grants: one with no rights (refused) and one with schema rights only (served).
- The privilege carve-out reuses `is_insufficient_privilege`; it belongs at the first-touch classification, ahead of `is_permanent_defect`, scoped to first touch so a 42501 elsewhere is not silently reclassified (INFERRED; the predicate's docstring already says it is checked before the defect classes, `dialects.py:1075-1077`).
- Scale and lock posture: one existence probe and at most one DDL statement per mount lifetime, inside the first-touch transaction that already holds the Postgres advisory lock (`engine.py:738-741`); no per-call or per-write cost (INFERRED against AGENTS.md's reference deployment multipliers).
- Rule 3 is dropped; the pgvector precondition is already the tree's design.
- Decisions this needs from roadmap §16: D3 (MariaDB's tier; the row carries the lean "Second tier" and is not marked Decided, READ `roadmap.md:1075`) bounds which engines create schemas; D2 (the freeze rule, decided in part 2026-11-15) bounds the facade addition in unit 3. D19 rides only through story D2's ordering.

# Study: Text program kernels, the measured text programs in Rust behind their Unix names

## Verdict

live-0.1.0, for slices 168a and 168b; 168c (`diff`, `cmp`) is placed at 0.1.x by the roadmap's not-in-0.1.0 table and is live but outside the 0.1.0 gates. Nothing of the spec is built, and nothing it stands on is built: the whole `vfs.shell` package of spec 167 is absent at HEAD, so the spec is a plan for the story F6 at gate f, after F4.

Its design stands, with four amendments forced by later landings and rulings: the kernel object may not hold a deadline (the 2026-11-07 bounded-work landing), the protocol number has moved from 10 to 15, the oracle walk does not descend into subpackages, and the `awk`/`jq` refusal hints may not promise an arrival the roadmap now puts at 0.2.

Precedent: the spec's own decision 1 (programs with too little measured use are not Rust kernels, `spec.md:9`), and 167's never-class refusals with hints (READ `167/spec.md:84`). INFERRED share: 26 of the measured segments, under 0.04% (the spec's figure, `spec.md:119`).
2. `sed -i ''` (BSD) beside GNU `-i[SUF]`, `cut -c` by characters, bytes crossing the pipe raw: already-ruled. Decided 2026-10-15, decisions 4, 5, 6 of the spec (`spec.md:12-14`); 167 decision 3 says the same of raw bytes (`167/spec.md:21`).
3. `awk` and `jq` as wasm programs, no Rust awk, no `jq` forms kernel: already-ruled. Decided 2026-10-15, decisions 2 and 3 (`spec.md:10-11`). The timing "until 169 lands" is overtaken: T6 is 0.2 unless D22, and D22's lean is ship without (READ `roadmap.md:1094`).
4. The `awk` refusal hint "awk arrives as an installed program" and the `jq` hint "naming the installed `jaq`" (`spec.md:61-62`). Verification: HOLDS-AMENDED. At 0.1.0 nothing installs `awk` or `jaq` (D22's lean), so a hint that promises one misleads. Amended text: "`awk` refuses `vfs.unrecognized`, exit 127, hint: for a line range use `sed -n 'A,Bp'`, for a field use `cut -d D -f N`; `jq` refuses the same way, hint: read the file and parse it in the caller." Precedent: 167's never-class hints point at the served alternative (`perl -pi` to `sed -i`, `git` to `stat`'s version), READ `167/spec.md:84`.
5. D34, the 0.1.0 program table: all of 167, 168a and 168b in; 168c, `awk`, `jq` out. Lean: as stated. Verification: HOLDS for the program part. Precedent: the measured tiers (READ `experiments/r168/call_tiers.out`, cited by `spec.md:21`: 139 of 13,746 calls) and the roadmap's §15 row for 168c (`roadmap.md:1063`). The shell spellings of `grant`, `revoke`, `grants` are F4's, not this spec's.
6. F6's capacity fallback: 168a ships as Python transforms inside F4 and the Rust port moves to 0.1.x (`roadmap.md:663`). No lean. Verification: NEEDS-A-RULING. Needs a ruling: whether the Rust port of the six and the four new kernels is in 0.1.0 (gate f) or 0.1.x, with Python transforms in `src/` serving the names until then. Both keep every name (the roadmap says so) and AGENTS.md permits a Python program as the only implementation where no kernel exists yet; it is a schedule choice, not a design one.
7. The seam's deadline: `TextKernel(..., deadline: float | None)` stored at construction, "as `ContentMatcher` takes it" (`spec.md:126,138`). Verification: FAILS. It contradicts the landed law that a deadline is never stored on a long-lived object (READ `src/vfs/deadline.py:14-15`), and `ContentMatcher` in fact takes a per-call `budget` (READ `src/vfs/_native.pyi:65-72`). The precedent determines the alternative: the constructor takes no deadline; `feed`, `end_input` and `drain` each take `budget: float | None`, cut by the Python layer from the stage's `Deadline` with `remaining()`, and the binding converts it with `Deadline::after` (READ `python.rs:124,144`).
8. `xargs -P N` accepted and run serially (`spec.md:102`). Verification: HOLDS. GNU findutils documents `-P max-procs` as "Run up to max-procs processes at a time", so one at a time conforms; POSIX defines no `-P`. Precedent: the GNU findutils manual, xargs invocation. INFERRED: D47's lean admits bounded concurrency inside a call, so a later form may run batches concurrently without a name change.
9. `xargs` exit statuses: 0, 123 for a child exiting 1 to 125, 124 for 255, 126 and 127 from resolution (`spec.md:103`). Verification: HOLDS. Precedent: GNU findutils xargs "Exit Status" (the same codes; 125 for a signal-killed child, which the spec omits and the conversion may add). Spec 167's status table is the home (READ `167/spec.md:71`).
10. `ARGV_BYTE_BUDGET` 128 KiB as "GNU's own default `-s`" (`spec.md:97`). Verification: HOLDS. GNU `xargs --show-limits` reports a 131,072-byte command buffer on Linux; precedent the GNU findutils manual for `-s`. It is a protocol-like constant from an external system, consistent with AGENTS.md's rule on caps.
11. `find -exec … ;` leaves `find` at 0 on a child failure and `-exec … +` makes it 1 (`spec.md:113`). Verification: HOLDS. Precedent: POSIX `find` (`-exec … ;` is a primary evaluating to the utility's status; `-exec … +` sets a non-zero exit status if an invocation fails) and GNU findutils.
12. The external merge sort as the future direction, "through `/.vfs/run` scratch" (`spec.md:162`). Verification: HOLDS-AMENDED. The direction is right (AGENTS.md: name the future direction, never a declared limit), but `/.vfs/run` is now T2, "the `/.vfs/run` record, as rows" (READ `roadmap.md:700`), not a scratch area. Amended text: "The docstring names the future direction, an external merge sort over bounded runs; where the runs live is that work's choice."
13. Recorded GNU fixtures from `scripts/record_shell_fixtures.sh` on the Ubuntu CI image (`spec.md:151`). Verification: HOLDS-AMENDED. F5 and F7 already require "one pinned-image script" for every shell fixture (READ `roadmap.md:656,645`); the amended text uses that one script and a pinned image, never a floating CI image whose coreutils can drift. Precedent: 167 slice E (`167/spec.md:173`) and the roadmap.

## Notes for the conversion

- Roadmap decisions this spec cannot be built without: D34 (the program table; a lean, needed by F4), D22 (whether `awk` refuses or a wasm host exists; a lean), D4 (Decided 2026-11-15: `delete` keeps its name, so `find -delete` calls `delete`). D47 (bounded `&`) and D54 (nondeterministic words) touch `xargs` only through F7 and H4 and do not block it. READ `roadmap.md:1076,1094,1106,1119,1126`.
- The durable run reaches unit 3: each `xargs` batch is a child dispatch the executor must key as `(stage, ordinal)` under F3 criterion 10 (READ `roadmap.md:629`), and a child that suspends on an ask (H5, D12's lean of exit 75) needs a row in `xargs`'s status mapping. INFERRED: 75 is not in 1 to 125's 123 bucket by intent, so the conversion states whether a suspended child suspends the `xargs` stage.
- F7's `while read -r line` serves part of what `xargs` serves; the measured `xargs` uses (52) stand, so the builtin stays. INFERRED.
- Production posture: every core either streams with at most one partial line held or counts its buffer against `MEMORY_BYTE_BUDGET`; pins count chunks, bytes across the seam and dispatches, never the clock (AGENTS.md, Performance tests). The 10,000-line `sort | uniq -c | sort -rn | head -5` pin (criterion 4) is the scale anchor and stays.
- `find -delete` batches by `ROWS_PER_CHUNK` (1,000), which already sits at Oracle's 1,000-element `IN` floor; the `delete` verb's own chunking is the binding cap, so the criterion counts `delete` calls, not statements. INFERRED from AGENTS.md's production posture.
- The two exceptions (`UnsupportedForm`, `InvalidForm`) would be the crate's first `create_exception!`; the conversion names where they are declared in `_native.pyi` and that `native.py` gains nothing (`spec.md:139`, consistent with `native.py`'s dispatch rule).
- No code comment or docstring may cite 167 or 168 by number (AGENTS.md, Code comments); the spec's "the Python form of spec 167" wording stays in the spec.

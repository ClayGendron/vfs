## Open choices, each verified

1. §3.4, `owner_id` at the read rung (lean) or only to `read_write` holders and the owner. Verification: holds. Precedent: POSIX `stat(2)` returns `st_uid` to any caller who can reach the file, with no read permission on it (POSIX.1-2017, `stat()`: "Read, write, or execute permission of the named file is not required"); roadmap F4 criterion 1 prints `owner_id` in `ls -l` for any lister (READ, `roadmap.md:634`); `docs/explanation/ownership-and-attribution.md:15` documents the column as a plain row fact. The stricter rule would add a rights fetch per listing on the verb-call multiplier (AGENTS.md, reference deployment, per verb call). The bare row stays `{path, kind}` (READ, `reads.py:1161-1165`).
2. §4.4, keep `observations=` as the row-addressed plural (lean) or replace it with `paths:`. Verification: holds. Precedent: the landed seam addresses rows by `path | observations` and the 10,000-row batch contract rides it (READ, `src/vfs/storage/protocol.py`; AGENTS.md, production posture); the router-keeps-routing landing kept the name on every verb (READ, archive spec `:3`).
3. §9, flat names or namespaces. Verification: already-ruled. Decided 2026-11-15: flat; the groups are documentation and freeze nothing (READ, `roadmap.md:1077`, D5; rulings spec decision 4, `context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md:59-61`).

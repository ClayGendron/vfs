## Open choices, each verified

- **§3.6, the time to live** (marker). Lean 24 hours. already-ruled: decision 10 of `context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md:83-85` and D11 (`roadmap.md:1083`): 24 hours, the default of a per-storage setting.
- **§6, `idempotentHint` on a tool whose verb has a form that applies twice** (marker). Lean: withhold. already-ruled: the same decision 10 and D11, "withhold". Whether append is served as its own tool is spec 171's choice (READ, decision 10).
- **§3.8, where the stored answer lives** (fork, A chosen). Lean A: a row in the mount, claim first, the whole answer packed in pages. HOLDS. It is consistent with the constitution's one `Result` and with AGENTS.md's bounded statements (one key or one page per statement). Precedent: the roadmap already builds H0, H3 and H4 beside this store, in the root binding's storage, and takes its claim-first shape (READ `roadmap.md:278`, `:322`); eve hands each call a replay-stable key and expects a re-issued 10,000-file write to be a no-op (READ `context/research/2026-09-15-eve-vercel-agent-framework.md:277`); MCP 2026-07-28 has no idempotency mechanism (READ `context/research/2026-08-10-mcp-2026-07-28-stateless-revision.md:59`).
- **§3.4, the claim comes first and a second send of the same key waits on it**. HOLDS-AMENDED. The wait falls only on sends of the same key, which are the same logical call, so no other caller queues behind it, and this keeps AGENTS.md's per-lock rule (INFERRED). Precedent: H4 adopts the same shape (READ `roadmap.md:322`). Amended text: "The claim row is a lock only sends of the same key need. The conversion names it under the reference deployment's per-lock rule. A counted test on every server engine shows that, while one keyed batch holds its claim, a read, a keyless write and a keyed write with another key each return." The SQL Server read of an uncommitted claim is covered by the drafted snapshot-read spec (READ `context/specifications/active/2026-11-15-on-sql-server-a-read-never-waits-on-a-write.md`).
- **§3.4 step 6, a failed `Result` is not stored**. HOLDS. Precedent: `_mutate` commits iff the batch succeeded (READ `backend.py:1469`, `:1495-1497`), so a failure left nothing to replay. The run ledger's step rows keep failures by their own rule, which the roadmap marks as different from the replay store (READ `roadmap.md:295`).
- **§3.4, the look-up comes before the rights gate**. A hit is served without a fresh judgment, to the same caller only. HOLDS. Precedent: none found in a vfs code path. It rests on the atomic-unit rule that an answer describes a committed change, and on §3.2's caller scope. The conversion states its order against the 2026-11-14 fence (look-up, then `fenced(fn)`).
- **§3.2, the anonymous caller may not use a key**. HOLDS. Precedent: none found; it rests on §3.2's own rule that keys are scoped per principal, and every anonymous caller is one principal (INFERRED).
- **§3.3, a reused key with other arguments refuses `invalid` and never describes the stored call**. HOLDS. Precedent: the `invalid` kind's contract, "the caller's input is wrong and the caller can fix it" (READ `src/vfs/results/kinds.py:79`).
- **§2.1, the key's alphabet: 1 to 255 printable ASCII, no space**. HOLDS. Precedent: `MAX_PRINCIPAL_ID_LENGTH = 255` is the house width for a caller-chosen identifier (READ `rows.py:142`). The IETF Idempotency-Key draft could not be fetched from this session (datatracker.ietf.org is outside the allowed network), so it is not cited.
- **§3.6, the replay marker is an `info` error entry, not a `Result` field**. HOLDS. Precedent: `info` is "advisory (capability skips, rollups); never a failure" (READ `kinds.py:115`). `merge` drops extras (READ `envelope.py:557-587`), and K4's criterion 3 has `Result | Result` clear even the declared `next_after` field (READ `roadmap.md:166`).
- **§3.6, the entry's `data` keys `vfs.first_at` and `vfs.expires_at`**. NEEDS-A-RULING, a small one. The kinds docstring says envelope machinery writes `vfs.`-prefixed keys and producer keys are unprefixed (READ `kinds.py:52-57`), yet producers already write `vfs.target` and `vfs.trashed` (EXECUTED, the probe). Needs a ruling: prefix the replay store's keys, as the `vfs.trashed` family does, or leave them bare (`first_at`, `expires_at`) as the docstring's producer rule says.
- **§1.1, the occupant mask: `kind` alone for a list-only caller**. HOLDS-AMENDED. Precedent: 2026-11-12 "the scan tier reveals nothing about rows a caller cannot read" and the active 2026-11-14 spec on a miss beneath a hidden row. Amended text: "A caller who cannot list the occupant gets no occupant facts, and the refusal is the one a hidden row answers today."
- **§1.5, a removal of what is already gone: relation rows succeed with a warning, a path refuses**. HOLDS. Precedent: today's code (EXECUTED, the probe; spec appendix A), POSIX `unlink` answering ENOENT, and the `not_found` kind's ENOENT mapping (READ `kinds.py:64`). The deletes spec may change where tombstones live (READ `context/research/2026-11-15-deletes-tombstones-and-a-move-that-keeps-its-identity.md:53-67`). It does not change the rule, only the `delete` and `restore` rows' data.
- **§4, the reclaim arm as two whole `DELETE ... WHERE expires_at < :now` statements until spec 180**. HOLDS-AMENDED. Roadmap K5 criterion 5 accepts the two whole statements (READ `roadmap.md:175`). But at the reference deployment a day can hold up to 100,000 expired head rows (READ, kernel rulings spec `:138`). On SQL Server a statement holding 5,000 locks on one table escalates to a table lock (READ `context/research/2026-09-04-mssql-membership-reads.md:197`). That lock would stall every keyed claim for the length of the delete. Amended text: "The arm deletes in windows from the start: `SELECT request_id ... ORDER BY expires_at` with a limit of at most `membership_budget`, then the two deletes by `request_id IN (window)`, repeated until a window comes back empty. Each statement stays under the escalation threshold, and spec 180 adopts the arm as its `replays` phase unchanged." That needs a roadmap edit to K5 criterion 5.
- **§5.2, `retryable` is true only for a keyed in-doubt call; retry class `refresh`**. HOLDS. Precedent: appendix C's executed probe (aiosqlite raises `connection_invalidated=True` at a closed commit). Oracle's Transaction Guard exists for this fault, known from prior knowledge and not fetched here, so the converted spec should cite it only after reading its page. `RetryClass.refresh` is the house class for "re-read state first" (READ `kinds.py`, the `KIND_CONTRACTS` table from `:158`).
- **§5.3, no server-side resolution of a keyed in-doubt call**. HOLDS. Precedent: none found in a vfs code path. It rests on AGENTS.md's per-lock rule: a server-side probe would hide the engine's wait on the dead transaction inside the call.
- **§2.2, a cross-mount keyed batch stores one slice per mount under the same key**. HOLDS. Precedent: a cross-mount batch is atomic per mount (the atomic-unit promise, roadmap domain A goal, READ `roadmap.md:112`).

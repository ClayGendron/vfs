# A stored WebAssembly command runs under the caller's rights and the line's budgets

A draft, written on 2026-11-25. It is not reviewed, and nothing of this unit is built. Checked against `dev` at `27f3d24d` for [roadmap T6, gate 0.2](../../context/standards/roadmap.md), converted from [169b](../../context/specifications/archive/169-programs-the-index-and-the-vfs-views/spec.md). It rests on PATH lookup, the executable bit, the line's budget and the Python guest's caller-bound file operations.

## The outcome wanted

On a base install of 0.2, `PATH=/work/bin:$PATH upper.wasm in out` runs the executable stored as `/work/bin/upper.wasm`. From the same directory, `./upper.wasm in out` runs the same bytes. Its input, output, exit and refusals belong to that stage of the pipeline. A read-only caller can transform stdin and print the result. A guest attempting a forbidden write receives an errno and the caller sees which write failed, even if the guest exits zero. A guest that loops without calling the host can still be stopped.

## What the code does today

There is no generic module loader, preview1 import adapter or wasm extra (`pyproject.toml:49–64`, `crates/vfs-core/src/shell_binding.rs:295`). The shell rejects the system actor, starts its own module and returns `stdout`, `stderr`, `exit_code` and `statuses` (`src/vfs/shell/host.py:137–165`, `:212–233`). A public read can already project `data`, `source`, `size_bytes` and `content_hash` beside the path (`src/vfs/base.py:802`, `src/vfs/models/entry.py:450–461`).

Executed on file SQLite and disposable Postgres with the same core command stored at `/bin/p.wasm`. Below `list`, the named session's read returned `vfs.not_found`. At `list`, stat exposed only path and kind, and read returned `vfs.permission_denied`. At `read`, the body was bytes, MIME `application/octet-stream`, version 1. A same-bytes write reported `unchanged` and retained version 1. Revocation restored `vfs.not_found`. Dev's `PATH=/bin p.wasm` returned 127. A prototype after the successful read ran the bytes' exported `_start` using Wasmtime 51.0.0 and an in-memory compiled module. First and second authorized runs compiled once in total on each engine. The revoked read reached neither instantiation nor the populated cache.

A separate Wasmtime 51.0.0 prototype on this checkout exhausted exactly 41 fuel units in a loop (`OUT_OF_FUEL`, zero left). Manually advancing the epoch before invocation gave `INTERRUPT` with all 41 left. A one-page memory under a one-page cap returned −1 from growth and kept 65,536 bytes. A cap one byte below the minimum refused instantiation. Explicit `unreachable` produced `UNREACHABLE`. A prototype `path_filestat_get` import on a Wasmtime worker posted two real session stats onto the event loop on in-memory SQLite. With revocation between them it returned success and size 5, then `NOENT` and no size. Two fresh processes using the Python binding with a 512 KiB stack compiled a simple core module and exited zero. Setting the Rust embedding's 4 MiB stack value through the Python binding instead ended the subprocess by signal 11. These probes used a temporary adapter; they did not run a stored command through dev's shell.

## The problem

A stored program needs two independent rights judgments. Reading an executable admits those bytes once. It cannot authorize a later path opened by the guest. The shell's engine also trusts its own embedded module, while the bytes of a stored command, their import names, requested memory and execution time all come from the caller. At ten million files, neither program startup nor a relative open can afford a directory scan to find one path.

## Decisions

1. **Decided 2026-11-25: add a host for binary WASI preview1 commands at gate 0.2, over `vfs-core`'s own Wasmtime embedding.** WASI preview1 is the system-call ABI imported as `wasi_snapshot_preview1` by wasm32 programs. Build the host as a new private module of `vfs-core`'s `python` feature beside the shell's embedding, on the same `wasmtime` crate 51.0.0 with the same engine settings: fuel, epoch interruption, the async stack, the store limiter and the slice thread (`crates/vfs-core/Cargo.toml:24`, `crates/vfs-core/src/shell_binding.rs:287–292`, `:337`, `:378`). Like `ShellMachine`, it runs the guest in slices and returns each storage-facing preview1 call as a request from `step`, taking the reply on the next step, so a guest call reaches Python only as a request that 172-1's dispatcher answers on the event loop and Wasmtime never calls into Python. The preview1 imports are hand-written over that protocol (decision 7); no `wasmtime-wasi` crate, no Python `wasmtime` binding and no `wasm` extra. The host is part of the required extension, so a base install at 0.2 runs a stored command and there is no missing-extra refusal. A native host that fails to start gives `vfs.unavailable`, 126. Reason: AGENTS.md places the engine in the project's own Rust crate with no second runtime; the shell's module already runs under exactly these limits; each wasi-python release requires exactly one `wasmtime` major (0.1.0 49, 0.1.1 to 0.1.5 50, 0.1.6 51), so a Python binding pinned here would conflict with the Python guest's runner at every bump that is not made in step (`wasi-python==0.1.0` beside `wasmtime==51.0.0` has no solution); and the Python binding faulted with signal 11 at the shell's 4 MiB stack (facts above). With no Python binding in this unit, it constrains no pin of 172-1 or 172-3. If D49 lands an accepted generic runner first, run this same import, rights, resource and status contract against it before using it behind this private boundary. A result about a specially prepared QuickJS artifact alone does not admit arbitrary stored bytes.

2. **Choose the interpreter from the authorized source and bytes.** Use the single execution-time read from 169-2, including `executable`, `source`, `kind`, `content`, `data`, `mime_type`, `size_bytes` and `content_hash`. Check admission and the bit before format or cache. A visible file without the bit gets Permission denied, 126. Hidden or missing at use gets 127. Text goes to executable-bit decision 5 and the Python shebang extension in 172-1 decision 2, including foreign-interpreter 126 even for a file named `x.wasm`. A bytes source starting with hex `00 61 73 6d 01 00 00 00` is a candidate, with any basename or stored MIME, including old octet-stream rows. A versioned component or another WebAssembly version is `vfs.unsupported`, 126. A truncated header, or other bytes claiming wasm by suffix or MIME without the header, are `vfs.invalid`, 126. Other opaque bytes keep 169-2's unsupported-format 126. Validate the complete module before it runs. No WAT text, filename stripping, second program read, MIME-based admission or fallback to another PATH entry after an execution-format failure.

3. **Link only the command ABI and instantiate a fresh store.** Accept a core binary with a `_start: () -> ()` export and ordinary unshared wasm32 linear memory exported as `memory` when imports access guest memory. Require correct preview1 function signatures. Reject unknown imports, imported memories/tables/globals, shared memory, memory64, multiple memories, reactors and component modules before executing initialization. A well-formed unserved ABI gets `vfs.unsupported`, 126. Malformed binaries or mismatched function signatures get `vfs.invalid`, 126. Install the store limits, fuel, interrupt and imported functions before instantiation, since a core start section can already call imports. Invoke `_start` once after successful instantiation. No host directory, socket, subprocess, host environment, native WASI default implementation or tool door is linked for a stored command. Trust never comes from a module name. Decision 12's packaged-guest profile is the one exception, admitted by a shipped digest and never for stored bytes.

4. **Carry the invocation and bytes through the shell's stage.** Pass the expanded command word as `argv[0]`, including its slash spelling, followed by the stage arguments in order. Use only the stage's exports, cwd and open pipeline streams. Capture bounded stdin through EOF before taking the guest slot. Empty stdin is successful EOF. Drain stdout and stderr separately as bytes through the stage, decoding only at the existing terminal boundary. A downstream guest can collect input while waiting for its own slot. The host pump allows the shell to consume output or close a pipe while its producer runs. An emitted chunk is acknowledged or refused by the pipe before admitting a later guest file operation. A reader's close ends the still-writing producer at 141, with no cancellation warning. Save the expanded word, class `file`, resolved path and SHA-256 of the executed bytes in the existing stage identity shape. Never expose another caller's path or hash on a miss.

5. **Keep cacheable code separate from per-run capability.** Compute SHA-256 over the admitted bytes, using VFS's `ContentHash` format (`src/vfs/models/entry.py:57`). Refuse a conflicting supplied digest as `vfs.unavailable`, 126. Key compiled code by digest, runtime version, target/CPU and engine-configuration fingerprint, including fuel, epochs and proposal switches. Use a private byte-bounded least-recently-used cache of trusted serialized modules in the worker's memory. Account for keys, entry overhead and serialized lengths. Evict before retention, skip oversize artifacts and let a zero cache ceiling disable caching. Only deserialize bytes produced by this embedding. Discard a bad entry and compile once from the authorized body. A restart begins cold. A cache entry holds no path, session, linker, descriptor, stream, store, authorization or exit state. This retains the archive's warm-run saving without introducing a persistent host-native executable format or a shared cache filesystem.

6. **One generic guest at a time runs in a supervised worker process per service process.** Queue asynchronously under the original line deadline, within the existing line admission limit. Start the worker without inheriting a live VFS router, database connection or caller credential. Its only application access is a bounded, typed byte-message channel to the calling event loop. Use a fresh request key per run, monotone callback ordinals, checked message lengths and a closed set of replies. The parent keeps the admitted session and line context, including policy, hop allowance and guards. It executes one requested operation at a time; the worker cannot set authority or select a method by arbitrary attribute. Finish or cancel and settle every in-flight call before releasing the slot. Never replay a mutator on a lost reply. A queued cancellation starts no worker task. Interrupt active wasm on cancellation or expiry. Kill and reap an unresponsive worker, including during native compilation, and discard its cache. No background guest outlives the line. The worker is a Python process that imports `vfs._native` and drives decision 1's host by `step`, forwarding each request over the channel and each reply back. This preserves the archive's single active guest and keeps the native compilation of caller-supplied bytes, which no epoch interrupts, killable.

7. **Serve the following preview1 imports with checked guest-memory access.** Use the preview1 types, little-endian layouts and descriptor rights. Check all pointers, lengths, offsets, iovec counts, result slots and arithmetic against live memory and remaining host budgets before copying or dispatching an effect. Out-of-range guest memory gives `FAULT`, bad scalar/encoding or flags give the appropriate preview1 `INVAL` or `ILSEQ`, an invalid descriptor gives `BADF` and a missing descriptor right gives `NOTCAPABLE`. Rights reductions and renumbering preserve or reduce capability. A declined operation performs no ambient host call. The archive's b2 and executed import inventory in [the module spike](../../context/research/studies/2026-10-15-agent-shell/10-wasm-program-spike.md) are the ABI precedent.

8. **Resolve every guest path within the virtual root before consulting storage.** Decode strict UTF-8 and validate both endpoints and all components. A raw absolute argument to a descriptor-relative import or a climb above the virtual root is `NOTCAPABLE`, before any verb. A libc absolute path addressed relative to fd 3 works normally. Relative climbs from fd 4 may reach the virtual root. Check raw and normalized components for `.vfs`, including on nested mounts or before a later `..`; return `NOENT` with zero verbs and omit the segment from listings, counts and cookies. For an ordinary opened directory descriptor also enforce its inheriting rights, without allowing traversal outside its preopen. Refuse ambient links. For each path use only 172-1's public session dispatcher. `path_filestat_get` is a fresh stat. Directory opens check the directory as caller, then list in bounded pages at the first readdir. Include `.` and `..`, serve byte-counted preview1 dirents using fd-local cookies, and use only strictly advancing VFS page keys. Keep any guest-visible replay of a page within the staging budget. Opening again starts a new rights check. `mkdir`, type-checked guarded non-cascading delete, and the single replacing move have the exact semantics of 172-1 decision 5. A directory as file is `ISDIR`, a non-directory ancestor `NOTDIR`, and a missing parent `NOENT`. A read-only mount, nonempty directory and cross-mount move retain their original facts.

9. **Stage whole file contents and guard each commit by that descriptor's observed identity.** An ordinary file open reads one admitted row with its source, bytes and vid. A directory-kind read failure can establish a directory descriptor for read, never one for writing. An existing truncate requires an admitted row with its source and vid and commits a guarded empty write at open. A bare list-only row supplies no authority to read or replace its contents. An exclusive create uses one create-only empty write at open, never a check followed by unconditional create. A nonexclusive create on a target miss tries exclusive create; on a competing create re-open once under the original flags and return the classified outcome. Neither creates parents. Read/write/seek then use the descriptor buffer. A fresh open must pass its own gate even if another fd already holds the bytes. `fd_sync`, `fd_datasync`, dirty close and ordinary exit write as the current caller with the captured vid. A successful flush advances that fd's guard and clears dirty. A rival change, replacement at the same path, move, or revoked grant cannot redirect a flush. For append-only descriptors keep only the pending tail and use a single guarded append at flush; no append of a full staged body. A positioned overwrite or truncate uses guarded replacement. Apply 172-1 decision 7's binary/text rules. Clean close issues no verb. Flush remaining dirty fds once in descriptor order on normal return or explicit exit. After a terminal budget, cancel, broken pipe or trap, discard uncommitted buffers, report the stop and retain earlier commits. Do not submit a final write beyond a terminal decision.

10. **Give each run finite limits before the first byte of code runs.** Reuse the line's absolute deadline, output ceiling, concurrent-line admission and verb counter. Debiting a public verb is atomic and precedes dispatch, including lookup, executable read, every page, kind probe, retry and flush. Charge one actual dispatch once, including on refusal. Start, feed, local descriptor access and the callback wrapping a verb do not debit it again. From a remaining allowance of N, at most N calls may reach the router; the next one ends the line with 137 before any effect. Sibling stages share that balance. A separate callback allowance also bounds locally refused paths, stub calls and zero-byte transfers. Reserve guest fuel from remaining line fuel, taking at most the guest ceiling. Include instantiation, report consumed fuel and return unused shares only upon verified settlement. An unknown final balance consumes its reservation. Install finite limits on linear memory, tables, instances and stack. Count shell and guest reservations together wherever they consume the same line allowance.

| Declared ceiling | Initial value and accounting |
|---|---|
| `wasm_fuel`, `module_memory_bytes` | At most 2 billion guest instructions per invocation, as in 172-1, and the configured line module-memory allowance (dev default 256 MiB). Reserve only the remaining share. One instance, at most one memory and one table. For a module with a table, cap elements at the smaller of its declared maximum (if any) and floor(module allocation / 128), and reserve eight bytes per allowed element before setting the memory limit. Without a table, allocate the full share to linear memory. A minimum that exceeds an effective cap is a classified budget stop before startup. |
| `wasm_staging_bytes`, `wasm_transfer_bytes` | Archive defaults of 256 MiB staging and one staging ceiling of cumulative transfers per run. Effective live staging is also bounded by the line's remaining host-memory allowance. Charge inputs, module bytes, staged bodies, argv/env, directory records, fd slots, pipes, serialization and simultaneous copies before retaining them. Meter guest-facing copies even when a single byte of a large file changes. Refuse an oversized body before copying it into the adapter. |
| `wasm_host_calls`, `wasm_open_files` | Initially the line's declared verb ceiling for attempted imports and 256 live fds inclusive of stdio and preopens. Debit each import, even one doing no verb. On a tightened fd cap below the five initial slots, refuse startup on budget. Never allocate a sparse vector up to a guest-supplied fd. |
| `WASM_CACHE_BYTE_BUDGET` | Host-only compiled-cache retention, initially the archive's 1 GiB per generic worker. Bound the input to compilation by the remaining staging and transfer budgets. The cache cap is separate from an active store. |

Before entering the guest phase, pause the shell slice, reserve from its actual remaining fuel and live memory, and limit subsequent shell or sibling growth to the unreserved balance until the reservation is released. Reconcile store fuel before each handoff so the same instructions cannot be granted twice. Use constructor ceilings and tighten-only `limits=` as in the line spec. Refuse an increase before start as `vfs.invalid`. Use the shell embedding's 4 MiB wasm stack with its matching async stack and the slice thread's known stack size (`crates/vfs-core/src/shell_binding.rs:38`, `:291–292`, `:337–341`), configured before engine creation. The same maximum on the Python binding ended its process by signal 11 in the checked runtime, one reason decision 1 sets that binding aside. A store growth beyond its hard limit may return failure to the program. Distinguish a known host limit from a subsequent unexplained guest panic. On the first import or allocator boundary that would exceed a guest ceiling, record its cause before unwinding; no next host call is necessary to make it visible. The line's deadline covers queueing, body load, compilation, cache work, initialization, callbacks, pipe waits and worker teardown admission. Native compiler memory and storage-side hydration are separate from guest linear memory and adapter retention.

11. **Classify once and retain what the stage already produced.** Use 172-1 decision 9's complete `WASI_ERRNO` by kind family and keep original VFS facts beside the numeric errno. Negative probes are bounded evidence. For a refused mutation keep the stage, phase, path and original kind once, even if the guest ignores errno; stderr identifies each distinct refused path within the existing evidence budget. An otherwise zero exit then gives stage 1. Keep the unmodified guest exit (or null on trap) with a failure as specified by 172-1. Preserve an explicit nonzero guest exit as its low eight bits and keep the full preview1 unsigned exit in guest evidence. A local guest ceiling ends that stage. Exhausting the shared line counter or crossing its absolute deadline ends the line. A fuel or verified resource stop gives 137/`vfs.budget_exhausted`, an expired deadline 124/`vfs.timeout`, parent cancellation 130/`vfs.cancelled` (external task cancellation propagates after settlement). An ordinary unreachable or memory-access trap gives 134/`vfs.internal` with its trap code. A failed grow alone is not proof of a budget kill. Record terminal cause in run-local state before unwinding, preserve bounded prior stdout/stderr and follow the line's existing terminal precedence. A late trap, exit or error from cleanup cannot replace it. Unexpected worker failure is `vfs.unavailable` at startup and a classified internal abort during execution. No errno string matching or second attribution column.

12. **One host serves stored commands and, on D49's fallback, the packaged QuickJS module, through two admission profiles.** Decided 2026-11-25. Reason: one host keeps one errno, guard and budget path for every wasm stage, as 172-3 decision 4 asks, and the packaged contract is the one the spike's `qjs-run.wasm` is built to, so the same artifact can serve either route of D49. ## Cost

At the [reference deployment](../../AGENTS.md), 150,000 verbs/day and about 20/s peak serve 10 million files. An invocation adds one gated read of its selected program after the resolver's batched stat, independent of directory size. At G starts/day with V guest dispatches each the cost is G program reads plus G × V public verbs, including each guarded write and each listing page, plus lookup. At 1,000 starts of the five-call fixture below this is 5,000 routed calls including lookup. Warm and cold runs cost the same database operations. Same bytes save compilation, not authorization or the one body read. Hashing and IPC each cost linear work in the charged byte count. A backend may already hydrate one whole projected body before the adapter can reject its size. There is no ranged-body or total process-RSS guarantee.

For D visible children, a directory drain consumes the ordinary keyset pages plus any filtered pages, never a corpus scan. Each subsequent page costs a verb from the same allowance. File writes retain the engine's normal version and statement costs. A fresh create followed by a fill costs up to two versions, a truncating open plus a fill up to two changes on an old row. The SQLite writer lock covers each ordinary commit. No database lock or transaction spans guest execution or a pipe wait. No new SQL, schema, membership list or lock enters either engine or the generic floor. Per service process the extra retained state is at most one cache ceiling plus the one active guest's linear/table allocation, bounded staging and finite engine overhead. Queued guests hold only state charged to admitted lines. At peak, a slow guest can delay other guests in that process up to their own deadlines; independent reads and writes need no guest slot. The host's Rust code enters the base wheel under the 50 MB wheel budget of `scripts/ci.sh:25`; it adds no crate beyond the `wasmtime` the shell already links, and its measured size is recorded at the build.

## Choices to confirm

1. **Release order.** Take D22's cheaper-to-reverse side, 0.2 for arbitrary stored programs and installation. A later D49 decision can bring forward only the host required by QuickJS. A move to gate b waits for the spike result and the resulting release ruling; the 0.2 contract does not wait on an upstream commitment.
2. **Generic embedding.** Take `vfs-core`'s Rust embedding, the shell's engine settings and its step protocol, in a separately supervised worker, for stored commands and for the QuickJS fallback alike. The other side is the public Python binding `wasmtime` in a `vfs-py[wasm]` extra; it needs no Rust, but its pin must equal the major the Python guest's runner requires at every runner release or the extras stop resolving together, it faulted at the shell's stack size, and it would be a second wasm runtime beside the required extension. An accepted upstream generic runner may still replace the Rust host behind this private boundary after passing the same contract. A storage-facing API or second public runtime would make either replacement harder.
6. **Enablement.** Take the host in the base install at 0.2, since its code is part of the required extension and an extra with no distribution of its own cannot be detected after install (172-3 decision 2). The other side is an opt-in, either a small companion registration wheel as 172-3 decision 2 uses or a host constructor setting; adding either later changes no stored file and no verb.
7. **Worker process.** Take decision 6's separate worker running the native host. The other side is an in-process slice thread as the shell runs; it saves a process and the channel's copies but cannot kill a native compilation of caller-supplied bytes, and could be taken once compilation is measured to be bounded by the staging ceiling.
3. **Interpreter selection.** Take source kind plus binary core magic. Reserving the `.wasm` suffix regardless of source could change the interpreter of existing executable text; it also misses old extensionless octet-stream modules.
4. **Cache persistence.** Take a bounded worker-memory cache. A persistent host directory with trust checks, atomic publication and cross-process eviction could be added later. The initial choice gives up warm starts after worker restart without ever reading host-native executable artifacts from a shared directory.
5. **Initial resource ceilings.** Take decision 10's finite defaults, with one active generic guest, bounded callback/transfer work and a separate compiled-code allowance. Tuning these downward or raising constructor ceilings after measurement needs no stored change. A wider concurrency promise would first require a measured bound on compiler, store and staged memory per active guest.

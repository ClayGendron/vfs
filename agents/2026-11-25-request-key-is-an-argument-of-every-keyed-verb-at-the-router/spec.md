# Every keyed verb takes the same request key, and the router checks the mount before dispatch

A draft, written on 2026-11-25. It is not reviewed, and nothing is built. Checked against `dev` at `27f3d24d` for [roadmap story K5](../../context/standards/roadmap.md), gate b, unit 177-4. Converted from §§2 and 6 of [the archived replay contract](../../context/specifications/archive/177-replay-the-contract-and-the-request-key/spec.md) and task 7 of [its tasks](../../context/specifications/archive/177-replay-the-contract-and-the-request-key/tasks.md). It rests on the per-mount answer store of 177-3, the four public faces and the mount capability gate.

## The outcome wanted

A caller that loses a move's reply can send the same move with the same `request_key` from a synchronous or asynchronous file system or session. The same effective call by the same authority at the same storage within its retention window gets the first answer, including the original destination row, plus a `vfs.replayed` information record. A mount that cannot keep that promise answers `vfs.unsupported` at its mount path before any mutation runs. A caller can still send the ordinary keyless verb to that mount.

## What the code does today

Executed on dev against the installed package. Across the twelve candidate verbs there were 48 signatures on `AsyncVirtualFileSystem`, `VirtualFileSystem`, `AsyncSession` and `Session`. Zero accepted the key and zero of 142 parameter rows named it. A public `write(request_key="K")` raised `TypeError`. On in-memory SQLite, as the system actor, creating `/f` with `a` and sending the same keyless append of `+` twice left `a++` at version 3. On that storage each of two successive `set_posture("/", "read")` calls reported two relabelled rows, two statements and one relabel transaction. The returned count comes after the grant-row transaction (`src/vfs/storage/backends/database/backend.py:1291`, `:1317`).

Executed through the real router with two recording storages and a two-entry iterable. Paths `/z` and `/b/y` reached the root and child as `/z` and `/y`, once each, with no key keyword. Masking `write` on the child and repeating the call gave one `vfs.unsupported` at `/b` and zero dispatches on either storage. The frozen snapshot is `Mount`, created for the root, added at a child and replaced by `update_mount` (`src/vfs/mounts.py:79`, `src/vfs/base.py:319`, `:716`, `:530`). The optional trait protocol is `SupportsTraits` (`src/vfs/storage/protocol.py:514`).

## The problem

A lost answer makes an append or a move unsafe to repeat. A host with a stable call id needs one argument that survives every wrapper, including a session that fills the caller's authority. Passing the key as an ordinary keyword to an older storage can raise a Python exception. Dropping it there can apply the mutation twice. A 10,000-file write can also reach several mounts. Discovering at dispatch that the last mount cannot replay is too late to refuse the batch whole.

## Decisions

1. **Decided 2026-11-25: the public set follows the storage contract actually available.** Declare `KEYED_OPS: Final[frozenset[Op]]` in `src/vfs/ops.py`. Its first landing has `write`, `edit`, `mkdir`, `delete`, `restore`, `copy`, `move`, `mkedge`, `rmedge`, `grant` and `revoke`. The twelfth candidate is `set_posture`, the name at `src/vfs/base.py:1753`. Add it to that set, the four faces, the table and the tests together only if 177-3 delivers its public guarantee. Derive no membership from idempotence or write access. The current write gate also covers `sweep`, `add_member` and `remove_member` (`src/vfs/ops.py:68`, `:94`), outside the source's keyed set.

2. **Each listed method takes keyword-only `request_key: str | None = None`.** On both routers place it before `authority`, on both sessions after existing arguments with no authority override. Do not move an existing positional parameter. Each wrapper forwards the supplied key and preserves the authority, closed-session and sync-runner paths it uses today (`src/vfs/session.py:153`, `src/vfs/sync.py:319`, `src/vfs/sync_session.py:124`). A session sends its effective arguments. If a later guard supplies a different precondition, the two storage requests have different fingerprints. A caller-supplied key never suppresses a guard or a session refusal. The shell host dispatches its component verbs at the public router (`src/vfs/shell/host.py:472`). Its reply ordinal at `:259` has no authority or retention scope and must never supply a replay key. A line-wide `cli(request_key=...)` belongs to the later line contract.

3. **One optional token row describes the key wherever it is accepted.** In `src/vfs/params.py` add the `token` member of `ParamKind` and one shared `_REQUEST_KEY` instance of `ParamSpec`, nullable, not required, default `None`, immediately before the authority row on members of `KEYED_OPS`. Each public router passes the value to `_gate_params`. The `token` branch of `_check_value` uses 177-3's validator and `MAX_REQUEST_KEY_LENGTH`. Check type and length before scanning the text. Accept 1 through that maximum (255) characters, each from ASCII `!` through `~` inclusive. Compare the original text, case included. A bad key returns one `vfs.invalid` that names `request_key` without echoing it, before path resolution, iterator consumption, mount calls or SQL. This follows the nullable and type-before-shape rules at `src/vfs/params.py:66`, `:572`, `:596`. For a valid key, the effective caller must be named or system, per 177-3 decision 3. Resolve identity by `caller_for` after argument validation, before routing, including an empty keyed batch. An anonymous actor receives one path-free `vfs.invalid` and no dispatch. An explicit or inherited authority is identical at every participating storage. Keyless calls retain the existing anonymous path.

4. **Snapshot support where the storage is bound.** Add `keyed: bool = False` on the frozen `Mount`. Its value is true exactly when the storage implements `SupportsTraits` and `storage.traits().get("replay") == "keyed"`. This uses the trait vocabulary defined by 177-3 and the exact-value precedent at `src/vfs/cursor.py:131`. Snapshot for the root and each new binding. When `update_mount(refresh_caps=True)` reads capabilities, read the declaration again outside the mount lock and publish both in the same replacement after the existing rechecks. A failed refresh publishes neither. Other policy updates copy the cached value. The generic floor and a storage without the trait method accept their normal keyless calls. Each addressed binding's snapshot governs the call that goes to that binding.

5. **Check the trait at the capability step of every addressed mount's existing gate.** Pass the presence of the validated non-null key to `_gate_entry`. First apply the ordinary masked verb capability, then the replay check, then the existing reserved-space and composed permissions checks (`src/vfs/base.py:2705`). Keep the prior outer path, busy and crossing checks where they run today. An otherwise supported verb at a mount without replay returns one ordinary `ErrorKind.unsupported`, for the original op, at the mount's public path, with detail “this mount does not support request_key”, no data and no row facts. This uses the kind contract at `src/vfs/results/kinds.py:204`. Never turn the refusal into a keyless retry. The same gate runs before the first dispatch for every entry, observation group, pair and edge. Even if the missing trait is discovered at the last item, all mounts see zero calls.

6. **One key follows each admitted mount slice.** Carry it through `_route_entry_batch` for either write form, `_route_single` and `_dispatch_grouped_observations` for path and observation forms, `_route_pairs` into `_route_two_path` for transfers, `_route_edge_batch` for edges and `_route_grant` for grant operations (`src/vfs/base.py:1826`, `:1882`, `:1950`, `:2322`, `:2403`, `:2436`, `:2518`). Forward a non-null string unchanged once per dispatched slice, with the existing local paths, effective preconditions, order and resolved authority. When omitted or explicitly `None`, omit the keyword at the storage seam, including against a strict legacy signature. Never attach a key to setup, lookup, metadata or housekeeping calls. An admitted empty batch has no slice, no receipt and no replay marker. Use call-local arguments throughout so overlapping callers' keys cannot mix.

7. **Merge the mount answers by the existing result rules.** A pair or edge with its own endpoints on different mounts still gives `vfs.cross_mount`: where unit 160-1 is built a keyless `copy` pair crosses, and a `copy` pair of a keyed call does not, refused at the crossing check before any mount's `replay` trait is read (unit 160-1's decision 19). Different legal pairs, edges, observations or entries can span mounts. Each storage owns its effective local slice and its saved answer under the same key. On a resend where one slice previously committed and another rolled back, the first supplies its earlier answer with one marker and the other executes once. Rebase observations, error sources and grant extras normally (`src/vfs/listing.py:212`, `src/vfs/results/envelope.py:565`, `src/vfs/base.py:234`). A hit on each of two mounts produces two mount-sourced markers. This is conditional on reaching the same backing stores and sending the same slices within their windows. Aliases of the same physical replay tables share a key space by 177-3 decision 1, so different local slices under that key can conflict with `vfs.invalid`. No global transaction, generated per-mount suffix or router receipt is required.

## Cost

At the reference deployment (`AGENTS.md:74`, `:82`, `:84`, `:85`), keying every single-file write and each nightly 10,000-file batch validates 50,100 keys per day, 100,100 at the design ceiling. The router examines at most `MAX_REQUEST_KEY_LENGTH` characters per keyed call, with constant temporary space. Each existing path gate adds at most one boolean read, at most 1,050,000 reads across those writes at the centre. A batch over M mounts adds one keyword reference per dispatched slice, using the existing groups. Each binding or explicit capability refresh reads at most one trait mapping and stores one boolean. Dispatch rereads no trait mapping, acquires no new lock, adds zero SQL statements, binds or commits on SQLite, Postgres and the generic floor, and adds no per-corpus or index work. The storage-side lookups, statement budgets, locks and answer pages are costed by 177-3.

The storage protocol, declarations, database changes and reclaim belong to 177-3. Keyless replay classifications belong to 177-1. The shell grammar, job resume and MCP server implementation are separate. The public parameter table provides the schema facts for the future wire projection. D11 governs M1's hint independently of whether the tool accepts the argument.

## Choices to confirm

- **The twelfth verb.** Inherit the open ruling in 177-3 decision 11. Removing `set_posture` from the final keyed set would keep an exact-answer contract for eleven verbs. Delivering twelve would require a durable posture completion contract including later relabel work and its counts. Publishing either answer binds callers. The eleven may land first. The build of keyed `set_posture`, its table row and the twelve-verb public promise waits for that ruling and its storage implementation.
- **The mount's JSON view.** Take the stored boolean on `Mount` and leave `MountPayload` as it stands for this landing. Python callers can inspect the snapshot and the storage declaration is public. Adding `keyed` to the JSON payload later is additive. Removing a field already consumed by a client would be harder.

## One line

A caller can send one keyword-only request key through any public keyed verb, and the router delivers it to every admitted mount slice or refuses a missing replay trait before dispatch.

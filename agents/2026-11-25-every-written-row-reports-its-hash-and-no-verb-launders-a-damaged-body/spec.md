# Every written file reports its recorded hash, and replacing a damaged body preserves the evidence

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing of this unit is built. It serves story K3 at gate b of the [roadmap](../../context/standards/roadmap.md), converted from [spec 175, section 4 and criteria 14–17](../../context/specifications/archive/175-integrity-verify-on-read-and-scrub/spec.md) and its [slice C tasks](../../context/specifications/archive/175-integrity-verify-on-read-and-scrub/tasks.md). It rests on the landed write preconditions, the checked read and the pending changes to vids and deleted paths.

## The outcome wanted

A caller can compare the hash on a file returned by `write`, `edit`, `copy` or `move` with the recorded hash at that version. An edit or append that would use a damaged body fails before changing any file in its mount batch. An authorized overwrite with independently supplied content succeeds, even when the caller resends the original bytes. Its row identifies the new body. Its warning identifies the version replaced, and that version retains the evidence of damage.

## What the code does today

`_fetch_committed` already selects `entry.c.content_hash` (`src/vfs/storage/backends/database/writes.py:438`). Both branches of `_finish` omit it from observations (`writes.py:481`, `writes.py:501`). The final topology select and the values captured for a destination that later moved away both lack it (`src/vfs/storage/backends/database/serialized.py:91`, `serialized.py:286`). The vid branches add identity there. The existing field and its populated-field mask are sufficient (`src/vfs/models/entry.py:457`, `entry.py:493`).

An in-memory probe run against dev created a file, changed only its `vfs_content.content` through SQL, then wrote the original text. Creation reported a null hash. The rewrite reported `unchanged` at version 1, leaving the damage in place. A subsequent write of different text succeeded with zero warnings and archived the damaged text under its own measured hash. The two decisions responsible are the digest-only equality test (`src/vfs/storage/backends/database/staging.py:549`) and the mint's use of the measured digest (`src/vfs/storage/backends/database/versions.py:146`, `versions.py:180`). An edit matches and validates on a worker without a pre-image check. A live text file with no content row reaches the same `wrong_kind` as an ineligible kind (`writes.py:305`, `src/vfs/storage/editing.py:39`).

## The problem

A successful batch cannot be checked from its result, and writing the trusted bytes can leave corruption in place. Editing, appending or keeping a snapshot with a freshly computed hash can erase the distinction between bytes that were written by VFS and bytes changed outside it. At the reference deployment a second stat per file for the nightly ingest alone would cost a million lookups. Hashing or fetching every file in the mount would cost ten million body visits per check.

## Decisions

1. **Populate the recorded hash on every returned file observation.** In `_finish`, use the final staged hash for a surviving change and the committed hash for a settled `unchanged` file. Repeated occurrences keep their existing order and statuses and describe the final material of their path. In `transfer_rows`, capture in each `PendingRow` the recorded hash of the root actually copied, the root claimed by the move, or the row read on a transfer to self. On a copy, take it from the subtree snapshot protected by the body-copy guard. Select the hash beside the vid in `final_rows`. Use that final pair when present, otherwise the captured pair. A directory has no hash and leaves it outside `populated`. A copied or moved unhashed file explicitly populates the field with null, which its mask preserves across `Result.to_payload()` and `Result.from_payload()`. The default mutation display remains the path (`src/vfs/results/projection.py:61`). This needs no additional stat, SQL statement, input argument or digest. Give the shared projection and observation helpers the transfer-specific hash only for these calls, so the trash callers at `src/vfs/storage/backends/database/trash.py:336` keep their envelope.

2. **A transfer reports the stamp it carried.** On a healthy file it equals SHA-256 of UTF-8 text or raw bytes. A local move keeps the source material, and a local copy reproduces the original body and original recorded hash, even a null hash or a missing body. The copy already guards the pair of source version and hash (`src/vfs/storage/backends/database/topology.py:546`). Neither operation hashes, repairs, or warns about the source. On SQLite, preserve raw text bytes through the copy, including malformed text, using the byte projection of the checked read and a bound cast back to text at insertion where needed. Cross-mount pairs on dev are refused (`src/vfs/base.py:2369`). A future transfer built on a checked read inherits that read's refusal. Clarify K3 criterion 3 to say *recorded* hash on returned files, equal to the digest for a healthy file. An unconditional equality there would require a transfer to bless the damage.

3. **Verify once per distinct committed edit target before applying any replacement.** Keep mount and row admission, miss classification, the vid check and the existing directory and bytes-source refusals ahead of verification. A bytes file remains ineligible for edit even when it has a text rendering (`writes.py:1169`). Join the content row's key beside its value in the edit snapshot. For each eligible text file use the checked read's classifier in order of missing row, absent digest, unequal digest. Empty text is a present body. Keep the finding set in the storage call outside the writer retry closure. On a new finding roll the attempt back and repeat the whole call, including authorization. Matching findings in two fresh snapshots return one `vfs.unavailable.integrity` error per damaged target in input order, at the caller's path, no observations and no committed mutation in that mount. Its severity is error, `retryable=False`, with the checked read's `reason`, `expected_hash`, `actual_hash`, `body`, old `version` and old `vid`. Changed evidence follows the checked read's bounded retry rule. Never log a body. A text pre-image that matches its recorded hash and is not UTF-8 is no finding: the edit or the append refuses it with the nonretryable `vfs.unavailable` of unit 175-1's decision 25, detail `the stored text is not UTF-8`, and changes nothing in that mount.

4. **Keep matching off the event loop and reuse the pre-image metrics.** Measure and verify in the existing edit worker (`writes.py:310`), then apply each occurrence to the preceding one's output. Split application of the edits from construction of the validated final `Entry` in `src/vfs/storage/editing.py`. Preserve the existing per-occurrence validity checks. Hash only the committed pre-image and each distinct final result, feeding the final metrics through `MEASURED_BODY` (`src/vfs/models/entry.py:248`). Carry the verified pre-image metrics on `StagedEntry` for the history writer. A healthy one-target edit therefore needs two body measurements, one matching hop and zero subsequent hashes in the mint. An edit whose result returns to its verified pre-image settles normally. Zero hops for a small edit in the archived criterion would remove the worker dev already uses for matching.

5. **An append checks what it extends.** After admission, on the snapshot taken after the append lock (`writes.py:355`), check the live file's authoritative body before `appended`, including for an empty tail. Use the same row-key presence and confirmation as decision 3. A rendering cannot stand in for absent bytes. A confirmed fault refuses the append atomically. An authorized create at a free name uses the supplied tail with no check of a former occupant. Preserve the write's precondition ordering: a create-only collision takes its ordinary refusal. A nonempty append on an occupied file that cannot pass its required vid returns the existing conflict before reporting damage. For an empty tail and stale vid, a healthy unchanged file follows the existing no-op rule; a damaged file fails the vid guard. This follows kernel ruling 9 because even appending at the `add` rung would otherwise store the damaged prefix under a new hash.

6. **Prove a plain write really is unchanged before dropping it.** After `admit_staged`, apply the current material comparison to the final occurrence at each live target. Only candidates that would otherwise be dropped need an additional body read. Compare the actual authoritative bytes, including presence, with the supplied bytes in bounded pages. A real match keeps its version and avoids all mutation even under a stale write vid. A discrepancy leaves the update staged and subject to its ordinary vid guard. With a valid guard or no guard, writing the original bytes repairs the file. A write of independently supplied bytes that happen to equal the damaged bytes also counts as an overwrite: it must advance the version, warn and preserve the old evidence. Two different cases would otherwise escape via `_same_material` or the mint's identical-body shortcut (`staging.py:558`, `versions.py:147`). For already verified edit and append bases reuse their proof. Keep only the disposition per candidate across pages.

7. **Capture the displaced identity and its recorded hash before changing any material column.** Carry base source, old version and recorded hash (including a known null) from the admitted live snapshot alongside `base_size_bytes`. An unseen rival winning a create is different from a known null hash. If ordinary overwrite arbitration encounters such a rival, roll back the attempt and redrive the batch from the snapshot. On native upsert, distinguish a returned rival id from the staged new id before publishing a result. On the generic catch-and-retry arm redrive before absorbing a rival file. Preserve the special outcomes for exclusive creation, conflicting kinds and directory adoption. The next guarded write then has the actual occupant's base fields and rights. Exhaustion returns the existing retryable conflict. This closes the archive's unobserved-clobber exception on both paths (`writes.py:628`, `writes.py:775`).

8. **An overwrite archives the recorded hash and reports one warning per damaged pre-image actually replaced.** Under the successful entry guard and before body replacement (`writes.py:537`, `writes.py:550`), the history mint classifies the old source's authoritative body, taking metrics from verified material in hand or measuring the existing bounded mint page. Healthy identical pre-images keep the existing no-history rule. A damaged pre-image always earns one snapshot at the replaced version with its recorded hash, original payload as found, existing attribution and subject rows. For a missing body, store both payloads null and zero actual size and lines. For a present unhashed body, store the payload and its size and lines with a null recorded hash. For missing bytes with surviving rendering, store no payload. For mismatched text preserve the raw UTF-8 octets as stored, including invalid octets on SQLite: copy through the database's text cast, never decode with replacement into the archive. Count text newlines in those octets under the existing line-count rule. The replacement is measured from the supplied body and a checked read must serve it. The warning has the same finding record as decision 3 at `Severity.warning`, and `success` is true. Locked replacement needs no confirmation redrive for the warning: the evidence archived is the pre-image the transaction displaced. Return warnings from the mint separately from the fatal errors of `_apply`. Buffer them per attempt and attach them in `_finish` only after all guards, body inserts and parent bumps succeed. A failed or rolled-back batch publishes neither evidence nor warning.

9. **History can represent the absence of a recorded hash.** Widen `vfs_versions.content_hash` and the stored `Version.content_hash` to allow null. The live column already permits it, while the version column and model require a string (`src/vfs/models/rows.py:378`, `rows.py:493`, `src/vfs/models/version.py:105`). Constructors of healthy history still require or derive the digest. Keep `Version.reconstruct`'s missing-payload and mismatch refusals for the target. A null target digest cannot verify. Increment `SCHEMA_FORMAT_VERSION` once from the format actually reached after the dependencies. Existing healthy row values require no rewrite or rehash. Use the existing first-touch format policy (`src/vfs/storage/backends/database/engine.py:922`), never a silent conversion on opening a mount. Dropping the version or assigning the empty body's digest would erase evidence required by D58.

## Cost

Per returned file the projection carries one 64-character digest and a mask entry. The nightly million healthy file results carry 64 MB of digest characters before wire framing. There are zero extra lookups for returning them. Copy and move add zero digest passes and visit no new descendants. None of these checks run during an index pass or rebuild.

For a batch with `u` candidate unchanged plain writes, page only those `u` distinct ids by `BLOB_PAGE_BYTES` and the dialect's live `membership_budget`; each subpage costs one select, no mutation. At the reference median of 4 KB, a nightly million apparent matches entails about 4 GB of comparisons, spread over 100 calls. This is a real new cost of proving no change. A different-hash overwrite already fetches its old material in the mint. Its ordinary statement count and a create's stay at their respective baseline (8 and 8 for dev's single-file SQLite pin at `tests/storage/database/test_writes.py:140`). A healthy single-file identical write goes from one metadata select to that select plus one proof select. No point query per member of a batch.

Use the existing `byte_chunked` and `membership_budget(profile, parameter_budget)` for reads and the profile's declared bulk-insert limits for versions and subjects (`versions.py:92`, `src/vfs/storage/backends/database/dialects.py:541`, `dialects.py:580`). Use the tighter effective budget of the serving engine, including SQLite's bind limit and the generic floor's smaller membership limit. One batch holds at most one additional page of fetched bodies, plus one compact disposition or finding per distinct target. A single oversized body occupies a page alone. The page meter uses recorded size, so unexpectedly enlarged raw bodies can make the actual bytes of that page exceed the estimate. Release the page before the next fetch. Apply the checked read's `MEASURE_OFFLOAD_BYTES` to measurement work in hand. Where the mint streams multiple pages, carry the call's threshold across pages and perform the remaining work in at most one awaited worker hop per nonempty page. Never retain earlier pages to combine hops. The edit already has one worker hop irrespective of size. A stable edit or append fault uses two attempts and zero mutation statements.

At the reference ceiling of 1.1 million file writes per day, old-body work is proportional to the affected files and their actual bytes. Ordinary different-body replacements reuse the mint's existing body pass. A create race costs a bounded whole-call redrive. No shared table lock, new serialization point or per-file lock is introduced. Postgres snapshot readers and SQLite WAL readers take no writer lock. Existing append row locks last through the update and commit, including verification of their locked file. SQLite still serializes writers and the in-memory host still serializes sessions. Confirmation backoff holds no lock between attempts.

## Choices to confirm

1. **How to prove an apparent no-op.** Take the bounded additional select on candidate matches (decision 6). An alternative joins and compares supplied bytes inside the first snapshot statement. The extra select is portable, confined to candidates and can later be folded into the snapshot without changing an answer.
2. **How to recover a competing create's old stamp.** Take a whole-attempt redrive on losing an unconditional file create (decision 7). An engine-specific upsert returning old and new row images could remove that retry. Redrive works on both served engines and the generic floor without a permanent arbitration exception.
3. **How to keep an absent historical hash.** Take a nullable history hash (decision 9). An additional field or table recording the absence beside a synthetic digest would need every history consumer to interpret two facts. Widening the existing column preserves every genuine digest and records absence directly.

## One line

Every written file reports its recorded hash, and an authorized overwrite repairs a damaged file while keeping its old body and old hash visible as evidence in history.

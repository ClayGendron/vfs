# Every kernel verb has a reviewed access path on SQLite and Postgres for each of three callers

A draft, written on 2026-11-25 against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. Unit 179-8 has no named roadmap story and its gate is unplaced. It converts [spec 179, section 9 and criteria 19–21](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/spec.md) and [task 11](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/tasks.md), as scoped by [the reassessment](../2026-11-25-the-backlog-converted/reassessment/seam.md) at 179-8. It rests on the conformance split in unit 179-1.

## The outcome wanted

A contributor can look up one call, such as a named caller overwriting a file, and see the ordered database statements, the rows and payload bytes that crossed the storage boundary, and whether the call succeeded. Adding a query, repeating a fetch, or moving work from a worker onto the event-loop thread produces a fixture diff. An ordinary test run shows the first difference and never accepts it on the contributor's behalf.

## The problem

A new query can leave every returned row unchanged. At the reference deployment one extra statement common to all calls costs about 150,000 executions a day. A body fetched twice by a metadata operation can cost far more than those statement counts suggest. Existing pins cover individual paths. Neither their union nor a ranking fixture compares every verb and actor in execution order. The operational rule is to count work on both engines (`AGENTS.md:62`, `:82`, `:94`, `:183` and the [constitution](../../context/standards/constitution.md), Article 5).

## Decisions

1. **Cover the live routed vocabulary at three explicit authorities.** Generate a required key for each member of `ALL_OPS` crossed with `system`, `named` and `anonymous`. Compare the coverage set for equality, including missing and obsolete keys. At the checked commit that is 25 × 3 = 75 verb/actor pairs per family before the extra cases (`src/vfs/ops.py:38`, `:107`). Use `Authority.system()`, `Authority.of(Principal("fixture"))` and `Authority.anonymous()` (`src/vfs/authority.py:155`, `:181`, `:186`). Use the live flat names, including `set_posture`, `search`, `traverse` and `sweep`. Decided 2026-11-15: `delete` and `move` keep their names, the verbs stay flat, and `sweep` becomes `destroy` when the deletes change lands ([the names ruling](../../context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md), decisions 2–4). A new or renamed verb needs cases in the same diff. Exercise the storage method directly. For `run`, exercise the public method on the one database-backed root: the database lacks `SupportsRun`, so today every actor gets `vfs.unsupported` and zero statements (`src/vfs/base.py:1679`, `:2738`, confirmed on file-backed SQLite). Do not skip an actor because its call is refused.

2. **Give each case a reproducible starting state.** Use fresh fixture storage or an equivalent clean copy, one root, the conformance hashing embedder, posture `read` on `/`, and a single `read_write` grant to `fixture` on `/docs`. Seed as system. Place ordinary targets and both ends of transfers under `/docs`. A root-level create deliberately lies outside the grant. Use fixed paths, ASCII bodies and deterministic entry order. Seed only the prerequisites for the particular call. Use an occupied destination for overwrite, an existing grant or membership for removal, an authored edge for removal or traversal, a tombstone for restore, a live file for explicit-path sweep. Give listings at the two depths equal child populations. Use distinct component names on a deep path, since segment postings deduplicate ancestor names (`src/vfs/storage/backends/database/segments.py:60`). First touch, seeding, an indexed world's `rebuild()`, one later dirty write, any rights-cache warm-up by `stat` as the subject, and settling SQLite statistics all finish before recording. For cold read, perform first touch and seed without resolving the named authority after clearing its storage-local rights cache. A mutation under one actor cannot supply the next actor's seed.

3. **Use this case matrix on both engines.** Every verb in the first five rows runs for every actor, including the administrative refusals that section 9.2 of the source omitted. The last three rows are additional dimensions. Case ids name the verb and variation, such as `write.create-d2@named`. Exercise one nonempty result or material change where allowed. Check the expected paths, content, grant or membership state, or refusal kind independently of the golden file before accepting counts. For example, a named root create is `vfs.permission_denied`, anonymous file writes are `vfs.unauthenticated`, and both nonsystem membership calls are `vfs.permission_denied` (`src/vfs/storage/backends/database/rights.py:1166` and its membership check). Check refusals left the addressed state unchanged outside the meter.

| Cases | Input |
|---|---|
| `stat`, `read`, `ls`, `tree` | File or directory as appropriate at depths 2 and 20, with identical leaf data or children and all ancestors present. |
| `write`, `edit`, `mkdir`, `delete`, `move`, `copy` | Create a file at depths 1, 2 and 20 with existing parents, overwrite a changed file, replace a single occurrence in a file, create an absent directory, delete a live file, move a file and a nonempty directory to vacant destinations, copy a file to a vacant destination. |
| `glob`, `grep`, `search`, `traverse`, `mkedge`, `rmedge`, `run` | Match a file glob, grep a dirty and a published match in separate worlds, search for a ranked term, walk one authored edge with `method="outbound", depth=1`, add or remove an authored edge, and run a path under the database root. |
| `restore`, `sweep` | Restore one file and destroy one file at its explicit path. |
| `grants`, `grant`, `revoke`, `set_posture`, `add_member`, `remove_member` | List rights at `/docs`, give and revoke a separate subject's read grant, change a child directory's posture to `list`, and add or remove that subject in `group:fixture`. |
| Large body, system | `stat` the file, `ls` its one-child parent, `read`, overwrite with a one-byte change, and `edit` a unique final byte. |
| Cold cache, named | `read` the same small file as for the warm read. |
| Batch, system, marked `slow` | Create and overwrite the fixed batch in one call each and list its parent. Assert that every expected file was returned or changed. |

4. **Record executed application SQL once in submission order.** A test-only `AccessMeter` listens to `before_cursor_execute` on the active storage's synchronous engine. Its context spans the awaited call through consumption of the result. Apply `is_statistics_statement(sql)` before registering the execution or attributing any binds, rows or bytes to it. For each remaining statement keep its leading SQL operation, the first actual mount table referenced (match the engine's table names, stripping schema qualification, or null for e.g. `SELECT 1`), its control flag and its counters. Keep repeats. Explicit `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT`, `RELEASE`, `PRAGMA` and `SET` count as control. Distinguish `BEGIN IMMEDIATE` from `BEGIN`. Pool checkout configuration and implicit driver transaction notifications sit outside this application-SQL boundary (`src/vfs/storage/backends/database/engine.py:955`). Count each asyncpg `copy_records_to_table` on that connection as one ordered `COPY` with its table, records and payload. Keep its real SQL prologue too (`src/vfs/storage/backends/database/dialects.py:704`). Other engines, concurrently idle results and excluded setup must not contribute. Remove every listener and restore each patched method on all exits.

5. **Measure rows and payload at the result and driver boundaries.** Count bind groups once per executed statement (one for a single execution including a parameterless one, the actual page's groups for executemany or an expanded multirow insert, the actual records for `COPY`). Count raw result tuples as consumed through `CursorResult._fetchone_impl`, `_fetchmany_impl`, `_fetchall_impl` and `_fetchiter_impl`, including scalars and returned mutation rows. Attribute by result execution context, never by the last statement seen. Forward fetch order, empty fetches and lazy iteration unchanged. Count each row once even if adapters nest. Count UTF-8 bytes of strings and the byte lengths of bytes-like values among bound and fetched values, including leaves of array binds. Count mapping values only. Native numbers, UUIDs and datetimes contribute zero to this payload definition, which excludes SQL text and protocol overhead. SQLite's driver representation of the same field can therefore cost a different amount. An opaque unmeasurable payload fails the supported leg and names the type and case, without logging its value. No exposed bytes may silently fall out of a comparison.

6. **Store one ordered record per case and per engine.** Use `tests/fixtures/access_paths/sqlite.json` and `postgresql.json`. Each case key maps to `path` (the ordered statement records), `statements` (non-control count), `control`, `rows_bound`, `rows_fetched`, `bytes_sent`, `bytes_fetched`, `success` and ordered error kinds. Row and byte totals sum the non-control records. Each statement also refers to its normalized SQL in one shared dictionary per fixture, so replacing a query with a different projection on the same table is visible. Key the dictionary by the SHA-256 hex digest of its canonical UTF-8 text, and print both texts on mismatch. Spell SQL with the test schema removed, whitespace normalized outside literals, and driver placeholders standardized outside literals. Represent a repeated bind list or identical VALUES tuples by the repeat count and one pattern. Preserve predicate, projection, clause and ordering differences. A raw `COPY` uses table and ordered columns. Keep no parameter values. Compare the whole fixture, including key sets, statement order and all counts. Sort object keys and end UTF-8 pretty-printed JSON with a newline. Files reside beside existing measured data under `tests/fixtures/`. Source section 9.3 supplies the per-family precedent.

7. **Assert the cost laws before a fixture can be replaced.** Declare test inputs and allowances once in the family: shallow and deep depths 2 and 20, body budget B = 4 MiB, metadata allowance H = 1 KiB for the one-file body world, batch budget N = 10,000 files and a 60-byte ordinary file (source sections 9.2 and 9.5). Compare per actor at equal state: `stat`, `read` and `ls` keep equal statement counts across depths, and `stat` fetches exactly the depth difference more rows. A successful deep create binds that difference more `vfs_segments` rows than a shallow create. Metadata reads fetch less than H payload bytes. The full read returns the body and fetches between B and B + H bytes. Overwrite fetches at most B + H and sends at most 2B + H. Edit fetches at most B + H and installs the changed body. No create, overwrite or edit targets `vfs_meta` or `vfs_lock` with DML (`src/vfs/models/rows.py:600`, `:635`). A single-root `AsyncVirtualFileSystem.read` and `write` must have the same ordered statement list and outcome as the direct storage call on an equivalent independent seed, for each actor. These checks also run on a candidate during repin. A violated law requires investigation, independent of a changed baseline.

8. **Pin native calls by callable and thread on the SQLite file leg.** Write `tests/fixtures/access_paths/native.json` for system `write`, `read`, `glob`, dirty and indexed `grep`, `search`, and the two storage maintenance passes `rebuild` and `refresh`. Supply the small deterministic corpus of the [source probe](../../context/research/studies/2026-10-24-ostep-principles-for-vfs/experiments/spec-179/native_calls.py): 50 markdown files in numeric order with its fixed text, patterns and query. Give refresh one changed file after a completed rebuild. Scope a test proxy to the live extension behind `vfs.native.extension()` (`src/vfs/native.py:50`), wrapping callable exports, constructors and methods on returned native objects, including factory-returned matchers such as `GlobSet`. Record name × loop/worker counts, and submissions to the VFS offload pool as a separate hop count (`src/vfs/offload.py:153`). Keep explicit empty call maps and zero hops. Exclude setup. A new extension call on the loop can cost no SQL and still delay other calls. The native pin is SQLite-only as in source section 9.6. SQL work for ranked search remains pinned on both engines.

9. **Record a baseline from the built dependency, and require a reviewed, deliberate repin.** Read fixtures by default. In repin mode compare the candidate key set to the live manifest. An old or absent file may then be replaced only after the candidate passes the independent checks. `VFS_ACCESS_PATHS_REPIN=1 uv run pytest -n 0 tests/storage/test_conformance.py -k access_path` collects candidates. Reuse `tests/ranking/pins.py:41`'s `rewriting()` rule to refuse xdist before any write. Set `VFS_TEST_POSTGRES_URL` for the Postgres leg. Stage rows in memory until a selected family has all required keys and its dimensions and outcome checks pass. A filtered or failed run cannot publish a partial file. Write complete candidate files by atomic replacement per file in a session-scoped fixture finalizer, only after a zero-failure run with that family's complete cases, outcomes and invariants recorded. Leave unselected files alone. The initial landing includes both engines and the native pin. A normal rerun on clean state must match. A deliberate change includes the code, fixture diff and reason for its cost in the same review. The later rights-revalidation fold (179-9) changes these pins in its own review.

## Cost

The meter adds zero application statements, production allocations and locks. It neither changes a transaction nor requires readers to wait for writers. For a run with C cases on one family and S executed statements, the recorder visits each bound or returned value once, does work proportional to text bytes counted and SQL text normalized, and retains O(S) count records plus distinct compact SQL shapes. It discards raw rows and binds after counting. The small worlds need O(deep depth) seeded ancestors, the body world O(B) bytes, and the batch world O(N) short entries, allocated only for those cases. Both engine legs measure the same N. Inserts use the live dialect's `insertmanyvalues_max_parameters` and `rows_per_statement`. Membership uses the tighter `membership_budget(profile, parameter_budget)` (`src/vfs/storage/backends/database/dialects.py:541`, `:580`, `:702`). A width-w page fits the statement's declared row budget. K such rows take ceiling(K / rows per page) pages on the paged bulk path. Count the Postgres COPY pages as well as SQLite executions. The test never expands a production parameter budget to fit its fixture. At 150,000 calls/day one extra B-sized fetch on fraction f of calls moves an extra 150,000 × f × B bytes/day.

## Choices to confirm

1. **How much SQL identity belongs in a reviewed file?** Take the compact normalized SQL dictionary beside the operation/table path. The source's cheaper pair alone misses replacing one query by another with equal counts against the same table. The dictionary is test-only and can be removed without changing the measured calls.
2. **How should an unmeasurable driver payload be handled?** Take failure with its type and case over the source's per-row `bytes_exposed: false` exemption. Both served families owe exact bytes. A narrowly documented adapter can be added once such a value occurs.
3. **Where should the three files live?** Take `tests/fixtures/access_paths/` beside existing data pins over the source's `tests/storage/access_paths/`. The lookup belongs to the test helper, so changing the directory later is one move.

# A file’s replaced versions are listed newest first, with the writer of each body

A draft, written on 2026-11-25. It is not reviewed, and nothing of this unit is built. Checked against `origin/dev` at `27f3d24d` for [roadmap story K8](../../context/standards/roadmap.md), gate f. Converted from [the history read in specification 180](../../context/specifications/archive/180-history-pack-on-reindex-and-the-bounded-sweep/spec.md). It rests on the landed listing envelope, the kernel name rulings, the vid mint, the split between live and deleted entries, the rewind body reader and the operation groups.

## The outcome wanted

A caller at `read` can ask `versions("/notes", limit=2)`, see the two newest replaced bodies and who wrote each, then resume with `after=page.next_versions["/notes"]`. A file just created has one creation row. A move carries history to the new path. A new file at a reused path starts with its own creator. An ETL caller can ask about many files in one call, and follow the files whose pages have more rows.

## The problem

Today the mint keeps a whole pre-image, under the version being replaced, and attributes it to the authority replacing it. It skips creates. Two writers in succession leave the first body beside the second writer’s identity (`src/vfs/storage/backends/database/versions.py:3`, `:145`, `:183`). The storage key already orders the history of one entry and the subjects have a matching key prefix (`src/vfs/models/rows.py:488`, `:513`). None of the routed ops reads those rows (`src/vfs/ops.py:38`). A nightly 10,000-file audit needs bounded metadata lookups without loading the file bodies or querying once per writer or file.

## Decisions

1. **Expose one metadata verb on the four faces.** Use `versions(path: str | None = None, observations: list[Observation] | None = None, *, after: str | None = None, limit: int | None = None, authority: Authority | None = None) -> Result` on the kernel and synchronous filesystem. Sessions supply their bound authority. The point-read shape and routing follow `src/vfs/base.py:802` and `:1826`. Exactly one of path and observations is required. In the batch form only paths are trusted, duplicate canonical paths count once in first-occurrence order, and an empty list succeeds with zero rows. A batch starts pages and takes no `after`. Each continuation addresses one file. No `columns` parameter is needed for a fixed, body-free row. Refuse malformed shapes as `vfs.invalid` at ingress, including at the direct storage face.

2. **Page each named file by descending version label.** The limit applies per file. Omission or `None` gives the declared `HISTORY_PAGE_ROWS = 100` for a single file (source §7.1) and `HISTORY_BATCH_PAGE_ROWS = 1` for an explicit batch. An explicit limit ranges from 1 through `INT_CEILING` inclusive, excluding booleans (the limit domain at `src/vfs/params.py:63`, `:145`). Group results by input path, newest first inside each group. Fetch at most one extra eligible label per file and give a continuation only where that extra row exists. An exact final page has no key. Repeated calls do not share a snapshot. A newer write after a page cannot repeat a label below its strict boundary.

3. **A continuation is the last shown label bound to the entry and mount.** Add the declared `Result.next_versions: dict[Path, str]`, empty by default. Its keys are only those returned file paths that have another page. A value is the canonical positive decimal label, a dot, and the row’s lowercase vid. Reject overlong or noncanonical text before numeric conversion, using the decimal width of `INT_CEILING` and `VID_LENGTH`. Use the string parameter kind for `after`. After admitting the live file, compare the vid with the mount mint of that entry at the supplied label. A foreign entry or mount gives `vfs.invalid` with the detail `version key belongs to another file; start again`. A rejected path yields only its ordinary path refusal, including when the token is stale. Never route by token. Passing a token to the same entry at its new path works after reauthorization. Fetch labels strictly less than the boundary. This implements D6 without publishing an entry id.

4. **The result identifies the body and its writer.** Every row’s exact `populated` mask is `path, kind, version, vid, content_hash, size_bytes, source, created_at, actor, provenance, source_identity, subjects, grant_revision`. The path is the current addressed path and kind is `file`. The time is when that body was written. Mirror the five missing attribution fields from `Version` in `Observation` and its mirror registry (`src/vfs/models/version.py:108`, `src/vfs/models/entry.py:437`, `:545`). Return the authority’s sorted subject tuple, including the empty tuple, and mark null fields as fetched. Return `text` or `bytes` as the source of the original body, including an empty body. Keep body columns, diff representation, line count and packing state out of the row. The default render projection is path, version, actor, created_at, size_bytes and content_hash. The remaining fields are projectable from the same result.

5. **Mint attribution when a file body is written, then complete the same row when it is replaced.** Take D36’s history-row side provisionally. Give `vfs_versions` a stored `source` and a boolean `body_is_live`, mirrored on `Version`. A new file, including a file copied into a fresh id, inserts row 1 with its metrics, time and writer, and inserts its subjects in the same transaction. A live-body row has no payload columns set, with `is_snapshot=True` and `body_is_live=True`. The one copy of the body is in the live storage. On a material body or source change, complete the previous live-body row in place with its pre-image and clear its flag. Insert the new attribution row under the new entry version. Its creation time, writer, sorted subjects, grant revision and source belong to that new body. A copy credits the copying authority, a replacing copy credits its writer on the destination entry. Normalize a trusted storage call without authority to `Authority.system()`, as `backend.py:1179` does. Preserve `anon` with its sole subject and `system` with no subjects (`src/vfs/authority.py:181`, `:200`). A directory has no body history. Aborted claims, retries and unchanged writes leave zero extra rows. Use the actual settled identities under the existing guarded update, including a losing create that clobbers a rival (`writes.py:542`). The copy mint runs alongside the new ids in `topology.py:450`. No separate creator column or duplicate body is needed.

   The immutable row label is the revision that first stored that body and source. Metadata-only edits, moves, delete and restore can advance the entry revision while the same body persists. For example, write at 1, move at 2, overwrite at 3: the completed row is 1 and the current body’s label is 3. Listing shows completed rows plus row 1 while it still refers to the live body. Later live-body rows stay internal until replaced. This gives a creator immediately, exactly one listed row per replaced body and a stable historical vid even across a move. It departs from source §7.1 for the creation row and from today’s `staged.version - 1` for a replacement after a gap.

   Adapt rewind decision 5’s private storage lookup in the same landing. After its existing target, vid, range and rights checks, seek the greatest body-start label at or below the requested revision using the same primary key. For a live-body row take the bytes from the owning entry, including its retained body for an admitted tombstone. For a completed row use its existing payload. A reader never calls `Version.stored_payload()` on a live-body row (`src/vfs/models/version.py:187`). This preserves the body-at-revision guarantee through a gap without mutating a published label. Advance `SCHEMA_FORMAT_VERSION` once from the then-current format and keep the first-touch mismatch refusal (`src/vfs/models/rows.py:135`, `src/vfs/storage/backends/database/engine.py:922`). A format-28 row records a replacer, so never present an old mount’s attribution as the original writer or invent a creator from its owner.

6. **Admit the current live file at read on every call.** Use the same `_viewed` snapshot, ancestor error classification, directory handling and read check as a point read (`src/vfs/storage/backends/database/backend.py:1197`, `reads.py:232`, `:915`). A named caller gets the identical `vfs.not_found` for a hidden path as for an absent one, `vfs.permission_denied` for a list-only file and `vfs.wrong_kind` for a visible directory. The existing anonymous posture gate can return `vfs.unauthenticated` before a lookup. A deleted file at its former name gets the normal miss, with the existing `vfs.trashed` hint only for a visible tombstone. Explicit trash-view file addresses provide no history until restore: give the same `vfs.not_found` at that address, without confirming a tombstone. Gate before reading version or subject rows or comparing entry-bound keys. The router retains its existing whole-batch ingress refusals (`src/vfs/base.py:1891`). After dispatch, row-level screening preserves per-target errors and the allowed files’ rows under scoped result semantics. Historic subjects or older grants never grant access.

7. **Use set-based, body-free page statements.** Resolve distinct live target paths in membership slices, fetching their ids and fields for the current view. Classify only unresolved paths through the shared ancestor and trash probes, and keep those probes separately counted. For a single admitted id, seek its primary key in descending label order with the optional strict boundary and `LIMIT L + 1`. Skip the one unlisted live-body row. Load subjects only for emitted pairs, ordered by entry, version and principal, including one query for a nonempty single-file slice. Never join to the body tables. A supported engine therefore uses one entry query, one label query and one subjects query on a nonempty ordinary single-file page past the gate, one more than source criterion 24 because K8 includes subjects.

   For a batch, drive the label query from admitted ids. Postgres uses a lateral limited seek per id. On SQLite use an input relation of ids, then a correlated descending seek to the last of the first `L + 1` eligible labels for each id (or floor 1). Range-join back to its labels at or above that floor, applying the same eligibility predicate. The bounded skip to locate that floor depends only on the requested page width. It never skips preceding pages. Group and order the bounded rows in the caller’s input order. Slice subject lookups on the full pair: `tuple_in` where declared, otherwise bounded OR arms via `arm_budget`. The generic floor uses the same bounded range on a parameter-limited derived input relation in an accepted SQL spelling. If its dialect cannot serve the optional history family it withholds the capability. No whole-history window rank, no client-side slicing of all versions, and no statement per target.

8. **Carry history identity and page keys through routing and results.** For history-to-history `|`, `&`, `-` and the equivalent merge, key by `(path, vid)` and keep the existing order, error and mask rules. History rows and ordinary entry rows have distinct identities. Refuse their mixed set operation as `vfs.invalid` under constitution Article 2.4 rather than attaching a historical actor to a live row. Ordinary operations keep their existing path identity (`src/vfs/results/envelope.py:466`). Public set operations clear continuation fields. Internal grouped dispatch for disjoint targets explicitly combines the per-file keys along with rows and errors, restoring request order. Rebase only the map paths on mount entry/exit, leave tokens unchanged and discard the key for any row lost to path overflow. Preserve keys on a row-preserving copy, clear them on a changed selection. Keep `next_after` empty. Wire round trips preserve the map, and rendering prints a continuation with path and token for each entry so a text caller can resume it.

9. **Register one optional, read-only history operation.** Add `versions` first in the `history` group, before restore, in `Op`, `READ_OPS`, `VERB_RUNGS` as `Needs("read")`, `PARAMS`, the projection and the four faces in group order. Add optional `SupportsHistory.versions` with the corresponding keyword-only storage signature and the `_FAMILY_OPS` registration (`src/vfs/storage/protocol.py:603`). The rewind trait `versions: kept` and `SupportsVersions.read_versions` are private body access and alone confer no listing capability. On an incapable mount the funnel reports `vfs.unsupported` with zero storage calls. When M1’s registry exists, register the one agent-facing tool `versions` with `readOnlyHint` and `idempotentHint` true. Its schema exposes `path`, `after` and `limit`; M1 excludes `authority`, `observations` and `provenance` from tool inputs (`roadmap.md:869`). Carry the key in the bounded tool result. If the adapter cuts a nonempty page earlier, use the last shown row’s label and vid so the next call cannot skip an elided row. K8 criterion 5 raises M1’s baseline from 21 to 22. If M1 lands later its registry and tool-count test must already include this op in that landing.

## Cost

At the [reference deployment](../../AGENTS.md#the-reference-deployment-the-scale-every-idea-is-filtered-through), 150,000 calls a day are the multiplier. With every call a nonempty single-file history page at its default, the upper workload is 450,000 data statements past admission and at most 15 million returned labels daily. Each admitted id costs an index seek and at most `L + 2` label visits on a single seek (lookahead and the one excluded current row). The two SQLite batch ranges cost at most twice that per id. The version rows fetched do not contain payload bytes. For `R` emitted rows the subject table returns at most `R × MAX_SUBJECTS` rows. Work and result memory scale with named paths, returned labels and their actual subjects. This touches zero unrelated files among ten million. Each page uses the existing read transaction with no writer or rights lock.

Write `B = membership_budget(profile, parameter_budget)` (`dialects.py:541`). For `P` distinct, present, readable paths on one mount the data path uses exactly `ceil(P/B)` entry statements and one label statement per nonempty id slice. Output pairs for subjects use slices of at most `min(B, floor((parameter_budget - fixed_binds)/2))` on tuple-capable engines and `arm_budget(profile, parameter_budget, 2)` on the generic floor, one statement per nonempty pair slice. Permission resolution, missing ancestors and the deletes spec’s tombstone probes are separately metered. A 10,000-file default batch with one result each therefore takes one entry, one label and one subjects statement on either served profile. EXECUTED: the declared SQLAlchemy parameter budget was 32,700, giving `B = 32,668` on SQLite and Postgres and 1,000 on the generic floor. These figures illustrate the formulas and are never chunk constants.

Creation adds one narrow row per file, ten million across the starting corpus, and at most one subject row per actual subject. Duplicating the bytes instead would add 3–7 TB across that estate. A material replacement closes one row and inserts one new narrow row plus its subjects, keeping the existing one-snapshot body cost. The daily multiplier is at most the 1.05 million writes that actually create or replace a body. New metadata inserts are paged by `rows_per_statement`, copy and writes reuse bulk insert, prior-body reads and bytes writes use `BLOB_PAGE_BYTES`, including the existing one-oversize-body rule (`versions.py:92`, `:154`). Read the grant revision once per nonempty write batch. Complete prior heads by entry/version in budgeted bulk updates inside the write transaction. Add no shared lock, per-file round trip, index-pass work or corpus backfill. A writer uses the existing entry guard and commit.

## Choices to confirm

1. **D36 and the creation row.** Take the additive history row for files, visible immediately for v1, with the live bytes held once. The alternatives are a separate `created_by` column or a second full snapshot at create. The history row preserves the complete writer tuple and can later supply a creator column without guessing past authors. The working label is the revision that introduced the body, so a later metadata change cannot displace the v1 creator. D36 is a lean, not a dated ruling.
2. **The batch page and its key.** Take per-file pages, one row by default in a batch, returned with a path-to-token map, then continue individual paths. A single global cursor requires an ordering across unrelated histories and a resume contract across mounts. Batch resumption by a map of incoming tokens can be added without changing the chosen single-file loop.
3. **Composition.** Take the version-aware identity for two history results and the classified refusal for a mixed set operation. Leaving the existing path-only algebra in place could silently discard versions. A later explicit mixed join on current path can be added without changing the identity of a history row.

## One line

At the current file’s read rung, `versions` returns bounded pages of attributed body revisions, and each continuation identifies the file and last version actually shown.

# Python runs numpy and pandas over the caller’s files, and each guest refusal reaches its stage

A draft, written on 2026-11-25. It is not reviewed, and nothing of the adapter is built. Checked against `dev` at `27f3d24d` for [roadmap T5a, gate b](../../context/standards/roadmap.md), converted from [the WASI Python runtime](../../context/specifications/archive/172-the-wasi-python-runtime/spec.md). It rests on the caller-bound shell, guarded writes, the program catalogue and the [wasi-python 0.1.0 mount and tool experiments](../../context/research/2026-10-23-wasi-python-0-1-0-over-vfs-the-mount-and-the-tool-door.md).

## The outcome wanted

With `vfs-py[python]` installed, `python3 analyze.py` can group a CSV by a column, write the result to another VFS file and read it back. For rows `(1,2), (1,3), (2,4)`, the sums are `[5, 4]` and the stage exits 0. Python can also call `from host import tools` and inspect a verb’s ordinary result. A file the caller cannot see looks absent. A script that catches a refused write still leaves the stage’s classified refusal and nonzero status.

## What the code does today

The optional dependencies and lock omit the runner (`pyproject.toml:49`). The wheel’s shell runtime links Wasmtime 51 without a WASI preview1 linker (`crates/vfs-core/Cargo.toml:24`). The shell checks its two Python refusal names before looking in the eleven-entry host program table (`src/vfs/shell/host.py:118`, `:439`, `src/vfs/shell/programs.py:760`). `Start` takes name, arguments and cwd. `Feed` carries stdin and EOF, but the present Python host runs the program on start and only drains prepared output on feed (`crates/vfs-shell/src/machine/mod.rs:212`, `crates/vfs-shell/src/programs/mod.rs:64`, `src/vfs/shell/host.py:450`).

Executed with file SQLite and a fresh local Postgres database. Two named sessions from `open_session` read the same file below posture `none`. The caller with no grant received `vfs.not_found`. The reader received its text through a worker-thread callback posted to the owning loop, then received `vfs.not_found` after revocation. At `list`, `stat` returned only path and kind and `read` was `vfs.permission_denied`. Empty create, duplicate create, guarded fill and stale fill returned version 1, `vfs.exists`, version 2 and `vfs.conflict`. The filled body survived. Both engines returned 127 with `statuses == [[127]]` for `python3 --version`. A separate SQLite-backed mount with `permissions="read"` refused an empty create with `vfs.read_only` at the requested path.

## The problem

A host interpreter would see files, environment and credentials outside VFS. A mount over a session can instead apply the same rights as the shell, but the runner only sees errno and returns its own stream, limit and failure records. Conflating an exclusive create, a failed close and a Python exit loses evidence or changes a rival’s file. At ten million files a directory probe also has to cost what the caller traverses, without listing the corpus or caching a past permission.

## Decisions

1. **Ship the pinned runtime only in the Python extra.** Decided 2026-11-25: add `python = ["wasi-python==0.1.6"]` in `pyproject.toml`; include the published universal wheel SHA-256 `4f96d2f9b79412daaac8637fdb88739c1399f649911855f20130de98a1253073` (123,032,382 bytes) in `uv.lock` and verify the wheel against it on the consumer leg. The extra names no `wasmtime`; the runner's own requirement `wasmtime>=51,<52` brings the Python binding, and `uv.lock` fixes it at `wasmtime==51.0.0` with the hashes of its published wheels and sdist (manylinux1 x86-64 `cb4a48bae3de3c0ca99a67e05debbe4bfe48bea7f25ac71ee42fb3fd681ef93c`). That runner is the only source of a Python `wasmtime` in any vfs extra: the `javascript` extra shares the same runner pin (172-3 decision 2) and the stored-program host runs over `vfs-core`'s own Rust embedding with no Python binding (169-4 decision 1), so one `uv lock` resolves all extras together and `pyproject.toml` declares no `[tool.uv] conflicts`. A move of the runner pin moves both guests in one landing after both consumer contracts pass, and it never touches `vfs-core`'s separately linked `wasmtime` crate. Reason: 0.1.6 is the newest release and the one the D49 spike measures; every runner release requires exactly one `wasmtime` major (0.1.0 49, 0.1.1 to 0.1.5 50, 0.1.6 51), so the older pin would also hold the Python binding two majors behind the shell's crate; and the public names this adapter uses exist at both releases (spike fact 9). Read the installed MANIFEST for versions, build date and package inventory. Leave the base and existing aggregate installs light. Resolve the runner lazily. Each stage starts from a fresh copy of the process's package image (decision 13) through `wasi_python.run_async`; its runtime and stdlib come from the wheel. No install verb, downloaded fallback, VFS rows under `/opt`, host-directory grant or custom preview1 linker. This follows D23 and the [release artifact](https://pypi.org/project/wasi-python/0.1.6/#files). A cold run of release 0.1.0 that ended at host exit 137 in one container (validation Layer 4) is a fact about that container's memory: in a 16 GB, four-CPU container on 2026-11-25 the same three-element NumPy and pandas sum completed cold with stdout `6` and exit 0 on both 0.1.0 and 0.1.6, at a peak child resident set of about 2.3 GB and 2.5 GB, when no fuel limit was set. Those peaks are the host process compiling the module cold, not the guest's linear memory, which decision 10 caps.

2. **Resolve two names to one program.** Register `python` and `python3` as names of one guest implementation in the host catalogue. When the extra is absent, neither has a runnable entry. A direct invocation then has the shell’s known-miss status 127 and `vfs.unrecognized` with the hint `install vfs-py[python] in the host environment`. Installed but unusable artifacts fail with `vfs.unavailable`, status 126, and run no code. `--version` and `-V` print one MANIFEST-derived line. Pass `-c CODE [args...]`, `-m MODULE [args...]`, a script with its arguments, and `-` or no operand for stdin. Accept `-I`, `-u` and `--` before an operand, preserve empty and non-ASCII arguments, and give malformed options status 2 with `vfs.invalid`. A readable `.py` is an operand regardless of its executable bit. Direct execution of a stored filename follows 169-2 decision 9 and [executable files, decision 5](../2026-11-22-a-file-carries-its-executable-bit/spec.md). Extend its interpreter list only for `#!/usr/bin/env python` and `#!/usr/bin/env python3`, dispatching the admitted interpreter and the already checked script. A suffix alone never substitutes a path or overrides a shebang.

3. **Start captures the exported environment and feed supplies stdin.** Extend the existing Start codecs to carry only the stage’s exported names and values, including prefix assignments. The old host-program path still runs ordinary programs as before. For a Python stage, hold its invocation by request key, accept bounded byte chunks and run once at EOF, then drain the two byte streams through the same feed replies, with status only on the last. This matches the runner’s finite stdin and output contract. It is a batch stage and cannot start processing an endless input stream. The call’s cwd is the guest’s cwd for relative opens, scripts and tools. Use a fixed in-guest launcher to set cwd, argv and the Python main namespace where the pinned API needs it. Supply arguments and source as data, never by interpolation into that launcher. The launcher runs the caller's code in a fresh `__main__` namespace, since the package image of decision 13 leaves `numpy` and `pandas` bound in its own `__main__`; modules already in `sys.modules` stay imported. Resolve an explicit guest `HOME` in VFS coordinates against that cwd, otherwise use the cwd itself. No directory or permission is created for HOME. No value is inherited from the host process.

4. **One caller and one dispatch function serve both doors.** Use the admitted line’s session context, obtained from `fs.open_session(authority)` for a direct kernel call (`src/vfs/base.py:655`). Retain the guarded context of an existing session line, including narrowing, stamps and closure. Reject the system actor at line admission. Mount exactly `Mount(VfsProvider(session, loop), "/", writable=True)`, omit `root` and pass no grants. The wheel’s own read-only library is the only runtime preopen outside this mount. Each synchronous provider method posts its typed request through `asyncio.run_coroutine_threadsafe` to the owning running loop and waits on the runner worker. A tool awaits that same dispatcher on the loop. Only the dispatcher can post a public verb or a guarded change, preserving the caller, charging the line and assigning a per-stage ordinal before dispatch. No storage import, second loop or host path. On exit or cancellation, stop admission, cancel and settle in-flight work, release the worker, cache and owned session, and keep the caller’s existing session open. A committed write stays committed. Never retry a mutation during teardown.

5. **The writable provider has eight methods.** Normalize relative operands using the stage cwd and the VFS path rules (`src/vfs/paths.py:396`, `:523`). Before a lookup, check each supplied path for a segment equal to `.vfs`, including after normalization and at either rename endpoint. Return `ENOENT` with zero verbs. Omit that segment from every listing, including on a child mount. The runner owns WASI descriptor offsets and directory cookies. The table gives the complete storage seam.

| Provider method | Admitted operation and reply |
|---|---|
| `stat(path)` | `session.stat(path)` gives file or directory, byte size and nanosecond mtime from the admitted row. Use zero where the row gives no size or timestamp. Bare path and kind convey no body permission. |
| `list(path)` | Drain `session.ls(path, after=key, limit=LISTING_PAGE)` in order, checking each advancing key, page budget and encoded directory size. Return immediate child name/kind pairs. An incomplete or refused drain returns an errno and releases the partial list. |
| `read(path)` | One fresh public read requests `content`, `data`, `source`, `kind` and `size_bytes` and takes the vid supplied on the row. Return bytes directly or UTF-8 encode text. A target directory is `EISDIR`. |
| `write(path, data)` | The runner supplies a whole body at create/truncate and at dirty sync, close or exit. Use decisions 6–7. |
| `mkdir(path)` | `session.mkdir(path, parents=False, exist_ok=False)`. An occupied target returns `EEXIST`. |
| `remove(path)`, `rmdir(path)` | Stat as caller, check file versus directory, then guarded `delete(path, cascade=False)` with the checked vid so a changed kind cannot be deleted. Directory to remove-as-file is `EISDIR`, file to remove-as-directory is `ENOTDIR`, nonempty directory is `ENOTEMPTY`. |
| `rename(src, dst)` | `session.move(src, dst, replace=True)`. Preserve the ordinary transfer gate and tombstone of the replaced file. Unsupported replacement, occupied directory and cross-mount refusal keep the router’s kind. There is no delete-then-move. |

6. **Bind write-back to the row the guest saw.** For a newly absent file, commit an empty `write(if_absent=True)` at open and keep the returned vid as the guard for the first fill. A competing create gets `EEXIST` and never falls through to an overwrite. A nonexclusive truncation with an established live target requires that target’s vid, then uses the returned vid for its dirty fill. An initial empty write with no prior positive observation can attempt exclusive create directly, avoiding a stat for a fresh name. If the runner trace proves a nonexclusive truncation and the path is occupied, obtain a fresh authorized target row, preserve its source, and use its vid for that truncation. If an exclusive open remains possible, return the original refusal and do not retry. Honor a previously observed absence with exclusive create even if a rival has since appeared. Use the guarded router, fixed session and `if_vid` on every whole-body replacement, including a zero-length close. Keep `vfs.conflict` as `ESTALE`. A mount without the required vid capability refuses the guarded operation with `vfs.unsupported` before mutation. Never substitute a fresh vid at close, a path/version pair or an unconditional write. Never mistake an empty payload for exclusive intent. A creation normally costs two versions, while an untouched empty file keeps its one version and unchanged writes obey the kernel’s existing settle rule.

   The public callback is `write(path, data)`. It supplies neither descriptor nor flags. Retain the set of still-possible open-time guards for each path since the first body read or create. Repeated opens at one vid share a guard. A first exclusive create at an unobserved or absent path has just its returned guard. A dirty write can proceed only when all possible descriptors agree on one guard. After sync, retain the old guard if another descriptor could hold it and add the committed guard for the synced descriptor. Clean closes are invisible, so retain ambiguous candidates until the run ends, compressing two distinct possibilities to an ambiguous mark. Reads, renames, removes and tool-side changes never retarget a prior open to a new occupant. Deny an ambiguous write with `vfs.unsupported`/`ENOTSUP` before dispatch. With no descriptor or append flag, a provider append is guarded whole-body write-back, never `append=True` of a whole staged file. An explicit verb-tool `write(append=True)` retains atomic tail append. This conservative departure from Unix descriptor semantics ends if a pinned public protocol supplies handles, open flags and flush boundaries.

7. **Keep source fidelity and share bytes only behind a fresh gate.** For an existing bytes row write `data`. For an existing text row keep `content` if strict UTF-8 without NUL, otherwise use `data`. For a new file also treat `png jpg jpeg gif tif tiff webp pdf zip wasm` and the case-folded keys of `OOXML_TYPES` as binary suffixes, including the initial empty create. This is the source’s write-back rule using `src/vfs/models/media.py:69` and the text validator at `src/vfs/models/entry.py:144`. Keep per-run decoded stat and staged-body entries keyed by vid, the public representation of (mount, entry identity, version). Dev’s observation exposes neither raw entry id nor vid. Without a vid there is no cache hit. A new open or stat always re-enters the corresponding authorized verb. A previous stat, missing path, unversioned bare row or cached body cannot answer for that caller now. Cache only derived data after admission, coalesce duplicate work within one callback and evict by charged bytes, including keys and empty entries. Discard affected paths and parent metadata after either door mutates, and discard everything at stage end. Write guards are separate from evictable cached bytes. If their charged keys no longer fit, stop on budget before mutation. The cache cannot replace a gate to meet a call count.

8. **The tool interface is a closed, schema-checked projection of session verbs.** `verb_tools(session)` constructs per-run asynchronous descriptors from the public session signatures and `PARAMS`. Use exactly `read stat ls tree glob grep search traverse write edit delete restore mkdir mkedge rmedge move copy` on this tree. A drift test compares this set with `ALL_OPS - GRANT_OPS - DEVELOPER_OPS - EXEC_OPS` at `src/vfs/ops.py:68–107`; a newly added verb requires review before exposure. Tools cannot set authority, change grants, execute another line or supply an internal vid. Unknown names and unexpected arguments fail before dispatch. Apply decision 5 to every path-bearing field including observations, batch pairs and edge endpoints, before issuing any verb of a batch. For discovery, omit meta candidates before counts, ranks, truncation and page keys reach the guest. An explicit hidden root costs zero verbs. Generate responses through the ordinary, rights-filtered VFS operations. Where a path-bearing result cannot be safely reprojected without changing its ranking, continuation key or error metadata, refuse it with a bounded `vfs.unsupported` result before exposing that data. Use ordinary argument defaults except that an omitted listing limit gets the declared page size. Keep caller-supplied legal paging arguments, evidence, ordering and `next_after` in the filtered result. Return the JSON-safe `Result.to_payload()`, including `success=False` on refusal. The file provider is the binary-body door. No MCP dependency or guest installation is required.

9. **Use one drift-checked errno table.** `WASI_ERRNO` belongs beside `ErrorKind` in `src/vfs/results/kinds.py:30`; store preview1 names as plain strings, resolving them to `wasi_python.Errno` inside the optional adapter. Map the first fatal fact with `kind_family`, use `EIO` for an unknown family and keep the original classified data and other facts for the stage. A target known to be a directory for a file read uses `EISDIR`; a non-directory ancestor stays `ENOTDIR`. This follows the original experiment’s table. Comparing its keys programmatically with the dev enum found exactly 24 on both sides.

| ErrorKind members | WASI errno |
|---|---|
| `not_found`, `exists`, `wrong_kind`, `not_empty` | `ENOENT`, `EEXIST`, `ENOTDIR`, `ENOTEMPTY`, respectively |
| `unauthenticated`, `permission_denied` | `EACCES` |
| `read_only`, `unsupported`, `unrecognized` | `EROFS`, `ENOTSUP`, `ENOSYS`, respectively |
| `invalid`, `unindexable_pattern` | `EINVAL` |
| `unaddressable`, `conflict`, `busy`, `cross_mount` | `ENAMETOOLONG`, `ESTALE`, `EBUSY`, `EXDEV`, respectively |
| `budget_exhausted`, `truncated`, `authority_budget`, `unavailable`, `backend_unavailable`, `schema_mismatch`, `internal` | `EIO` |
| `timeout`, `cancelled` | `ETIMEDOUT`, `ECANCELED`, respectively |

10. **Charge the runner and the line at the level each can see.** Pass finite `fuel`, `deadline_s`, `memory_bytes`, `output_bytes`, `max_file_calls`, `max_tool_calls`, `max_tool_request_bytes` and `max_open_files` to `run_async`. Use the remaining line deadline (`src/vfs/deadline.py:66`), remaining line output and verb allowance, and tighten each by its configured guest ceiling. Use the runner’s declared defaults for streams, open files, file calls, tool frames and request bytes, and the line’s host-memory allowance for adapter-owned copies. No unlimited runner sentinel. Fuel is the runner’s count of executed guest WebAssembly instructions (`Completed.fuel_used`), the unit the line’s own fuel counts (`crates/vfs-core/src/shell_binding.rs:33`). It charges the caller’s code and nothing before it: the stage starts from decision 13’s package image, whose import of NumPy and pandas measured 4,575,385,419 units, is paid once per process as host setup and is restored by a host memory copy that spends no fuel. A stage’s fuel is the smaller of the declared `GUEST_FUEL`, 2,000,000,000, and its reservation from the line’s remaining fuel. The ceiling comes from the outcome’s own job: from the image the CSV fixture’s group-by measured at most 10,415,264 units and the three-element sum 3,768,003, so 2,000,000,000 is about 192 times the job; it keeps the archived guest budget, and at the measured rate (the 4.6-billion-unit import took about 2.3 seconds) it is about one second of computation, inside the line’s 30-second `DEADLINE_SECONDS` (`src/vfs/shell/host.py:77`). Guest memory is the runner’s `memory_bytes`, the guest’s linear memory, capped by the declared `GUEST_MEMORY_BYTES` of 1 GiB, the runner’s own default. The image holds 70,516,736 bytes of it, so the cap fits; the 2.3 to 2.5 GB peaks under decision 1 and a measured 2.87 GB are the host process compiling the module cold, once per process while the compiled-module cache is empty, against 285 MB for a process running the job from a cached module. Concurrent guests in one process are bounded by the runner’s worker pool (`defaults().async_workers`, the CPU count, at most 8), so guest linear memory in a process is at most that count times `GUEST_MEMORY_BYTES`. `GUEST_FUEL` and `GUEST_MEMORY_BYTES` are declared in `src/vfs/shell/host.py` beside `LIMITS`; their names `guest_fuel` and `guest_memory_bytes` join the budgets that `shell_budgets` sets per router and that `cli(limits=…)` may only lower ([line budgets, decisions 2–3](../2026-11-21-a-line-has-a-verb-budget-and-cli-tightens-it/spec.md)), validated as termination decision 4 validates fuel, and `run_line` takes them out of the mapping before it builds the machine. That follows `run_line(fuel=…)` for the line’s fuel and `hop_budget` and `close_timeout`, which a host sets at router construction (`src/vfs/base.py:296–297`). Fuel and the deadline are both always passed and neither is the only bound. Fuel is a count independent of machine speed and load, and it stops a computing loop the same way on every machine: `while True: pass` under 2,000,000,000 trapped `out of fuel` at exactly 2,000,000,000. The deadline bounds wall time, including callbacks, verb awaits and the wait for a worker, which spend no guest fuel: the same loop with no fuel trapped `deadline`. A stop on fuel is 137/`vfs.budget_exhausted` and a stop on the deadline 124/`vfs.timeout` (decision 11). Reserve finite fuel and output shares before a stage starts so parallel guests cannot each claim the remaining pool. Return unused reservations on completion when usage is known. Debit actual VFS dispatches immediately from the line’s single verb counter, including pages, kind checks and tool verbs, before any effect. Avoid counting a wrapper request and its sole verb twice. File/tool counters separately count attempted protocol work, including hidden-path probes, refusals and tool-list frames. Bound combined stdin, serialized tools, directory entries, caches, diagnostics and outstanding replies by checking remaining bytes before each adapter-owned copy. A guest waiting for a worker consumes the same line deadline. No storage transaction spans Python execution.

11. **Preserve the original failure, the guest’s exit and the stage’s status.** Capture original `ResultError` facts on both doors at refusal. Join `done.files.refused` by invocation order, method and path(s), preserving phase and cause, including a refused final flush that guest code never sees. Record it once, also when the full result’s errno collides with a different kind. Synthesize `vfs.internal` for an unexpected provider fault and `vfs.budget_exhausted` for a limit the runner refused before callback. Include tool protocol failures from `done.tools.outcomes`, including a caught budget exception. Bound distinct facts and add the existing counted rollup for omitted occurrences, including runner-reported overflow. Keep negative stat/read probes, including hidden addresses, as bounded nonfatal stage evidence. A known-missing path carries only the supplied address. These probes do not turn a successful script into a failure. A failed mutator or verb-tool call has its original kind on the stage, one stderr line per distinct refused mutation path, and turns guest exit 0 into stage 1. A completed line retains the host’s warning projection (`src/vfs/shell/host.py:334`) and pipeline status rules. On a guest refusal add a nested `data["guest"]` record to the projected fact with the stage key, the unmodified runner exit code (null on a trap), and, where present, write-back phase and cause. Preserve the original kind, path and kernel data. The line’s warnings do not convert a completed line into a fatal transport error.

| First terminal cause | Stage status and fact |
|---|---|
| Parent line cancellation or deadline | Latch the parent’s result first. Machine cancellation is 130/`vfs.cancelled`; external task cancellation is re-raised after settlement. |
| Runner `trapped == "deadline"` | 124, `vfs.timeout` |
| `"out of fuel"`, `"out of file calls"`, or a positively identified adapter or runner resource limit | 137, `vfs.budget_exhausted`. Tool-frame exhaustion and a truncated stream count even when the runner merely records them. |
| Other runner trap, including a runner-local `"cancelled"` without parent cancellation | 134, `vfs.cancelled` for that tag and `vfs.internal` otherwise. Arbitrary trap text cannot identify a memory-limit refusal. |
| No trap or latched limit | Keep the explicit Python exit and the two bounded streams. An ordinary exception keeps its Python traceback and status. Apply the caught-refusal rule only to a zero status. |

12. **Report an unavailable import as a guest diagnostic.** For an uncaught `ModuleNotFoundError` for a package outside the MANIFEST, the fixed launcher identifies the exception type and module in the guest, prints the normal traceback plus the package-set hint and sends a bounded guest diagnostic through one private runner tool, `report_guest_error`, on the same transport. It accepts only the unsupported-module code and a module-name string fitting the request budget. Its descriptor carries no storage capability. Include this diagnostic separately when comparing the published VFS verb list with the runner descriptors. Treat this as guest-reported evidence only. It confers no rights, triggers no VFS verb and cannot claim a host failure or another path. A caught optional import and mere traceback-like text on stderr do not create that stage error. Reject `python3 -m pip` before instantiation with status 126/`vfs.unsupported` and the host-side packaging hint. Top-level `pip` and `uv` keep the never table’s 127. The published wheel, including scipy where present, defines which imports are outside the set.

13. **Start every stage from one package image made per process.** On the first Python stage in a process, call `make_package_snapshot(["numpy", "pandas"], root=False, fuel=PRELUDE_FUEL, deadline_s=PRELUDE_DEADLINE_SECONDS)` once, keep the `Snapshot` in memory and pass it as `snapshot=` to every stage’s `run_async`. At 0.1.6 the runner’s public surface offers exactly this: `make_package_snapshot`, `make_snapshot`, `Snapshot` and `snapshot=` on `run`, `run_async` and `Session`, with the MANIFEST’s `x-snapshot-package` lines naming the modules each distribution imports. The wheel’s own `python-snapshot.wasm` holds only the stdlib’s bootstrap, with no package. The making has no mount, grant, tool, environment value or caller data, and with `root=False` it needs no host directory, so the image is shared process setup like compiled code ([termination, Interfaces and edge cases](../2026-11-22-shell-runtime-termination/spec.md)) and confers nothing. Each call restores a private copy, so nothing one stage does reaches the image or another stage. `PRELUDE_FUEL` is 10,000,000,000 and `PRELUDE_DEADLINE_SECONDS` is 60, declared beside `GUEST_FUEL`: the measured 4,575,385,419 units with about 2.2 times headroom, and about 26 times the 2.3 seconds the making took with a cached module. They are host constants, never a caller budget, and the making is never debited from a line. A stage waiting for the making waits under its own line deadline. A making refused for fuel, a nonzero exit or an open file is deterministic, so it is latched for the process with its `SnapshotFailed` reason, and every Python stage then ends 126/`vfs.unavailable` with no code run. A making that passed its deadline is not latched, and the next stage tries again, one making at a time. The image’s HOME, `/tmp/.home-snapshot`, is a path under the root mount, so a package call that writes there goes through the provider as the caller, like any other path. Another distribution joins the image only with its prelude fuel measured and `PRELUDE_FUEL` restated.

## Cost

At the reference deployment (`AGENTS.md:75–100`), 150,000 agent verbs/day, 20/s at peak and 10 million files share one database. For G instances of the counted CSV fixture, budget at most 21G routed guest verbs, excluding shell lookup and the outer invocation, and count both separately. At G = 1,000 that is at most 21,000 inner calls. Count storage statements at the actual verbs on SQLite and Postgres; one routed verb is not one statement. A page of P entries needs at most P visible rows plus the existing lookahead. D returned children require about ceil(D/P) pages, plus any filtered pages, with one key per directory. A new nonempty file incurs at most one extra version over a single write. If all 50,000 organic writes were guest creates the upper increment is 50,000 versions/day. There is no write per pre-existing file or index visit.

For V admitted verbs, F callback attempts, T tool frames, M staged bytes and O output bytes, the runner may hand over M bytes per dirty flush, so repeated sync can cost O(F × M) bytes copied, even for a one-byte edit. Cap callback work, live byte totals and the cumulative transfer per line using the host-configured allowance for bytes written or, in its absence, a guest transfer ceiling initially equal to the guest memory budget. Debit bytes at each transfer, including repeated flushes. The adapter’s outer retained state is bounded by the line’s host-memory ceiling plus the runner’s own staged and guest-linear-memory limits per admitted guest. Count simultaneous copies. A backend’s own whole-row hydration can cost one complete addressed body before an oversize result is refused; this release makes no hard process-RSS or ranged-read promise. No corpus walk, schema change, new SQL, dialect-specific shortcut or shared lock. SQLite’s existing bind/chunk limits, the Postgres leg and the generic backend floor stay with the public verbs. Reads never queue behind guest computation and a write holds a storage lock only for its commit.

Fuel and memory at the reference deployment, where a Python stage’s share of the peak 20 verb calls a second is an *assumption*, taken here as one in ten, two stages a second. Without the package image each stage would spend 4.6 billion units on imports, about 2.3 seconds of one core: two a second would keep about 4.6 cores importing. With it, the making costs 4.6 billion units once per process and the CSV job 10.4 million a stage. By Little’s law, guests at once are arrivals times duration: two a second times the 0.1 seconds the job took from the image is about 0.2 guests. If every stage ran to the 30-second line deadline, 60 would be wanted; the runner’s pool admits at most 8 per process, and the rest wait under their own deadlines behind line budgets decision 4. A process’s guest linear memory is then at most 8 × `GUEST_MEMORY_BYTES`, 8 GiB, beside a process base of 285 MB measured with a cached module and a 2.87 GB peak while a cold module compiles, once per process. Typical demand is 0.2 to 8 guests at about 52 to 70 MB each, under 0.6 GB. A host sizes the worst case by lowering `guest_memory_bytes`, and fuel needs no sizing beyond `GUEST_FUEL`, since a stage’s fuel also comes out of its line’s own.

## Choices to confirm

1. **HOME.** Take the stage cwd as the default, honoring an explicit guest path. A per-principal home would require a new directory, lifetime and permission policy. A host can add that later without making every invocation write during setup.
2. **Indistinguishable write-backs.** Take a classified refusal when the path-only protocol cannot identify the open-time guard. Taking the latest path observation can irreversibly erase a rival’s change. An upstream descriptor-and-flags hook could later admit these operations and genuine atomic append without changing callers. No hook is required for the single-writer CSV job.
3. **Direct script names.** Take explicit Python invocation or a recognized Python shebang on an executable file. Running any suffix-only executable as Python would change the interpreter of existing scripts under the executable-file decision. Adding a new suffix rule can be decided separately.
4. **Initial resource ceilings.** Take a `GUEST_FUEL` of 2,000,000,000 a stage, with the NumPy and pandas import exempted by the package image of decision 13, a `GUEST_MEMORY_BYTES` of 1 GiB, the runner’s other finite defaults with the line ceilings, and a cumulative transfer cap equal to the guest memory ceiling. The image is the reversible side: dropping it is one argument, and the ceiling stays a declared, host-set budget. The other side is no image and a default raised to cover the import, about 10,000,000,000 (the measured 4,785,258,931 for import and sum, doubled), which charges every stage about 2.3 seconds of a core before its first line runs. A smaller default that a host raises, or a memory default of 512 MiB, about seven times the image, is also reversible, since a host raises either without a caller change; lowering a published default later would break scripts that fit it. Preserve the 21-call fixture and publish measured counts before changing a default.

5. **Runner release.** Take 0.1.6, the newest release and the spike's, with the binding the lock resolves for it. Release 0.1.0, which the archived experiment ran, is the other side; it requires `wasmtime` 49, would hold the Python binding two majors behind `vfs-core`'s crate, and leaves the two guests on different releases unless the JavaScript guest also moves back. Going back is a one-line pin change and a lock refresh, since the public names used are the same at both.

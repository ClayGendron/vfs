# Spec review: VFS serves SQLite and Postgres only

One fresh reader that did not write the spec read [spec.md](spec.md) as an uncommitted draft on the branch `vfs-serves-sqlite-and-postgres-only` at `c42dccd4`, with [research.md](research.md) and [inventory.md](inventory.md) beside it, `AGENTS.md`, `context/standards/constitution.md`, `context/standards/roadmap.md` and the live tree. It was given no summary of the spec, no transcript, no reasoning and no expected verdict, and it trusted neither the memo nor the inventory: every claim a decision rests on was checked against `src/`, `tests/`, `pyproject.toml`, `uv.lock`, `docker/`, `.github/` and `.claude/skills/`. Probes run: a SQLite engine whose dialect instance is renamed `exotic` resolves to the floor through `_policy()` and then fails first touch with "AUTOINCREMENT is only allowed on an INTEGER PRIMARY KEY", classified `unavailable`, retryable; the same file with its own name writes and reads. A 10,000-file write on SQLite issues 10 `INSERT INTO vfs_entries` statements at 28 binds a row (one per depth layer, nine for the files) and 4 `SELECT`s. SQLAlchemy's `insertmanyvalues_max_parameters` is 32,700 on pysqlite, asyncpg and psycopg, and `membership_budget` gives 32,668 on both tuned profiles and 1,000 on the floor. Under Python's default filter, two warnings with the same text from one line print once. `make_url("sqlite+aiosqlite:///notes?v2.db").database` is `'notes'`. In `uv.lock`, only oracledb needs cryptography, and cffi stays for pyzmq. `DatabaseStorage(` occurs 502 times in `tests/`, and `profile: DialectProfile` 188 times in 31 modules of `src/`. Two pending branches touch this work: `a-reserved-owner-is-refused-and-vfs-has-a-logger` and `a-cancelled-call-leaves-its-storage-intact`, neither in `origin/dev` (`93f3d297`). The box was 45 minutes, because the spec touches the storage backend, the public surface and the gate; all thirteen steps were reached. Labels: EXECUTED means run in this review; READ means the cited file was read; INFERRED means reasoning from the two.

## The questions asked of this review, answered first

- **Landing 1 changes no statement on SQLite or Postgres.** Holds for every deletion the spec names (READ). Each deleted arm is selected by a profile value that only `MSSQL`, `MARIADB` or `ORACLE` sets, or by a dialect name that only they carry. `SQLITE`, `POSTGRESQL` and `GENERIC` keep `row_lock_hint=None`, `membership="in_list"`, `like_bracket_class=False`, `range_entry_hint=None`, empty `range_hints`, no value cap and empty `retryable_driver_codes` (`dialects.py:503-658`). The classifiers are not reached on the two engines: SQLite returns early on `sqlite_errorcode`, and asyncpg and psycopg carry `sqlstate`, so `_driver_code_of` and the `args[0]` SQLSTATE arm never decide there (READ, `dialects.py:1000-1030`). The proof the spec offers for this, the statement diff, is underdetermined (M2).
- **Deleted fields, arms or constants reached on SQLite, Postgres or the floor.** None on SQLite or Postgres. On the floor, two deletions do change behaviour: the pyodbc SQLSTATE arm of `_sqlstate_of` and the errno rungs of `is_unique_violation` and `is_value_too_large` serve any unknown dialect whose driver has no `sqlstate` attribute. That contradicts decision 2 (M1). `ShareLock`'s `"exclusive"` form, `door`, `_lock_stamps` and the literal-`OR` relabel arm are floor or Postgres code and the spec keeps them (READ, `labels.py:283`, `524-537`, `660-663`).
- **The warning design.** The site is right: `_policy()` is the one place both a URL-built storage and a borrowed factory reach, and it resolves once per host because `_profile` is set once and never reset (READ, `engine.py:232`, `564-584`). Three things are wrong or missing. The latch adds nothing, and under the default filter a second storage on the same dialect prints nothing (L1). The first resolution happens inside `VirtualFileSystem.__init__` through `storage.capabilities()`, not at first touch (READ, `base.py:349`) (L3). And the channel departs from the roadmap's logger ruling without naming it (H2).
- **The named-constructor design.** The form is sound: subclasses that only construct, the profile still choosing behaviour, `DatabaseStorage` kept as the shared type (READ, `memory.py`, research section 2). The mismatch refusal cannot live where the spec puts it (H1). The `path=` argument needs a URL object, not a formatted string (L8).
- **The tests.** The landing 2 and landing 3 tests are countable. The landing 1 statement diff is not, as written (M2). Two of the re-pointed tests are described wrongly (L5). The warning test recipe works only for counting warnings, because first touch fails on a renamed SQLite dialect (L4).
- **The proposed `AGENTS.md` text.** Its numbers hold (EXECUTED: 32,700, 32,668, 28 binds, nine statements; READ: SQLite's 32,766 variables and depth 1,000; asyncpg's 32,767 arguments, INFERRED from the driver's documented limit). Three faults: item 2 names a warning class landing 1 does not build (M3), the Engines row says "17 or later" where decision 7 says 17 and 18 are tested (L7), and item 2 keeps "exactly as a tuned engine does" for a floor no engine is shown to serve (L9).

## Findings, most severe first

- **H1. The mismatch refusal is placed where no refusal can be made.** [Decision 10](spec.md#10-sqlitestorage-and-postgresstorage-are-named-constructors-over-the-one-storage-class) and "Where the code goes" put the expected-profile check in `EngineHost._policy()`, which "refuses a bind of another dialect as `unavailable`". `_policy()` is synchronous, returns a `_ResolvedPolicy`, and is called by the `profile` and `parameter_budget` properties from about 50 sites, the first of them `storage.capabilities()` inside `VirtualFileSystem.__init__` (READ, `engine.py:264-275`, `564-584`; `backend.py:242-251`; `base.py:349`). It cannot return a `ResultError`. A raise there escapes the kernel's constructor as an exception, and a check in `_first_touch` leaves the mount declaring the other engine's capabilities until its first call. Consequence if built: the build picks one of two behaviours the spec does not choose between. Fix text: "The check runs first in `EngineHost._first_touch`, before any file setting, and returns `unavailable` naming both dialects. `_policy()` only records the expected name. Until first touch, `capabilities()` reports the bound engine's profile."
- **H2. [Earlier decisions this reverses](spec.md#earlier-decisions-this-reverses) names only `AGENTS.md`. Decision 2 chooses `warnings.warn` with a new public category and says "`src/` has no logger", which is true at `c42dccd4` and false once the branch this spec lands after reaches `dev`. Consequence if built: two channels for the same kind of message, and gates for engines that no longer ship. Fix text, for the reversals list: "The 0.1.0 promise in `context/standards/roadmap.md` section 1.1 and its items D1, D3, D5, D6 and D18 are void for the dropped engines; the roadmap is not edited, because `context/` takes no new work."

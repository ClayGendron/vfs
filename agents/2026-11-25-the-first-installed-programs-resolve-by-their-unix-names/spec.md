# The first installed programs resolve by their Unix names

A draft, written on 2026-11-25. It is not reviewed, and nothing in this unit is built. Checked against `dev` at `27f3d24d` for [roadmap story T6, gate 0.2](../../context/standards/roadmap.md). Converted from [169, “Lands after spec 171 — the first programs”](../../context/specifications/archive/169-programs-the-index-and-the-vfs-views/spec.md). It rests on the host console command, exact-name lookup, executable files and the generic WASI host.

## The outcome wanted

After `vfs install --url sqlite+aiosqlite:///work.db`, a caller with read access can ask `command -v pr`, see `/opt/bin/pr`, and run `pr -t`. The same shell can pipe JSON through `jq '.users[].name'` and sum a column with `awk -F, '{s += $2} END {print s}'`. Opening the database from a new process finds the same programs. A damaged download leaves no installed file. Repeating a successful installation preserves the files and their versions.

## What the code does today

The package declares no console script (`pyproject.toml:13–66`). The shell seeds `PATH=/usr/bin:/bin` and dispatches a fixed table (`src/vfs/shell/host.py:53`, `crates/vfs-shell/src/machine/exec.rs:1094–1129`). Executed on dev through the public router on in-memory SQLite and disposable Postgres: a fresh `stat("/opt/bin")` returned `vfs.not_found`. The shell printed that default PATH. `command -v` for each of `pr`, `jq` and `awk` produced empty stdout and status 1.

On both engines a system create-only batch wrote the eight core-header bytes at `/opt/bin/coreutils` and a text launcher at `/opt/bin/pr`. A second batch naming both and a new `fmt` returned two `vfs.exists` errors, left `fmt` absent and retained the binary at version 1. At a read posture a named caller read the original bytes and their independently computed digest and was denied creation. After the directory posture became `none`, the same caller's point stat returned `vfs.not_found`. These were ordinary dev rows without executable bits.

## The problem

An ordinary binary can already be stored. A release still needs a trusted digest and a command to install it. A multicall binary contains many utilities in one body. Reading a program directory on each command, or storing a full copy for each utility, would put the cost of finding a short name on the 150,000-call daily path or multiply the largest artifact by the utility count.

## Decisions

1. **Decided 2026-11-25: add a host-only install subcommand at 0.2.** Its grammar is `vfs install --url URL [coreutils|jaq|awk]`. Omitting the package installs all three. A single selector installs that package and its names. Use the M2 router for that URL and explicit `Authority.system()` on the host's local administrative operations. Parse and validate arguments before opening a router or fetching. This subcommand accepts no `--as`, arbitrary source URL, caller-supplied checksum, destination or version override. A shell word, kernel verb, MCP tool or guest cannot invoke this host authority. Installation can run without the optional runtime on a provisioning host. Execution needs the runtime on the serving host. This keeps T6 at its stated gate under D22 and keeps `awk` and `jq` out of the 0.1.0 shipped table under D34 (`context/standards/roadmap.md:846–848`, `:1233`, `:1245`).

2. **Append one real directory to the 0.2 shell default.** Fresh shells and the default search of `command -p` use `/.vfs/bin:/opt/bin`. An explicit PATH, a slash word, a shell function, a builtin, and a PATH component earlier than `/opt/bin` follow 169-2. The default is part of the release, so an install never edits a stored session, a process environment or a profile. An absent directory contributes no names. The served catalogue wins a default collision. An absent optional name retains its ordinary lookup outcome and existing execution hint, while a visible runnable file takes precedence over a missing-command hint. This extends 169-2 decision 1 at gate 0.2 and preserves its exact-name rule.

3. **Pin three raw artifacts and their complete recipes in the release.** Commit a machine-readable manifest packaged with the wheel and sdist. Each row names the package, exact upstream source version and immutable source digest, target and features, pinned toolchain and dependency lock, release tag and asset name, positive byte length, lowercase SHA-256, installed names and the associated licence notices. Require exactly the three package keys, one nonempty tagged release, exact digest syntax and unique asset and destination names. Only the reviewed names in the manifest may become path segments. The tag and asset name select one project release URL. Include all required third-party notices with the published guests and the manifest. Use the raw module bytes as the unit of verification. A checksum delivered by the download server alone cannot establish the pin.

| Package | Published raw asset | Executable below `/opt/bin` | Initial build input |
|---|---|---|---|
| `coreutils` | `coreutils.wasm` | `coreutils` plus one short text launcher per advertised applet | uutils `feat_wasm`, `wasm32-wasip1`, starting with the full revision identified by the catalogue spike's `4945ecf`. |
| `jaq` | `jaq.wasm` | `jq` | jaq 1.6.0 without default features on `wasm32-wasip1`. The [jaq build and stdin spike](../../context/research/studies/2026-10-15-agent-shell/10-wasm-program-spike.md) records this combination and two failed newer builds at lines 40–46. |
| `awk` | `awk.wasm` | `awk` | Try GoAWK v1.31.0 first with `CGO_ENABLED=0 GOOS=wasip1 GOARCH=wasm`. Its [module file](https://raw.githubusercontent.com/benhoyt/goawk/v1.31.0/go.mod) declares no other Go modules. The [Go port](https://go.dev/blog/wasi) targets preview1. |

4. **Store one ordinary shell launcher per uutils name.** The exact UTF-8 body for `pr` is `#!/bin/sh\nexec /opt/bin/coreutils pr "$@"\n`, with the two escapes denoting line feeds. Generate it only from manifest names made of lowercase ASCII letters, digits, underscores or hyphens and starting with a letter or digit. Validate each as a VFS basename within the segment budget (`src/vfs/paths.py:41–42`). The guest sees `argv[0]="/opt/bin/coreutils"`, then `"pr"`, then the original arguments, for either spelling of the launcher. A direct `jq` or `awk` keeps the typed word as its own argument zero. This uses the [upstream multicall interface](https://github.com/uutils/coreutils/blob/main/docs/src/multicall.md). CI runs the pinned multicall binary with `--list` and splits its output into applet words. Commit its sorted legal names minus the release's shell builtins, syntax and shipped programs. Fail on duplicate paths across packages or drift in that list. Verify at least `pr`, `fmt`, `tsort`, `numfmt`, `shuf` and `csplit` at the initial release. A launcher and its fixed target each undergo an ordinary lookup and fresh execution read as the caller. There is no resolver alias, link support, full-body copy per applet or recursive search for the target.

5. **Build and qualify the bytes before publishing the console that trusts them.** A repeatable release script builds the three locked inputs in a pinned clean environment. Pin all build tools and inputs by exact version and digest, including the Rust dependency closures. Strip paths and timestamps from the build where needed. A preparation run yields the candidate manifest, notices and exact digests for review. On the release ref CI rebuilds, compares bytes against the committed sizes and digests, inspects imports and exports against 169-4, and runs the real fixtures in Tests under its default limits. Verify the pinned licence terms, dependency notices and ability to redistribute each shipped artifact. An unsupported import, failure under the host limits or unverified redistribution terms prevents release. Do not extend host capabilities or substitute a partial awk to pass this gate. Attach the verified raw files, notices and checksum list to that tag. Existing equal assets can be reused, a nonmatching occupied asset blocks publication. Make the PyPI publish job depend on successful asset verification and attachment. Manual dispatch builds and checks without publishing. The runtime never consults a moving tag or builds from source. This follows the release tag check at `scripts/check_release_tag.py:31–41` and keeps large modules out of platform wheels.

6. **Verify all selected downloads before the first VFS mutation.** Validate the packaged manifest and planned output paths first. Use TLS verification and form the URL from the project repository in `pyproject.toml:44–47`, `/releases/download/`, the pinned tag and the literal asset name. Follow redirects only to that HTTPS origin or `https://release-assets.githubusercontent.com` on the default port. Never forward authorization across origins. Limit redirects with `INSTALL_MAX_REDIRECTS` (initially three). Send no database URL, authority, cookies or credentials to the download host. Fetch each selected raw body once, sequentially, with identity encoding. Use `INSTALL_FETCH_TIMEOUT` (initially 60 seconds per asset, one deadline across redirects and reads) and `INSTALL_READ_BYTES` (initially 64 KiB per block). A non-success response, disallowed redirect or deadline fails the command. Reject contradictory lengths, short streams, extra bytes, a different digest and a non-core header. Read at most the remaining expected length plus one byte to detect overrun, even without a Content-Length. Bound the total verified bodies plus generated launchers by `INSTALL_PAYLOAD_BYTES`, initially the shell's existing `READING_BYTES` allowance (`src/vfs/shell/host.py:85`). Refuse an excessive manifest before fetching. Only the verified buffers feed the writes. Dispose of buffers on every exit. No execution or compilation occurs during installation.

7. **Use one create-only publication in the target database.** After verification use ordinary `mkdir("/opt/bin", parents=True, exist_ok=True)` and batch point `stat` of exactly the planned file names under the host authority. Creating parents inherits the deployment's ordinary rights. Existing directories, postures and grants are preserved. Provision shared directories and their grants as ordinary deployment operations, as 169-2 decision 11 requires. A matching live file has the expected source, size, recorded digest and executable bit. Omit matching names. Any other live occupant, including a directory or the right bytes with the bit clear, is an occupied-name refusal. Treat only genuine absences as creatable. Fail on any other result. Construct one batch of missing `Entry` values using `data` for modules, `content` for launchers and the D66 per-entry `executable=True`. Issue `write(entries=..., if_absent=True)` once on M2's single URL-backed mount. All new names on that mount commit together. There is no unguarded replacement, grant, chmod window or automatic upgrade. A later package version meeting a different file requires an explicit ordinary guarded change by the host. On a lost reply or competing create, make at most one fresh batch stat. Complete success requires every planned name now to match. Otherwise report the classified refusal or uncertain write and allow a fresh invocation to reconcile. A directory created before a refused write can remain empty. Concurrent ordinary edits after an observation retain their ordinary effects.

8. **Make the console result distinguish a usable install from a failed download.** Success exits 0 and prints each requested final VFS path once in lexical order, including matching files from an earlier call. No success list is printed on failure. Use M2's usage exit 64 for a bad invocation and configuration exit 78 for a malformed manifest or an invalid target configuration. Exit 65 identifies a download length, format or SHA-256 mismatch by package and expected pin. Exit 69 identifies an unavailable transport or fetch deadline. Exit 73 preserves the VFS refusal kind and target path for publication errors. Report a credentials-free diagnostic on stderr. These are host process exits. The shell's stage statuses, including 126 without the runtime, belong to 169-2 and 169-4. The [public names ruling, decision 9](../../context/specifications/active/2026-11-15-the-kernels-public-names-and-argument-families-are-ruled.md) concerns a damaged stored body; a failed asset check writes no row.

## Cost

At the [reference deployment](../../AGENTS.md), 10 million files and a million directories serve 150,000 verb calls a day. Installation costs one fetch per selected package, at most three. For total pinned bytes S plus W bytes of launcher text there are S bytes to hash and at most S + W payload bytes to stage, bounded by `INSTALL_PAYLOAD_BYTES`, plus one read block and ordinary validation and driver copies. Network byte work on an overrun stops at the first surplus byte. With A applet names a full fresh install creates A + 3 files. The multicall body is stored once. A successful repeat still checks the selected downloads and writes zero files.

Publication uses one mkdir, one grouped stat, at most one grouped write and at most one reconciliation stat. The ordinary per-mount builders split membership and multirow statements by the dialect's declared parameter and row-width budgets (`src/vfs/storage/backends/database/dialects.py:541–548`, `:629`), including on SQLite, Postgres and the generic floor. No new SQL, database table or filesystem-wide enumeration. Download, hashing and planning hold no VFS writer lock. Ordinary writes hold their existing transaction through commit. At P bare external lookups per day the extra default PATH component adds at most P point candidates, at most 150,000 if every reference call were such a lookup, and zero directory scans. Each executed uutils launcher adds one fixed-target lookup and one execution read beyond directly running the multicall module. Retain the caller's line budget for both.

## Choices to confirm

1. **Multicall layout.** Take small executable shell launchers plus one fixed `coreutils` file. Per-name binary copies multiply stored bytes; a new alias type changes every resolver. The extra lookup and read for each launcher can be measured, and these are ordinary replaceable files.
2. **Which awk to distribute.** Take GoAWK as the first candidate over One True Awk. Both were named in [the earlier text-program ruling, decision 2](../../context/specifications/archive/168-text-program-kernels/spec.md). GoAWK's small declared closure can be tried with the Go preview1 target and C interoperation disabled. The public basename and package selector stay `awk` if the candidate must change. Publication waits for a licensed locked build that passes the actual host's stdin, file, refusal and budget fixtures. If GoAWK fails qualification, return the evidence for selection of the alternative before publishing an awk asset.
3. **Occupied names.** Take create-only installation with exact matches accepted on repetition. An automatic upgrade would require durable provenance for files the host might have edited. A guarded upgrade can be added later. Failure preserves the occupant and the caller can identify it from the diagnostic.

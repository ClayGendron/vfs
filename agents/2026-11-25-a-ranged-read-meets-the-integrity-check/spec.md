# A ranged read reports whether the stored body passed its hash check

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing is built. This is unit 178-3 of [roadmap story K6](../../context/standards/roadmap.md), gate b, converted from [the ranged read, section 7 and criterion 11](../../context/specifications/archive/178-the-ranged-read/spec.md) and [task 6](../../context/specifications/archive/178-the-ranged-read/tasks.md). It rests on the ranged point read and the whole-read integrity check.

## The outcome wanted

A caller asking for four bytes of a four-byte file gets the same integrity answer as a caller reading the file whole. If the source row has disappeared, even a one-byte or zero-byte request reports the loss. A header cut from a larger file can still be read at the cost of the header. Its row tells the caller whether a successful comparison with the stored whole-source hash backs those bytes. A caller who needs that guarantee can ask for a whole source read on a checking mount.

## The problem

A SHA-256 of a prefix cannot be compared to a SHA-256 of the source. Even comparing a prefix whose length equals the recorded size can give a false assurance. Executed through dev's `InMemoryStorage` on SQLite 3.46.1 and `PostgresStorage` on Postgres 16.2: write `abcd`, append `!` to `vfs_content.content` with SQL, then delete that body row with SQL. The three warm system reads issued one body select each. They succeeded with `abcd`, `abcd!` and null respectively, each reporting size 4 and the original hash. The last two returned no errors. The entry and the two independently joined body tables are at `src/vfs/models/rows.py:316`, `:378`, `:453` and `:465`. Today's point reader admits and observes each target at `src/vfs/storage/backends/database/reads.py:913`. Neither dependency is implemented there.

## Decisions

1. **Apply the source check after the usual target and rights decisions.** A text file's selected `content` and a bytes file's selected `data` are sources. Use 175-1's joined source key, hash, version and vid from the same point select, including when the caller omitted them from the projection. For every admitted source and every range, a null joined key is `missing`. A present source with a null recorded hash is `unhashed`, even on a partial request. Determine both before comparing any bytes. With both faults present, report `missing`. An absent path, a directory, a hidden descendant and a list-only target retain their ordinary classifications without a finding. A bytes file's `content` is a rendering with its own existing render notes. Selected null `data` on a text file supplies no body. Neither case is a missing source. This follows the ownership and screening rules of 175-1 decisions 6–8, including in the trash view.

2. **Establish completeness from the same snapshot as the window.** Consider the raw fetched window before text snapping, including its two lookaround edges. Let `w` and `e` be its zero-based start and exclusive end from 178-2 decision 3. It contains the complete stored source exactly when `w == 0` and there is no stored byte at `e`. For prefix windows add a private boolean column `source_ends_in_window` to the point select. Ask the same source-slice builder for one byte at `e` and apply the profile's `stored_length` to this binary expression inside SQL. Coalesce a null length to zero and test for zero. Only the boolean crosses the seam. At the builder's `SQL_INT_MAX` return true for the end test by its storage bound, avoiding a one-based overflow. For nonprefix windows the test is false without an engine probe. This works at exact equality, for an overlong request, for a shortened body, and when the text lookaround contains the whole file though the result serves fewer characters. At offset zero an empty window is complete only for a present empty source. A length or digest recorded on the entry cannot prove that no suffix exists. The length function is already declared at `src/vfs/storage/backends/database/dialects.py:344` and `:444`.

An independent SQLite prototype swept seven bodies including empty, appended, malformed and multibyte data, offsets and lengths 0–26, and the raw and widened window forms. All 10,206 windows and end decisions agreed with direct byte slicing and full-length comparison. Exact `abcd` at four bytes reported end, `abcd!` did not. A Postgres 16.2 SQL prototype had zero disagreements in 10,206 binary-expression cases and 108 UTF-8 text-prefix end checks. These exercised the proposed expression, not a ranged VFS verb.

3. **Send only complete sources to the existing digest.** Compare the raw source before any decode, slice or replacement. A complete source matching its stored hash backs the returned interval. A complete mismatch, or either structural fault from decision 1, uses the ordinary finding, confirmation, caller-visible path, severity, retry flag and data of 175-1. The first finding alone never leaves the call. Re-run the range and admission in the fresh attempt. A repair serves the latest window, a revoke returns only the latest access verdict, and a changing finding exhausts the ordinary conflict budget. For a stable fault the default omits that target and keeps good siblings. Salvage returns exactly the requested slice of a confirmed mismatched or unhashed source with one integrity warning. A missing body still has nothing to salvage. No digest of a partial source, lookaround fragment, decoded rendering or replacement text is reported as `actual_hash`.

4. **Serve an otherwise readable partial native source without a hash comparison.** With a present source and recorded hash, a window that fails decision 2 has no finding, redrive or digest under either setting of `verify`. Its bytes may differ anywhere from the written body, including inside the selected interval. For example, changing only the fifth byte leaves a four-byte raw prefix readable and unverified. This takes the archive's lean in choice 1. It qualifies the whole-read promise of 175-1 decision 18 on an engine-cut range. Comparing the whole source in the engine on each call would cost a complete read to check each header.

5. **Carry the evidence on the slice.** Add `range_verified: bool | None = None` to `Observation` and `OBSERVATION_QUERY_FIELDS` beside the range bounds. Populate it on every delivered ranged body, even an empty one. True means that a whole-source comparison matched for the version supplying this row. False means that no such match backs the slice, including a partial unchecked source, a rendering, a storage without `read_check`, or a salvaged fault. The existing warning distinguishes a confirmed fault. No delivered body means no range fields in the mask. Carry the flag with the selected body and bounds through 178-2 decision 7's merge group, mount rebasing and the wire. A false value adds the words `source hash unverified` to decision 8's existing marker inside its closing bracket. Insert a comma and a space before the note, for example `[slice: bytes 0–4 of 32; next offset=4, source hash unverified]`. The note adds no error and no characters to the body. This makes the note visible in both structured and rendered answers without labelling a healthy prefix a failure. The query-field and mask precedent is `src/vfs/models/entry.py:420` and `:531`.

6. **On a derived range preserve the evidence from the ordinary read.** A storage declaring `read_check` but no `read_range` checks before the router cuts. A source refused by that read stays refused even if the damage is outside the request. A healthy checked source gives a verified slice. Salvage keeps its warning and marks the slice false. The direct database generic floor follows the same rule. Request `source` privately when needed to distinguish a checked source from a rendering, associate warnings with the read target before rebasing, and restore the caller's projection. A storage declaring no check supplies no evidence of a match, whether it cuts the interval itself or the router cuts it. Never manufacture a missing-body finding from an opaque backend's null projection. The router supplies false if a ranged body arrives without evidence. These paths run no second read or second digest merely to cut an interval. This is the whole-read fallback of archive section 7 subject to the capability declaration in 175-1 decision 18.

7. **Preserve a valid text result when stored source bytes cannot decode.** For a complete source use 175-1 decision 16 before serving salvage. Slice the resulting salvage text using its UTF-8 representation and mark the result false. After the structural checks of decision 1, a populated, hashed source whose partial window cannot decode has no hash finding. In that case the default keeps 178-2 decision 3's nonretryable `vfs.unavailable` and omits the row. Malformed bytes prove a decoding fault, not any particular whole-body hash. Under explicit salvage only, fetch the full text as bytes for those already admitted targets in the same attempt, in membership-budgeted groups by entry identity. Pass it through the same whole-source check and confirmation, then cut the returned replacement text as on a derived range. Consequently the salvage offsets refer to the UTF-8 representation with replacements, not to byte positions in malformed storage. A matching digest over independently restamped invalid UTF-8 still cannot yield ordinary text. In that case use the same decoding refusal, or serve the replacement text with the flag false and one nonretryable `vfs.unavailable` warning on salvage. Use the detail `the stored text is not UTF-8` for the decoding fault. An integrity warning already returned for a confirmed mismatch or absent hash suffices on salvage. A malformed rendering follows the existing rendering rule, without this source fetch. This limits the exceptional full transfer to an explicit request for text that a partial window cannot supply as stored.

## Cost

At the reference deployment there are 10 million files, a median of 4 KB per file, and about 112,500 read-shaped calls out of 150,000 calls a day (`AGENTS.md:74`, `:77`, `:82`). For a 4,096-byte prefix of a 4 MiB raw source the database sends 4,096 body bytes plus the end bit. Hashing the complete source for every such prefix would process 1,024 times the requested bytes. A prefix's extra engine expression inspects at most one returned byte internally using the same slice form. SQLite can materialize the stored value and Postgres text can read or decompress a prefix or the whole stored value as 178-1 decision 9 describes. The one-byte bound is on the expression's result, not physical page reads.

For each native attempt on a mount, let `K` count distinct targets and ancestors and `M = membership_budget(profile, parameter_budget)`. The usual `ceil(K/M)` body statements carry the existing slice and at most one additional binary-slice expression per row, at most three additional fixed binds per statement, inside the existing reserve (`src/vfs/storage/backends/database/descent.py:168`, `dialects.py:535`). Render the zero comparison and constant one for the extra byte as SQL literals where necessary to keep that bind bound. Both probed engines supplied `M=32668`. Thus 10,000 sibling targets plus the directory and root fit in one select on either, with smaller declared budgets giving more chunks. Transfer for positive length `n` and `D` raw plus `T` text mappings remains at most `D × n + T × (n + 6)` body bytes per attempt. Zero length transfers zero body bytes on the ordinary native path.

Each distinct admitted whole source with a recorded hash costs one digest per attempt, with the one per-call offload rule of 175-1 and its declared `MEASURE_OFFLOAD_BYTES`. Partial comparisons cost zero hashes. The flag and end bit cost constant space per returned row or fetched mapping. A stable fault takes two attempts, churn at most `retry_attempts` (`src/vfs/storage/backends/database/engine.py:170`). On malformed partial text under salvage only, add at most `ceil(U/M)` source fetches and the total source bytes of those `U` distinct affected rows per attempt. The ordinary derived path already transfers whole bodies and verifies what its backend declares. There is no corpus scan, write, index maintenance or new lock. Checks use the existing read snapshot, and the confirmation wait follows session close. In-memory SQLite retains its existing serialized-session behavior (`src/vfs/storage/backends/memory.py:13`).

## Scope

In scope are the joined projection in `src/vfs/storage/backends/database/reads.py`, the dependent modules `point_reads.py`, `integrity.py` and `slices.py` in that package, `src/vfs/storage/slicing.py` and its caller at the read dispatch, `src/vfs/models/entry.py`, `src/vfs/results/envelope.py`, `src/vfs/results/render.py`, the trait and read docstrings and the named tests. The existing traits, arguments, snap, integrity kind and retry mechanism belong to the two dependencies. No schema, repair operation, page-hash store, shell interface or past-version read is added.

## What the docs must say

The public `read` docstring in `src/vfs/base.py`, the `Observation` field and the `SupportsTraits` contract in `src/vfs/storage/protocol.py` describe what true, false and absent mean. Give the four-byte prefix example, explain why the ordinary checked fallback can refuse that same prefix, and distinguish the general unverified note from a salvage warning. Document replacement-text coordinates and the exceptional full-body cost of malformed text salvage. To verify a complete object assembled by a caller, its pieces must come from the same version and the digest must cover the whole source in order. A rendering has no source digest of its own.

- The combined verb, warning propagation, redrive races, malformed salvage, generic and third-party fallback, and 10,000-row cost pins could not be run against dev because it implements neither `range` nor `verify`. The ordinary reads on both engines above exercised dev. No test suite was run.

## Choices to confirm

1. **Integrity of a proper native window.** Serve it unverified with a note. The other choices hash the full source inside the engine on every range or store hashes for independently verifiable pages. The first adds full-body work to every small prefix and the second requires a storage format, write maintenance and backfill. The selected side needs neither and can be strengthened later without changing an existing digest.
2. **Where to put the note.** Use one query-only boolean per served slice and render the caveat from it. A documentation-only note cannot distinguish two rows from differently capable mounts. A per-row informational error would need a new kind and could be rolled up on the wire (`src/vfs/results/envelope.py:759`). The additive field keeps that evidence with the body.
3. **An undecodable partial source under explicit salvage.** Take the targeted whole-source fallback and slice its salvaged text. Alternatives are a refusal requiring another public call or replacement within the fragment with offsets that need not match the salvaged whole text. The selected branch reuses the whole-text law, spends extra bytes only on this exceptional request and changes no stored data.

## One line

A ranged read checks the complete source whenever it has it, classifies missing and unhashed sources at any offset, and marks every slice that lacks a successful whole-source comparison.

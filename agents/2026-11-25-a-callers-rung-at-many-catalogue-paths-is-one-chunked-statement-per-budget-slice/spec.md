# A catalogue can ask which paths a caller may list or read in one batch

A draft, written on 2026-11-25. It is not reviewed, and nothing in this unit is built. It was checked against `dev` at `27f3d24d`. It serves [roadmap story I3a](../../context/standards/roadmap.md), gate b, and converts [archived spec 170 §5.1](../../context/specifications/archive/170-tools-and-mcp-servers-as-views/spec.md). It rests on the job spec's batch rights check and the membership spec's element budget.

## The outcome wanted

Given three catalogue names, one hidden, one listable and one readable, a listing asks the rights question once at `list`. It gets two paths back, one marked `list` and the other `read`. From the same answer it can show both names and identify the one it may read. The answer is the same whether the names occupy stored rows or exist only in the catalogue.

## The problem

An all-or-first-refusal answer cannot filter a mixed catalogue. Repeating a one-path question for each of 10,000 names repeats the same rights resolution and reads the same shared ancestors 10,000 times. Inferring rights from a listing of stored entries also loses every catalogue name with no entry. The reference deployment serves 150,000 verb calls a day against 10 million files (`AGENTS.md:74-83`).

## Decisions

1. **Add the keyword-only argument `per_path: bool = False` to `SupportsHolds.holds_all`.** The required `paths: Sequence[Path]`, `level: Rung`, optional `authority: Authority | None = None` and return type `Result` are decision 18's. With the default, callers get precisely decision 18's answer, including its first refusal and the absence of any per-path report. With `per_path=True`, `level` is the minimum rung to include. This lets a caller request both listability and readability in a single call without changing the meaning of an existing authorization check.
2. **On a completed per-path check, return `Result(ops=(HOLDS,), rungs=...)` with one entry per distinct qualifying path in first-input order.** The `rungs` extra is a `dict[Path, Rung]` in the storage's coordinates. Its value is the highest rung held. A path below `level` is omitted. At `level="none"` every supplied path appears, including those marked `none`. An empty input or no qualifying paths gives an empty mapping, zero observations and zero errors. Success in this mode means the question was answered. A consumer must read the mapping to authorize a path. As with the existing `grants` extra, the envelope can carry a storage answer without inventing observations for nonexistent entries (`src/vfs/results/envelope.py:333-335`, `src/vfs/results/projection.py:38`). A catalogue consumes the map locally and emits only the names that pass its own threshold.
3. **Use the batch check's one authority resolution and one read of the distinct posture keys on the same read session.** For each distinct mount-relative path, compute the everyone rank with `label_of(postures, path)`. Walk `Resolution.compiled()` highest first and take the level of the first `Rights.reaches(path, everyone_rank)` that passes, or `none`. Filter by `LEVEL_RANK` after finding that level. This is the existing path-only judgment, including the deepest covering everyone posture, the union of each subject's own and group grants, and the intersection across subjects (`src/vfs/storage/backends/database/labels.py:213-215`, `src/vfs/storage/backends/database/rights.py:196-228`, `src/vfs/storage/grants.py:169-179`, `:477-499`, `:625-643`). An entry owner, a stale stored label or a visible descendant gives no right at the queried path. Anonymous follows the current everyone posture. The system authority, including the trusted direct storage default (`backend.py:1178-1181`), answers `read_write` for every supplied path. Empty input and the system case need zero rights reads.
4. **Publish the mapping only when the whole read succeeds.** Keep the database backend's retry, classification and read snapshot around resolution and every chunk (`src/vfs/storage/backends/database/backend.py:1346-1376`, `src/vfs/storage/backends/database/dialects.py:420`). A failed authority resolution, including `vfs.budget_exhausted.authority` for excessive group depth, or a classified backend failure yields the existing failed result with no `rungs` extra, even if earlier chunks succeeded (`src/vfs/storage/backends/database/rights.py:1241-1258`, `src/vfs/results/kinds.py:92`). A caller must fail closed on a failed or missing report. This avoids turning a lookup failure into an empty or partially authorized catalogue.
5. **Count exactly one Postgres posture SELECT per slice of distinct ancestor keys.** Let `K` be the size of the union of `ancestors_and_self(p)` for the supplied paths, including the paths themselves and the root. Let `B` be the effective element budget supplied by the membership owner. On a successful nonempty, non-system attempt the count is `ceil(K / B)`. Deduplicate across the entire request before slicing. Each statement reads only `path_prefix, level` for the everyone principal and the keys in its slice, using the existing unique key `(principal_id, path_prefix)` (`src/vfs/models/rows.py:778-788`, `src/vfs/storage/backends/database/labels.py:135-146`). First touch, transaction setup and the single authority resolution are separate from the posture count. The latter's SQL already depends on cache state, subject count and group depth (`src/vfs/storage/backends/database/rights.py:360-387`). SQLite and the generic floor share the verdict and follow their membership owner. This replaces I3a's count over input length and its engine wording: a repeated input adds no key and a deep path adds several.

## Cost

The multiplier is one catalogue listing or resolution on one storage. For 10,000 distinct direct children of `/.vfs/bin`, a Python probe of `ancestors_and_self` on dev produced 10,003 keys, including `/`, `/.vfs` and `/.vfs/bin`. With `L` such calls a day the path-dependent Postgres cost is `L × ceil(10003 / B)` statements. If the owner's budget covers those keys, even 150,000 such listings would cost 150,000 posture reads. Cache revalidation or a cold compile is paid once per non-system attempt. No entry or content table is read.

For `N` input paths, `U` distinct paths, maximum component depth `D` and at most `S` compiled spans per rung, deduplication takes `N` insertions and chain construction visits at most `U × (D + 1)` prefixes. Sorting the keys takes `O(K log K)` comparisons. Each path has one lookup along its posture chain and at most `len(GRANTABLE_LEVELS)` span searches of `O(log(S + 1))` (`src/vfs/storage/grants.py:79`, `:334-343`). These count operations on path strings, each bounded by `MAX_PATH_LENGTH` (`src/vfs/paths.py:41`). The request retains at most `K` distinct keys and as many matching postures, plus `O(U)` paths and output entries. Each database read binds at most `B` elements on SQLite as on Postgres, and the generic floor uses its conservative budget. The check runs as a reader alongside a writer and takes no writer lock.

## Scope

In scope are the `SupportsHolds.holds_all` declaration in `src/vfs/storage/protocol.py`, its existing database entry point once decision 18 lands, the per-path report and in-memory judgment in `src/vfs/storage/backends/database/rights_reads.py`, and the named test files. Keep the backend entry point a delegate and its module within the size baseline (`tests/lint/allowlist.py:28-29`).

The storage seam answers rights for a single binding. Catalogue construction, rebasing, mount capability masks, the behavior of a binding without the rights seam, and the visible tool-listing and invocation results belong to the catalogue stories. The aggregate's mount-change rules already live at `src/vfs/mounts.py:355-375`. This unit adds no routed verb, schema column, dialect budget or public result field.

## What the docs must say

The `SupportsHolds.holds_all` docstring distinguishes the aggregate authorization verdict from successful completion of a per-path inquiry. It gives the two-name `list`/`read` example, states the threshold, path coordinates and order, and identifies whole-call failure by its error and absent map.

## Not checked

The batch check and the array-bind changes have not landed. The new behavioral tests, Postgres execution plan, cache overhead and statement counts were not run. The 10,003-key figure and the ability of `Result` to carry the proposed mapping were checked in Python against dev.

## Choices to confirm

1. **How should a caller select and receive the per-path answer?** Take an opt-in `per_path=True` on `holds_all` and return the highest qualifying rung in the local `rungs` mapping. A boolean verdict per requested path would need a second call to distinguish listable and readable names. The mapping is additive, follows the grant-result precedent and leaves existing job checks untouched. The choice can be reversed before catalogue callers adopt it.

## One line

One batch rights check gives a catalogue every qualifying path and its highest rung, with one Postgres posture read per membership slice of distinct path and ancestor keys.

# The `cli` tool runs one shell line per call at the wire

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed. The shell is built and its MCP tool is unbuilt. This is [roadmap story M1](../../context/standards/roadmap.md), gate b, converted from [spec 171 §§1.4 and 3, criteria 3 and 8 and the appendix](../../context/specifications/archive/171-the-mcp-adapter-and-the-cli-tool/spec.md). It rests on the [171-3 reassessment](../2026-11-25-the-backlog-converted/reassessment/mcp-guests-and-identity.md), the shell, the serving front and its bounded result projection.

## The outcome wanted

A client offered only `cli` can run `grep needle notes` in a chosen directory and distinguish a search with no match from a line that timed out. The next call starts at its own working directory. A final `cat pixel.png` can show the file as an image. Sending the same read into `wc -c` shows its byte count. Both operate with the rights of that request.

## What the code does today

On dev the host starts each machine with the declared environment and `PWD=cwd`, and collects two byte streams which it decodes with replacement (`src/vfs/shell/host.py:51–57`, `:219–233`, `:246–275`). A file open reads `content, data, content_hash` through the caller's public `read` and checks version and hash if evicted (`:90`, `:369–400`). `cat` distinguishes a plain copy from transformed output (`crates/vfs-shell/src/programs/text.rs:43–105`). The shell builtin `read` assigns from a descriptor (`crates/vfs-shell/src/machine/builtins.rs:683`). The `cli` front has no entry in `PARAMS` or `ALL_OPS` (`src/vfs/ops.py:115`). There is no `src/vfs/mcp/` on dev.

Executed the public shell on in-memory SQLite and disposable PostgreSQL. On each, `false` and a no-match `grep` returned success, exit 1 and `[[1]]`. A missing-file `cat | wc -c` returned success, exit 0, `[[1, 0]]` and a `vfs.not_found` warning. A loop completed and malformed `if` failed with exit 2 and `vfs.invalid`. After a call that changed directory and exported a variable, a fresh call saw root and the variable unset. At `cwd="/notes"`, reading a 68-byte PNG took one public read, yielded replacement-decoded stdout and zero observations. Its pipeline into `wc -c` printed `68\n`; a different principal without the read grant got exit 1, empty stdout and zero observations. Literal `destroy` and `sweep` each exited 127.

## The problem

Decoding the text has already lost the PNG's first byte. Inferring a file from the command string also mistakes a short-circuited command, a local function or a redirected write for the public read that actually ran. Reading a guessed path after execution can attach another version. At the reference deployment, one redundant read per call would add up to 150,000 public reads a day before accounting for their rights checks.

## Decisions

1. Decided 2026-11-25: register the front as `cli` with a closed JSON object input. Require `line: string`, allow `workdir: string` defaulting to `"/"` and `timeout_ms: integer` with minimum 1. No other keys. A string may be empty or contain newlines. Pass it unchanged. Normalize the supplied directory with `resolve_path` as a non-mutating path (`src/vfs/paths.py:396`), use the canonical value as `cwd`, and do no directory probe. This supplies the shell's starting path without introducing an existence oracle. Validate JSON types without coercion and reject nulls, booleans for integers, malformed Unicode and unknown keys before dispatch. Answer bad input with `refused_line(classified(ErrorKind.invalid, …))`, naming only the argument, exit 2 and zero shell calls. In particular `command`, `argv`, `stdin`, `authority`, `limits` and session handles have no wire spelling here. Both listing and dispatch use the serving allowlist. Use the common `ResultPayload` where the revision supports it. Omit advisory read-only, destructive and idempotent promises for arbitrary shell text. This follows the landed string-only kernel signature and 171-1 decision 3.

2. Decided 2026-11-25: publish the following single paragraph verbatim as `CLI_DESCRIPTION` for both a full tool set and a host exposing only `cli`. The examples name programs already present and work without a sibling tool. The tool schema remains the machine-readable argument reference.

> Run one Bash line against the VFS filesystem with this request's rights. Pass the shell text in line. Each call starts at workdir (default /) with fresh shell state. Changes to files persist subject to their permissions. Pipes, redirects, loops, functions, arithmetic and arrays run inside the shell. There is no access to the host operating system or network. Use cat, ls and grep to inspect files, search to rank matches, and traverse to follow links. Output includes stdout and stderr. A completed command can return a nonzero exit_code, including 1 for a grep with no match. A shell refusal, exhausted budget or timeout is a tool error. timeout_ms may shorten the deadline. A final plain cat of one image can return it inline within the media budget. Use head, tail or sed -n to narrow large output.

3. Decided 2026-11-25: invoke `await fs.cli(line, cwd=workdir, authority=request_authority, limits=…)` exactly once, with default empty stdin and the shell's declared starting environment. Use the verb-budget spec's tightening path for the deadline alone. At wire admission take the least of the requested milliseconds (unbounded if absent), the host's configured line ceiling and `WALL_TIME_BUDGET` in milliseconds (`src/vfs/deadline.py:36`, ten seconds on dev). Compare as integers before converting the bounded duration to the host deadline. Name the duration entry `deadline_ms` if the budget landing has not already named it; use its one existing equivalent otherwise. Let the shared admission code construct one absolute expiry and carry it through queue, VM and verb waits. No restart at a stage boundary or second competing timer. Other host limits stand. A wire request above a ceiling is clipped before it reaches the kernel's refusal for a raised override. This reconciles M1 criterion 3 with verb-budget decision 3 and the in-process shell's separate `DEADLINE_SECONDS` (`src/vfs/shell/host.py:77`).

4. Decided 2026-11-25: project the actual `LineResult` once under the negotiated revision with `isError = not result.success`. Use its own fatal facts and warnings, bounded stdout, stderr, exit_code, statuses and fuel_used under 171-1 decisions 4–6. Neither a returned status nor the presence of stderr changes the verdict. A command returning 124 under its own power is distinct from a machine deadline (`vfs.timeout`, exit 124). A failed validated call and a stopped line go through the same projector as a successful line. Keep completed output and statuses when the shell returns them. Legacy replies retain the same `isError` with the blocks their revision allows. This follows the built shell verdict over the conflicting stage-failure sentence in archived §3.

5. Decided 2026-11-25: select an image by the executed read. A candidate is the last stage of the last executed foreground top-level pipeline, resolved to the library's plain `cat` with exactly one expanded file operand other than `-`, inheriting the terminal's standard output with no stdout redirect. Ordinary quoting, a variable, the `--` separator or a single glob match may yield that operand. The unmodified copy must finish successfully, reach EOF, and emit one contiguous terminal-stdout span at the end of stdout. Earlier stdout and separate stderr are permitted. Use the resolved program and plain-copy path after command lookup, the pipe/descriptor destination and the actual file-open key. Never parse the line again, sniff stdout to infer identity, or use the last host read. A pipe feeding that final `cat file` does not disqualify it. A skipped or failed read, a transformed or multi-file `cat`, stdin, redirection, captured output, an interleaved writer, a compound final stage, a shadowing function or a later executed foreground pipeline clears eligibility or never establishes it. The Bash builtin `read` names variables, so the archive's second file-reading spelling would describe a different command. This limit follows the archive's single-read rule and the existing top-level pipeline status boundary (`crates/vfs-shell/src/machine/exec.rs:323–349`).

6. Decided 2026-11-25: keep one optional capture per wire shell call. In core, install a private task-local capture for exactly the `fs.cli` invocation, bind it to the new host at admission and reset it in `finally`. Keep MCP types outside the shell. The machine marks the prospective terminal open on its existing read request and reports its completed raw stdout offsets and open key at pipeline completion. Invalidate the candidate on entry to the next top-level pipeline that runs, any overlap with a competing stdout writer, mismatch, incomplete write, failure of the line or cancellation. Acquire no new file open to obtain the image. For a marked open only, extend the host's existing column set with `path, kind, source, mime_type, size_bytes, version` and `vid` when available. Take the bytes and identity from the same successfully admitted observation. A conflicting reread discards capture. Preserve the actual shell effects, byte stream, output limit and statuses even when no attachment can be admitted.

For `source="bytes"`, supply that row's metadata to the wire renderer and the exact raw body only when allowed by its type, measured length, per-block and total raw budgets and media count. If the private capture lacks required identity or the marked span does not match the complete open, fall back to ordinary shell output. A valid empty byte body is distinct from an unpopulated body. For an oversized or unsupported binary keep its authorized metadata with `data` cleared and removed from `populated` for the adapter's link/placeholder rule. A text source retains plain stdout. Complete the wire copy before UTF-8 replacement obscures the offsets: decode the ordinary prefixes and present the marked span once as the source row's placeholder using 171-1 decisions 4 and 7. The displayed placeholder substitutes for that range in the bounded stdout projection. The public Python streams and any run record keep the original stream contract. Only a shown observation can carry a media block. The adapter owns MIME eligibility, base64, metadata, row cut, fallback and revision handling. For the wire's source-file placeholder discard any duplicate run-output placeholder for the same span. Provenance never comes from a log or a second path lookup.

7. Decided 2026-11-25: pin D57 at the served boundary, including anonymous `read_write` where the host explicitly serves an open mount and an admitted named caller. Neither the tool list, shell host registry nor a dynamic program resolution may dispatch the irreversible developer method. A local function is ordinary shell code with the same limits on dispatch. A literal or expanded `destroy` resolving as an external name returns the program-table refusal, exit 127. `rm` routes to `delete`. The current `sweep` and future `destroy` must both see zero calls through all these paths. This is a regression pin on the existing public-verb boundary (`src/vfs/ops.py:101`, `src/vfs/shell/host.py:476–490`), independent of when the rename lands.

## Cost

Per wire call there is one shell admission, one projection and zero additional public reads, database round trips or body fetches for the attachment. At 150,000 agent calls/day and about 20/s peak over 10 million files (`AGENTS.md:74–82`), even if every call were a terminal read the added round trips remain zero. The eligible read adds a fixed number of projected metadata columns to the existing read on SQLite, PostgreSQL or the generic floor. No query, bind list, writer lock or stored row grows with the corpus. The ordinary shell still incurs its original whole-body read and output costs. This is an incremental bound, including when an ineligible or large body already had to be read to execute the line.

Each of at most the declared verb budget's requests needs at most a fixed marker and key. Share the existing raw body and output buffer. Retain at most one row with one path under `MAX_PATH_LENGTH` and at most B bytes of attachment, where B is the smaller configured per-block and total raw media budget, zero when no media slot remains. Compare lengths and offsets before copying, charge any retained body against the line memory budget and release it immediately upon invalidation. The optional full-span verification visits at most B bytes when retaining an image; metadata-only fallback uses the machine's open key, byte count and EOF. Encoded size is at most `4 * ceil(B / 3)` bytes for this one block, in the adapter's existing budget. With C admitted lines, capture adds at most C rows and C × B retained bytes; no state survives the call. Bound the wire prefixes and escaped payload by the adapter's declared limits.

## Choices to confirm

1. Use a task-local, opt-in read capture tied to the executed file open. A second point fetch can race a rename, replacement or grant change; a new public binary stdout field would duplicate the observation channel. The private hook can be replaced without changing callers.
2. Start with a directly executed plain-file `cat` as the final foreground stage, including one expanded operand. Leave compound final stages, transformed reads and ambiguous interleaved output on ordinary output. Evidence can later admit more shapes without taking a currently returned attachment away.
3. Use one fixed description even for a sole-tool server. The archive allowed two copies differing by a reference to the sibling `read` tool. Omitting that optional cross-reference keeps one accurate byte-for-byte listing. Changing the prose later requires no schema migration.

## One line

One `cli` call runs one line with the request's rights, preserves the shell's verdict and status, and can show the image from the terminal file open.

# A JavaScript program runs in QuickJS-NG over the Python guest’s file provider and verb door

A draft, written on 2026-11-25. It is not reviewed, and nothing of the guest is built. Checked against `dev` at `27f3d24d` for [roadmap T5b, gate b](../../context/standards/roadmap.md), converted from [the WASI runtime, §6 and slice 172d](../../context/specifications/archive/172-the-wasi-python-runtime/spec.md). It rests on the Python guest’s adapter, the shell’s program catalogue and the QuickJS runner spike that supplies the evidence for D49.

## The outcome wanted

With `vfs-py[javascript]` installed, `qjs /work/job.js` can read a JSON file, sum its values and write the answer to a sibling as the caller. The same script runs as `node` or `js`. Plain `type node` identifies QuickJS-NG and its limits before any code runs. A guest can open files or ask VFS to run a verb. Both ways enforce the same visibility and preserve the same classified refusals as Python. A base install still imports `vfs` without either guest.

## What the code does today

The eleven names in `PROGRAMS` have no guest. The shell passes their names to the machine, resolves a start and holds its output for feed (`src/vfs/shell/host.py:228`, `:439`, `:463`). The machine’s `type` builds its own human-readable or terse answer (`crates/vfs-shell/src/machine/builtins.rs:1936`). The project extras omit both runtimes (`pyproject.toml:49`). The installed environment has no `wasi_python`. The shell’s compiled module, instruction metering, epoch interruption, memory limiter and import linker are in `crates/vfs-core/src/shell_binding.rs:29`, `:287`, `:290`, `:378` and `:453`. Its Wasmtime 51 dependency has no WASI preview1 linker (`crates/vfs-core/Cargo.toml:24`).

Executed through `open_session` on file SQLite and a fresh local Postgres database. `qjs -e true`, `node -e true` and `js -e true` each exited 127 with empty stdout and no classified fact. `type node`, `type -t node` and `command -v node` each exited 1. Under posture `none`, a reader of `/private.js` got its source. Another caller, a genuinely absent path and the original reader after revocation all got `vfs.not_found`. On both engines a direct session read of `{"x":[1,2,3]}`, empty exclusive create and guarded fill of the sibling produced versions 1 and 2 and the text `{"sum":6}`. These are kernel observations, not guest verb counts.

An independent ECMAScript oracle ran the transform under the local Node interpreter, passing two real SQLite session-read payloads in version-1 success frames. The JavaScript code decoded the visible input and the hidden read’s `success: false`, then emitted a write frame that the same session executed. The sibling read back as `{"sum":6}`, and the denied read kept `vfs.not_found`. This exercised the proposed distinction between a successfully delivered refusal and a broken tool frame. It did not exercise a WebAssembly import.

## The problem

A JavaScript filename currently reaches neither a guest nor the caller’s files. Running the host’s Node executable would expose a different filesystem. A second implementation of file rights, errno or stage completion would make a script’s result depend on which language made the same call. At ten million files, resolving an import by enumerating names would also put a corpus operation on the path of a single module read.

## Decisions

1. **Select the engine once, from D49’s evidence.** Decided 2026-11-25: consume the spike report, including artifact hashes, stand-ins, failed probes and per-verb counts. On `runs`, or on delivery of the accepted upstream changes, use the runner’s public module, mount and tool interfaces as a thin adapter. Validate the shipped artifact against every required probe with the production packaging. Keep a stand-in only if the selected public interface supports it and it grants no access to a host path. On `does not run` with no accepted runner route, wait for the D49 ruling. If it advances 169-4, use its preview1 linker, bounded module instantiation, provider forwarding and single `host::call` over the existing `vfs-core` embedding. Instantiate only the verified QuickJS module. Package any QuickJS-only native linker in the optional distribution so that the base wheel gains no guest engine payload. Both engines deliver the same events to decision 4. Neither a native interpreter nor runtime selection by retry after a trap is an alternative. D22 keeps arbitrary binaries and package installation off the 0.1.0 path.

2. **Keep artifact bytes and program enablement in extras.** Ship an exact-version optional dependency with a plain `wasm32-wasip1` QuickJS-NG module, a manifest identifying its source revision, toolchain, entry code and module SHA-256, and its license. Keep the archive hash in `uv.lock` and an independent expected module digest and byte length in the private descriptor in VFS. Verify length and streamed SHA-256 before compiling the very bytes verified. Cache only the verified, immutable compiled module per digest and engine configuration. Start each stage with a new instance. No download, host directory preopen, install command or system grant occurs at execution. Neither the module nor a snapshot enters the VFS wheel or a VFS row. Artifact identity and its final digest come from the selected build, never from a tag alone. This follows T5b criterion 5 and spike decisions 3–7 and 17.

   On the shared-runner branch, the spike pins `wasi-python==0.1.6` while the Python unit pins `0.1.0`. First read the spike's second run, at the Python pin (spike decision 19); repeat the required probes with that pin only where the report reads `At 0.1.0: not measured`. If they pass, keep that pin. Otherwise test the JavaScript-passing release against the entire Python consumer contract, including classified refusals and the CSV ceiling. Change both to a single passing pin and hashes in the same landing. An untested or incompatible pair blocks release. Installing the runner alone cannot tell which extra requested it. If it includes the Python payload, have the Python extra install a small VFS-owned registration wheel as well as its runner. Discover the Python name from that distribution and the JavaScript name from the QuickJS artifact distribution, using package metadata without importing either runtime. On a runner with separately distributed guest artifacts, those two artifact distributions themselves supply the markers. Base, Python-only, JavaScript-only and combined environments then expose zero, one, one and two guest kinds respectively. Keep the existing `all` selection light as in Python decision 1.

3. **Make the catalogue the source of names and trust text.** In the shell host program table register two rows in a private guest table, `python` and `javascript`, each with its names, manual, artifact descriptor and entry strategy. Expose only the installed rows. `qjs`, `node` and `js` all address `javascript`. Discovery, direct invocation and manual reads use the same served names. Absent extra gives the ordinary known miss, 127 and `vfs.unrecognized` with `install vfs-py[javascript] in the host environment`, for direct invocation. Discovery returns an ordinary miss. A present but unusable or hash-mismatched artifact gives 126 and `vfs.unavailable`, with zero code run. Keep shell-local precedence and any higher-priority file on the caller’s PATH. Only the shipped JavaScript entry carries the description `QuickJS-NG, not Node: no npm, no network, no native modules`. Append it in parentheses to the resolved address line of plain `type` and the matching line of `type -a` for these names. This specializes catalogue decision 10 for the human-readable form as T5b criterion 1 requires. Terse and path-only forms keep their existing output. A shadowing function or stored `node` gains no such description.

4. **One host adapter serves both rows.** Factor the Python stage lifecycle into private `GuestAdapter`. Each row supplies argument handling, a checked artifact and the selected runner entry, while admission, stream collection, completion and teardown use the same class. Each invocation gets the Python unit’s `VfsProvider(session, loop)`, `verb_tools(session)`, dispatcher, ordinal, refusal recorder and `WASI_ERRNO` by reference. Reuse its fresh authorization for opens, hidden `.vfs` checks before dispatch, write-back guards, tool allowlist, disposal of stage state and reservation of line resources. No JavaScript provider, errno map or interpreter-specific grant. A guest-originated filesystem operation, including a module load, can touch only the caller-bound mount. The packaged module is read by the host, never by traversing a guest-visible host directory. Do not inherit environment, filesystem descriptors, network, process creation or dynamic native loading. Import only the supported subset of `wasi_snapshot_preview1` and the single private tool import `host::call`. Reject another import before instantiation and preserve the artifact’s unusable status. This applies equally to the conditional host.

5. **Give JavaScript a small, explicit invocation and loader.** Accept `qjs [-e code | script.js | -] [args...]`, `--` before a script, no operand for stdin source, and `--version` for a QuickJS-NG version line derived from the verified manifest. Apply the identical grammar to all three names. Reject missing eval text and unknown switches with status 2 and `vfs.invalid`. Use strict UTF-8 source, a fresh VM context, the stage cwd, exported environment and bounded stdin. Pass arguments as data, retaining empty and Unicode arguments. Expose `scriptArgs` starting with the script operand, `-e` or `-`; after a named script or eval, stdin remains data. Run the entry as an ES module, drain pending jobs within the same budgets, keep stdout and stderr distinct, and treat uncaught JavaScript exceptions as interpreter status 1 with diagnostics. An ordinary explicit exit keeps its status. Support QuickJS’s `print` and the WASI-backed `std` file and stream operations needed by the fixture. There is no Node package resolver or REPL. A readable named script is an operand. This unit adds no extension-based shell execution or shebang override.

   Load static and dynamic imports of explicit `.js` addresses relative to the importing module, or from the guest root for absolute addresses. Resolve relative imports from eval/stdin against the stage cwd. Normalize in VFS coordinates after the provider’s literal hidden-segment check, and check the resulting path again. Use one exact canonical address for module identity, cycles and the per-instance evaluated-module cache. A new instance reads its modules afresh. Load the source through the provider, with no index scan, extension probing or host path fallback. Accept only the packaged `std` built-in in addition to these addresses. Unsupported bare package names, URL schemes, native suffixes and `node:` specifiers fail before any lookup, with a bounded diagnostic carrying `vfs.unsupported` and the trust text. Report an uncaught unsupported import by the typed, bounded private diagnostic of Python decision 12, with the rejected specifier as guest-reported evidence. A caught optional import or stderr text cannot forge a host failure. A denied source read keeps the provider’s original fact. The archived module-loader requirement is thereby read under the landed path rules (`src/vfs/paths.py:396`).

6. **Use the existing tool frames from JavaScript.** Ship a synchronous `tools.list()` and `tools.call(name, args)` in the guest entry, using spike decision 9’s version-1 JSON requests and matching response IDs. A successful call frame yields its unmodified `value`, even when that Result says `success: false`. A failed or invalid protocol frame throws a bounded guest exception and the adapter keeps the protocol failure. A small `vfs` global forwards methods for the same reviewed tool names with an argument object. Accept a path-string shorthand for `vfs.ls(path)` so the archive’s `node -e 'vfs.ls("/")'` runs as one tool call. Derive the facades from the published VFS verb descriptors, excluding the interpreter’s private diagnostic. There is no dynamic host method or authority argument. Charge the frame, its reply and its one routed operation as in Python decisions 8 and 10. This uses the same wire on either engine.

7. **Use the shared budgets and terminal result.** Pass Python decision 10’s remaining line fuel, verb, output, deadline and host-byte allowances and its finite file, tool and open-file caps. Tighten JavaScript linear memory by a declared `JAVASCRIPT_MEMORY_BYTES` default of 64 MiB, following the archived cap and spike decision 16. Lower it further when the configured allowance is smaller. Charge module source, names, graph entries and distinct zero-byte modules as well as staged bytes before copying or evaluating them. Fuel bounds both evaluation and pending jobs. The engine enforces the deadline independently of JavaScript cooperation. An identified limit yields 137 and `vfs.budget_exhausted`, a runner deadline 124 and `vfs.timeout`, another guest trap 134 with the classification of Python decision 11. The parent’s first terminal cause still wins. A mutating refusal caught by code that exits 0 yields stage 1, one fact with the original kind, and original exit 0 in its guest evidence. The same rule covers a refused final flush. A negative file probe may be nonfatal. Do not classify by matching stderr.

8. **Re-enter through the same dispatch boundary on resume.** Make fresh construction, stage-relative ordinal and canonical request data available to H5 before an effect from either door. Use the H5 fingerprint of operation and arguments, including the addressed file, write content and conditions where present. A resume instantiates again under the original caller. Matching requests get recorded replies without redispatch. The recorded answer satisfies the original ask. A changed fingerprint causes one fresh, counted request and one divergence record, and a different asking call asks again. Discard the first instance and avoid replaying its stdout twice. Fuel and wall allowance restart per walk as H5 specifies. Pin this against an in-memory journal test double until H5 can run the same contract against the durable store. No memory snapshot, private replay database or new result kind is introduced by this guest.

## Cost

Let `J` be JavaScript stages per day and `N` the counted routed verbs for the fixed job. At the [reference deployment](../../AGENTS.md), a single-stage share `s` of 150,000 calls gives `J = 150,000 × s` and `J × N` inner calls. The share is unmeasured. Spike decision 16’s 64 is the fixture’s file-call ceiling, not a measured value of `N`. Pin the full-shell per-verb histogram for script load, JSON read, create and guarded close, separating setup, executable lookup, tool frames and verification reads. Compare like phases with spike probe 3. Investigate discrepancies before setting the regression count. Keep statement counts by engine separately. No new SQL, bind list, index visit or storage schema is required on SQLite, Postgres or the generic floor. A fresh file filled after create adds at most one version relative to a single write, per such create, not per ordinary write or nightly indexed row.

Per stage, module lookup is one bounded path resolution and authorized provider read per distinct module loaded, plus the provider’s counted metadata probes. Outstanding module bodies and cached names draw on the memory allowance. Reachable modules and pages exhaust a file or verb allowance before scanning arbitrary rows. Hashing is linear in the declared artifact length, once per admitted compiled digest per process; at most one compiled QuickJS artifact is retained for the selected release. Concurrent stages reserve from the line and host admission budgets. Their writable memory is bounded by admitted concurrency times their per-instance memory ceiling, plus the charged host buffers. No SQL transaction or shared lock spans guest evaluation. On SQLite the provider’s separate committed calls leave readers free during guest work.

## Choices to confirm

1. **Engine and compatible runner release.** Wait for the D49 report. Favor the public shared runner and the Python pin when both consumer contracts pass. A negative report requires a ruling between waiting for an accepted upstream change and advancing the QuickJS-only host half of 169-4. Neither the fallback implementation nor an incompatible release pin is chosen in advance.
2. **Who ships the artifact.** Prefer an independently versioned, VFS-owned companion wheel built from unpatched pinned QuickJS-NG plus the narrow reactor entry. If the runner project publishes the required artifact and supported contract, the private descriptor can point to that distribution. Do not assume an external release commitment. The choice is reversible because the public extra, guest names and import contract are independent of the artifact’s publisher.
3. **Separating the two extras on a bundled runner.** Take the small Python registration wheel if the shared dependency carries CPython. A separately packaged upstream runner core and two language payloads remove the marker without changing either public extra. Inferring the requested extras from an installed runner would make a JavaScript-only installation advertise Python.
4. **Module names and the trust display.** Take explicit `.js` paths, one built-in `std` module and a description appended to the resolved address in human-readable `type`. Additional import conventions and supported built-ins can be added later. Replacing the address with a description would remove the existing catalogue’s route back to the selected program.

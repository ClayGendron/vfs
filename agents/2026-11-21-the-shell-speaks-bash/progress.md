## Decided inside the laws

- A case runs as `bash --norc --noprofile -c "$script" bash` in `/work`, as an unprivileged user, with the environment in `tests/shell/README.md`.
- Bash parses and runs one top-level command at a time, and this shell parses the whole line first. A syntax-error case puts its error in the first command, so the two agree. Two extglob cases are malformed to bash only because `extglob` was off when bash parsed them.
- Refused before anything runs: `eval`, `source`, `.`, `exec`, `trap`, `jobs`, `fg`, `bg`, `disown`, `suspend`, `alias`, `unalias` and `coproc`. A refused word reached at run time also ends the line with status 2.
- A request key is the path of the task in the walk (one index for each enclosing pipeline stage, subshell, substitution and job) and the request's ordinal in that task.
- Process substitution runs its list to its end into a buffer before the command that names it. `>(list)` feeds its list once the command ends.
- A redirection is opened as bash opens it, before its command runs, so no command acts before its file is refused. A simple command that can act on nothing else before it ends (`echo`, `printf`, `:`, `true`, or `cat` with no operands, and no function of that name) has its file judged by a `stat` of the target, and of its directory when the target is absent, and written once when the redirection ends, creating, truncating or appending as the operator says, with `if_absent` under `set -C`. Any other command has its file opened by a write of no bytes, and its bytes follow in a second write: the roadmap's one write holds for the commands that only print, and not for a group or a program, since a refusal can be known only by writing. A read or a listing of the same path inside the line writes first. Output past 8 MiB is written in more than one request.
- A loop iteration is one run of a loop's body.
- The vfs host holds the bodies a line reads, up to 64 MiB, and forgets them at any mutation; the body being read is held whatever its size, so a reader takes it in chunks from one `read`. A verb a program was refused is kept as a warning: a program's failure is not the call's.
- `cli` is a management method, not an op, and joins `MANAGEMENT_METHODS`. On the synchronous face it is a management hop, so a closed face raises as the other management methods do.
- The budgets the runtime adds, each a named constant: `FUEL` 20,000,000,000 instructions (about five seconds of the machine's work), `FUEL_SLICE` 10,000,000 (about a millisecond), `MODULE_MEMORY_BYTES` 256 MiB, a 4 MiB native stack for the module's frames and an 8 MiB shadow stack in its memory, and `DEADLINE_SECONDS` 30 in the host. The machine adds `OUTPUT_BYTES` 16 MiB and `NESTING` 1,000. The deadline ends a line with status 124, as `timeout` does, and the kind `vfs.timeout`.
- One nesting budget counts compound commands, function bodies and substitutions together, so the product of the function depth and the parse depth no longer reaches the stack. Each link of an arithmetic or `[[ ]]` chain counts against its parse depth, so `1+1+…` 70,000 links long is an arithmetic error where bash computes it. The stacks are sized so that every declared budget fires before the runtime's stack limit, measured by the probes above.
- A regular-expression search that spends its step or depth budget fails: `[[ =~ ]]` returns 2, `grep` reports the file and exits 2, `sed` exits 4. It never answers "no match".
- A `printf` precision or a brace-expansion width past 65,535 is written out by the machine, since the standard formatter panics there; the digits past a double's exact expansion are zeros.

- The known failures were sorted by what a difference does. Where the shell acted or decided otherwise than bash, it is fixed (`f26a556`): `PIPESTATUS` is set after every pipeline, `set -n` runs nothing more, an unbound variable in arithmetic under `set -u` ends the script, a subshell and a substitution start outside every loop, `break 0` leaves its loop with status 1, a trailing slash in a file test wants a directory, a background job's status drops its pipeline's `!`, and `test` with three arguments reads a binary operator before a leading `!`. Four such cases stay listed: `1<> f` writing in place and `< f > f` truncating before the read, which need a file position the machine has not got, and two finds under `found/`, a variable inside an extglob group that is not expanded and a here-document ended by the end of input, which is a syntax error here. The other 117 were sorted by their names and areas, not read one by one; by those, most print different text from the same decision (`printf` floats as `long double`, `declare -p`, `mapfile` and `read` options, xtrace, programs' long options) or use bash 5.3's newest forms. `agents/2026-11-21-the-shell-closes-its-known-failures/spec.md` holds them all.

## Reported and not taken

- `cli` takes no `limits`, `fuel` or `deadline`; `run_line` takes all three. A caller of `cli` reaches it over MCP and must never raise its own budget, so the host sets the budgets and a call may only tighten them: `agents/2026-11-21-a-line-has-a-verb-budget-and-cli-tightens-it/spec.md`, with the verb-call budget and a bound on concurrent lines.
- `grep -r` and `find` walk through `list` and `read` instead of the indexed verbs. The program request now lets the vfs host serve them itself, as it serves `search`; doing so means printing what GNU grep and find print from the verbs' rows, which is not built.
- `traverse`, `grant` and the other verbs with no Unix name are not programs yet; each is one more entry beside `search`.
- The parse depth of 200 counts each grammar rule a construct passes through, about six for one `$( )`, so 33 nested substitutions parse and 35 do not, where bash runs 40. Counting one level for each construct changes what the budget means. Compound commands carry no span of their own.
- The fuzzer's grammar covers the language tier only, with no programs, no `set -e` and no job control; widening it is a matter of more productions.
- The Oils spec-suite rate is not measured. The prior-art memo ran 468 Oils cases against the crate: 363 agree, 39 differ, 66 were skipped; its section 6 lists the differences not in the corpus.
- The weighted sample's raw run rate is 72%; its in-scope rate is 93.5%. The standing table's unbuilt programs are `agents/2026-11-21-the-shell-runs-the-standing-program-table/spec.md`.
- Roadmap F1 (removing `SupportsRun`), `move(replace=)` and `glob(case_mode=)` are not built.
- `printf` floats use 64-bit doubles where bash uses `long double`, so `%.20f` and `1e309` differ.
- The regular-expression engine backtracks, with no back-references, and fails a search past 4,000 characters of depth; a Pike-style engine would be linear. Glob and extglob matching backtrack too: `*a*a*a*a*b` over 100,000 characters spends the line's fuel where bash answers in milliseconds.
- The module's boundary is JSON with every byte in base64. Its decoder looked each character up by a scan of the alphabet; with a reverse table (`2512f14`) `cat` of 1 MB spends 269 million instructions (642 million before), `wc -c <` 356 million (729 million) and `grep -c` 1.13 billion (1.50 billion), so a line reads about 70 MB under the default fuel. A binary wire is `agents/2026-11-21-the-shell-crosses-its-boundary-in-binary/spec.md`, and serving `grep -r` and `find` from the indexed verbs moves the heavy case off the boundary.
- The roadmap's one write per redirection holds for a command that only prints; a group, a loop or a program has its file opened by a write first, since only a write can learn that the caller may not write the file, and bash refuses the redirection before the command runs.
- The Rust toolchain is not pinned, so the module, and the instructions a line spends, differ between wheel builds. The first line in each process compiles the module, about 260 ms and 180 MB of peak memory on macOS. Both are in the boundary spec.
- A line in a slow pattern match holds a worker of the shared offload pool until its fuel runs out, so many such lines delay other callers; a pool of the shell's own and a bound on concurrent lines are in the budget spec.
- The building of a wheel from the sdist now needs the `wasm32-unknown-unknown` target beside the Rust toolchain.

## Findings, most severe first

- **H1** (Adversarial, breach) The depth budget leaks on every backtracked arithmetic attempt, so valid scripts are refused. `crates/vfs-shell/src/syntax/parser.rs:948` (`try_arith_command`), `:1718` (`$((` in `read_dollar`), `:2171` (`read_inner` enters, then returns early on error), `:1767` (`read_command_sub` enters and returns early on error). A failed `((` or `$((` attempt resets `pos` but not `depth`, `tokens`, `footprint`, `pending` or `heredocs`, and every `enter()` passed before the error stays counted. EXECUTED: eight lines of `echo $((echo a) )` give `Budget("depth", 200)`, as do 190 lines of `((echo a); (echo b))`; bash 5.2 runs both. Closes with: save and restore all parser state on every backtrack (depth, tokens, footprint, pending and recorded here-documents), and a test per family that parses each construct many times over; fix H2 in the same change, since restoring depth alone lets each fallback rescan to the end of the source again, which is quadratic in a 1 MiB line.
- **H2** (Contract, breach) The arithmetic attempt runs past a `)` that closes depth zero and reads quotes and comments as arithmetic text, so a subshell whose later text holds `))` becomes one arithmetic command. `parser.rs:2251` (`depth.saturating_sub(1)` at depth zero keeps scanning) and `read_inner` with `Inner::Arith` (single quotes and `#` are plain bytes there). EXECUTED: `((echo a); echo b)  # ))` parses to `Arith("echo a); echo b)  # ")`, where bash prints `a` and `b`; `((echo a); echo b)` followed by `echo '))'` is refused as a syntax error at line 2, where bash prints `a`, `b`, `))`. Closes with: bash's rule, that the attempt fails as soon as a `)` closes depth zero without a second `)` directly after it, and tree tests for these two lines.
- **H3** (Contract, breach) A here-document opened inside a command substitution in an unquoted here-document body loses its body, and its redirect points at the outer document. `parser.rs:386` builds a sub-parser for the body, and `absorb` at `:400` keeps its counts but drops its `heredocs`, while the inner redirect keeps the sub-parser's index. EXECUTED: `cat <<A` / `$(cat <<B` / `inner` / `B` / `)` / `A` yields one here-document, whose body holds a `cat` redirected from `HereDoc(0)`, the outer document itself; bash prints `inner`. A machine that follows the tree reads a cycle. Closes with: merge the sub-parser's documents into the parent with rebased indices (or read bodies in place), and a tree test.
- **H4** (Tests, gap) The parser fuzz target is absent. Step 2's scope names it, decision 9 counts it as one of the four walls and decision 18 says how it runs; no seeded generator, no declared iteration count and no gate step exist. H1 and H2 are the kind a grammar-driven fuzz run finds. Closes with: the seeded target over `parse` on the stable compiler, run for a declared number of iterations in `cargo test` and so in the gate, asserting no panic, no budget leak (a valid line parses alone and repeated) and a bounded count of steps.
- **H5** (Tests, survived mutant) The decision 4 source rule cannot see a grouped import. `crates/vfs-shell/tests/source_rules.rs:41` greps for the text `std::fs`, `std::process` and the rest. EXECUTED: appending `use std::{env as _e, fs as _f, process as _p};` and a function that reads `/etc/passwd` and `HOME` to `src/lib.rs` leaves all four source-rule tests green. Closes with: a check that reads every `use std::` tree, braces included, and every path expression starting `std::`, with a negative self-test that feeds it the grouped form.
- **H6** (Tooling, gate red) `scripts/ci.sh` and the CI Tests job are red at the tip. EXECUTED: `uv run ruff check src/ tests/` reports `T201 print found` at `tests/shell/world/src/main.py:8`, a seed-tree file that lies under `tests/`; `ci.sh` stops there, so its new shell step never runs; the Tests job in `.github/workflows/test.yml:65` runs the same command (INFERRED red). Closes with: keep the seed tree out of the Python gates (an `extend-exclude` for `tests/shell/world` in the ruff and ty configuration, so its contents stay as bash sees them), then `scripts/ci.sh` green end to end.
- **M1** (Tests, gap) Nothing pins the tree the parser returns. `parse_corpus` checks only parse-or-malformed; EXECUTED: a mutant `parse` that returns an empty `Script` for every input fails 82 of 3,320 cases, so 3,238 well-formed scripts would pass with no tree at all; no test covers spans, positions, the four budgets, refusal names or here-documents. In the harness, `Case::judge` and the listed-passes branch of `score` never execute, because `run_case` always fails: EXECUTED, a mutant `judge` that returns `Ok` survives every test. Closes with: tree tests for the families probed here (here-documents in `$( )`, `case` in `$( )`, `((` against `( (`, `[[ =~ ]]`, arrays, the function forms, comments, line continuations), budget tests at the limit and one past it, and a `score` test driven by a fake runner that exercises `judge` and the listed-passes branch.
- **M2** (Contract, breach) Decision 3's positions and spans are not as declared. A sub-parser for backquotes or a here-document body builds its own line table (`parser.rs:150`) and `position` at `:238` reads it, so lines and columns count from the sub-text: EXECUTED, `echo a` / `echo b` / ``echo `fi` `` reports line 1 column 1 (bash names line 3), and `fi` inside a here-document body on line 3 reports line 2. `ParseError::Budget` (`syntax/mod.rs:43`) carries no position. `CompoundCommand` (`ast.rs:119`) gives `If`, `While`, `Case`, `Brace` and `Subshell` no span, nor do `List`, `Stage` and `CaseArm`. Closes with: sub-parsers that share the parent's line table, a position on every error, a span on every node, each pinned by a test; or a Disposition answer that changes the decision, which is reported and not taken.
- **M3** (Security, confirmed medium) The depth budget keeps no stack bound that any test holds. EXECUTED: on a 1 MiB thread in a debug build, `f() { ` repeated 49 times (445 bytes) aborts the process with a stack overflow before the budget of 200 is reached; at 1.5 MiB debug and at 128 KiB release every family reaches the budget, and 64 KiB release overflows. The WebAssembly module is a release build with a 1 MiB stack, so it has margin; a native debug host on a small thread does not, and decision 9 promises that no input crashes the host. Closes with: a test that parses the worst input of each nesting family at exactly the budget on a thread of a declared stack, in the profile the gate runs, and that stack stated on `ParseLimits::depth`.
- **M4** (Security, confirmed low and needs_validation) Refusal by the first static word is bypassed. `parser.rs:703` checks only the first word; EXECUTED, `command eval echo`, `builtin eval echo` and `command exec ls` parse as plain commands, as do the dynamic `e=eval; $e echo` and `f() { "$@"; }; f eval echo`. Decision 3 makes the tree what a host judges before anything runs. The missing fact is whether the machine of step 3 refuses a refused builtin reached at run time; no machine exists to test. Closes with: refuse `command` and `builtin` followed by a refused name at parse, and a step 3 obligation, written into the spec or a delta, that the machine refuses a dynamically named refused builtin at run time.
- **M5** (Contract, breach) The deltas carry no record of the shell's own answer. `deltas.txt` names 35 cases and none has a `.shell.json`; `corpus.rs:44` checks only that a `.shell.json` is listed, never that a listed case has one; `Case::expected` (`support/mod.rs:59`) then falls back to bash's record, so the 35 refused cases can never pass, and must stay known failures, though decision 16 says a delta is not a known failure and passes against its own record. Closes with: a `.shell.json` for each, holding the refusal's status and output, and the test made two-way.
- **M6** (Harness, gap) A record is not shown to be a function of the script. Both runs happen in one container (`scripts/shell_record.py:52`), seconds apart, so the host name, the clock and anything else fixed within one container pass the two-run check. EXECUTED: a case printing `$HOSTNAME` and the minute was recorded without complaint, and recorded again as `host=41722b19c25a` then `host=9b68957c7e66`. A record also holds no digest of its script or of the seed tree (`:95`), so a script edited after recording keeps its stale record and nothing notices. The README's list of forbidden constructs is enforced by nothing; a scan of the corpus found no use of one (READ). Closes with: the two runs in two containers started apart, a sha256 of the script and of `world/` in each record with a test that compares them, and a corpus lint for the README's list.
- **M7** (Harness, gap) The ratchet is exact but not monotone. `scripts/shell_score.sh --write` rewrites `known_failures.txt` from the run, so a change that makes a passing case fail, followed by `--write`, keeps the gate green while the score falls; `corpus.rs:3` says the list "can only shrink". The list also drops duplicate names silently (`read_list` builds a map). INFERRED from the code. Closes with: a gate check that the list gains no name over its merge base with `dev`, a refusal of duplicate names, or a Disposition answer that the spec's wording is taken as exactness only.
- **M8** (Contract, breach) `MemoryHost`, part of step 2's scope, does not exist, and the crate's front page documents it. `crates/vfs-shell/src/lib.rs:7` links `machine` and `host::MemoryHost`; EXECUTED, `cargo doc -p vfs-shell` warns that both links are unresolved. Closes with: the host built, or the item moved to step 3 in the work directory with the reason, and the crate doc matching the crate.
- **L1** (Contract, misclassification) A here-document inside backquotes is reported as a syntax error, though it is a refusal. `parser.rs:1685`. Fix: return `ParseError::Refused(position, "here-document inside backquotes", "write it as $( ) instead")`.
- **L2** (Adversarial, divergence) Three lines that `bash -n` accepts are refused at parse: `echo $(cat <<E` / `a` / `E)` (bash takes `E)` as the delimiter line), `[[ a =~ ( ) ]]`, and `echo ${x@}` (bash reports a bad substitution when it runs). Fix: add each as a case recorded by bash 5.3, so the corpus decides.
- **L3** (Contract, latent) `arith.rs` spends about fifteen depth levels on each parenthesis (`binary` at `arith.rs:329` enters once per precedence rung), so 14 nested parentheses exceed a depth of 200 while bash evaluates 20; nothing calls it yet and nothing tests it. Fix: count depth once per parenthesis and unary operator, and test it beside its first caller.
- **L4** (Harness, smell) Nine cases under `tests/shell/cases/options/` carry both `# world: none` and `# world: seed`; the runner and the recorder both take `seed`, but the recorder greps the whole file and the runner only the header block. Fix: delete the `# world: none` line from those nine, and make `load_cases` refuse a case without exactly one `tier` and one `world` header.
- **L5** (Harness, smell) A case that hangs is recorded with status 137 from the 10-second `timeout -s KILL`, as if bash had answered. Fix: in `_read_run`, refuse a status of 137 with "timed out" in place of a record.
- **L6** (Ownership, misplacement) `pub fn is_name` sits under the `Internal helpers` banner (`parser.rs:2276`); `plain` takes an unused `_start` (`:2303`); `DocSlot` wraps one field; `syntax/mod.rs` puts its constants after the struct that uses them. Fix: move `is_name` beside `parse` and `line_starts`, drop `_start`, store `HereDoc` directly, and lift the constants above `ParseLimits`.

## Security

Method: `.claude/skills/security-audit/SKILL.md` in guidance mode; no run folder, no output directory, no `findings.json`.

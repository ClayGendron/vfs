## Findings, most severe first

- **H1** (Contract, breach) A redirection the caller may not write is refused only after its command has run, so a destructive command bash never runs is run. `crates/vfs-shell/src/machine/exec.rs:1906` (`open_write`) and `:1923` (`openable`) judge the target by `stat` alone, and `files.rs:152` defers every write to the flush; the commit message of `2913e50` scopes the early refusal to "a directory, a missing directory or a noclobber clash". EXECUTED (`p4_denied.py`): with `ada` granted `read_write` on `/w` and `read` on `/ro`, `{ rm /w/keep.txt; echo done; } > /ro/out.txt; echo status=$?` prints `status=1` and `/ro/out.txt: Permission denied`, and `/w/keep.txt` is gone; bash performs the redirection before the command, so the group never runs and the file stays (bash manual, "Redirections"; INFERRED, since the pinned image was not started for it). Closes with: a write-permission judgement before the command runs that writes nothing (a host request that asks whether a write would be admitted, or an empty `if_absent` create of an absent target, decided in the spec), and a test with this exact line on the vfs host and on `MemoryHost`.
- **H2** (Security, confirmed high; Adversarial, breach) The process dies on a small thread stack. `crates/vfs-core/src/shell_binding.rs:38` and `:264`-`:265` let the module's frames take 4 MiB of native stack, but a slice runs on whatever thread calls `step` (`:155`), and nothing sets or checks that thread's stack. EXECUTED (`p2_stack.py`): with `threading.stack_size` at 2 MiB or 1 MiB before the offload pool starts, `f(){ if :; then { ( f ); }; fi; }; f` through `fs.cli` ends the Python process with exit 139 (SIGSEGV); at 4, 6 and 8 MiB every line ends on its budget and the process lives. The Windows wheel ships, and CPython's threads there take the executable's default reserve, which is smaller than 4 MiB (INFERRED, needs_validation on a Windows runner). Closes with: run every slice on a thread the binding owns with a declared stack (at least the wasm stack plus a margin), or use wasmtime's async stacks so the module never runs on the caller's stack, and a test that runs this line from a 1 MiB thread and sees status 137.
- **H3** (Adversarial, breach) A line can make `cli` raise instead of returning a `LineResult`. `src/vfs/shell/host.py:298` accepts `rest[1].isdigit()` and `:299` calls `int()`, which refuses digits such as `²`; the drive loop at `:177` catches only `CancelledError`. EXECUTED (`p1.py`): `fs.cli("search -n ² alpha")` raises `ValueError: invalid literal for int() with base 10: '²'`. Closes with: `rest[1].isascii() and rest[1].isdigit()`, an answer of usage and status 2 for anything else, a guard that turns any exception from `_Host.answer` into a classified internal fact on the result, and a test for this line.
- **M1** (Contract, gap) The spec's done-when for steps 2 to 5 and 6 to 7 is not met: 135 language-tier cases remain listed, 145 in all, the measured sample runs at 72%, and the Oils rate is not measured. `tests/shell/known_failures.txt`. EXECUTED (the count above). The structural review, which the developer ruled taken, stopped the reduction for its five items; nothing rules that the branch lands with them. Closes with: the cases fixed, or the developer's answer in the Disposition that the pull request lands with the list as it stands, recorded in the spec.
- **M2** (Scale, growth; Security, confirmed medium) The vfs host holds every body a line reads, whole, for the rest of the line, outside every machine budget. `src/vfs/shell/host.py:224` and `:246`-`:254`. EXECUTED (`p1.py`): `for f in /t/*; do head -c 1 $f; done | wc -c` over 200 files of 100 KB holds 20,000,000 bytes in `_bodies` at its peak while the machine read 200 bytes; `grep -rc zzz /t` holds the same. Only the 30-second deadline bounds it, at about 20 calls a second at the reference deployment's peak. Closes with: drop a body once its reader reaches the end, or bound the cache by a declared byte count, and a test that counts the bytes held.
- **M3** (Scale, growth) A redirection past 64 KiB becomes one append per 64 KiB, and an append rewrites the whole body, so the bytes stored grow with the square of the output. `crates/vfs-shell/src/machine/files.rs:170` (flush at `CHUNK`), `src/vfs/storage/editing.py:51` (`appended` concatenates the stored body and the tail). EXECUTED (`p1.py`, `p5.py`): a 4 MiB redirection issues 64 `write` calls and leaves `/big` at version 64; at the database backend each append carries the whole body so far, about 136 MB written for 4 MiB (INFERRED from `writes.py:365`). ## Security

Method: `.claude/skills/security-audit/SKILL.md` in guidance mode; no run folder, no output directory, no `findings.json`. The probes ran this repository's own code in the review's container, with in-memory storage, dummy principals and no service.

Boundaries: (1) a line from a lower-trust caller, an agent, enters `cli`; the controls are the parse budgets, fuel, the module memory limit, the epoch deadline and the trap; the sinks are the host process's stack, memory and time. (2) Each request the machine asks becomes a verb; the control is that every verb is called as the caller's authority and the system actor is refused; the sink is a file or a listing the caller may not reach. (3) Program names the line chooses; the control is the host's table; the sink is a program vfs runs (`search`).

# A mount can serve a verb through its file operations

A draft, written on 2026-11-25. It is not reviewed, and nothing in this unit is built. Checked against `dev` at `27f3d24d` for [roadmap story K7](../../context/standards/roadmap.md), gate f, unit 179-10. Converted from [the storage seam as the kernel](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/spec.md), §§1.3, 2.1–2.3 and 4, and [tasks 14–15](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/tasks.md). It rests on the family regroup, listing cursor, range, replay and guarded edit. The file families alone lack two guarantees the proposed derivations require. The choices at the end state the build gates.

## The outcome wanted

A backend can supply file reads and writes and let the kernel walk directories, copy a subtree, match paths and file contents, and edit text under a guard. A caller can discover which verbs the mount serves and which the kernel composes. Calling one returns the native verb's envelope, with the same visible rows, ordering, populated fields, refusals and per-mount commit boundary. A derived scan can do more work. An unsupported argument is discovered before work begins. Reading an unprivileged listing must never turn a refusal to copy the whole source into a successful copy of its visible fraction.

## What the code does today

`Mount.caps` is computed from the declaration minus the mask (`src/vfs/mounts.py:110`). The read family requires `tree` (`src/vfs/storage/protocol.py:131`, `:172`, `:493`). Every admitted operation reaches a typed native arm (`src/vfs/base.py:2852`). A recording storage with all seven file verbs declared but no `tree` declaration returned one `vfs.unsupported` for `tree("/x")` with zero calls in a dev probe. Each storage method owns its transaction (`src/vfs/base.py:2865`).

The following probes ran against the public router with SQLite in memory (3.46.1) and a disposable Postgres database. The walk and file-operation compositions are prototypes; the other calls used dev's native implementation.

| Input | Observed on both engines |
|---|---|
| Five descendants of `/d`, including `a/x`, sibling `a.txt` and an empty directory | Two levels of batch `ls`, sorted by full path, equalled every projected native `tree` row at `columns=frozenset()`. A native two-row page ended at `/d/a.txt`, before `/d/a/x`. |
| One hidden source child under an otherwise readable directory | A named caller's `ls` omitted the child and returned no error. Native `copy` refused `vfs.permission_denied`. A system `stat` of the destination returned `vfs.not_found`. |
| Copy to a deleted file, then write there with `if_absent=True` | Copy returned `vfs.exists`. The write succeeded as `updated` at version 3. |
| Caller with `read` at a file, edit text absent from its body | Native `edit` returned `vfs.permission_denied`; ordinary `read` succeeded. An unchanged write of the standing body by the system actor with `if_version=555` returned `unchanged` at version 1. |
| Scoped search, with a readable file containing two hits, a list-only file containing a hit and a hidden file containing a hit | Native `glob` included the root, readable and list-only names. Native `grep(output_mode="count", allow_scan=True)` returned only the readable file with score 2 and no errors. Chained grep of the tree added a `vfs.permission_denied` for the list-only row. |

A separate SQLite prototype listed `/t`, committed one batch creating `/t/new` and `/t/sub/new`, then listed `/t/sub`. The assembled walk contained only the second new path. Neither committed tree had that shape. On the same engine a directory and four descendants written as explicit entries all committed in one batch, but returned five rows where native copy returned only the destination root. A rival replacing an edit target with different material before the prototype's version-guarded write caused `vfs.conflict` and left the rival's body intact.

## The problem

At ten million files the difference between one indexed native call and a walk is large enough to expose to callers. Correctness is the harder difference. A missing right can be indistinguishable from a missing row at the read seam. Separate calls can observe different commits, and the identity a keyed write records is the write's identity, even if it happens to carry the bytes a copy would produce. A fallback which merely loops over public methods cannot fulfill K7 for every backend which passes today's structural checks.

## Decisions

1. **Decided 2026-11-25: read K7 criterion 5's argument declaration as `traits()`.** Retain one authoritative declaration per argument. An absent or unrecognized value supplies no guarantee. A backend author declares the native argument values through the existing optional `SupportsTraits` protocol. A caller with a mount can read its storage declaration and the mount's effective ops without probing the verb. `capabilities()` continues to declare native verbs. Dev's `listing_cursor: keyset` is already a one-valued trait (`src/vfs/storage/protocol.py:96`, `src/vfs/cursor.py:131`). The vid branch and the range, replay and replacement specifications follow that precedent. Amend the criterion at `context/standards/roadmap.md:201` on landing to name the five operations and the qualified composition guarantee settled below. `rmdir` belongs to a front using `delete(cascade=False)` (`src/vfs/base.py:1077`), outside the kernel verb set. Choice 1.

2. **Compute native and derived operations once for each frozen mount.** Add `native_caps = declared_caps - deny_ops` and `derived` to `Mount` in `src/vfs/mounts.py`; expose their union as `caps` and the sorted derived names as `derived` in `Mount.to_payload()`. The existing union over mounts then advertises the served set (`src/vfs/base.py:665`). Put one acyclic prerequisite table `DERIVED_FROM` in `src/vfs/ops.py`. Its rows, in dependency order, are `tree ← ls`, `glob ← tree, stat`, `grep ← tree, stat, read`, `copy ← tree, stat, read, write`, `edit ← stat, read, write`. A usable native prerequisite satisfies a row without its own prerequisites. Each added op needs the guarantees of decisions 4–8; edit additionally needs `vid: entry_version`. An explicitly masked verb is never added, even transitively. Masking `write` removes derived copy and edit but a separately declared native copy can still run. Existing validation forbids masking read operations (`src/vfs/mounts.py:172`). Refresh declarations and composition assurances outside the topology lock for root, bind and `update_mount(refresh_caps=True)`, publishing them together after the existing rechecks. A mask-only change recomputes from the stored declarations. A failed refresh leaves the prior binding whole.

3. **Dispatch at the mount-local typed arm after the original gate.** `_call_storage` prefers a masked-in native declaration. A lying declaration or a native refusal is its own answer: do not retry by derivation. For an effective derived verb call a private function of the same name in new `src/vfs/derived.py`, below `vfs.base` and above `vfs.chain` in `tests/lint/test_code_shape.py:46`. It receives the bound file operations, local arguments and the effective authority of the *outer* verb. Keep recursive calls inside that binding. `MountListing.called`, its tree overlay and its root probes retain responsibility for public coordinates, deeper mounts, visibility of mount heads and partial failures (`src/vfs/listing.py:212`, `:278`, `:478`). Retain closed, transport, busy, reserved-space, composed-permission and cross-mount handling of the original call; a primitive result is relabelled with the outer op without re-rooting twice. No new public verb, error kind or argument.

4. **A derived read has one coherent view per addressed binding and public call.** Distinct public pages may observe distinct commits, as the listing contract allows. All internal listing, hydration and authority checks for one page must see the same view, including an immutable snapshot supplied by a snapshot backend when both namespace and authority view are fixed. Walking on a mutable binding needs a call-scoped snapshot or equivalent storage guarantee. A mutex in one router cannot cover another client or a rights change. The SQLite counterexample above and Constitution article 5 make this a release condition for the read arms, not a footnote about cost. Choice 2 governs how a binding can prove it.

5. **Tree walks directories with batch `ls`, then yields full path order.** Start at the literal local root, take a file target as its own row and a directory target as its children. Keep road directories bare, descend them like other directories, and stop descent at `max_depth`; retain the caller's projection. Use a bounded directory frontier per call and merge by complete path, never by discovery order. Carry the live or trash address separately from the row's displayed path when constructing the next request. In a SQLite probe after cascading deletion of `/d`, `ls("/.vfs/trash")` returned `/d` and `ls("/.vfs/trash/d")` returned `/d/f` and `/d/n`. Using those returned paths directly as live lookup addresses loses their children. Preserve the landed trash addressing if its owner changes it. `Cursor.asking` may pass its local key and limit directly only when this particular *verb* is native and declares keyset paging. Otherwise its existing whole-answer slice and frontier merge run exactly once. This matters when `ls` pages natively but `tree` or `glob` is synthesized.

6. **Use the same matching rules for a namespace scan as the native scan.** Walk from each requested local scope root or the longest directory prefix proved literal by a path-pattern arm; a leaf-only or unrestricted arm starts at the mount root. A missing inferred prefix contributes no match, while a missing caller-named root retains the root probe's error. Deduplicate by addressed path and process in path order. Keep the entry-wide and root-relative channels, typed kind, extension filters, exclusions, explicit metadata and trash rules of `SupportsPatternSearch` (`src/vfs/storage/protocol.py:277`, `src/vfs/pattern_matching/glob.py:115`). Root rows come from the existing root probe. Factor the pure admission and hit-shaping code where needed so `vfs.chain`, the scan and the native implementation use the same matcher without importing a database adapter into the router. The in-hand path intentionally keeps duplicates and trusts supplied fields, so it cannot be the namespace wrapper (`src/vfs/chain.py:65`, `:106`). Glob applies `max_count` to admitted rows in final order. Grep reads only content-bearing candidates readable at the caller's rung; a bare list-only file cannot consume the candidate budget, produce a diagnostic or contribute a hit. Distinguish a scope refusal from a body outside the readable view. Preserve pattern validation, `case_mode`, literal, word and inverted matching, context, lines/count/files projections, populated masks, and per-file `max_count`. Read projected rendering text for a bytes file. A derived grep is the scan tier and ignores `allow_scan`. Use the existing shared verifier and one absolute deadline per matching stage across batches, with native candidate and wall truncation records; operational scan counts describe the actual scan (`src/vfs/storage/backends/database/grep.py:195`, `:335`, `:395`).

7. **A copy stages a complete authorized source and commits its destination slice whole.** Require copy's own passing and creation rights across *every* live source row and destination, with all masked, path and shape checks in their native order (`src/vfs/ops.py:170`, `src/vfs/storage/backends/database/topology.py:118`, `:186`). A readable subtree listing cannot establish complete coverage; no elevated second listing may expose hidden paths. Visit pairs in input order against the staged overlay, including a later pair sourcing an earlier destination. Honor missing parents, occupied destinations including dev tombstones, the root refusal, self-copy, cycles, overflow and destination-rights revalidation at commit. Carry text, raw bytes and their native rendering facts, mint fresh destination identities and apply destination ownership/posture as native copy does (`topology.py:92`, `:450`, `:527`). Stage explicit directory entries, including empty ones, parent before child, alongside files. Separate committed `mkdir` calls cannot preserve a batch. Expose only the final destination row for each input pair, with native status and ordering, or the native errors with no successful rows or effects. No cross-mount transaction. Choice 3 covers the missing destination and source guarantees.

8. **An edit guards its actual inputs and preserves the outer edit's admission order.** After the vid branch lands, admit every target at edit's rung before matching, checking caller guards or revealing a version. Classify missing targets as native edit does; compare an explicit required vid, including `ABSENT`, against the initial target even when it is a directory. Then refuse bytes-sourced targets with `vfs.wrong_kind`, retain the file's media type, apply `vfs.storage.editing.edited_entry` sequentially, and feed repeated paths their own staged text. A bad target aborts the mount slice before publishing any result rows. Commit the final batch once with *every* target guarded by the vid read, including targets without an explicit precondition. A rival that invalidates the guard gets the branch's `vfs.conflict` with the standing version and vid. Preserve the native status, mask, version and vid for each target. Ordinary guarded `write` by itself cannot provide the stronger order: on the branch the write's `settle` drops equal material before checking stale guards, whereas native edit first judges its guard (`origin/edit-requires-a-vid:src/vfs/storage/backends/database/staging.py:475`, `writes.py:1450`). Never infer write authority from successful hydration. Choice 3.

9. **Use each argument owner's native, derive or refuse arm, including on a derived verb.** A range on native `read` delegates exactly as 178-2 decision 6 specifies: a declaration receives the range, absence makes one ordinary read of the same projection and targets, followed by the owner's whole-character or raw-byte slice. An omitted argument adds no keyword to a legacy seam. For a non-null `request_key`, apply 177-4 decisions 4–6 at every addressed binding before any call. A derived copy or edit may accept a key only if the backend can replay the *outer operation*, original inputs and original result under the same authority before reading or transforming inputs again. Replay of `write` alone does not promise this. Otherwise use the owner's `vfs.unsupported` refusal, at the mount path with no row data and zero storage calls across the batch. Never strip the key, forward it to a component write or invent a second receipt. Apply 167-7's corresponding native guarantee to `replace=True`; do not emulate it with delete and write. Range and key implementation belong to their owning units. The integration here is selecting the correct arm without treating the declaration for a component as a declaration for the composed verb.

## Cost

The mount closure has five fixed rows per bind or policy refresh, one set membership per dispatch, no SQL and no corpus multiplier. Native calls retain their statement counts. The work rides only on a derived call. For D directories and N visited rows spread over levels of widths W, batch `ls` at most `DERIVED_READ_ROWS` parents per call: the sum of `ceil(W / DERIVED_READ_ROWS)` over expanded levels, including the first root. Define that private row budget once in `derived.py` with the archive's initial value 256. An individual unpaged wide directory can still return all its children. Whole-answer sorting costs O(N log N) comparisons and O(N) projected rows, repeated per derived public page without a native keyset. A 10,000-row listing drained in ten such pages visits about 100,000 rows. The cheapest native path wins. Prefix pruning matters at the reference estate of 10 million files and one million directories (`AGENTS.md:74`).

Body batches flush at that declared row allowance or `vfs.offload.CONTENT_BYTE_BUDGET` (`src/vfs/offload.py:95`), whichever is reached first. Use known selected-body sizes; put an unknown or oversized body in its own batch and account for actual fetched bytes. A size estimate for raw bytes cannot bound a rendering's size. Move the existing `SCAN_TIER_BUDGET` (`src/vfs/storage/backends/database/scope.py:78`) to `src/vfs/offload.py` beside the shared matching budgets, and import the same constant from both callers. Fetch at most the remaining admitted candidate budget plus one to detect a cut; scope discovery may still walk more names. Use `WALL_TIME_BUDGET` at the stage boundary. Neither allowance truncates a copy or edit. At the reference mean size a 10,000-file copy carries 3–7 GB, though only about 40 MB at the median. Bounded read batches alone do not bound a `write(entries=list)` waiting on every body. A composition facility must stage in bounded chunks within one atomic publication or document its full-material cost before claiming support. The build may not introduce a fixed corpus limit or one commit per chunk.

The router adds no SQL. The adapter applies its own `membership_budget(profile, parameter_budget)` and `rows_per_statement(parameter_budget, rows)` (`src/vfs/storage/backends/database/dialects.py:541`, `:580`), including for SQLite's smaller bind allowance and the unknown-dialect floor. No router or table lock spans matching, body transfer or a walk. Reads do not wait on writers; a contested publication lock may be held only for its commit. No per-file-write, rebuild, rights-cache or idle-mount charge.

## Choices to confirm

1. **One argument declaration.** Take the existing traits and amend K7 criterion 5. The alternative adds `features()` alongside them. Keeping one reader for each declaration is cheaper to reverse: a later additive accessor could project the same facts without making every backend maintain two independent declarations. No build wait on this choice.
2. **A consistent view for a composed read.** A mutable backend's independently committed `ls` and `read` methods cannot promise Constitution article 5's one snapshot. Requiring a storage-owned call-scoped view of *every* bare file backend would strengthen the frozen minimum. An optional additive view (an immutable backend can supply itself) would qualify the roadmap's unconditional eligibility. After the freeze, requiring an extra method breaks existing implementations and retracting a promise of universal service changes their published capability contract. Neither change is reversible at gate f. The build waits for the ruling on mandatory support before freeze versus optional support with explicit eligibility before advertising multi-call reads on arbitrary mounts. No implicit assumption of immutability and no weakening of the snapshot guarantee.
3. **An authorized, atomic composition for copy and edit.** The ordinary file methods cannot distinguish an omitted hidden child, validate edit authority before applying a replacement, guarantee strict comparison of an equal-material rival, or keep an outer replay receipt with the effect. A storage-owned composition scope could provide the original verb's admission, snapshot, atomic publication with a final guard and optional outer replay, while the kernel owns the walk, matching and staging. Making that facility part of the minimum changes the obligations of every backend. Making it optional preserves the minimum and leaves some file-only mounts unable to serve copy or edit. Weakening native parity would change rights and mutation outcomes. No side is taken between mandatory and optional support for the public claim. Publication of those two derived capabilities waits for the ruling and a conformance-tested storage contract; a vid declaration alone does not unblock it. The argument integrations and native path can land independently.

## One line

The kernel selects a native or composed verb from declared mount capabilities, uses traits for argument support, and requires the native visibility, snapshot and commit guarantees before advertising the composition.

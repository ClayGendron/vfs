# `serve` answers each request under its own authority and refuses an open mount

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing of this unit is built. It serves [roadmap stories M1 and I2](../../context/standards/roadmap.md), gate b. It converts the serving, identity and resource rules of [archived spec 171](../../context/specifications/archive/171-the-mcp-adapter-and-the-cli-tool/spec.md). It rests on the [171-2 reassessment](../2026-11-25-the-backlog-converted/reassessment/mcp-guests-and-identity.md), the wire projector, the verified-token door and the vid precondition.

## The outcome wanted

An MCP client can discover the operations of the served file system, call a tool and follow a `vfs:///` link. The same HTTP endpoint can serve two tenants without mixing their listings, search evidence or bytes. Missing credentials get exactly the rights of the anonymous caller. The host can see every anonymously writable mount before exposing the first request. A client can protect a later change with the vid it received even when another process serves that change.

## What the code does today

`fs.mounts()` returns frozen bindings in path order, including the root. `fs.capabilities()` takes the union of their unmasked capabilities. A missing authority resolves to the router's default or anonymous. The router logs a warning when constructed with a system default (`src/vfs/base.py:299`, `:331`, `:581`, `:665`, `:2881`, `src/vfs/authority.py:227`). The public `grants(path)` reads grants on the path and its ancestors (`src/vfs/storage/backends/database/rights_reads.py:35`). Asking about the root cannot discover a deeper open posture.

Executed against the real router on in-memory SQLite and disposable PostgreSQL with a root at `read`, `/nested` at `add` and `/sealed` at `none`. On both engines the available set plus `cli` counted 21. An anonymous write at the root returned `vfs.unauthenticated` with zero mutation statements. An anonymous write beneath `/nested` succeeded. A principal granted `read` on `/sealed` read `/sealed/x`. A different named principal received zero rows and `vfs.not_found`. A prototype of the startup query selected only `/nested` in one SELECT on each engine.

On the same engines a metadata-only `stat` returned two bytes for `é`. Replacing the file with eight copies of that character before the subsequent public `read` delivered sixteen bytes. A successful size check at the front and a later unrestricted read cannot enforce a resource limit.

## The problem

At the reference deployment, 1,000 callers share 10 million files and issue about 150,000 verb calls a day (`AGENTS.md:74–82`). A system fallback would bypass the grants of every one of them. A per-principal record of the last read would also mix independent conversations of the same principal. A normal file read may materialize the whole file. These three hazards occur at different points: before binding the transport, on admission of each request and when fetching its resource.

## Decisions

1. Decided 2026-11-25: export the coroutine `serve(fs: AsyncVirtualFileSystem, *, transport: Literal["stdio", "http"], authority: Authority | None = None, token_verifier: TokenVerifier | None = None, host: str = "127.0.0.1", port: int = 8000, tools: Collection[str] | None = None, allow_open: bool = False) -> None` from `vfs.mcp`. The async router is the one whose verbs can be awaited. Use SDK stdio or Streamable HTTP at `/mcp`, retaining the SDK's host/origin checks. Run until the transport closes, release its resources and leave the supplied router with its host. Add `mcp>=2.3,<3` to the same extra as the types and `pyjwt[crypto]`, put the SDK in the dev group and refresh `uv.lock`. A plain `import vfs` never imports this package. Precedent: archived §0, the [published 2.3.0 distribution](https://pypi.org/project/mcp/2.3.0/) and 149-2 decision 6.

2. Decided 2026-11-25: validate configuration before inspecting storage, creating a listener or reading stdin. Stdio requires a host-supplied non-system authority and refuses a verifier. HTTP requires a verifier and refuses an authority. Both refuse the system default on the supplied router, even with a named stdio authority or `allow_open=True`. Test `Authority.is_system`, never object identity. Use a private router accessor to inspect its configured default without invoking the fallback. Refuse an unknown transport, closed router, malformed host tool filter or invalid flag with `ValueError` naming the setting. A non-system default does not supply missing credentials. This strengthens the constructor warning at the served boundary as I2 requires.

3. Decided 2026-11-25: apply the [verified D15 rule](../2026-11-25-the-backlog-converted/decisions/c-identity-and-the-trust-edge.md) before either transport starts. Inspect the root and each binding, plus each installed `/.vfs/tools` and `/.vfs/mcp` catalogue policy, under their public prefixes. An everyone row at **any** prefix at `add`, `contribute` or `read_write` makes that binding open. These are the rungs starting at the first anonymous create (`src/vfs/ops.py:125–133`). A named grant, including a group grant, never does. Mount masks, a read-only mount setting and a closed parent posture do not erase an open posture row. A binding with no grant family counts as open at its root. Deduplicate by binding path and show every open row in global coordinates, in path order. Without the flag raise one `ValueError` whose diagnostic lists all open bindings and their rows. With the flag log exactly one `WARNING` per such binding on `vfs.mcp`, naming its prefixes or missing enforcement, before accepting requests. No warning for a closed binding.

4. Decided 2026-11-25: inspect policy through an optional host-side storage seam `open_postures()` that streams the writable everyone prefixes in mount coordinates. It is neither a kernel verb nor a served tool. A grants-capable plugin that lacks the inspection seam is conservatively reported as unverified and treated as open. A failed inspection of an advertised seam aborts startup with `RuntimeError` naming the binding, even with the flag. A missing catalogue contributes no invented binding. Each catalogue can supply its own policy through the same inventory, including an in-memory one. On a database storage finish lazy provisioning, then select only `path_prefix` from `vfs_grants` where `principal_id = EVERYONE_NAME` and `level` belongs to the three writing rungs, ordered by `path_prefix`. Use the existing unique key on `(principal_id, path_prefix)` (`src/vfs/models/rows.py:773–790`). This is a trusted startup inspection, with no system-authority filesystem operation. Snapshot the inventory, discard the assessment and fail startup if its bindings changed while it was being inspected. No topology lock spans I/O. D15 is a start check per binding. Later host changes to topology or posture take effect through the ordinary gate. The wire has no topology or posture administration.

5. Decided 2026-11-25: derive authority before every HTTP MCP method, including discovery, resource requests, list methods and legacy-session traffic. An absent Authorization header supplies `Authority.anonymous()`. A present credential must be one well-formed bearer that passes the configured verifier. Malformed, duplicate and rejected credentials receive HTTP 401 with a Bearer challenge and `vfs.unauthenticated` before any handler or storage call. Use the SDK's request-local verified context or a single wrapping middleware that preserves presence, never a second token decode. A successful proof alone goes through `authority_from_token`; its classified invalid identity gives HTTP 400 with `vfs.invalid` and zero storage calls. An unexpected verifier failure aborts that request with a generic server error. Never downgrade any failure to anonymous. Stdio supplies the configured immutable value anew to each dispatch. Pass the explicit authority through to every router call including probes, resource reads and `cli`. No global current caller, credential logging, authority in a response, or authorization reuse from a preceding request. Drop request-local context on success, error and cancellation. Precedent: I2 criteria 1–3, 149-2 decisions 1 and 5, and the [MCP authorization specification](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization).

6. Decided 2026-11-25: `tools/list` returns one tool per name in `((AGENT_OPS & fs.capabilities()) | {"cli"})` intersected with the host's optional allowlist. Use the same admitted set for `tools/call`; never dispatch an arbitrary method by name. Return names in lexical order. An empty collection serves zero tools, duplicates coalesce, and unknown or unavailable strings add none. All available tools are discoverable even by an anonymous caller. The underlying verb checks authority for the requested path. Today the database contributes 20 eligible verbs, or 19 on the generic floor where `search` is withheld (`src/vfs/storage/backends/database/backend.py:228–239`). With `cli` these are 21 and 20, or one for `tools={"cli"}`. Future `versions` follows the capability declaration and updates the integration pin. No developer op, management method, `append` alias or storage helper joins this surface. Recompute capability membership per request to follow host-side changes.

7. Decided 2026-11-25: register descriptions, annotations, input schemas and revision-supported output schemas from 171-1. For a listed verb call `call_args` exactly once, fill an explicit authority, set `mkedge` provenance to `agent` for a service actor and `user` otherwise, then call the router once. The dev default for that provenance is `system` (`src/vfs/base.py:1183`). Project the result once with the caller's display projection and negotiated revision. Method arguments reject `authority`, `observations`, `provenance` and forbidden nested entry fields before dispatch. Unknown or filtered tool is JSON-RPC `-32602`. A known tool's bad arguments or VFS refusal use a normal tool reply with `isError` equal to the negation of success. For a path listing that supports a cursor, pass `pageable=True`. In an otherwise pageable `ls`, `tree` or `glob`, supply a positive default and maximum page size `WIRE_LIST_ROWS` equal to the adapter's default text-character budget, lowering a larger positive `limit` and preserving smaller limits and `after`. One row consumes at least one character. This admits the 10,000-file criterion while bounding the native candidate page. Validate the caller's original arguments before applying this policy. A valid `glob(max_count=...)` keeps that argument and gets no incompatible cursor parameters. Publish the effective maximum with the tool. The CLI registration delegates its argument schema and one-line execution to 171-3.

8. Decided 2026-11-25: the wire guard is a value the client carries. Tell callers of `write`, `edit`, `delete`, `move` and `restore` to pass the `vid` observed for the affected row back as `if_vid`, or the corresponding eligible path-to-vid map as `if_vids`. Preserve the shape actually exposed by 171-1: withholding `observations` also withholds row-based batch addressing, even if the kernel accepts a map. A supplied guard is passed unchanged to the kernel. An omitted guard stays omitted. Mutation refusal, `"absent"`, missing traits and successful returned vids follow the vid spec. No read upgrades a guard on a later request. No `if_version` alias, stamp cache keyed by principal or connection, session handle, or implicit `open_session`. This carries the [D51 verification](../2026-11-25-the-backlog-converted/decisions/d-mcp-serving-and-credentials.md) onto the vid series: a value written by another conversation cannot satisfy the first conversation's stale precondition.

9. Decided 2026-11-25: negotiate through the SDK and register private, zero-lifetime cache hints for `tools/list`, `resources/list`, `resources/templates/list` and `resources/read` (`ttlMs=0`, `cacheScope="private"` on revisions that carry them). Advertise tools and resources with no change notifications or subscriptions. Return complete replies. Legacy handshake bookkeeping conveys revision only. It never vouches for the next caller. A lost response does not replay a call. Shield an admitted mutation, including a `cli` line that can mutate, from stream disconnect and retain it in the server's task group until it settles. Propagate cancellation for ordinary reads. Drain admitted mutations and release SDK tasks on shutdown without closing the host's fs. Replay after a lost response follows the kernel's individual replay rules, including an explicitly supplied `request_key` only where supported. Precedent: archived §0 and [SDK revision support](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/whats-new.md).

10. Decided 2026-11-25: `resources/list` is empty and `resources/templates/list` returns exactly `vfs:///{+path}` named `vfs path`. For `resources/read` use the strict shared URI codec from 171-1 decision 8. Invalid URI is `-32602` before routing. A link carries no proof of access. Ask for metadata with the request's authority first. A missing, hidden or denied row, including a bare file visible only by name, produces the same `-32602`, message and `data={"uri": <requested URI>}`; no error text or underlying row fields distinguish them. A visible directory produces `-32602` with `reason="directory"`. For a readable row with populated `size_bytes > RESOURCE_READ_BYTE_BUDGET` return `-32603` with `data={"size_bytes": actual, "budget": limit}` after one stat and zero body bytes fetched. Lack of trustworthy size or body on an otherwise readable file, unsupported bounded retrieval and backend failure produce a generic `-32603`. Do not disclose size when the read gate denies access, including a mount that masks `read` while permitting `stat`. Apply its read admission before exposing a size diagnostic.

11. Decided 2026-11-25: declare `RESOURCE_READ_BYTE_BUDGET = 12 * 1024 * 1024` in `vfs.mcp.resources`. Charge the original bytes or the UTF-8 bytes of the original text. Return exactly one `BlobResourceContents` with standard padded base64 and MIME type for a bytes source (fallback `application/octet-stream`), or one `TextResourceContents` with the original text, including empty text, and its MIME type when populated. Use the shared codec for the canonical result URI. For a byte source with a text rendering, read only the original bytes. The raw limit is inclusive. At the limit the base64 field alone takes 16 MiB; the raw allowance makes no promise about a particular client's whole-frame limit. There is no shortened resource pretending to be the whole file.

12. Decided 2026-11-25: enforce the byte bound at the body fetch as well as at stat. Carry the limit on a private single-target read through the ordinary kernel read admission, mount rebasing and storage dispatch. Use an optional storage method `read_bounded(*, path, byte_budget, authority)` returning the normal read `Result`, without adding a public verb, MCP argument or optional-package import in core. A custom storage lacking that contract gets no unbounded fallback. On a database open the ordinary read snapshot, resolve the target with the existing metadata classification and visibility, and check read rights again. Select only the admitted target's body by its entry identity, and only the column for its source. Guard both the current stored size and the actual body's octet length in the body-producing SQL, so a replaced, oversized or defective body cannot reach the driver. Use `octet_length` on PostgreSQL and `length(CAST(content AS BLOB))` for SQLite text, `length(data)` for SQLite bytes. On the generic floor only an implementation that guarantees an equivalent bound qualifies. Return an internal read refusal with kind `vfs.budget_exhausted` and the authorised size and budget for a current oversize row, or `vfs.unavailable` for an inconsistent representation. Map these to decision 10. Handle rights loss, disappearance or source change between the two calls from the second snapshot. No retry from the older stat. Precedent: the public read classifies from its own visibility at `src/vfs/storage/backends/database/reads.py:889–934`; the first fetch there includes ancestors, whose bodies this bounded operation must never fetch.

## Cost

One startup inventory visits each of M bindings and streams one SELECT per database binding after provisioning. The query has a constant principal and three rung binds. It may examine all S everyone rows on that binding; the grant key does not index level. It visits zero file bodies. Use the host's declared membership budget for streaming partitions. With E open rows the requested complete diagnostic necessarily retains O(E) paths; it runs only at startup. Catalogue entries are counted by policy binding, never by tool or file. No schema or index migration. No read takes a writer lock.

At 150,000 calls/day the HTTP edge performs at most 150,000 local verification attempts for that many bearer-bearing requests and makes zero per-request grant-inventory scans. List membership is O(M × number of declared ops); schemas may be precomputed by name and revision without caller data. A request retains one authority and zero cross-call stamps. The native listing page reads up to `WIRE_LIST_ROWS + 1` candidates per mount before the merge, subject to existing filters and cursor implementation. Derived listings on a non-keyset storage may still materialize the whole matching listing (`src/vfs/cursor.py:106–109`). The front neither drains the cursor nor counts the corpus. Adapter projection costs and special search, depth and `max_count` costs remain those of their verbs.

A resource costs one metadata operation and at most one bounded body operation. Rights and ancestor metadata use the kernel's existing membership-budget chunks on SQLite and PostgreSQL. The body query takes one identity and a constant number of byte-limit binds, independent of corpus size. Per admitted request at most B raw bytes reach Python and a binary response adds at most `4 * ceil(B / 3)` base64 bytes, plus serialization. Computing a text octet length can inspect the stored representation in the engine. Concurrent memory follows the number of live admitted reads, not a per-principal cache.

## Choices to confirm

1. Treat a grants-capable storage without inspection as open and allow an explicit override. Rejecting it unconditionally would make existing plugins unservable. A positive inspection can be added later. A failing inspector is a startup error.
2. Start the default and maximum wire listing page at the adapter text budget in rows. A smaller independent page reduces work but changes where a client sees the first cursor. The selected bound permits the 10,000-file M1 check and can be tuned at the front with no kernel change.
3. Use a private bounded-fetch seam and refuse resource contents on a backend that cannot guarantee the bound. A public byte-limit parameter or a ranged fallback changes the general read contract, and an unrestricted read followed by truncation cannot enforce the allocation bound. Adding support to a backend later admits new reads.

## One line

`serve` checks open postures before start, binds every tool or resource request to one explicit caller, forwards the client's vid and limits each resource at the storage read.

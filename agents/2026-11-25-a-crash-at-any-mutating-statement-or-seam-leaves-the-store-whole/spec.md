# A batch interrupted before commit rolls back, a redriven batch lands once, and an interrupted pass finishes on the next call

A draft, written on 2026-11-25 against `dev` at `27f3d24d`. It is not reviewed, and nothing in this unit is built. It serves [roadmap story K7](../../context/standards/roadmap.md), criterion 2, gate f, and converts sections 5.1, 5.4 and 8 of [the storage seam specification](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/spec.md) and tasks 6, 7, 9 and 10 of [its task list](../../context/specifications/archive/179-the-storage-seam-as-the-kernel/tasks.md). It rests on the per-method atomicity table, classified engine codes, the full-image oracle and the commit boundary.

## The outcome wanted

An ETL caller interrupted anywhere before its batch commits can reopen the mount and find every stored value as it was. After a lost reply to a completed commit it finds the whole change once. A transient refusal followed by a successful retry gives the same stored result as a single successful call, and the storage reports one redrive. An interrupted index pass or relabel leaves readers with the access they should have at that instant. Repeating the same pass once finishes the work.

## The problem

K7 needs evidence about a failure after some writes have run. A refused input or a cancellation at one selected point cannot detect a forgotten rollback on a later statement. A successful retry can conceal a double application, and a successful maintenance result can conceal missing derived data. At the reference deployment a nightly million files pass through 100 batches alongside indexing. A fault test needs to expose either loss on a small isolated store without adding a production image scan, a cross-process counter row or a read that waits on the writer.

## Decisions

1. **Drive storage methods through their ordinary entry points on each of the three existing conformance legs.** Add `CrashRows(ContractBase)` to `StorageContract` in the new package. Compare the set of exercised method names to both partitions of `METHOD_ATOMICITY`. The whole-batch scenarios are system and named `write` of an overwrite, fresh text, bytes and a minted parent, a nonempty append, `edit` of matching text, `mkdir` with missing ancestors, `move` and `copy` of a populated directory, recursive `delete`, `restore` of that tombstone, `sweep` of a seeded expired trash root, creation and removal of an authored edge (`mkedge`, `rmedge`), `grant`, `revoke`, `add_member` and `remove_member`. Where unit 180-4 has landed, `destroy` of the seeded expired trash root is a resumable scenario and not a whole-batch one (its decision 24): the root is destroyed by a pass of four transactions, one a phase. Seed a row to remove for each removal. Use a named transfer to exercise destination postures. Each clean call must succeed, produce its intended material change and have a positive mutation count. The dev signatures start at `backend.py:693`, `:781`, `:879`, `:912`, `:1021`, `:1098`. These are the source's small worlds for independent cuts, not another run of the large-input family.

2. **Count each actual execution in the foreground attempt, including each raw Postgres COPY page.** In `tests/support/faults.py`, `EngineFaults.record()` records a clean trace and `at(n, *, retryable=False, times=1)` records and fails the one-based ordinal before submission. Attach a scoped `before_cursor_execute` listener to the tested engine. Use the SQLAlchemy execution context for compiled INSERT, UPDATE and DELETE, including statements beginning with WITH, and identify the mutation operation of raw driver SQL (including MERGE). Fail the harness on an unclassified writable statement. A driver executemany call is one execution, each separately emitted page is another. Discard setup, reads, transaction and savepoint control, and `is_statistics_statement(sql)` (`tests/support/statements.py:19`). Intercept `asyncpg.Connection.copy_records_to_table` only on the tested attempt's driver connection. `dialects.py:708–718` runs one `SELECT 1` before a loop with potentially many COPY calls. Counting that SELECT as one mutation would miss the second page. The raw wrapper raises the driver-shaped cause before the chosen COPY so production wraps it at `dialects.py:916`. For SQLAlchemy event cuts raise `sqlalchemy.exc.OperationalError(statement, params, orig)` directly, as in source section 8.1. Preserve ordered operation/table pairs, attempt boundaries and firing counts, never bind contents. Gate listeners by a test context bound to the single call, reset the ordinal on entry to the actual attempt callable supplied to `with_retry`, and remove every hook in `finally`.

3. **Measure the range on a successful independent store for the same engine and seed.** If its trace contains M mutations, cut ordinals 1 through M individually on a failing store. Require one firing and the same trace prefix through that ordinal on every cut. The fatal cause carries SQLite `SQLITE_IOERR` (10) or Postgres SQLSTATE `58030`, with one retryable `vfs.unavailable` answer, its engine field, no successful rows, zero committed outer mutations and zero additional attempts. The reopened full image must equal the same store's before-image. Reuse that store only after equality. At each ordinal also start a fresh seeded world, raise `SQLITE_BUSY` (5) or `40P01` once, and require two attempt entries, one firing, one successful outer commit, the clean result (observations, errors and extras, normalized by decision 5) and logical image, and a tally change of `(1, 0)`. Re-arm at the same ordinal on each attempt for exhaustion. For limit A there are A firings, zero commits, a retryable `vfs.conflict` with the last retryable engine code, tally change `(A−1, 1)` and exact rollback. Use driver attributes and fresh exceptions, not fabricated messages parsed as codes. These are the archived sections 8.1–8.3 with measured per-engine widths.

4. **Reopen the same stored data and compare the right images.** Memory retains its only handle and starts a fresh read session after the failed session ends. Closing it destroys the database (`memory.py:12–16`). For file SQLite close and open the same file with the same options. For Postgres retain ownership of the test schema, close the writer and use `tests/support/server_schemas.py:98` for a new handle on it. A reference or a new successful trial gets a different file, memory database or private server schema. Settle statistics, snapshot tallies on the writing host before close, then take each image using 179-6 decision 2. The reopen helper never reprovisions a missing baseline as evidence of equality.

5. **Use a second oracle only where independent successful stores cannot match byte for byte.** Extend `tests/support/images.py` with `logical_image` and an exhaustive `LOGICAL_COLUMNS` classification from mount metadata. Preserve multiplicity and every stable value including content, version deltas, binary data, hash, flags, labels, grants, membership, revisions and vector coordinates. Canonicalize seed identities by original path, fresh identities by their creation path, parents, trash roots and edge endpoints through that same map. Keep a baseline identity map for a move, sweep or overwrite. Resolve chunk IDs by logical entry and chunk ordinal, and physical posting IDs through their referenced rows. Normalize allocation-only row keys, the mount's generated identity, allocated signal-generation tokens and epoch references consistently across tables. Keep content-derived generation fingerprints, index options and version ordinals verbatim. Preserve timestamp nullness, effective trash status and ownership links. Fail on a dangling reference that the clean world does not have, lost duplicate or unmapped column. For whole-batch success compare all tables including seeded derived state. For maintenance compare primary content, versions, grants, memberships, authored and derived relationships, pending marks, live published index contents and available vectors. Unpublished epochs are inert by design (`indexing.py:51`, `:611`) and have their own physical reclamation policy. For a resumed posture compare effective grants, memberships, label values and the ordering and equality relationships between their revision stamps. ## Cost

The tally adds zero SQL, zero persisted rows and zero extra locks. One failed attempt costs at most one redrive increment and a terminal failure one exhaustion increment. At 150,000 calls per day and the default four attempts the ceiling for calls with one transaction each is 450,000 redrive increments, with zero in a fault-free day. Maintenance costs the same per actual retried transaction. The dictionary grows with the fixed operation vocabulary, never callers or file count. A snapshot copies only operations with retries.

The refresh mark costs one boolean per entry, about ten million file flags plus directory rows at the reference deployment, and one index key per outstanding re-split entry. First writes, reads and the index's roughly 100 million chunks get no extra round trip per row. One indexed empty-range probe suffices for no pending embedding work. For D pending entries, use the host's membership budget for keyset pages and its live parameter budget and compiled bind width for version-guarded clearing. There are at most one extra seek per page plus the terminating seek and one bounded clear per fitting guard batch, with vector writes and chunk reads retaining their existing budgets. If all one million files written overnight are re-split, the incremental passes set up to one million marks on existing updates and clear up to one million marks in bounded batches, roughly two million index-entry changes. They add no per-file statement to the ingestion calls. No branch scans all unembedded chunks on refresh. The index lookup and clearing do not hold a lock across a provider call. Reads take no new writer lock.

The exhaustive trace is test-only. For M mutation events, one clean call, M fatal calls and M redriven calls cost at most `1 + 3M` attempts excluding the explicit exhaustion case. Images read one select per registered table per observation and hold only the isolated fixture's rows. No 10,000-row scenario is multiplied by M. Size a forced two-page COPY by lowering the test dialect's existing page budget, with a third row crossing it, rather than hardcoding a driver limit. SQL stays within the live SQLAlchemy parameter ceiling, SQLite's variable and expression limits and asyncpg's bind limit ([deployment budgets](../../AGENTS.md), lines 62–64).

## Scope

In scope are the storage retry loop, mount counter method, refresh recovery mark and its schema/queries in `src/vfs/models/rows.py` and `src/vfs/storage/backends/database/{backend,engine,retries,indexing,maintenance,embed}.py`, the content writes and render landings that reset dirty state (`writes.py:1327`, `render.py:369`), the fault and image helpers, conformance mixin, fixtures and named tests. The docstrings for `counters()` and `refresh()` state the counting boundary, lifetime, and the distinction between interrupted embedding and an answered provider outage. The change preserves the module-size ratchet and changes only those existing cost or schema assertions affected by the new indexed mark.

Outside this unit are cross-mount atomicity, crash inside the engine's commit, a killed server or power loss, physical purge of unpublished index generations, retry tuning, provider-level retries, rights-cache counts and a router metrics endpoint. The generic dialect floor has no conformance leg ([engine policy](../../AGENTS.md), line 65).

## Choices to confirm

1. **Where can an operator read the tally?** Take a storage-local snapshot, as in decision 9. A routed admin call or exporter can consume it later. Introducing either now would require an additional public operation and an authorization policy for cross-mount reads.
2. **How does the next refresh find only interrupted embedding work?** Take the indexed entry flag in decision 8. A separate durable queue would need the same version guards and an independent lifecycle for deleted entries. The flag leaves a single owner for those guards and can be replaced by a queue without changing any caller's result.

## One line

Each storage transaction has a tested outcome on both sides of commit, each actual redrive is counted, and one subsequent maintenance call restores the reader-visible state on memory, SQLite and Postgres.

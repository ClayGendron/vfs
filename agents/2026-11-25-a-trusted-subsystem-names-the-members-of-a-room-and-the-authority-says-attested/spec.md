# A trusted subsystem names the members of a room and the authority says attested

A draft, written on 2026-11-25 and checked against `dev` at `27f3d24d`. It is not reviewed, and nothing of this unit is built. It serves [roadmap story I1](../../context/standards/roadmap.md), gate b, under D14. It converts rule 2 of [the token-to-authority spec](../../context/specifications/archive/149-serve-auth-token-to-authority/spec.md) on the [149-3 reassessment](../2026-11-25-the-backlog-converted/reassessment/mcp-guests-and-identity.md), the verified-token door and the request-local serving front.

## The outcome wanted

A room service sends its own bearer token and the current members’ identifiers with a request. With the issuer’s permission to attest, it can read a private file shared by every member. A file shared only with the service or only with one member stays hidden. An overwrite of a shared file records the service as actor, the room members as subjects and `attested` as the proof. An ordinary call on the service’s own behalf still records `edge`. A job interrupted during the room’s call resumes with the same attribution and the members’ current rights.

## What the code does today

The runtime `Provenance` literal and the typed `Version.provenance` admit three values (`src/vfs/authority.py:43`, `src/vfs/models/version.py:110`). The actual history column is `vfs_versions.provenance` at `src/vfs/models/rows.py:497`, a `String(16)`. The column at line 573 named in the reassessment describes a graph edge’s origin. The two vocabularies have different purposes.

Executed on in-memory SQLite and disposable PostgreSQL using the real `DatabaseStorage`, a constructed service actor `bridge` and subjects `a` and `b`. Under root posture `none`, a read returned one row on a file granted to both, and zero rows with `vfs.not_found` on files granted to just the actor or just `a`. Replacing `b` with an unseen name hid the shared file and still returned one row at a public `read` posture. Changing the shared file’s body wrote one version with actor and source `bridge`, proof `constructed` and subject rows `a` and `b`. A rolled-back fixture update stored and read back the literal `attested` on each engine. The dev Python type adapter rejected that same literal.

## The problem

A token proves the service’s identity once for a request. It supplies no proof for the people in the room. Reusing the service’s rights would disclose its private files, and recording a member as edge-verified would misstate the evidence on every version the call creates. The room can change between two of the reference deployment’s 150,000 daily calls (`AGENTS.md:82`), including calls on the same connection.

## Decisions

1. Decided 2026-11-25: carry the assertion only in the current HTTP MCP request’s `params._meta["dev.vfs/members"]`, a JSON array of identifiers. For example, `{"_meta":{"dev.vfs/members":["a","b"]}}` is part of the method parameters, alongside any tool name and arguments. The service obtains the complete membership from its trusted room state. The list is data supplied by that authenticated service. It is neither a bearer credential nor independently verified proof for a member. This follows source rule 2, “No token carries a set”, and the `dev.vfs/` metadata namespace used at `context/specifications/archive/171-the-mcp-adapter-and-the-cli-tool/spec.md:139`. No claim, second HTTP header, argument, result metadata or connection state supplies members. Absence selects the ordinary request authority even for a service allowed to attest. Presence, including JSON null, selects the attestation path and cannot silently fall back.

2. Decided 2026-11-25: authorize attestation only for an HTTP bearer verified on this request whose sole subject is the service itself, with the exact, case-sensitive scope `vfs:attest-members` in its issuer-declared scopes. A delegated token with `act` is ineligible even if the identifiers repeat. Apply 149-2 and 171-2 once to obtain the ordinary proof. At the new door require `provenance == "edge"`, a service actor, `subjects == {actor}`, `source_identity == actor.sub` and membership of the scope in `actor.scopes`. This last check also excludes a repeated delegated actor, whose scopes 149-2 decision 4 empties. A token’s `groups`, member claims and nested scopes confer no permission. The scope lets the service vouch for **any lawful room member in the receiving issuer’s principal space**. It grants the actor no file rung. Only services trusted to supply that whole list may receive it.

3. Decided 2026-11-25: validate the presented list atomically. Require a JSON array with at least one entry. Check its raw length against `MAX_SUBJECTS` before scanning any item or removing duplicates. Validate every entry as a bare subject identifier by the same helper as 149-2 decision 2. It preserves spelling and checks the declared `MAX_PRINCIPAL_ID_LENGTH`, nonblank Unicode, no NUL or unpaired surrogate, and no system, anonymous, everyone or group identifier. Reject the attesting service’s own identifier in this room profile. Accept no objects, per-member kinds, scopes, issuer selectors or group expansions. Coalesce repeated valid strings by exact equality. A malformed item refuses the entire request, with no accepted prefix. A lawful unknown identifier is retained; dropping one would enlarge the meet. There is no principal directory lookup. As the probe shows, source rule 2’s “holds nothing” applies to private grants, subject to the ordinary owner floor and everyone posture.

4. Decided 2026-11-25: add `attested` to `Provenance` and add one synchronous door, `authority_from_attestation(service: Authority, members: object) -> Authority | ResultError`, in `vfs.authority`, re-exported from `vfs`. Its first argument is the successful ordinary edge authority. Use one literal `provenance="attested"` with one `door=_DOOR`, and list the new door in `_DOORS`. Preserve the service actor, source identity and narrowing. Replace the subjects with a frozen set of `Principal(sub)` for the validated names. These named subjects have the default user kind and empty scopes. The service’s scope is on the actor alone. Even one vouched-for member records `attested`. A room of one has the existing single-subject ownership rule; a room of several owns no row as a set (`src/vfs/authority.py:204-216`). The ordinary mint continues to be the sole issuer of fresh `edge` proof, and `Authority.on_behalf_of` retains its in-process meaning (`src/vfs/authority.py:165-178`).

5. Decided 2026-11-25: apply the following admission order before method execution, including discovery, tool and resource requests. Complete ordinary authentication and identity validation before interpreting member data, then test eligibility before inspecting the list. On success pass the resulting authority to every nested router operation and discard it after this request. Consume the recognized metadata key at the front. Never copy it into tool arguments, replies, logs or remote calls. A history reader authorized to see an attribution record still sees its stored subjects. Another request starts from its own proof and data. The permission error for an ineligible service discloses nothing about a proposed member. These are admission errors before storage; downstream path errors continue to be those of the ordinary verb.

| Request with the metadata key | Refusal |
|---|---|
| HTTP bearer absent or proof fails | HTTP 401, Bearer challenge, `vfs.unauthenticated`. Without the key, an absent bearer follows 171-2’s ordinary anonymous rule. |
| Proof succeeds but the identity is invalid | 149-2’s HTTP 400 `vfs.invalid`. |
| Valid identity is ineligible | HTTP 403, `classified(ErrorKind.permission_denied)`. |
| Eligible, list exceeds the input count | HTTP 400 with `classified(ErrorKind.authority_budget)`, whose wire kind is `vfs.budget_exhausted.authority`. |
| Eligible, any other defective list or member | HTTP 400 with `classified(ErrorKind.invalid, detail="invalid attested members")`. |
| Stdio supplies the key | JSON-RPC `-32602` with `data.kind="vfs.invalid"` and the fixed message `attested members require HTTP bearer authentication`, even for a host-configured service authority. |

All admission errors omit member strings, claims, credentials, source and paths. The HTTP errors use the classified identity-refusal representation of 171-2. The no-path, fixed-detail construction is supported at `src/vfs/results/envelope.py:235-249`; the three applicable kinds are declared at `src/vfs/results/kinds.py:73-74` and `:92`. The pure door returns the eligibility, count and shape errors without HTTP concerns. Executing those three `classified` constructions on dev returned the named kinds and null path, source and data.

6. Decided 2026-11-25: use the existing version mint and its subject side table unchanged. A body-changing overwrite that mints a version records the actor and source of the service, `attested` and one side row per distinct member. Identical-body overwrites follow the existing no-version rule (`src/vfs/storage/backends/database/versions.py:141-156`). The shared type change admits the value in `Version` and its serialized model as well. There is no column change, migration, backfill, new version reader or change to `EdgeProvenance`. Upgrade proof readers, including any deployed jobs worker, and every serving replica before enabling the scope at the issuer; an older front ignores the member key.

7. Decided 2026-11-25: the jobs serializer and trusted stored-authority rebuild accept `attested` without reinterpreting it as `edge` or `constructed`. Preserve every stored field, including the members, their scopes, actor scopes, narrowing and source; keep accepting older provenance values. Restore only kernel-written caller records using the jobs door of 149-1 decision 12. Apply the normal authority invariants and validate the attested shape from decisions 2–4 (a scoped service actor with matching source and a nonempty set of lawful, distinct user members with empty scopes, excluding the service’s id). A malformed stored record fails restoration before dispatch. At the jobs boundary classify this as `vfs.unavailable` with fixed detail `invalid stored job caller` after the ordinary job visibility check, with no state transition. Wire data cannot exercise this decoder. Restoring the stored value never invokes the external mint, calls a verifier or accepts a replacement list from the answering caller. Jobs decision 22 already requires a fresh check of the stored subjects’ rights. The new value fits the specified JSON text without a jobs format change.

## Cost

For `S` input entries, `L = MAX_PRINCIPAL_ID_LENGTH`, the edge examines at most `MAX_SUBJECTS × L` identifier characters and retains at most `S` principals plus a set of distinct names. Length precedes scanning, so an oversized decoded list or string is refused in constant work before copying it. This bound starts at the SDK’s decoded parameters; the transport still pays to receive and parse the request frame. At the reference ceiling of 64 members each in 150,000 daily calls, this is 9.6 million member visits per day. There is one ordinary proof verification per bearer request, zero further token verifications, zero membership lookups by the mint, zero new SQL statements and zero locks for admission on SQLite, PostgreSQL and the generic floor. No per-file check consults the issuer.

For `V` changed pre-images the existing version path emits `V` version rows and at most `V × MAX_SUBJECTS` subject rows. A 10,000-file batch of changed bodies at the bound can therefore produce 640,000 subject rows. The existing writer may accumulate those dictionaries for the bodies in one mint group; this is not constant memory per batch. SQLite and PostgreSQL keep their existing `bulk_insert` paths, paged under `rows_per_statement` and the dialect’s live parameter budget (`src/vfs/storage/backends/database/dialects.py:673-710`); the generic floor retains Core’s executemany. No new read locks, bind lists, per-member queries, index visits or per-row provenance statements. A saved job pays the existing caller JSON cost once per stored job, bounded here by the member count and ID lengths plus the single actor’s 149-2 scope budget.

## Choices to confirm

1. Use `params._meta["dev.vfs/members"]` on HTTP requests. A signed token claim freezes the set into a reusable credential and departs from source rule 2. A separate HTTP header needs its own list encoding and limits. The metadata key reuses the existing namespaced JSON shape and can be withheld until all fronts understand it.
2. Use the one literal scope `vfs:attest-members`, with no configurable alias or implication from broader verb scopes. The name and metadata key are new wire vocabulary. One explicit grant is the smaller trust surface and leaves additional issuer profiles additive.
3. Start with a service acting as itself and bare member ids other than its own. Coalesce repeats inside the raw item budget. Accepting delegated credentials, principal objects or self-inclusion later would admit new calls. Rejecting duplicates instead would require senders to normalize an already bounded set. There is no build-blocking choice.

## One line

A scoped service can vouch for a room’s members on one request, use their common rights and leave both file history and saved jobs with the proof recorded as `attested`.

# A mounted server is called with the credential the host resolves for the caller

A draft, written on 2026-11-25. It is not reviewed, and nothing is built. Checked against `dev` at `27f3d24d`, it serves [I4, gate f](../../context/standards/roadmap.md), and replaces the shared-identity rule of [archived spec 170 §3.1](../../context/specifications/archive/170-tools-and-mcp-servers-as-views/spec.md) for servers configured to act as the caller. It rests on the mounted MCP client, the verified-token door, D16 and the kernel's private records.

## The outcome wanted

Two callers run the same tool path. Each gets the data its own upstream account can read, even if both calls arrive together through one service actor. One hundred calls by one caller inside the list floor initialize once and list tools once. The second caller gets a second initialization, a second list and its own catalogue. Withdrawing the first caller's credential refuses its next invocation at the tool path before the transport sends a byte. A host can still choose one static upstream identity for a server.

## Builds on

- [170-4, the mounted MCP client](../2026-11-25-a-connected-mcp-server-is-a-directory-of-tools-resources-and-prompts/spec.md), a conversion draft. Decisions 2–5 supply the host-only `add_mcp(name, server, *, list_floor_ms=None, credentials=None)`, “one task owns the entire lifetime of one connection”, immutable catalogue snapshots and fresh rights at the canonical leaf. Decisions 7–11 supply resource resolution, single-send dispatch, failures, continuation and owner-only run blocks. Its decision 2 already specifies no credential or explicit environment on stdio, a clean child environment and an origin-bound static HTTP bearer. Keep those contracts. The per-principal form changes the unit of discovery, refresh and supervision.
- [149-2, the verified-token door](../2026-11-25-a-verified-token-becomes-an-authority-at-the-edge-and-nowhere-else/spec.md), a conversion draft. Decisions 1–4 give “one issuer per principal space”, one verified subject and a separate delegated actor. Decisions 5, 8 and 10 supply constant proof failures, `MAX_TOKEN_BYTES` and credential-free result envelopes. [The serving edge](../2026-11-25-serve-answers-each-request-under-its-own-authority-and-refuses-an-open-mount/spec.md), another conversion draft, decision 5 gives “the explicit authority through to every router call”. Use that request boundary for the inbound-bearer pin.
- [D16](../2026-11-25-the-backlog-converted/decisions/d-mcp-serving-and-credentials.md) rules host resolution, no inbound forwarding, no credential store, no token exchange inside `Authority`, refusal of a subject set and least-recently-used eviction under a declared connection bound. [The kernel records spec](../2026-11-22-the-kernel-keeps-records-of-its-own/spec.md), decisions 3, 21 and 22, says “a place never prints a password”, and gives producers the private query, commit and buffered-write boundary. The store is in flight on `origin/the-kernel-keeps-a-store-of-its-own` (`src/vfs/kernel_store/store.py:191` there), the buffer on `origin/the-kernel-writes-records-behind-and-sweeps-them` (`src/vfs/kernel_store/behind.py:172` there). The [action-log cost study](../2026-11-21-what-a-log-row-per-call-costs/spec.md), decision 4, measured the metadata row outside `src/`. H0 is outstanding on dev (`context/standards/roadmap.md:280`).
- Build the resolver and pool after 149-2 and 170-4. Integrate the HTTP request pin with the serving edge and the durable leak pin with the kernel store, run publisher and H0 when those producers land. A fake sink alone does not close the gate.

## What the code does today

`Principal` has a subject id, kind and scopes. `Authority` carries subjects, actor, provenance, narrowing and source identity. Its `owner_subject` is the sole named subject's id, or absent for anonymous, system or a set (`src/vfs/authority.py:80`, `:119`, `:205`). The async session supplies its own authority to `run` (`src/vfs/session.py:419`). There is no client, resolver or MCP extra in the dev package (`pyproject.toml:49–63`). `Result.to_payload()` includes extra data and error details (`src/vfs/results/envelope.py:747`).

Executed on in-memory SQLite and disposable Postgres with the real router and `DatabaseStorage.holds` (`src/vfs/storage/backends/database/backend.py:1093`). Below a listable server path, one grant at a tool leaf admitted its named subject both directly and with a delegated service actor. It refused a different subject, the two-subject set and anonymous. System passed the local gate despite having no owner subject. Revoking the grant then refused the delegated subject. On both engines a synthetic secret supplied as `classified(..., detail=...)` appeared in the serialized error's `message`. A newly classified unauthenticated error carried none of it.

## The problem

A shared credential can return records the caller's own upstream account could never read. A shared catalogue exposes different callers' tool names, prompts and resource URIs before a tool even runs. At 1,000 callers, replacing the one connection with an unbounded dictionary could retain 1,000 sessions per server. A single such credential copied into a replayable result can also survive transport close, database restart and log retention. The [code-mode study, item 12](../2026-11-23-code-mode-prior-art/2026-11-23-code-mode-keeps-the-tool-catalog-out-of-the-context-and-vfs-can-add-search-and-authority-to-it.md) identifies the upstream rights gap.

## Decisions

1. Decided 2026-11-25: extend the async and synchronous host registration of 170-4 with a structural `CredentialResolver`. Its only method is `async resolve(server: str, authority: Authority) -> Credential | ResultError | None`. Pass the validated registration name and the exact effective authority of this operation. Define `Credential` as the public type alias for a bearer string. Export both names from `vfs.mcp` in its `__all__`, with no SDK import needed to define the protocol. Keep the optional import at the same boundary as 170-4 and expose the names from the admin signature by their public module, following [the naming rule](../../documentation/maintainers/how-we-name.md). A bare callable without the method or a resolver on stdio is a registration `ValueError` before I/O. The absent and static forms keep 170-4 decision 2. For a resolver, validate configuration and publish only the local server directories at registration. There is no principal at installation to authenticate or discover as.

2. Decided 2026-11-25: apply the local path and operation gate first. Use the open session's caller throughout, including shell pipelines, resumed work and the inbound MCP handler. At a per-user server, more than one subject is `vfs.invalid` with fixed detail and exit 2. Anonymous and system have no named upstream owner and receive `vfs.unauthenticated`, exit 126. Those refusals call no resolver and send nothing. A local hidden or forbidden path retains the earlier gate's classification. The served anonymous-startup inventory can therefore exclude resolver-backed callables, which cannot be called anonymously under any posture. Static registrations keep their full inventory and ordinary mixed-subject meet. Using the actor or first member would widen a delegated call or the meet of a set.

3. Decided 2026-11-25: resolve once on **each** locally admitted tool invocation, including a warm connection, and once on a concrete resource-body read before serving even a cached body. Never memoize a successful resolution as permission to make the next call. The resolution also covers the call's cold initialization and discovery, with zero further callbacks inside any list method, refresh, retry or wire send. Before the first byte of this operation, classify `None`, a returned `ResultError` of any kind, a malformed answer, or an exception from the resolver as a new `classified(ErrorKind.unauthenticated, path)`. Discard the original error and its chain. Require a nonempty ASCII bearer with no whitespace or controls, bounded by 149-2's `MAX_TOKEN_BYTES` before encoding. Local deadline expiry remains `vfs.timeout` and external cancellation propagates. Withdraw this context's snapshot on failed resolution, discard its lease and abort any unused transport locally without sending a protocol close on behalf of the refusal. Never try another subject, a stale bearer, static configuration or the inbound header.

4. Decided 2026-11-25: an ordinary catalogue enumeration never resolves a credential. With no eligible snapshot, an otherwise authorized enumeration or manifest lookup in a per-user catalogue returns `vfs.unauthenticated` at the addressed path, zero private rows and zero wire requests. Global traversal may expose only independently visible local road directories and must preserve the scoped refusal without leaking any private names. To discover before choosing a tool, explicitly `stat` the single server root under its local list right. This point operation may resolve once and warm the caller's connection. Internal probes, batch stat, listing, help and path completion cannot trigger that bootstrap. A first direct `run` at a locally readable tool path or a concrete resource read can also open its own connection. Recheck local rights and installation after a resolver or pool wait and before discovery. Validate the requested descriptor and arguments after discovery, and recheck installation, rights and applicable policy immediately before any effect. A name absent from that caller's snapshot is `vfs.not_found`, exit 127 on invocation, with zero `tools/call`. A warm enumeration uses just the matching snapshot and 170-4's floor. On expiry it may refresh on that same live connection without a resolver. A rejected upstream authorization invalidates that generation and yields `vfs.unauthenticated` at the authorized target, without a retry. Resolve-free reads can reflect an already admitted snapshot until its freshness ends. Removing the server withdraws it immediately.

5. Decided 2026-11-25: key the pool by installation identity and sole subject id. Different subjects never share an owner, transport, cookies, MCP session id, response slot, page, negative lookup, TTL, prompt, resource body or reconnect state, even if the resolver supplies identical bytes. The current generation additionally binds its credential and authority context. Compare the full immutable authority, including actor and scopes, before a read can reuse that context. Equal values from separate HTTP requests qualify. A changed authority context or changed bearer on explicit resolution retires the old generation and invalidates all its snapshots, including in-flight refreshes. Only the matching generation can publish or send. Simultaneous first calls for a key share one initialization and list walk, while each call still obtains its own authorization. Serialize resolution and generation admission per key, release it before awaiting a tool reply. A new credential arriving while an old request is in flight withdraws old admissions immediately. Complete already sent work for its original waiter only, return `vfs.busy` to the new call until the old owner closes, and never replay either request. This keeps one live connection per key and prevents a late callback from reinstalling an older generation. A resumed elicitation resolves afresh after the job gate. Keep only a nonsecret random generation identifier alongside 170-4's installation/subject/revision binding. If rotation, eviction or restart has destroyed the proof of continuity, return the job's conflict before sending its continuation.

6. Decided 2026-11-25: declare `MCP_PRINCIPAL_CONNECTIONS = MCP_SERVER_LIMIT` as one process-local budget **per router across all resolver registrations**. Count reserved, opening, active and closing owners. Keep idle owners in least-recently-used order, refreshing recency on admitted use. For a new authenticated key at capacity, withdraw the oldest idle owner, await its close and then reuse its slot. If all are busy, refuse `vfs.busy`, exit 1, without upstream bytes. Make admission to resolution bounded too: at most `MCP_IN_FLIGHT` simultaneous or queued resolver operations per router, with the same busy failure on excess. An unsuccessful answer cannot evict a different caller. No unbounded per-subject locks, tombstones, queues or reconnect timers survive eviction. Removal, close, cancellation during open and re-registration invalidate the installation reservation and join all its owners, including draining owners, under 170-4 decision 3. Hold the pool lock only for in-memory state transitions. Perform resolution, discovery, transport shutdown and grant checks outside it. The LRU precedent on dev is `src/vfs/storage/backends/database/rights.py:260–309`.

7. Decided 2026-11-25: assemble outbound credentials only at the origin-bound HTTP transport of 170-4. Construct fresh request headers, without inbound headers, cookies, environment proxy credentials, redirected authorization or a fallback bearer. Keep the transport's secret field out of representations, exception chains and diagnostic hooks. At the serving edge compute a process-keyed comparison tag for the current inbound bearer, discard the raw bearer after verification, and carry the private tag with this request's admission only. Compare it to the proposed transport bearer's tag before every credentialed operation, including static registrations and internal discovery. An exact match gives the same local unauthenticated refusal with zero bytes. A live cached listing is also checked before it is exposed or refreshed. Pass this guard explicitly with dispatched work. A supervisor created by the first caller must not inherit that caller's ambient request context. No tag enters `Authority`, a cross-request cache, job state, audit or result. This enforces the inbound-token rule even if a host resolver accidentally returns the inbound value.

8. Decided 2026-11-25: check each bounded upstream reply before publishing any of it. If the active credential appears in peer-controlled wire data, decoded strings or binary media, discard the whole reply and return a fixed `vfs.unavailable.backend` at the admitted local path, exit 1. Check keys as well as values, JSON escapes after decoding, decoded media and final contiguous output before spill, including text assembled from several blocks. Apply the same rule before publishing catalogue snapshots and before persisting elicitation state. No raw frames, SDK request/response objects, resolver diagnostics, HTTP headers, configuration or bearer-derived comparison tags are printable, placed in a row, emitted to a logger, copied into child argv or environment, or submitted to an H0 or kernel-store producer. Construct log facts from the existing typed fields and approved local path. Pass only the checked result to 170-4's run and job publishers. On failures classify outside the caught exception so traceback or `exc_info` cannot retain its message in a record. Keep wire debug/body tracing off on this transport, including dependency loggers, without changing process-wide logging. These are producer checks before serialization, queueing and commit. Filtering a printed URL would miss an error's extra data, the write-behind buffer and an already committed run page.

## Cost

At the [reference deployment](../../AGENTS.md), if every verb call invokes one mounted tool, the host resolves 150,000 times per day, about 20 times a second at peak. Explicit bootstrap and resource reads each cost one resolution per such operation, ordinary listings zero. For a one-page server, 100 calls on a resident key inside the floor cost 100 resolutions, one initialization, one tools list and 100 sends. Cold discovery bounds the four list methods by `4 * MCP_LIST_PAGE_BUDGET` pages per generation. Eviction can make every call cold. There is no per-corpus work.

With 1,000 callers per server, total live owners are bounded by `MCP_SERVER_LIMIT + MCP_PRINCIPAL_CONNECTIONS`, including static owners. A hot key uses 170-4's `MCP_IN_FLIGHT` request budget. Charge retained contexts, credentials, snapshots, staged replacements and reply buffers to the existing bounded router pools before retention, including old generations until joined. Bound copied identity material by `MAX_TOKEN_BYTES` per context: check lengths and member count before encoding, sum the bytes of the two principals, scope strings, provenance, narrowing and source identity, and refuse oversized context as `vfs.invalid` before resolution. LRU lookup and victim selection are constant-time with separate idle order. Credential comparison and echo checks scan bounded bearer and admitted frame/projected bytes with a linear substring matcher. Streaming scans keep at most one credential-length prefix of matching state across fragments. Added SQL, binds, schema changes and writer locks are zero on SQLite, Postgres and the generic floor. Ordinary rights reads and the existing claim/completion transactions retain their own budgets. No database lock spans a resolver or network wait.

## Scope

Extend the 170-4 admin signatures in `src/vfs/base.py` and `src/vfs/sync.py`, its `src/vfs/mcp/client.py`, `catalogue.py` and `supervisor.py`, and the inbound request guard in `src/vfs/mcp/serve.py`. Put the resolver protocol, admission checks and private pool in proposed `src/vfs/mcp/credentials.py` and export the two public types in `src/vfs/mcp/__init__.py`. The listed tests use the prerequisite client, record producers and both storage fixtures. There is no action-log schema change. Host secret acquisition, expiry and rotation policy belong to the host. Interactive OAuth, a credential store, exchange and a multi-subject upstream credential belong outside I4. The host and its resolver are trusted with the material they supply.

## Not checked

Executed an independent loopback HTTP prototype with Python's HTTP client and a bearer-varying peer. One hundred calls under the first subject and one under the second produced 101 resolutions, two initializations, two tool lists, distinct catalogue names and 101 calls. A missing answer and a two-subject proposal added zero peer requests. With two idle slots a third subject evicted the oldest and the next call by that subject initialized a second time. A real child given a clean environment saw none of the synthetic parent sentinel. These were HTTP messages in a sequential oracle, not negotiated MCP sessions.

The MCP SDK is absent in this checkout. SDK framing, debug logging, parallel admission/close, identity changes across a job, actual inbound verification and record scans through H0 could not be exercised end to end because their prerequisite implementations are absent from dev. The disposable Postgres and SQLite probes exercised the real local rights and result paths only. No suite or remote identity service was run.

## Choices to confirm

1. Take an async resolver and a bearer-string alias. A structured credential with expiry, headers or a stable upstream account identifier could be added later. A stable host-declared identity could also permit continuation after eviction; the smaller contract currently refuses it when continuity cannot be proved.
2. Take a cold listing refusal and an explicit point stat to warm the server. Resolving as a side effect of enumeration breaks the counted contract. A separate host priming API could be added later. Point stat works even for a server with only resources and requires no new verb.
3. Take named single subjects only, and exact authority context for warm catalogue reads. Allowing anonymous, system or an actor with changed scopes to reuse a catalogue would require an additional upstream identity or equivalence rule. Broader reuse can be added after that rule exists.
4. Take a router-wide pool initially sized like 170-4's server limit, with idle-only eviction and busy backpressure. A per-server quota or a larger budget can be added without changing the identity key. A generation change retires old admissions and preserves already sent work. Closing active calls to make room would change their outcomes.

## One line

A host resolver selects the upstream bearer for a locally admitted caller, a bounded pool keeps that principal's connection and catalogue private, and only credential-free facts reach results, durable records, logs and child processes.
